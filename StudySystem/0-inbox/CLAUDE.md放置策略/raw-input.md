# CLAUDE.md 放置策略 - 心得原始输入

## 场景描述

如果我有一个项目，项目文件夹下有一个子文件夹，该子文件夹实现主要功能（skills、agent、CLAUDE.md 都放在这个子文件夹下）。但是生成的内容是在项目根目录下。我需要在项目根目录再生成一个 CLAUDE.md 吗？

## 分析

这是一个非常经典的工程目录结构问题。简单来说：**不需要两个完全相同的 CLAUDE.md**，但是否需要根目录放一个，取决于平时习惯在哪个目录下运行 claude 命令行工具。

Claude Code 默认会读取当前终端所在目录下的 CLAUDE.md 作为系统级指令。

## 方案一：直接将 CLAUDE.md 放在项目根目录（🌟 最推荐）

- 如果习惯用 VS Code 或终端打开**整个项目的根目录**，然后输入 `claude`，则应把 CLAUDE.md 放在根目录
- 运作方式：Claude 启动时读取根目录 CLAUDE.md，了解所有 rules、phases 和路径配置
- 路径配置优势：可以清晰定义"skills 和 agent 都在 ./core/ 目录下，生成内容输出到 ./（根目录）"
- 建议：把子文件夹里的 CLAUDE.md 移出来放到根目录，并补充一句："本系统的底层 skill 和 agent 代码存放于 [子文件夹名]/ 目录下"

## 方案二：根目录放"路由/指针"性质的 CLAUDE.md（适合复杂项目）

- 适用于项目很大，根目录还有别的代码/逻辑，不想把长篇指令混在一起
- 采用"双文件策略"，职责分明：
  - **子文件夹 CLAUDE.md**：保持不变，写满具体执行逻辑
  - **根目录 CLAUDE.md**：只写几行作为入口点（Entry point）

### 根目录 CLAUDE.md 示例

```
# 项目根指令

本项目包含一个子系统：Study System。
如果用户要求"学习某某知识"、"整理笔记"或执行工作流，请务必首先读取并严格遵循 `./[子文件夹名]/CLAUDE.md` 中的所有指令和执行计划（Phases）。

生成的笔记内容请放置在根目录下的相应文件夹中。
```

### 优势
- 解耦良好
- 根目录的 Claude 知道去哪里找详细的"说明书"
- 不会把根目录的配置文件搞得太臃肿

## 选择建议：方案一 vs 方案二

### 选方案一（单文件，放根目录）
适合场景：
- **项目功能单一** — 整个项目围绕一个核心任务展开，没有多个子系统
- **团队规模小** — 1-2 人维护，不需要复杂的职责划分
- **核心逻辑自洽** — 项目的 skill、agent、规则都属于同一套体系，拆开反而增加理解成本
- **习惯在根目录启动 Claude** — 终端默认打开项目根目录

典型例子：一个个人博客系统、一个简单的 CLI 工具项目。

### 选方案二（双文件，根目录做路由）
适合场景：
- **项目复杂、有多个子系统** — 比如既有 Study System 又有其他独立模块，各有各的规则
- **多人/多角色协作** — 不同子系统由不同人维护，职责边界清晰
- **不想污染根目录** — 根目录已经有 README、配置文件等大量文件，不想再加一个长篇指令
- **根目录同时是代码项目** — 根目录不"属于"Claude 工作流，Claude 只是其中的一个工具

典型例子：Monorepo 项目、既有业务代码又有 AI 工作流的大型仓库。

### 快速判断表

| 维度 | 方案一（根目录单文件） | 方案二（双文件路由） |
|------|----------------------|-------------------|
| 项目规模 | 小-中 | 中-大 |
| 子系统数量 | 1 个 | 2 个及以上 |
| 根目录文件量 | 较少 | 较多 |
| 维护复杂度 | 低 | 中 |
| 解耦程度 | 低 | 高 |

[来源: 个人经验]
