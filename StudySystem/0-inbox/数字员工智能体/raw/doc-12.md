# n8n vs Dify vs Coze vs LangGraph 完整对比

## 四款工具的定位

### n8n
开源可自托管的可视化自动化与Agent编排平台。拖拽节点串联合，强调将Agent嵌入**更大的业务流程**中。适合把AI能力转化为对外可售的服务或API。

### LangGraph
代码优先（Python/TS）的状态机式Agent框架。通过代码定义`StateGraph`，节点、边、条件路由全部在代码层显式编排。内置检查点记忆、长时运行与中断机制。

### Dify
开源AI应用低代码框架，聚焦"把LLM应用低代码打包上线"（RAG、工具调用、对话等），更像一个"应用工厂"。

### Coze
AI-first的封闭平台，极简的bot/助手搭建体验，但深度定制与跨系统编排时边界明显。

## 总览对比

| 维度 | n8n | Dify | Coze | LangGraph |
|------|-----|------|------|-----------|
| 核心定位 | 可视化自动化+Agent编排 | 低代码LLM应用工厂 | 快速做bot的封闭平台 | 代码优先的Agent状态图 |
| 落地速度 | 快（拖拽+模板+海量集成） | 快（应用级） | 最快（平台内闭环） | 视团队代码能力 |
| 控制粒度 | 中等（可插代码/条件/子流程） | 中（应用参数化） | 低 | 最高 |
| 多代理/记忆 | 有 | 有 | 有限 | 原生多智能体+检查点 |
| 集成生态 | 500+预置+HTTP+Webhook | 以LLM应用为主 | 平台内置为主 | LangChain生态与Python包 |
| 对外变现 | 工作流暴露为API/端点 | 应用对外发布 | 平台内能力为主 | 以代码/服务形态 |

## 选型决策

1. **是否需要强可编程控制与多智能体协作？** → 是：LangGraph
2. **是否需要快速对接大量外部系统？** → 是：n8n
3. **核心需求是快速打包LLM应用？** → Dify
4. **其他→ Coze（最快出原型场景）

## 组合使用方案

| 组合 | 分工方式 |
|------|---------|
| LangGraph + n8n | LG编排智能体内核，n8n承担流程一体化与对外API |
| Dify + n8n | Dify输出对话/RAG应用，n8n负责触发→审批→分发→计费 |
| Coze + n8n | Coze快速做bot MVP，n8n作为"自动化外骨骼" |

## 核心结论

> "没有'最好'的工具，只有'最合适'的组合。"

对于追求业务落地的团队，推荐的黄金组合是 **LangGraph + n8n**，将智能体内核的工程化控制与业务流程的灵活编排相结合。
