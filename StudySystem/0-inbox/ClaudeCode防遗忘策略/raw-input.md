# 用户原始输入：如何 100% 确保 Claude Code 执行工作流（防遗忘策略）

## 核心误区：试图用 Hook 强制 AI "读规划"

在工作流的关键节点触发 Hook 来提醒 AI 读规范，这种思路在实际操作中是一种反模式（Anti-pattern），原因有三：

1. **触发机制错位**：Hook 是基于"物理工具调用"（如 Write 文件、执行 Bash）触发的系统事件。AI 的"思考完毕"或"阶段结束"没有物理触发器，Hook 无法精准在对话中间拦截。

2. **灾难级的 Token 浪费**：如果用 Hook 把规范强行塞回终端，Context Window 会被重复的规则文本塞满，不仅极其费钱，还会导致 AI 彻底丧失对有效信息的注意力。

3. **大模型的惰性**：即便 Hook 把规则怼到了 AI 脸上，大模型依然可能回复"好的了解"，然后继续跳过步骤。

## 解决方案：三层防跳步架构设计

要保证长线工作流被严格执行，不能靠"反复念经"，而必须将抽象的"规范"转化为具体的"系统约束"或"文件读写动作"。

### 防御一层：剥夺执行权（用 Hook 兜底纯机械步骤）

对于不需要动脑的体力活，不要指望 AI 记住，直接用系统脚本替它执行。

- **适用场景**：代码保存后的 Lint 格式化、Docker 配置文件修改后的 `docker-compose up -d` 自动重启
- **实现方式**：在 `settings.json` 配置 PostToolUse Hook。一旦监听到特定文件被写入，宿主机底层自动静默执行脚本。规范因此被 100% 物理执行。

### 防御二层：状态机模式（用 TODO.md 倒逼 AI 守规矩）

解决长流程遗忘最经典的工程手段。把短期记忆（Context）变成长期记忆（硬盘文件）。

- **原理**：大模型对"调用工具读写文件"的执行力，远高于"在脑子里记住某件事"

- **实现方式**：在 Skill 中写入如下强制 SOP：
  1. 任务开始前，必须在当前目录创建 `SETUP_TODO.md`，列出所有阶段
  2. 每完成一个阶段，必须调用 `Write` 工具在文件里打上 `[x]`
  3. 在进入下一个阶段前，必须调用 `Read` 工具检查文件，确认上一步已完成

### 防御三层：设置"红绿灯"（利用 MCP/自定义脚本做阶段验收）

在极度危险或关键的阶段切换时，强制打断 AI，拉起人类或脚本进行验收。

- **原理**：伪造一个只有得到人类或脚本确认才能返回"通行证"的工具
- **实现方式**：编写一个简单的本地校验脚本或 MCP 工具（如 `finish_stage`）。在 Skill 中规定："严禁擅自进入下一阶段。当前阶段做完后，必须调用 `finish_stage` 工具，等待校验返回的绿灯结果后，才能继续。"

## 架构总结：完美的工作流金字塔

在运维开发环境中，理想的工作流调度应该长这样：

- **宏观思考层（Skill + TODO.md）**：Skill 负责下发拆解好的小步骤 SOP，并强制 AI 维护一个实体进度文件
- **微观机械层（Hook）**：接管所有收尾、格式化、重启等固定动作，把 AI 从琐事中解放出来
- **监督校验层（MCP/本地 Checkpoint）**：在极度危险或关键的阶段切换时，强制打断 AI，拉起人类或脚本进行验收
