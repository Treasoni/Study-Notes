# 舍弃记录

## 本次整理：无舍弃

经过对所有 16 篇原始资料的系统分析，本次整理**未舍弃任何来源**。

### 原因分析

所有资料的内容相互补充，无完全重复的情况：

| 资料对 | 看似重叠的部分 | 实际差异 |
|--------|---------------|----------|
| R01 + R06 | 都介绍核心哲学 | R01 是项目概览和快速入门，R06 是深度概念参考 |
| R02 + R12 | 都是入门教程 | R02 是官方深色模式示例（新版命令），R12 是社区厨房计时器（旧版命令），展示不同的使用场景和命令风格 |
| R04 + R05 | 都涉及工作流命令 | R04 是命令的语法参考，R05 是工作流的哲学和状态机原理 |
| R06 + R13 | 都解释核心概念 | R06 是官方概念文档（完整权威），R13 是社区个人博客（带有个人见解和对比） |
| R13 + R16 | 都包含对比分析 | R13 的对比是简要表格，R16 是详细的四维度对比（vs SuperPowers/Spec Kit/Kiro/no-SDD） |
| R14 + R06 | 都介绍核心概念 | R14 是 10 分钟快速入门博客，侧重最佳实践和 FAQ，面向中文初学者 |

### 高重叠但不舍弃的理由

R12（Gigazine）虽然时效性较低（2025-10）且使用旧版命令语法（`/openspec-proposal` 而非 `/opsx:propose`），但它是**唯一完整的端到端第三方教程**，展示了从零到一的完整流程，与官方教程互补。保留作为历史参考和不同使用模式的示例。

R15（Reddit）虽然权威性低（个人 Reddit 帖子）且时效性不确定（仅标注 2026 年），但它是**目前唯一的 OpenSpec 真实世界使用经验分享**，提供了官方文档无法覆盖的实际使用模式和问题，具有独特价值。
