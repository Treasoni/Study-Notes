# 第四章：诊断命令组 —— info / jobs / resolution

> [!summary] 本章讲什么
> 本章讲三组排障利器：`ha info`（系统总览）、`ha jobs`（后台任务队列）、`ha resolution`（Supervisor 健康检查）。掌握 `done: null` 堆积的已知 bug 处理、`Another job is running` 报错排查，以及一套「总览 → 任务 → 健康」的诊断组合拳。

系统报错、行为诡异、升级失败……这类时刻你需要的不再是"操作命令"，而是"诊断命令"。这一章讲三组排障利器：`ha info`（系统总览）、`ha jobs`（后台任务队列）、`ha resolution`（Supervisor 健康检查）。学会它们，你就能在系统出问题时先看清全局，再定位病灶。

## ha info：系统总览

`ha info` 是最先该敲的命令，它一行汇总了整台设备的关键信息：

```bash
ha info
```

输出的关键字段：

| 字段 | 含义 | 排障价值 |
|------|------|---------|
| `arch` | 架构（aarch64/amd64/x86_64） | 确认系统架构是否被官方支持 |
| `channel` | 更新渠道（stable/beta/dev） | 判断当前是否在激进渠道 |
| `docker` | Docker 版本 | 过低版本会触发 unsupported |
| `hassos` | HAOS 版本 | 确认 OS 是否落后 |
| `homeassistant` | Core 版本 | 确认 Core 是否落后 |
| `hostname` | 主机名 | — |
| `machine` | 设备型号（树莓派/NUC 等） | — |
| `supervisor` | Supervisor 版本 | 升级第一优先级 |
| `timezone` | 时区 | 时区错误会影响自动化触发 |
| `supported_arch` | 支持的架构列表 | 判断当前架构是否被支持 |

配套的还有 `ha core info`、`ha supervisor info`、`ha os info` 可以分别看每一层的详细版本。查版本落后情况、确认渠道，一个 `ha info` 就够。

## ha jobs：后台任务队列

Supervisor 后台跑着一堆任务（升级、备份、重建容器等）。`ha jobs` 让你看到它们在排队还是卡住了。

```bash
# 查看运行中/排队任务
ha jobs info
```

输出要点：每个任务有 `name`、`state`（running/success/failed）等字段。最典型的问题是看到 **`done: null` 的任务越积越多** —— 这是已知 bug（备份子任务未被清理），堆积时会导致内存高、后续任务无法排队。

当遇到 `Another job is running for job group home_assistant_core` 这类报错，说明有任务卡住占用了 job group：

```bash
# 查看卡住的任务
ha jobs info

# 重置任务队列
ha jobs reset
```

> [!tip] 处理顺序
> 先 `ha jobs info` 确认有 stuck job → `ha jobs reset` 清掉堆积 → 如果还不行，`ha core stop` 再 `ha core restart --safe-mode` → 最后手段是重启宿主机。卡住的常见诱因包括某些集成（如 Entso-e）长时间占用任务。

`ha jobs options` 还可以管理任务运行条件（如允许/禁止某类任务并发）。

## ha resolution：Supervisor 健康检查

`ha resolution` 是 Supervisor 自带的体检报告，它会列出系统检测到的所有问题（issues）、建议（suggestions）和健康检查（checks）。

```bash
# 查看当前所有问题/建议
ha resolution info
```

输出的三块：

| 区块 | 含义 | 示例 |
|------|------|------|
| `checks` | 健康检查项 | 各检查项的 pass/fail |
| `issues` | 检测到的问题 | `unsupported: job_conditions` |
| `suggestions` | 针对问题的修复建议 | 建议关闭某条件 |

### 手动触发健康检查

```bash
# 立即运行一次健康检查
ha resolution check run

# 查看各检查项状态
ha resolution healthcheck
```

### 处理问题与建议

```bash
# 忽略某个问题（不想让它再报警）
ha resolution issue dismiss <slug>

# 应用某个建议
ha resolution suggestion apply <slug>

# 忽略某个建议
ha resolution suggestion dismiss <slug>
```

实战场景：当 Web UI 顶部出现 "This system is unsupported / unhealthy" 的黄色警告横幅，先用 `ha resolution info` 看具体是什么问题，再决定是修复（`suggestion apply`）还是确认无害后忽略（`issue dismiss`）。比如常见的 `unsupported: job_conditions`，就可以通过关闭对应条件或应用建议来解决。

### 排障组合拳

把三组命令串成一套诊断流程：

```bash
# 1. 全局总览
ha info

# 2. 有没有卡住的任务
ha jobs info

# 3. Supervisor 发现了什么问题
ha resolution info

# 4. 手动跑一次健康检查
ha resolution check run
```

按这个顺序，从"版本/渠道"到"任务队列"再到"健康问题"，基本能覆盖 90% 的"系统哪里不对劲"的场景。如果这三步都没发现问题，再看日志（`ha core logs -f`、`ha supervisor logs -f`）。

## 本章小结

- `ha info` 是系统总览第一命令：一个输出里含 arch/channel/docker/hassos/homeassistant/supervisor/timezone 等关键字段，排障前先敲它。
- `ha jobs info` 看后台任务队列；`done: null` 堆积是已知 bug，用 `ha jobs reset` 清掉；`Another job is running` 报错按"查 jobs → reset → 安全模式重启 → 重启主机"的顺序处理。
- `ha resolution info` 输出 checks/issues/suggestions 三块；`check run` 手动体检、`issue dismiss` 忽略问题、`suggestion apply` 应用建议。
- 标准诊断组合拳：`ha info` → `ha jobs info` → `ha resolution info` → `ha resolution check run`。

下一章讲数据安全中最关键的一环：备份与恢复。`ha backups` 命令组能让你在命令行里完成全流程备份、查看备份、以及灾难后的恢复。
