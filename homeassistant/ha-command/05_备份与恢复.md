# 第五章：备份与恢复 —— backups

> [!summary] 本章讲什么
> 本章讲 `ha backups` 命令行备份恢复全流程：full vs partial 的区别、备份加密与 emergency kit 密钥机制、`new/list/info/restore/remove/options` 等子命令实战，一条灾难恢复链路，以及用 `hassio.backup_full` 做自动化全量备份的建议。

升级翻车、硬盘损坏、误删配置……这时候唯一能救你的就是备份。`ha backups` 命令组让你在命令行里完成创建备份、查看备份、恢复备份的全流程。这一章会讲清楚 full vs partial 的区别、备份加密与密钥机制，以及一条完整的灾难恢复链路。

## 备份的核心概念

先建立两个概念，否则后面命令会踩坑。

### full vs partial

| 类型 | 内容 | 何时产生 |
|------|------|---------|
| **full（全量）** | 所有 addon + 所有文件夹 + Core 配置 | 通过自动化 `hassio.backup_full`、或 Web UI 显式全量备份 |
| **partial（部分）** | 只含指定的文件夹/addon | 命令行 `ha backups new` 不带 `--app/--folders` 时容易产出 partial |

> [!warning] `ha backups new` 默认易产出 partial
> **`ha backups new` 默认经常产出 partial**，而"可完整恢复的备份"建议用自动化调 `hassio.backup_full` 服务（compressed: true）。所以日常自动化备份，优先用 `hassio.backup_full`，而不是命令行。

### 备份加密与密钥

- 备份用 **AES-128 加密**，加密密钥只保存在 emergency kit（应急套件）里，Nabu Casa 不存。
- 如果你更换了密钥，**旧的备份只能拿旧密钥解密**——所以换密钥前要想清楚，旧备份要不要留着。
- 恢复时的 `--password` 参数是**备份加密密钥**（Web UI 里配置的那个），不是你的用户登录密码。这是恢复操作最常见的错误来源。

## ha backups 子命令实战

### 创建备份

```bash
# 创建一个带名字的备份
ha backups new --name "before-upgrade-2026-08"

# 带加密密码的备份
ha backups new --name "encrypted" --password "your-encryption-key"

# 部分备份：只备份指定的 addon 和文件夹
ha backups new -a core_mosquitto -f homeassistant --name "partial-backup"

# 备份时排除 Core 数据库
ha backups new --homeassistant-exclude-database --name "no-db"

# 指定备份位置（如果有多个备份位置）
ha backups new -l /backup --name "to-network"

# 不压缩
ha backups new --uncompressed
```

参数速查：

| 参数 | 作用 |
|------|------|
| `--name` | 备份显示名 |
| `--password` | 备份加密密钥 |
| `-a/--app` | 指定要包含的 addon（partial 备份用） |
| `-f/--folders` | 指定要包含的文件夹（partial 备份用） |
| `-l/--location` | 备份位置 |
| `--homeassistant-exclude-database` | 排除 Core 的数据库 |
| `--uncompressed` | 不压缩 |

### 查看备份

```bash
# 列出所有备份（裸 ha backups 默认就是 list）
ha backups list

# 查看某个备份的详情（能区分是 full 还是 partial）
ha backups info <slug>
```

`info <slug>` 输出里能看到这个备份的类型（full/partial）、包含哪些 addon 和文件夹、创建时间、大小。恢复前**必看**，确定要恢复哪些内容。

### 恢复备份（灾难恢复核心）

```bash
# 恢复整个全量备份
ha backups restore <slug>

# 恢复时指定加密密钥（注意：是备份加密密钥，不是登录密码）
ha backups restore <slug> --password "your-encryption-key"

# 部分恢复：只恢复某些文件夹和 addon
ha backups restore <slug> --folders homeassistant --app core_mosquitto
```

> [!warning] partial 恢复必须显式指定内容
> 恢复 partial 备份时**必须显式指定 `--folders` 或 `--app`**，否则会报错。常见报错 `only a partial backup` 就是没指定恢复内容；而 `--password` 被拒，基本就是拿登录密码当加密密钥了。

### 管理备份

```bash
# 删除备份
ha backups remove <slug>

# 设置"过期"策略：超过多少天的备份标记为 stale（默认 30 天）
ha backups options --days-until-stale 30

# 暂停/解冻备份引擎
ha backups freeze
ha backups thaw

# 重载备份列表（新备份文件放到目录后刷新）
ha backups reload
```

> CLI 没有 `download` 子命令。下载备份文件需要走 Web UI（Settings > System > Backups），命令行只能管理本地备份。

## 灾难恢复完整链路

把上面的命令串成一条灾难恢复流程：

```bash
# 1. 列出所有可用备份
ha backups list

# 2. 查看目标备份详情，确认类型与内容
ha backups info <slug>

# 3. 恢复（partial 必须指定内容，加密备份要带密钥）
ha backups restore <slug> --folders homeassistant --app core_mosquitto --password "your-encryption-key"

# 4. 恢复后确认 Core 起来了
ha core info
```

如果是全量备份，直接 `ha backups restore <slug> --password ...` 即可，恢复完成系统会自动重启。

## 自动化全量备份建议

命令行适合手动备份；真正的安全要靠定时自动化。建议用自动化调用 `hassio.backup_full` 服务：

```yaml
alias: Daily full backup
trigger:
  - platform: time
    at: "03:00:00"
action:
  - service: hassio.backup_full
    data:
      name: "Daily backup {{ now().strftime('%Y-%m-%d') }}"
      compressed: true
```

这样的备份才是**可完整恢复的全量备份**，且会自动压缩，比命令行 `ha backups new` 更可靠。

## 本章小结

- `ha backups new` 创建备份（注意默认易产出 partial）；要全量可恢复备份，用自动化 `hassio.backup_full` 服务。
- `ha backups list` / `info <slug>` 查看备份，`info` 能区分 full 与 partial。
- `ha backups restore <slug>` 恢复备份：partial 必须显式 `--folders/--app`；`--password` 是**备份加密密钥**，不是登录密码。
- 备份 AES-128 加密，密钥只在 emergency kit；换密钥后旧备份需旧密钥。
- 灾难恢复链路：`list` → `info` → `restore --folders/--app/--password` → `core info` 验证。
- CLI 没有 download 子命令，下载备份走 Web UI。
