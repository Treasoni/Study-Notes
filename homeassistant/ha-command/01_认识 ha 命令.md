# 第一章：认识 ha 命令

> [!summary] 本章讲什么
> 本章讲清 `ha` 命令的本质（Supervisor REST API 的 1:1 封装）、它只存在于 HAOS / HA Supervised 两种环境、三种进入终端的方式，以及 `ha` 与已弃用 `hass-cli` 的命名澄清，最后给出全局 flags 速查，为后面几章的实战打底。

当你想在终端里管理 Home Assistant，却不知道 `ha` 到底能干什么、为什么敲下去提示 `command not found`，这一章就是你的起点。我们会先讲清楚 `ha` 命令的本质、它只活在哪些环境里、怎么进到能敲它的终端，最后给出全局 flags 速查，为后面几章的实战打底。

## ha 命令是什么

`ha` 是 Home Assistant 官方提供的命令行工具（前身叫 `hassio-cli`，2020 年改名为 `ha`）。它的语法高度统一：

```bash
ha <group> <command> [args] [flags]
```

从本质上讲，`ha` 是对 **Supervisor REST API** 的 1:1 封装。你在终端里敲的每一句 `ha`，背后都是一次对 Supervisor 的 HTTP 请求。[官方文档](https://www.home-assistant.io/common-tasks/command-line/) 把这一点说得很直白：理解了这个结构，你就明白为什么 `ha` 命令的形态如此规整 —— 每个命令组对应 Supervisor 的一个功能域，每个子命令对应一个 API 端点。

### 19 个顶层命令组

`ha` 顶层一共约 19 个命令组，覆盖了 Supervisor 的全部管理面：

| 命令组 | 职责 | 使用频率 |
|--------|------|---------|
| `ha core` | 管理 Core（Home Assistant Python 应用本体） | 高频 |
| `ha supervisor` | 管理 Supervisor（管理/编排层） | 高频 |
| `ha addons` | 管理 Addon（开发版改名为 `ha apps`） | 高频 |
| `ha host` | 宿主机管理 | 高频 |
| `ha os` | HAOS 操作系统管理 | 高频 |
| `ha network` | 网络配置 | 高频 |
| `ha hardware` | 硬件信息 | 中 |
| `ha info` | 系统总览 | 高频 |
| `ha jobs` | 后台任务队列 | 排障用 |
| `ha resolution` | 系统健康问题/建议 | 排障用 |
| `ha backups` | 备份与恢复 | 高频 |
| `ha audio` | 音频引擎 | 低 |
| `ha dns` | 内部 DNS 解析 | 低 |
| `ha docker` | Docker 后端 | 低 |
| `ha multicast` | 组播服务 | 低 |
| `ha observer` | Observer 组件 | 低 |
| `ha cli` | `ha` 工具本体升级 | 低 |
| `ha banner` | 打印欢迎横幅 | 低 |
| `ha auth` | 用户认证管理 | 低 |

> 开发版（dev channel）还新增了 `ha mounts`、`ha security`、`ha store` 三组，尚未进入官方 19 组文档，暂不展开。

本书会在后续章节把高频组逐个讲透，低频组统一收进第八章速查表。

## ha 命令只存在于哪些环境

这是全书最重要的一条前提：**`ha` 命令只存在于 HAOS 与 HA Supervised 这两种带 Supervisor 的部署方式里。**

| 部署方式 | 有没有 `ha` 命令 | 说明 |
|---------|-----------------|------|
| HAOS | 有 | 官方系统镜像，系统控制台直接可敲 |
| HA Supervised | 有 | 宿主机 shell 里敲；找不到时用 `docker exec` 进 CLI 容器 |
| Docker Container | **没有** | 只有 Core 容器，没有 Supervisor |
| Core（venv 直装） | **没有** | 仅一个 Python 进程，无 Supervisor |

> [!warning] 环境前提
> 这一点直接和部署方式的选择挂钩：如果你当初用的是 [[Home Assistant 三种部署方式对比与选型]] 里的 Docker Container 或 Core 直装方案，本笔记的大部分命令对你都不适用 —— 你需要走 Supervisor REST API 或 `hassio.*` 服务。

另外，Home Assistant 官方已宣布从 2025-12 起弃用 Core（venv）/Supervised 安装模式与 32-bit 系统，只支持 HAOS 与 Container 两种方式，架构仅剩 aarch64/amd64。[官方公告](https://community.home-assistant.io/t/deprecating-core-and-supervised-installation-methods-and-32-bit-systems/893617/3)

## 三种进入终端的方式

要在 HAOS 上敲 `ha`，先得有终端。三种主流方式：

| 方式 | 特点 | 适用场景 |
|------|------|---------|
| SSH & Web Terminal addon | root 登录，Bash 自带 `ha` 命令补全；可访问宿主机 D-Bus/音频/UART/GPIO/Docker | 推荐首选，日常运维 |
| Studio Code Server（VS Code） | 图形化编辑器内嵌终端；仅支持 AMD64/aarch64 | 边改配置边敲命令 |
| HAOS 系统控制台 | 键盘+屏幕直连；提示符为 `HA>` | 本地紧急操作；部分本地终端专用命令仅此处可执行 |

SSH & Web Terminal 是官方推荐终端方案，安装后即可在 Web UI 里打开终端页面，也可以走 SSH 从外部登录。[Advanced SSH & Web Terminal](https://github.com/hassio-addons/app-ssh) 是社区增强版，功能更丰富。

### 进入终端与 command not found 应急

HAOS 系统控制台默认停在 `HA>` 提示符，输入 `login` 进入 root shell 才能敲 `ha`：

```bash
HA> login
# 进入 root shell 后：
ha info
```

如果是 HA Supervised 部署、宿主机 shell 里提示 `command not found`，说明 `ha` 命令封装在 CLI 容器里，用 Docker 进入：

```bash
docker exec -it hassio_cli bash
# 进入后即可使用 ha 命令
ha supervisor info
```

## 命名澄清：ha vs hass-cli

两个名字很容易混，但完全是两回事：

| 工具 | 本质 | 管理对象 | 现状 |
|------|------|---------|------|
| `ha` | Supervisor REST API 的 CLI 封装 | 系统层（Supervisor/Core/Addon/OS） | 当前官方工具，本笔记主角 |
| `hass-cli` | 独立的 Python 客户端 | Core 层（实体/服务/状态） | 已弃用，勿再使用 |

同样地，`ha core` 与 `ha supervisor` 也要分清：

- `ha core` 管理的是 Core —— 那个跑自动化、处理实体状态的 Python 应用；
- `ha supervisor` 管理的是 Supervisor —— 编排层，负责管理容器、Addon、系统组件。

一句话记忆：**Core 是"房子"，Supervisor 是"物业公司"，`ha` 命令是找物业公司办事的对讲机。**

## 全局 flags 与环境变量

`ha` 的所有全局 flags 都支持用 `SUPERVISOR_` 前缀的环境变量替代，这让远程调用成为可能：

| Flag | 作用 | 对应环境变量 |
|------|------|-------------|
| `--api-token string` | Supervisor API token（远程必填） | `SUPERVISOR_API_TOKEN` |
| `--endpoint string` | Supervisor 端点（默认 `supervisor`，远程 `http://IP:PORT`） | `SUPERVISOR_ENDPOINT` |
| `--config string` | 配置文件（默认 `$HOME/.homeassistant.yaml`） | — |
| `--log-level string` | 日志级别（默认 WARN） | `SUPERVISOR_LOG_LEVEL` |
| `--no-progress` | 禁用进度动画 | — |
| `--raw-json` | 输出原始 JSON（脚本解析友好） | — |
| `-h/--help` | 帮助；`ha <group> --help` 看子命令 | — |

本地环境下直接用 `ha <group> --help` 就能看到该组所有子命令，这是探索未知命令组的第一入口，也是后面各章的通用技巧。

## 本章小结

- `ha` 命令语法是 `ha <group> <command> [args] [flags]`，本质是 Supervisor REST API 的 1:1 封装，共约 19 个顶层命令组。
- `ha` **只存在于 HAOS 与 HA Supervised**；Docker Container / Core 直装没有此命令，这是最常见的误用场景。
- 进入终端有三条路：SSH & Web Terminal（推荐）、VS Code addon、HAOS 系统控制台（`HA>` 提示符下先 `login`）。
- `ha` ≠ `hass-cli`：前者管系统层，后者已弃用；`ha core` 管 Core 应用，`ha supervisor` 管编排层。
- 全局 flags 可用 `SUPERVISOR_*` 环境变量替代，是远程调用的基础。

下一章进入实战，我们从最高频的三个命令组开始：`ha core`、`ha supervisor`、`ha addons`，把它们常用的子命令和参数逐个过一遍。
