# 客户A · 维护手册

> 每月例行 + 季度巡检的执行清单。**更新节奏的事实修正见 §0**——HA 不是自动更新的，必须主动维护。

## 0. 事实修正（重要）

> ❌ 旧认知：「HAOS ~8h OTA 自动更新」。
> ✅ 事实（2026-08 核实）：HA 每月发布（首个周三），**OS/Core 无原生用户可配置自动更新**，仅 Supervisor 自更新。有社区定时更新方案（scheduled-update blueprint），但默认必须**人工安排更新窗口**。

**影响**：「可持续维护」= 主动执行每月维护窗口，不能靠系统自动推送。

## 1. 每月例行维护（远程，15–30 分钟）

| # | 步骤 | 命令/入口 |
|---|------|----------|
| 1 | **先做快照备份**（铁律） | Supervisor → 备份 → 立即备份（或 API） |
| 2 | 更新 HAOS OS/Core | Supervisor → 更新（有更新才升；大版本升级前先查风险清单 §3） |
| 3 | 更新 Agent / 组件 | Agent 仓库 `git pull` → 重建镜像；HACS 组件如有 |
| 4 | 更新 NAS/UGOS（延迟 1–2 天追新版） | NAS 控制面板；看社区反馈再升 |
| 5 | 检查设备在线 | 告警自动化 + 手动抽查；处理离线设备 |
| 6 | 验证备份可恢复 | 抽查快照文件大小/时间戳；每季度做一次真实恢复演练 |
| 7 | 检查告警/日志 | HA 日志、Frigate 事件、NAS 存储与硬盘健康 |
| 8 | 输出简报 | 更新内容、处理事项、剩余风险 → 微信/邮件给客户（一句话版） |

## 2. 每季度深度巡检

| # | 内容 |
|---|------|
| 1 | 风险清单复查（§3），核对 HA 大版本/厂商公告 |
| 2 | 空调季节曲线、窗帘作息校准（夏→冬切换） |
| 3 | NAS 硬盘健康（SMART）、存储空间、阵列状态 |
| 4 | 摄像头存储轮换与关键录像抽查 |
| 5 | 异地备份盘实际恢复一次（把 HA 快照恢复到测试机） |
| 6 | 更新客户使用手册（如功能有变） |
| 7 | DeepSeek 模型名/参数、各品牌集成版本核对（ch8.4 机制） |

## 3. 风险清单复查（复用笔记 ch8.4 的 6+9 机制，客户化）

**通用 6 项（对全部客户）**

- [ ] Supervised 弃用状态（本项目不用，确认不漂移）
- [ ] DeepSeek 模型名/价格/API 变更（当前 `deepseek-v4-flash`）
- [ ] 镜像链可用性（ghcr fallback 链各源是否仍通）
- [ ] `xiaomi_home` 版本与 HA 兼容（当前锁 v0.4.7）
- [ ] Frigate / 组件版本
- [ ] 华为等无路径品牌确认（如有客户意向）

**客户A 专属**

- [ ] 美的 V3 token / 米家账号授权是否失效（token 有时效）
- [ ] 涂鸦本地 local_key 是否仍有效（若用）
- [ ] 摄像头 RTSP 流是否正常
- [ ] 中枢网关在线、固件更新
- [ ] 壁挂平板 kiosk 是否卡死/令牌失效
- [ ] 异地备份盘同步是否正常
