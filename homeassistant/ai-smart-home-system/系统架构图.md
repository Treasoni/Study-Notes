# 系统架构图：跨品牌 AI 智能家居一键部署系统

> 四层架构：**用户交互层 → 智能体层 → 核心平台层 → 基础设施层**，配合云端 LLM 与跨品牌设备接入。完整构建细节见 [[基于 Home Assistant 的跨品牌 AI 智能家居一键部署系统]]。

## 架构总览

```mermaid
flowchart TD
    subgraph L1["① 用户交互层"]
        WE["微信 / WeChat"]
        APP["HA App"]
        WEB["Web 前端"]

    end

    subgraph L2["② 智能体层（Python FastAPI Agent）"]

    subgraph L3["③ 核心平台层（Home Assistant Container）"]

        SCENE["场景 packages<br/>回家 / 离家 / 睡眠"]

    subgraph L4["④ 基础设施层（Docker Compose + 国内镜像链）"]

    MATTER["Matter / MQTT / Zigbee 兜底"] -.-> BRAND
```

## 数据流示例：「把客厅灯调暗」

```mermaid
sequenceDiagram
    participant U as 用户（微信/Web）
    participant A as FastAPI Agent
    participant D as DeepSeek v4-flash
    participant H as Home Assistant
    participant S as 灯（米家/涂鸦…）

    U->>A: 把客厅灯调暗
    A->>D: chat.completions（tools=control_device）
    D-->>A: tool_call(entity_id=客厅灯, service=turn_on, brightness=100)
    A->>H: POST /api/services/light/turn_on
    H->>S: 局域网/云下发指令
    S-->>H: 状态更新
    H-->>A: 200（变更后状态）
    A->>D: 工具结果回填（tool_choice=none）
    D-->>A: 「客厅灯已调暗」
    A-->>U: 客厅灯已调暗
```

## 分层说明

| 层 | 职责 | 关键组件 | 备注 |
|----|------|----------|------|
| ① 用户交互层 | 多入口触达 | 微信 / HA App / Web / 语音 | MVP 用微信 + Web，不做语音硬件 |
| ② 智能体层 | 自然语言 → 设备控制 | FastAPI + DeepSeek Function Calling、entity_map、工具白名单 | 单轮 N=1，不套 LangChain/编程 Agent |
| ③ 核心平台层 | 设备管控 + 自动化 | HA Core、Automation/Blueprint、场景 packages、跨品牌集成 | Container 官方路径，Supervised 已弃用 |
| ④ 基础设施层 | 编排与部署 | docker-compose、ghcr 回退链、.env | host 网络 + TZ=Asia/Shanghai |
