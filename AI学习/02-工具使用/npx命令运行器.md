# npx 命令运行器

> [!info] 概述
> **一句话定义**：npx 是 npm 自带的命令运行器，允许从 npm 包（本地或远程）运行任意命令，无需全局安装。
>
> **通俗比喻**：npx 就像餐厅的「按需点餐」服务——你不需要提前买好所有食材（全局安装包），只需要告诉服务员你想吃什么（指定包名），厨房就会临时准备（按需下载）并上菜（执行命令）。

## 核心概念

### 是什么

npx 是随 npm 5.2.0 引入的命令行工具，作为 npm 的内置命令运行器。它的核心定位是**类似于通过 `npm run` 运行脚本，但更加灵活，可执行任意包命令**。

### 为什么需要

在使用 Node.js 开发时，我们经常需要运行各种命令行工具（如 eslint、prettier、create-react-app 等）。传统做法是全局安装这些工具，但这会带来以下问题：

- 全局环境污染
- 版本管理混乱
- 多项目间切换困难

npx 解决了这些问题，**避免污染全局环境，远程包按需下载使用**。

### 通俗理解

可以将 npx 想象成一个「临时工调度中心」：

- 你不需要养一个全职员工（全局安装）
- 需要时打个电话叫人来帮忙（npx 调用）
- 任务完成后自动离开（不占用全局空间）

## 命令格式

### 基本语法

npx 支持多种命令格式，通过位置参数、`--package` 选项或 `-c` 参数指定要执行的包和命令。

| 格式 | 说明 |
|:---|:---|
| `npx -- <pkg>[@<version>] [args...]` | 执行指定包的默认命令 |
| `npx --package=<pkg>[@<version>] -- <cmd> [args...]` | 执行包中的特定命令 |
| `npx -c '<cmd> [args...]'` | 执行任意 shell 命令（需加引号） |
| `npx --package=foo -c '<cmd> [args...]'` | 指定包并执行 shell 脚本 |

## 核心功能

### 主要特性与行为

npx 具有智能包管理、版本匹配、安装提示等功能，确保命令正确执行：

| 特性 | 说明 |
|:---|:---|
| **PATH 自动配置** | `--package` 指定的包会自动添加到执行命令的 PATH 中 |
| **按需安装** | 如果包不在本地依赖中，会自动安装到 npm 缓存并添加到 PATH |
| **安装确认提示** | 安装前会显示提示，可用 `--yes` 或 `--no` 抑制（v7+） |
| **版本匹配规则** | 不带版本说明匹配本地版本，带版本说明则必须完全匹配 |

### 命令推断规则

当未指定 `-c` 或 `--call` 时，npx 根据包的 `bin` 字段和包名自动推断要执行的命令：

1. **单一 bin 条目**：如果包的 `bin` 字段只有一个条目，直接使用该命令
2. **多个 bin 条目**：如果包有多个 bin 条目且其中一个匹配包名，使用该命令
3. **无法推断时**：当有多个 bin 条目且无匹配时，报错提示用户明确指定命令

## 实践示例

### 执行本地依赖中的工具

直接运行本地已安装的包（如 tap）的默认命令：

```bash
npx tap --bail test/foo.js
```

*说明：运行本地 tap 包测试文件*

### 指定包运行特定命令

使用 `--package` 指定包名，然后用不同命令名执行：

```bash
npx --package=foo bar --bar-argument
```

*说明：执行 foo 包中的 bar 命令*

### 组合命令执行

通过 `-c` 执行包含多个命令的 shell 脚本：

```bash
npx -c 'eslint && say "hooray, lint passed"'
```

*说明：执行组合 shell 命令，先运行 eslint，成功后播报提示*

## npx vs npm exec 对比

npx 和 npm exec 功能相似，但**标志位置规则不同**：npx 要求所有标志在位置参数之前，npm exec 可用 `--` 分隔符。

| 对比项 | npx | npm exec |
|:---|:---|:---|
| **标志位置** | 所有标志必须在位置参数之前 | 可用 `--` 分隔符区分 npm 选项和命令选项 |
| **package 选项** | `npx --package=foo bar` | `npm exec --package=foo -- bar` |
| **shell 脚本** | `npx -c '...'` | `npm x -c '...'`（npm x 是 npx 的别名） |

**等价命令示例：**

```bash
# 以下两条命令等价
npm exec -- tap --bail test/foo.js
npx tap --bail test/foo.js

# 以下两条命令等价
npm exec --package=foo -- bar
npx --package=foo bar
```

## 版本兼容性说明

npx 在 **v7.0.0** 经历了重大重写，部分旧特性被废弃或移除，使用时需注意版本差异：

### 已废弃/移除的选项

| 选项 | 状态 |
|:---|:---|
| `--no-install` | 已废弃 |
| `--ignore-existing` | 已移除 |
| `--npm` | 已移除 |
| `--node-arg` / `-n` | 已移除 |
| `--always-spawn` | 已移除 |
| `--shell` | 已移除 |
| **shell fallback** | 不再自动降级到系统 shell 执行命令 |

### 新增功能

- 现在支持任何 npm config 值
- `--yes` / `-y` 抑制安装提示

### 注意事项

> 在 npx 中 `-p` 是 `--package` 的简写（在 npm 中 `-p` 是 `--parseable`）

## 常见问题

### Q: npx 和全局安装有什么区别？

**A：** 全局安装会将包安装到系统目录，长期占用空间且版本固定。npx 则是按需下载到缓存，临时使用，不污染全局环境。

### Q: 首次使用 npx 会自动下载包吗？

**A：** 是的，如果指定的包不在本地依赖中，npx 会自动安装到 npm 缓存并添加到 PATH。v7+ 版本会显示安装确认提示，可用 `--yes` 跳过。

### Q: 如何指定包的版本？

**A：** 在包名后加 `@version`，如 `npx -- cowsay@2.0.0 "hello"`。
