# Claude Code自我学习机制

## 背景

在日常使用 Claude Code 时，每次出现错误都会将错误过程保存到 `.learnings/LEARNINGS.md` 中。但随之而来的问题是：Claude Code 怎么保证下次不犯同样的错？需要在 CLAUDE.md 中指明吗？

## 过程

### 问题的发现

Claude Code 每次执行任务时，可能会在不同的会话中重复犯下相同的错误。用户开始思考：为什么已经记录了错误日志，但 Claude Code 依然会犯同样的错？

### 根因分析

经过深入思考，发现问题出在大模型的 **无状态（Stateless）本质**：

- 每次启动新的 Claude Code 会话时，它的"大脑"都会被重置为初始状态
- 它并不知道你昨天在 `.learnings/LEARNINGS.md` 里写了什么
- 除非你主动把这个文件塞进它的上下文窗口里

> [!tip] 类比
> 这就好比你写了一本"错题本"放在书架上，但在每次考试前都不翻开看——毫无意义。

### 解决方案

打通闭环的关键是在 `CLAUDE.md` 中增加明确的 **初始化指令**，强制 Claude Code 在执行任何新任务前先读取并内化错题本：

```markdown
## 核心行为准则 (Core Directives)

1. **强制读取经验库：** 在执行任何实际的文件创建、资料整理（/collect, /curate, /write 等）或回答问题之前，你必须首先静默读取 `.learnings/LEARNINGS.md` 文件。

2. **严格遵循经验：** 该文件记录了你在以往任务中犯过的错误和用户的纠正。你必须将这些记录作为最高优先级的规则，绝对避免在本次任务中重蹈覆辙。
```

### 进阶优化：经验管理

如果每次都要读取 LEARNINGS.md，文件会越来越大，导致：

- 严重消耗 Token
- 拖慢运行速度
- 大模型在海量信息中"失焦"

> [!warning] 最佳实践：提炼成"铁律"而不是记录"故事"
>
> ❌ **坏的记录**：
> "在 2026年4月的一天，我在解答一道题目时，用户说'不是吧，Y也应该作为输入变量中的一个吧'，我意识到自己搞错了逻辑电路的变量划分，我以后会注意。"
>
> ✅ **好的记录**：
> "数字逻辑防错：在进行逻辑电路分析时，务必全面检查所有引脚定义，绝不能遗漏像 Y 这样的隐性输入变量。"

或：

> "数学推导防错：进行复杂展开时，必须严格与官方标准答案的步骤格式对齐，禁止跳跃性推导。"

## 心得

| 要素 | 说明 |
|------|------|
| **核心机制** | 大模型无状态 → 必须显式读取经验文件 |
| **打通闭环** | 在 CLAUDE.md 中添加强制读取指令 |
| **高效管理** | 提炼为规则（RULES.md），而非堆砌错误日志 |

> [!tip] 关键洞察
> 错误日志本身不是学习，只有当错误日志被纳入每次执行的上下文时，才真正形成闭环。

## 踩坑

> [!warning] 常见误区
> **现象**：记录了错误但下次依然犯同样的错
> **原因**：只存不看，大模型无法自动获取历史上下文
> **解决**：在 CLAUDE.md 中添加强制读取指令，或使用 RULES.md 提炼规则

## 延伸

### 后续更新笔记的方法

当有了新感悟需要加入笔记，或笔记内容过久需要更新时，使用 `/update` 技能：

| 场景 | 模式 | 说明 |
|------|------|------|
| 有新感悟要加入 | **INSERT** | 插入新内容到指定位置 |
| 笔记内容过时 | **REFRESH** | 刷新过时内容，可选 mini 研究 |
