# 第 3 章 动手前的准备（网络、目录、配套软件）

> [!summary] 一句话看懂
> 开装前必须先想清三件事：**网络**要能顺畅访问 TMDB 与 GitHub；**目录**要让「下载目录」和「媒体库目录」待在**同一个根目录**下（否则硬链接不成立）；**配套软件**（下载器、媒体服务器、CookieCloud 插件）要装齐、版本达标。

这一章解决「动手之前必须先摆平的三件事」。任意一件没想清楚，后面都会返工：网络不通 → 元数据匹配、升级、装插件全失败；目录规划错 → 硬链接报错、白占硬盘；配套软件没装 → MoviePilot 起来了也「孤掌难鸣」。

## 3.1 网络前提：TMDB 与 GitHub 要能顺畅访问

MoviePilot 靠两件事「吃饭」：调 **TheMovieDb（TMDB）** 的 API 来读取和匹配媒体元数据；访问 **GitHub** 来执行程序升级、安装插件。官方把「有顺畅连接上述网址的网络环境」列为「能流畅使用本软件的前提」[^c3-ready-1]。

| 它要连谁 | 用来干嘛 | 连不上会怎样 |
| --- | --- | --- |
| TheMovieDb（TMDB）Api | 读取、匹配媒体元数据 | 刮削匹配不到，海报简介出不来 |
| GitHub | 程序升级、安装插件 | 升级失败、插件装不上 |

> [!tip] 大白话
> 把 MoviePilot 想成**只认两个供货商的采购员**：一个供「资料卡」（TMDB 的海报、简介），一个供「新工具」（GitHub 的插件、升级包）。渠道一断，采购员就两手空空——软件能开，但啥也干不成。网络怎么配（走代理、换 TMDB API 地址等）官方另有专章；本章你只要先确认一件事：**连得上**。

## 3.2 目录规划（本章的实体落点）：下载目录与媒体库必须同根

这是本章最该停下来想的一节。先给你**一棵可以直接照着建的目录树**：

```text
/media/                              ← 唯一根目录（整个映射进容器）
├── downloads/                       ← 下载器把片子下到这里
│   └── ...（qBittorrent / Transmission 的下载文件）
└── media/                           ← MoviePilot 整理后放这里（媒体库）
    ├── 电影/
    └── 剧集/
```

关键**只有一句**：如果你打算用**硬链接**来整理文件，那么「文件下载目录」和「整理后的媒体库目录」**只能映射一个根目录，不能分开映射**，否则会导致跨盘无法硬链接[^c3-install-1]。

> [!question] 为什么非要「同一个根目录」？
> 硬链接的本质是「同一个文件、两个名字」。**同一个文件，必须待在同一个文件系统里**——一旦跨盘（不同磁盘 / 同盘不同分区 / 被拆成两个映射路径），操作系统就造不出这个「第二个名字」，只能退化成「复制一份」，白白多占一份空间。
>
> 所以正确做法：先建一个根目录（如 `/media`），把下载目录和媒体库都放它下面，**把整个根目录一次性映射进容器**。

官方点明了三种「一定跨盘、一定失败」的情形[^c3-install-2]：

| 情形 | 为什么不行 |
| --- | --- |
| 下载目录和媒体库目录分别在两个不同磁盘 | 属于不同文件系统 |
| 同盘，但在两个不同分区 / 存储空间 / 存储池 | 仍是不同文件系统 |
| 同盘同分区，但被当作两个目录路径分别映射进容器 | 对容器而言已成两个挂载点，等同跨盘 |

> [!tip] 大白话
> 把硬链接想成**「给同一本书贴第二个书签」**：书得还在同一个书架（同一个文件系统）上，你才贴得上第二个书签；书一旦被挪到另一个书架，你就只能「再买一本」（复制）——费钱又费力。

## 3.3 配套软件清单与最低版本

MoviePilot 只是「一环」：它需要下载器来真正下载、需要媒体服务器来管理和展示[^c3-ready-2]。开装前先把这些装好，并确认版本达标[^c3-ready-3]：

| 配套软件              | 作用                   | 版本要求                   |
| ----------------- | -------------------- | ---------------------- |
| Qbittorrent（下载器）  | 真正执行下载               | **>= 4.3.9**           |
| Transmission（下载器） | 真正执行下载（与 QB 二选一）     | **>= 3.0**             |
| Emby（媒体服务器）       | 展示、管理媒体库             | 建议 **>= 4.8.0.45**     |
| Jellyfin（媒体服务器）   | 展示、管理媒体库（与 Emby 二选一） | 推荐 **latest** 分支       |
| Plex（媒体服务器）       | 展示、管理媒体库（三选一）        | 无特定版本要求                |
| CookieCloud 浏览器插件 | 同步站点 Cookie、批量加站点    | 必装（服务端 MoviePilot 已内置） |

> [!warning] CookieCloud 浏览器插件必须装
> CookieCloud 服务端 MoviePilot 已经内置，**但浏览器插件是必装的**——它是把站点 Cookie 同步进 MoviePilot 的通道[^c3-ready-4]。
>
> 另外记住「二选一」：下载器在 QB / Transmission 里挑一个，媒体服务器在 Emby / Jellyfin / Plex 里挑一个，不必全装。

## 3.4 进阶可选：用 portainer 简化容器配置编辑（新手可跳过）

> [!tip] 新手可跳过
> 如果你习惯直接用命令行编辑 `docker-compose.yml`，这一节完全可以跳过。

官方建议：如果你计划用 Docker 部署，**先确认你的环境能否方便地编辑容器配置**，否则建议装 **portainer** 来简化容器操作[^c3-ready-5]。portainer 是一个带网页界面的 Docker 管理工具，改容器配置点点鼠标就行。

```bash
# 安装 portainer（装完访问 http://宿主机IP:9000）
docker run -d --restart=always --name="portainer" \
  -p 9000:9000 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  6053537/portainer-ce
```

> [!note] 这条命令在做什么
> `-p 9000:9000` 把网页界面开在宿主机的 9000 端口；`-v /var/run/docker.sock:/var/run/docker.sock` 把 Docker 的「操作手柄」交给 portainer，它才有权限管理你的容器。

## 3.5 fnOS 本地注意：3000 端口的社区说法（社区经验，待实机验证）

MoviePilot 的 Web 界面**默认走 3000 端口**（安装指引里写明默认用 3000 作 Web 服务端口，可按需调整）[^c3-install-3]。所以「3000 会不会被飞牛自己占用」值得你心里先有个数。

> [!warning] 社区经验，待实机验证——不要当结论
> 有社区帖称：飞牛应用中心的浏览器会**占用 3000 端口**，且改 MoviePilot 端口可能导致安装失败。
>
> 这条说法**一手未证实**（来源原文未能取得）。本节只做**提醒**，不写成结论。到第 4 章部署时，若正好撞上 3000 端口被占，再按实际报错处理；没撞上就无需理会。

> [!summary] 本章小结
> - 网络是前提：TMDB 供元数据、GitHub 供升级与插件，必须顺畅可达。
> - 目录是易错点：下载目录与媒体库必须在**同一个根目录**下、整体映射进容器，硬链接才成立。
> - 配套软件要装齐：下载器（QB >= 4.3.9 / TR >= 3.0）、媒体服务器（Emby / Jellyfin / Plex 三选一）、CookieCloud 浏览器插件（必装）。
> - portainer 属可选增强，新手可跳过。
> - 「fnOS 3000 端口被占用」是**社区经验，待实机验证**，不作结论。
