# Note Style Contract（小白友好写作契约）

本规则定义学习笔记的**内容可读性**标准，与 `note-system.md` 互补：

- `note-system.md`：管 frontmatter、标签、Callout、双链、MOC 等**格式**；
- 本文件：管**内容写得让人能不能看懂**。

适用于所有产出或改写笔记内容的环节：`chapter-writer`、`note-beautifier`、`note-updater`、`legacy-note-importer`。

## 适用范围与档位

| 档位 | 适用笔记 | 要求 |
| --- | --- | --- |
| **入门优先（默认）** | 学习、教程、概念、原理、上手指南类笔记 | 全套契约必须执行 |
| **参考豁免（精简）** | 纯速查表、参数 / API 对照表、命令清单、配置模板 | 保留结论性表格与必要解释，**不**强加白话铺垫、开场比喻和分节 |

判定顺序：先看 `00_intent.md` 的笔记类型或用户显式说明；无法判断时按「入门优先」处理，并在交付时用一句话询问用户是否要精简。

**豁免不等于免写**：参考类笔记仍须结论清晰、表格可扫、命令准确，只是不堆砌解释。

## 写作契约（入门优先档）

按顺序执行：

1. **结论先行**：开篇 3 句话内说清「这篇解决什么问题 / 一句话看懂」，再展开细节。
2. **比喻先于术语**：先用生活化类比（「把 X 想成……」），再给正式定义；比喻后要「所以……」回到实际意义。
3. **术语首次出现即解释**：每个专业词第一次出现时给一句大白话；同类术语密集时，加一张「名词扫盲表」。
4. **概念与进阶操作分离**：代码、命令行、进阶配置集中到靠后的「动手实践」小节，并标注「新手可跳过」，避免正文被代码打断。
5. **抽象概念要有可见落点**：给实体产物（文件内容、目录树、命令输出、路径示例）或可对比表格，让读者有可停留的东西，而不是只抛结论。
6. **引文摆放可读**：一段引 ≥3 处、含整句外文、或 >300 字符时，改用「官方原文 / 说人话」两列对照表，结论单独成句；引文逐字不改，脚注归属不动。
7. **分级可读**：先给「零基础入口」，复杂内容再分层深入；不为求浅显牺牲准确性。
8. **更新不降级**：更新既有笔记时，若原文面向进阶读者，保留其深度与结构，只补充可读性，不改写成降级版本。

## 与其他规则的关系

- 格式遵循 `note-system.md`。
- 本文件是「用户长期偏好」的 canonical 载体；`chapter-writer` 的内嵌通俗化条款视为本契约的展开实现，二者冲突时以本文件为准。
- 具体笔记类型仍以 `00_intent.md` 为准。

## 自检清单

- [ ] 开篇 3 句内是否有「一句话看懂 / 解决什么问题」
- [ ] 核心术语首次出现是否已解释；术语密集处是否有名词扫盲表
- [ ] 是否「比喻 → 术语 → 实际意义」成对出现，没有只抛术语
- [ ] 代码 / 进阶操作是否与正文概念分离，并标注可跳过
- [ ] 抽象概念是否给了实体落点（文件 / 目录树 / 输出 / 对比表）
- [ ] 引文墙是否已改为对照表；遮住一列仍能读懂
- [ ] 若为参考类笔记：是否保持精简，没有被强行塞入白话铺垫
