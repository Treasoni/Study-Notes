# 第三章：Overlay 网络核心 — VXLAN

> [!note]
> 笔记类型：概念笔记
>
> 目标读者：已理解 [[VLAN]] 基本概念
>
> 核心问题：VLAN 只有 4094 个，云计算时代动辄上万租户，怎么办？

## 开篇

上一章我们学习了 VLAN 如何通过 802.1Q Tag 在物理网络中划分子网，实现了二层隔离。但 VLAN 有一个硬伤——12 位的 VLAN ID 最多只能提供 4094 个虚拟网络。这个数量在私有云、公有云动辄数万甚至数十万租户的场景下，远远不够。更致命的是，VLAN 依赖物理网络拓扑，无法跨越三层边界。

本章要解决的正是这个问题：**如何在现有的三层 IP 网络之上，构建无限量、与物理拓扑解耦的二层虚拟网络？** [[VXLAN]]（Virtual Extensible LAN）就是答案——它通过 MAC-in-UDP 封装，将二层帧"打包"进 UDP 包在三层网络传输，实现了 1600 万个独立虚拟网络。

---

## 1. 从现实世界理解 Overlay/Underlay

### 1.1 一个类比：大楼里的虚拟楼层

想象一栋 50 层的写字楼（物理建筑），每一层都有自己的楼层号和空间布局。

- **Underlay（底层网络）**：就是这栋大楼的物理结构——承重墙、电梯井、水电管道、楼层地板。它是真实存在的、看得见摸得着的。
- **Overlay（覆盖网络）**：就像大楼内各公司自己搭建的隔断和装修。A 公司在 10 层和 20 层都有办公室，通过内部 VPN 连接，从员工视角看就像在同一层。B 公司在 15 层也有独立办公区。两家公司的"虚拟楼层"完全独立，互不感知。

**关键 insight**：装修隔断（Overlay）和物理楼层（Underlay）可以独立变化。A 公司从 10 层搬到 30 层，只需要改变其"虚拟办公区"的映射关系，不影响 B 公司。这正是 [[Overlay网络]] 的核心价值——**逻辑拓扑与物理拓扑解耦**。

### 1.2 技术上：Overlay / Underlay 分层

在虚拟网络中：

- **Underlay 层**：底层的物理 IP 网络（三层），由路由器、交换机、光纤组成，负责提供基础的 IP 连通性。Underlay 只负责"把 IP 包从 A 送到 B"，不关心里面装的是什么。
- **Overlay 层**：在 Underlay 之上构建的逻辑二层网络。虚拟机看到的是一张巨大的二层以太网，但实际上它的数据帧被封装在 UDP 包里，通过 Underlay 的三层网络传输。

```
+--------------------------------------------------+
|                  Overlay 层                        |
|   虚拟机 A  <-- 逻辑二层 -->  虚拟机 B             |
|   (10.0.1.2/24)              (10.0.1.3/24)       |
|                                                   |
|   VXLAN 封装层：MAC-in-UDP                         |
+--------------------------------------------------+
|                  Underlay 层                       |
|   物理主机 1  <-- 三层 IP 网络 -->  物理主机 2     |
|   (192.168.1.10)               (192.168.1.20)    |
+--------------------------------------------------+
```

> [!note]
> 两个层次可以独立规划、独立演进。Underlay 网络升级（比如换交换机）不影响 Overlay 网络配置；Overlay 创建新虚拟网络也不需要在物理交换机上做任何配置。

## 2. VXLAN 核心原理：MAC-in-UDP 封装

### 2.1 为什么是 MAC-in-UDP？

VXLAN 的核心理念：**让二层帧在三层网络里"坐飞机"**。

原始的二层以太网帧天生不能跨越三层边界（路由器会丢弃非本网段的帧）。VXLAN 的做法是：给原始二层帧"加一个信封"——外面套上 UDP 头、IP 头和 MAC 头，变成普通的 UDP 包通过三层网络传输。

这个信封的结构如下：

```
 原始以太网帧（Inner Frame）:
 +--------+-----------+----------+-----------+
 | DMAC   | SMAC      | VLAN Tag | IP Payload|   ← 原始的二层帧
 +--------+-----------+----------+-----------+

 VXLAN 封装后（Outer Frame）:
 +----------+----------+---------+--------+----------+-----------+
 | Out.MAC  | Out.IP   | UDP hdr | VXLAN  | Inner    | Inner     |
 | (14B)    | (20B)    | (8B)    | Header | Ethernet | IP Payload|
 |          |          |         | (8B)   | Frame    |           |
 +----------+----------+---------+--------+----------+-----------+
                            ↑                    ↑
                      UDP dst: 4789        原始帧完整保留
                       VNI: 24-bit
```

封装各层详解（从内到外）：

| 层次 | 内容 | 大小 | 说明 |
|------|------|------|------|
| 内层帧 | 原始以太网帧（含源/目的 MAC、VLAN Tag、IP 载荷） | 原始大小 | 完整保留不动 |
| VXLAN 头 | VNI（24 位）、标志位 | 8 字节 | VNI 是虚拟网络标识 |
| UDP 头 | 源端口（哈希计算）、目的端口 4789 | 8 字节 | 标准 UDP 封装 |
| 外层 IP 头 | 源/目的 IP（物理主机 IP） | 20 字节 | IPv4 或 IPv6 |
| 外层 MAC 头 | 源/目的 MAC（物理网卡 MAC） | 14 字节 | 用于 Underlay 传输 |

**关键数据**：VXLAN 总封装开销 = 14（Outer MAC）+ 20（Outer IP）+ 8（UDP）+ 8（VXLAN）= **50 字节**。

> [!note]
> **技术细节**：UDP 源端口通过哈希内层帧头计算，目的端口固定为 IANA 分配的 4789（标准端口）。部分实现（如 Linux 内核 VXLAN）默认使用 Linux 特有的 8472 端口，使用时需注意一致性。

### 2.2 类比验证

想象你要给远方的朋友寄一封信（原始二层帧）：

1. **原始信**：写在信纸上，装在小信封里（内层帧）
2. **加 VXLAN 头**：在小信封上贴一张标签，写明"这封信属于虚拟网络 #10086"（VNI）
3. **加 UDP 头**：选择快递服务（UDP），标注收件人编号 4789
4. **加外层头**：写上实际的寄件地址和收件地址（物理主机 IP 和 MAC）

快递员（Underlay 网络）只关心外层的实际地址，完全不看里面的信纸内容。收件人收到后拆开外层，取出原始信交给收件人。

## 3. VXLAN 关键组件

### 3.1 VTEP — 隧道端点

**VTEP（VXLAN Tunnel End Point）** 是 VXLAN 的核心。它负责：

- **封装**：收到虚拟机发来的原始以太网帧，加上 VXLAN/UDP/IP/MAC 头
- **解封装**：收到远端 VTEP 发来的 VXLAN 包，去掉外层头，取出原始帧
- **转发决策**：根据 MAC 表和 VNI 决定要不要封装、发给谁

每个 VTEP 由一个唯一的 IP 地址标识（就是物理主机的管理 IP）。

```
虚拟机 A ──→ [VTEP-1 (10.0.0.1)] ──VXLAN Tunnel──→ [VTEP-2 (10.0.0.2)] ──→ 虚拟机 B
                      ↓                              ↑
                  封装帧                         解封装出原始帧
```

### 3.2 VNI — 虚拟网络标识

**VNI（VXLAN Network Identifier）** 是 VXLAN 的"VLAN ID"，但有本质不同：

| 维度 | VLAN ID | VNI |
|------|---------|-----|
| 位数 | 12 位 | 24 位 |
| 数量 | 4094 | 约 1600 万（2^24） |
| 位置 | 802.1Q Tag 中（帧内） | VXLAN 头中（隧道内） |
| 作用域 | 物理交换机端口 | 跨越整张 Underlay 网络 |

**技术要点**：VNI 是全局逻辑网络的标识。具有相同 VNI 的 VTEP 属于同一个虚拟二层网络。不同 VNI 之间完全隔离——VNI 1 的广播风暴不会泄漏到 VNI 2。

### 3.3 BD — 广播域

**BD（Bridge Domain）** 与 VNI 一一对应。可以理解为：

- VNI = 虚拟网络的"名字"（逻辑标识）
- BD = 虚拟网络的"实体"（逻辑交换机）

每个 BD 维护一张 MAC 地址表，记录该虚拟网络内所有已知的 MAC 地址及其对应的 VTEP。

```
BD-10000 (对应 VNI 10000)
┌────────────────────────────────────┐
│ MAC 地址表                         │
│ MAC_A → 同一物理主机（本地直连）    │
│ MAC_B → VTEP-B（10.0.0.2）         │
│ MAC_C → VTEP-C（10.0.0.3）         │
└────────────────────────────────────┘
```

### 3.4 NVE — 网络虚拟化边缘

**NVE（Network Virtualization Edge）** 是 VTEP 的功能性抽象，代表"网络虚拟化的边界点"。可以简单理解为：

- VTEP 是"做什么的设备"（隧道端点）
- NVE 是"怎么做"的功能模块（封装/解封装逻辑）

在配置文件中，你会看到 NVE 接口的配置命令，它定义了 VTEP 的具体行为。

## 4. 转发流程：同子网 vs 不同子网

VXLAN 有两种完全不同的转发模式，取决于通信双方是否在同一个虚拟子网内。

### 4.1 同子网转发（桥接模式）

当源 VM 和目标 VM 属于同一 VNI 下的同一子网时，VXLAN 按**二层桥接**方式工作。

**场景**：VM1（10.0.1.2/24, MAC_A）与 VM2（10.0.1.3/24, MAC_B）在同一 VNI 10000 下，位于不同物理主机。

```
          物理主机 1                         物理主机 2
    ┌──────────────────┐              ┌──────────────────┐
    │ VM1 (10.0.1.2)   │              │ VM2 (10.0.1.3)   │
    │ MAC_A             │              │ MAC_B             │
    │      ↓           │              │      ↑           │
    │ VTEP-1 (NVE)     │              │ VTEP-2 (NVE)     │
    │ MAC 表:           │              │ MAC 表:           │
    │ MAC_B → VTEP-2   │              │ MAC_A → VTEP-1   │
    └────────┬─────────┘              └────────┬─────────┘
             │                                  │
             │    VXLAN 隧道 (UDP 4789)         │
             └──────────── 10.0.0.1 ── 10.0.0.2 ──┘
                          (Underlay IP 网络)
```

**转发步骤**：

1. VM1 发送帧给 VM2（目的 MAC = MAC_B）
2. VM1 的原始帧到达 VTEP-1
3. VTEP-1 查询 VNI 10000 的 MAC 表，发现 MAC_B 对应远端 VTEP-2（10.0.0.2）
4. VTEP-1 执行 VXLAN 封装：
   - 内层：保留原始帧（VM1 发往 VM2）
   - 外层源 IP：10.0.0.1（本机 Underlay IP）
   - 外层目的 IP：10.0.0.2（VTEP-2 的 Underlay IP）
   - VNI：10000
5. VTEP-2 收到后检查 UDP 端口 4789，识别为 VXLAN 包
6. VTEP-2 解封装，取出原始帧
7. VTEP-2 查询本地 MAC 表，确认 VM2 在本机，将帧交付给 VM2

> [!tip]
> **关键理解**：同子网转发对虚拟机完全透明。VM1 和 VM2 认为自己在同一二层网络内直接通信，实际数据走了三层隧道。

### 4.2 不同子网转发（路由模式）

当 VM 需要跨子网通信时（例如 10.0.1.0/24 与 10.0.2.0/24 之间），需要经过 **VXLAN 三层网关（BDIF）**。

**场景**：VM1（10.0.1.2/24）需要访问 VM3（10.0.2.2/24），VNI 不同，子网不同。

```
                  VXLAN 三层网关（BDIF）
                ┌──────────────────────┐
                │  BDIF-10000           │
                │  10.0.1.1/24 (GW)     │
                │  BDIF-20000           │
                │  10.0.2.1/24 (GW)     │
                │  ──────────────       │
                │  路由表：10.0.1.0/24→BDIF-10000│
                │          10.0.2.0/24→BDIF-20000│
                └──────────────────────┘
                      ↕        ↕
                ┌──────────────┐
                │    交换核心    │
                │ (VXLAN终结+路由)│
                └──────────────────────┘
                      ↕
         ┌──────────────────────────┐
         │  VXLAN Overlay 网络       │
         │  VNI 10000    VNI 20000  │
         │  10.0.1.0/24  10.0.2.0/24│
         └──────────────────────────┘
```

**转发步骤**：

1. VM1（10.0.1.2）检查到目的 IP（10.0.2.2）不在本网段，将帧发往默认网关 10.0.1.1（BDIF 的 IP）
2. 帧经 VXLAN 封装到达网关所在 VTEP
3. VTEP 解封装，原始帧进入 BDIF-10000
4. BDIF（三层接口）查看目的 IP 10.0.2.2，查路由表发现从 BDIF-20000 转发
5. BDIF-20000 构造新帧：
   - 源 MAC 改为 BDIF-20000 的 MAC
   - 目的 MAC 改为 VM3 的 MAC（通过 ARP 获取）
6. 新帧在 VNI 20000 内进行 VXLAN 封装，发往 VM3 所在 VTEP
7. VTEP 解封装后将帧交付 VM3

> [!note]
> **与 VLANIF 类比**：VXLAN 的三层网关 BDIF 在功能上相当于 VLAN 中的 VLANIF 接口，解决的都是"跨子网路由"问题。区别在于 VXLAN 网关连接的是虚拟广播域（BD）而非物理 VLAN。

## 5. MAC 学习机制

VXLAN 网络中的 MAC 地址学习分为本地学习和远端学习两种。

### 5.1 本地学习

当 VTEP 收到本地虚拟机发出的帧时，它从帧中提取源 MAC 和 VNI：

```
MAC 表条目 = {源 MAC, VNI, 入接口（本地端口）}
```

这告诉 VTEP："MAC_A 在 VNI 10000 中，连接在我自己的端口上"。

### 5.2 远端学习

当 VTEP 收到远端 VTEP 发来的 VXLAN 包并解封装后，从内层帧中提取源 MAC：

```
MAC 表条目 = {源 MAC, VNI, 远端 VTEP IP}
```

这告诉 VTEP："MAC_B 在 VNI 10000 中，在远端 VTEP-2 那边"。

### 5.3 完整学习流程示例

```
初始状态：VTEP-1 和 VTEP-2 的 MAC 表都是空的。

1. VM_A (接在 VTEP-1) 发送 ARP 请求"谁有 10.0.1.3 的 MAC？"
   → VTEP-1 学习：MAC_A → 本地端口

2. VTEP-1 需要将广播帧发到 VTEP-2（头端复制）
   → VTEP-2 收到解封装，学习：MAC_A → VTEP-1
   → 把 ARP 广播给本地所有同 VNI 的虚拟机

3. VM_B (接在 VTEP-2) 回复 ARP 应答
   → VTEP-2 学习：MAC_B → 本地端口
   → 封装后单播发回 VTEP-1

4. VTEP-1 收到解封装，学习：MAC_B → VTEP-2
   → 把 ARP 应答交给 VM_A

现在两台 VTEP 的 MAC 表都完整了，后续通信直接单播封装。
```

## 6. 头端复制与广播优化

### 6.1 什么是头端复制？

VXLAN 网络中，广播、未知单播、组播帧（BUM 流量）需要发送给所有同 VNI 的 VTEP。**头端复制（Head-End Replication）** 就是由源 VTEP 复制多份报文，逐个单播给所有远端 VTEP。

```
不使用头端复制（依赖组播）：
VTEP-1 ──── 组播 ───→ VTEP-2
         └── 组播 ───→ VTEP-3
         └── 组播 ───→ VTEP-4

使用头端复制（单播替代组播）：
VTEP-1 ── 单播 1 ──→ VTEP-2
         ── 单播 2 ──→ VTEP-3
         ── 单播 3 ──→ VTEP-4
```

**优点**：不需要 Underlay 网络支持组播（绝大多数数据中心 IP 网络都不开组播）。

**缺点**：当同 VNI 的 VTEP 数量很多时（例如 100 个），每个广播帧要复制 99 份，对源 VTEP 的 CPU 和带宽造成巨大压力。

### 6.2 优化方案

| 方案 | 原理 | 适用场景 |
|------|------|---------|
| **组播辅助** | Underlay 开启 IGMP/组播，利用组播树分发 | 网络设备支持组播的中大规模部署 |
| **头端复制** | 源 VTEP 逐一向所有远端发送单播 | 小规模部署（< 20 节点） |
| **EVPN 控制平面** | 通过 MP-BGP 通告 MAC/VTEP 映射，避免数据面泛洪 | 大规模生产环境（推荐） |

> [!note]
> EVPN（Ethernet VPN）是目前 VXLAN 生产环境的标准方案。它通过 BGP 在控制面通告 MAC 地址和 VTEP 映射关系，VTEP 之间不再需要数据面的泛洪学习。

## 7. VTEP 部署模式

| 模式 | 实现方式 | 性能 | 灵活性 | 典型场景 |
|------|---------|------|--------|---------|
| **软件 VTEP** | vSwitch（Open vSwitch、Linux Bridge）+ 内核 VXLAN | CPU 受限，~5Gbps | 极高，可编程 | 虚拟化平台、云主机 |
| **硬件 VTEP** | 交换机 ASIC 直通 | 线速，100Gbps+ | 低，设备绑定 | 数据中心 TOR 交换机 |
| **混合模式** | 硬/软 VTEP 共同工作 | 按需 | 中等 | 大规模混合部署 |

**软件 VTEP 典型配置**（Linux Bridge + VXLAN）：

```bash
# 创建 VXLAN 网络接口
# - id 10000: VNI 标识
# - dstport 4789: 标准 VXLAN UDP 端口
# - dev eth0: 绑定的物理网卡（Underlay 接口）
# - local 10.0.0.1: 本机 VTEP IP
ip link add vxlan100 type vxlan id 10000 \
    dstport 4789 dev eth0 local 10.0.0.1

# 启动接口
ip link set vxlan100 up

# 将 VXLAN 接口桥接到虚拟交换机
ip link add br100 type bridge
ip link set vxlan100 master br100
ip link set br100 up

# 将 VM 的 veth 接口也加入桥
ip link set veth-vm1 master br100
ip link set veth-vm1 up

# 查看 MAC 学习表
bridge fdb show dev vxlan100
# 输出示例：
# 00:11:22:33:44:55 dst 10.0.0.2 vni 10000 self permanent
# 66:77:88:99:aa:bb dst 10.0.0.3 vni 10000 self permanent
```

**添加静态 FDB 条目**（不依赖 MAC 学习）：

```bash
# 手动添加远端 MAC 对应关系
bridge fdb add 00:11:22:33:44:55 dev vxlan100 \
    dst 10.0.0.2 vni 10000 self permanent
```

**查看 VXLAN 隧道状态**：

```bash
# 查看 VTEP 信息
ip -d link show vxlan100
# 输出示例：
# 6: vxlan100: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1450 ...
#     link/ether 8a:9b:c7:1d:2e:3f brd ff:ff:ff:ff:ff:ff
#     vxlan id 10000 ...
#     ...
```

> [!warning]
> **MTU 注意事项**：VXLAN 增加 50 字节头开销，因此 VXLAN 接口的 MTU 必须设为 1450（标准以太网 1500 - 50）。如果 Underlay 支持 Jumbo Frame（9000），可设为 8950。MTU 不匹配会导致分片或丢包，这是 VXLAN 部署最常见的故障之一。

## 8. VLAN vs VXLAN 全面对比

这是本章最重要的对比，帮助你理解什么时候该用哪种技术。

| 维度 | VLAN | VXLAN |
|------|------|-------|
| **标准** | IEEE 802.1Q | RFC 7348 |
| **层次** | 数据链路层（L2） | L2 over L4 UDP（Overlay） |
| **网络标识** | 12 位 VLAN ID | 24 位 VNI |
| **最大网络数** | 4094 | 约 1600 万 |
| **封装方式** | 帧头插入 4 字节 Tag | MAC-in-UDP，50 字节封装 |
| **传输范围** | 单一二层网络内 | 跨越三层 IP 网络 |
| **依赖设备** | 物理交换机支持 | 软件 VTEP 或硬件支持 |
| **配置范围** | 每台交换机逐端口配置 | 仅在 VTEP 上配置 |
| **拓扑依赖** | 依赖物理拓扑 | 与物理拓扑解耦 |
| **MTU 需求** | 标准 1500 | 需 1450（减少 50 字节） |
| **广播域** | 物理 VLAN 内所有端口 | 同 VNI 内所有 VTEP |
| **MAC 学习** | 物理交换机自学习 | VTEP 间远端学习 |
| **三层网关** | VLANIF 接口 | BDIF 接口 |
| **性能** | 硬件线速（ASIC） | 软件封装 5-33% 开销 |
| **部署复杂度** | 低（传统网络） | 中到高（需规划 Overlay） |
| **适用规模** | 中小企业局域网 | 数据中心、公有云 |

### 8.1 什么时候选 VLAN？

- 网络规模小（少于 200 个子网）
- 所有设备在同一二层网络
- 已有传统交换机基础设施，不想改造
- 对性能要求极高，不能接受封装开销

### 8.2 什么时候选 VXLAN？

- 需要超过 4094 个虚拟网络
- 虚拟机/容器需要跨三层数据中心通信
- 需要与物理拓扑解耦，灵活迁移
- 多租户公有云或大型私有云场景

> [!tip]
> **现实中的混合方案**：绝大多数数据中心 VLAN 和 VXLAN 共存。接入层用 VLAN 连接物理服务器，服务器内部用 VXLAN 连接虚拟机和容器。VXLAN 封装在服务器 CPU 或智能网卡中完成，物理网络完全不用动。

## 章节总结

- **Overlay/Underlay 分层**是 VXLAN 的核心设计思想：Underlay 提供物理连通性，Overlay 提供虚拟网络隔离，两者独立演进。
- **MAC-in-UDP 封装**将原始二层帧完整保留在内部，外面依次封装 VXLAN 头（含 24 位 VNI）、UDP 头（端口 4789）、外层 IP/MAC 头，总开销 50 字节。
- **关键组件关系**：VNI 是虚拟网络标识，BD 是逻辑交换机（与 VNI 1:1 绑定），NVE 是虚拟化边界功能模块，VTEP 是隧道端点设备。
- **转发分两种场景**：同子网按二层桥接直接 VTEP-to-VTEP 封装转发；不同子网需经过 BDIF 三层网关做路由后再封装。
- **MAC 学习分本地和远端**：本地学习（MAC+VNI+端口）和远端学习（MAC+VNI+远端 VTEP IP），生产环境常用 EVPN 控制平面替代数据面泛洪。
- **VLAN vs VXLAN 的本质区别**：不是简单的"增量的改进"，而是从"物理交换机配置"到"逻辑 Overlay 网络"的范式转变。VXLAN 的核心价值在于**与物理拓扑解耦**和**标识空间无限扩展**。
