## 第三节 DNS 是啥？一本全世界一起维护的「电话簿」

前两节我们认识了域名——它是给人看、好记的文本名字。可电脑不认名字，只认数字 IP。两者之间缺一个「翻译」：负责把域名翻成 IP 的这套系统，就是 DNS（Domain Name System，域名系统）。

把整个互联网想象成一座巨大的城市：域名像人名，IP 像电话号码，DNS 就是这座城市的电话簿——你报上名字，它翻出号码。但它跟我们手边那本纸质电话簿有一个关键区别：它不是某个地方印好、从此一成不变的书，而是由全世界无数台服务器一起维护、还在不断更新的「活电话簿」。

那为什么不干脆造一台超级电脑，把全世界域名都塞进去？因为域名数量实在太大、还在每天增长，任何单一组织都存不下，也扛不住所有人同时来查。于是 DNS 换了一种思路：把整本电话簿拆散，交给许多台服务器分工保管、分层协作。某一台出问题，还有别人能顶上。这种「不靠单点、大家一起扛」的设计，术语叫**分布式**。

> [!tip] 大白话
> 你把域名报给 DNS，它把 IP 报给你——至于它背后有多少台机器在接力、怎么查到的，你都不用管。它是一本「很多人共同维护、随时更新」的电话簿，不是某个藏在角落的单一网站。

普通人上网时，需要自己满世界去翻这本电话簿吗？不用。你身边就有一个现成的「查号台前台」，术语叫**递归解析器**。它通常由你的宽带运营商或本地网络自动配好，不需要你动手；你只管把域名报给它，它会替你把路跑完，再把 IP 告诉你。

> [!note]
> 除了运营商默认的解析器，你也能手动把设备的 DNS 换成「公共 DNS」——也就是公司或机构免费开给大家用的查号台，例如 `223.5.5.5`、`1.1.1.1`。换它有时更快或更稳，但这不是本笔记的重点，知道有这回事就好。

到这里，「DNS 是干嘛的」和「平时该找谁问」已经清楚了。至于递归解析器替你跑腿时，路上会遇到哪些角色、每个人手里有什么，下一节我们跟着它完整走一趟。

> [!warning] 易错点
> DNS 不是一个网站，也不是某一台电脑；一次查询往往要很多台服务器接力完成。另外要记得：光「设置了域名」，网站并不会凭空出现——域名背后还得有一台真正的服务器，并配上对应的解析记录，这部分到第五节再展开。

## 第四节 输入网址后发生了什么？一次「问路」接力

上一节，我们把「翻译域名」这单活儿交给了身边的递归解析器，并叫它查号台前台。但前台也不是全知全能——当它手头没有现成答案时，它得替你出门，一路问过去。这一节我们就跟着它走一趟，看它怎样把 IP 一步步带回来。

### 四类角色：接力问路里的每一站

这趟路会遇到四类角色，先记一张速览表：

| 角色 | 手里有什么 | 职责 | 一句话比喻 |
| --- | --- | --- | --- |
| 递归解析器 | 以前查过的旧答案（缓存） | 收下你的查询，替你把最终 IP 找回来 | 替你跑腿的查号台前台 |
| 根服务器 | 「顶级域名的服务器在哪儿」名单 | 只指路：告诉你去问哪台 TLD 服务器 | 只认大片区、不记门牌的保安 |
| TLD 服务器 | 该后缀下「每个域名归谁管」的索引 | 只指路：告诉你去问哪台权威服务器 | 管一个后缀的街道办 |
| 权威服务器 | 域名真正的记录（域名 → IP） | 最后一站，翻记录直接作答 | 手握登记册的物业 |

理解这套流程，最好用的类比是「接力问路」：你想去一栋楼但不知道门牌，便让前台（递归解析器）去打听。前台先问路口只认大片区、不记门牌的保安（根服务器），保安指了街道办；再去问街道办（TLD 服务器），街道办又指了物业；最后找到物业（权威服务器），物业翻出登记册报出门牌。全程每一站都不亲自带路，只说「下一站找谁」。

> [!tip] 大白话
> DNS 查询就像接力问路——每一站都不亲自带你去，只告诉你下一站该找谁，直到最后一站才给出真答案。

### 冷缓存：完整走一遍

「冷缓存」的意思是：各处都还没有记过这个域名，递归解析器没有旧答案可用，只能老老实实出门问。假设你第一次访问 `example.com`：

> [!example] 冷缓存下的完整链路
> 1. 浏览器把 `example.com` 交给身边的递归解析器：「帮我查它的 IP。」
> 2. 递归解析器先问根服务器。根服务器不存任何具体域名，只回答：「`.com` 的 TLD 服务器在哪。」于是它拿到 TLD 服务器的地址。
> 3. 递归解析器再问 TLD 服务器。它也不存 `example.com`，只回答：「`example.com` 的权威服务器是哪台。」于是它拿到权威服务器的地址。
> 4. 递归解析器最后问权威服务器。这次不再被指路——权威服务器翻出自己的记录本，直接回答：「`example.com` 的 IP 是 `93.184.216.34`。」
> 5. 递归解析器把 IP 带回浏览器。浏览器这才拿着 IP 去连接那台服务器，网页开始加载。

数一数会发现，递归解析器真正向上游问路，只问了 **3 轮**：根、TLD、权威各一轮。网上「DNS 要 8 步、10 步」的说法，多半是把浏览器和每一轮往返都数了进去，属叙述口径不同，不是事实冲突。你只需记住三句：问 3 轮路；前两轮只指路、不存具体域名；最后一站才给真答案。

> [!warning] 易错点
> 别去背「8 步 / 10 步」这种精确数字，重点是问了几轮、每轮谁在回答。最容易误解的是根服务器——它并不存全世界的域名，只是拿着一张「顶级域名服务器名单」，专职指路。

这里还能顺带分清两个常听到的词：**递归**和**迭代**。递归解析器对你是「递归」——代你问到底，你坐等结果；它往上游问那 3 轮时则是「迭代」——每站只告诉它下一站是谁，它再自己去问。一句话记法：递归 = 代你问到底；迭代 = 指路、自己接着问。

### 第二次为什么快：缓存

刚才走的是完全没有现成答案的最坏情况。现实中，递归解析器问完并不会把答案扔掉，而是记在自己桌上。等下次再有人问同一个域名，它一翻桌上有答案，直接把 IP 交出去，连门都不用出，上游那 3 轮全部省掉。

> [!note]
> 第二次为什么快？因为查号台把答案贴在了自己桌上（这就是缓存），下次直接照抄，不用再出门问。

不过它不会永远留着这张便签：每条记录都自带一个「保质期」，术语叫 **TTL**，到点就撕掉、重新去问。这里先按下不表，第六节细说。

缓存也不止解析器这一层。浏览器、操作系统、运营商的解析器都会各留一份；查询时通常从离你最近的那份翻起——浏览器没有就问操作系统，再没有才轮到递归解析器出门跑全程。所以多数时候，你根本感觉不到背后有这么多环节，不是每次上网都会完整走一遍。

递归解析器还有省事捷径：缓存过这个域名的 NS 记录（即知道权威服务器是谁），就跳过前两轮直接去问权威；缓存过 TLD 那层信息，连根都不用问。这些是提速细节，理解大意即可。

> [!note] 实操提示
> 部分路由器也会做 DNS 缓存，视型号而定。如果你改了某些网络设置却感觉「半天不生效」，路由器里那份旧缓存有时也是原因之一——背后的道理同样是缓存还没过期，到第六节一起说清。

这一节我们走完了全程：四类角色接力、向上游共问 3 轮路、权威服务器给出真答案，再靠缓存让第二次变快。下一节我们走进权威服务器，看看记录本里「域名背后的记录」长什么样——A、CNAME、MX 这些名字，分别都在干嘛。
