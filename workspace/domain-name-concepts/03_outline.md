## 第一节：域名是啥？一句话——它是给人看的「门牌号」

- **篇幅**：约 850–1000 字
- **覆盖要点**：
  - 机器之间靠数字 IP 互访（IPv4/IPv6），但这串数字人记不住；域名是「给人看、好记」的文本地址
  - 域名 ≠ IP ≠ URL ≠ 网站：URL 还带协议和路径；光有域名、没有服务器，不会凭空出现网站
  - 建立第一层心智：域名解决「让人好记地找到一台机器」，翻译工作交给后面的 DNS
- **素材引用**：M, CFd, IC
- **写作要点**：
  - 类比：以「手机通讯录昵称 ↔ 真实电话号码」为主类比——你喊昵称，手机替你拨号；浏览器喊域名，DNS 替你找 IP（门牌号作为备选）。
  - Callout 位置：
    - `> [!tip] 大白话`：域名是给人看的昵称，IP 是机器用的号码，DNS 是替你翻通讯录的帮手。
    - `> [!note]`：域名 ≠ 网站。要分清「名字」和「名字背后跑的东西」。
    - `> [!warning] 易错点`：地址栏里整串是 URL，别把协议和路径都当成域名。
  - 易错点：域名 / URL / 网站三词混用。
  - 是否含表格：有 —— 一张 3–4 行对照表（域名 / IP / URL / 网站：是什么、给谁看、一个例子）。若嫌重复可退化为 bullets。

## 第二节：域名长啥样？从右往左一层层读

- **篇幅**：约 1200–1450 字（含子小节「谁在管」）
- **覆盖要点**：
  - 域名是点分隔的标签串，**从右往左读**，语义由笼统到具体（例：`www.google.co.uk`）
  - 最右一段 = 顶级域名 TLD：`.com/.org/.net` 通用；`.cn/.uk` 国家/地区；`.gov/.edu` 有用途限制；`.xyz/.top` 等近年新增通用顶级一句带过、不展开
  - TLD 往左是二级域名（主域），再往左是子域；不强制只有三层，可自建子域分流（如 `developer.mozilla.org`）
  - 标签书写规则：1–63 字符、只含字母/数字/连字符、连字符不可在首尾、大小写不敏感（习惯小写）
  - `### 顺带：域名是「租」的，不是「买」的`——注册局管 TLD 主库、把保留权委托注册商；注册人按年付费租用、可续期、没有所有权；WHOIS 公开可查 + 隐私保护一句话
- **素材引用**：M, CFd, IC（注册局/注册商/WHOIS 以 CFd、M 为主）
- **写作要点**：
  - 类比：快递/邮政地址（国家 → 城市 → 街道 → 门牌）。强调「从左到右是越写越小，域名从右到左才是从大到小」。
  - Callout 位置：
    - `> [!tip] 大白话`：像寄快递，先国家再城市，一层层具体到门牌；域名是把地址「从大到小」写成一串，从右往左读。
    - `> [!example]`：拆 `www.google.co.uk`——uk 是 TLD，co 是二级，google 是主域/三级，www 只是其中一个主机名。
    - `> [!note]`：`.cn/.uk` 这类是国家/地区顶级域；`.gov/.edu` 申请受限。
    - `> [!warning] 易错点`：`www.` 不是语法必需品，它只是很常见的一个子域/主机名。
  - 易错点：把「域名从右往左的层级」和「网址从左到右的习惯」搞混；以为每个域名必须带 `www`。
  - 是否含表格：有 —— 「`www.google.co.uk` 每段是什么」拆解表（位置 / 例子 / 名称 / 作用），可另附 1 个其他例子。WHOIS 那句不用表。

## 第三节：DNS 是啥？一本全世界一起维护的「电话簿」

- **篇幅**：约 800–1000 字
- **覆盖要点**：
  - DNS = 把域名翻译成 IP 的分布式电话簿
  - 为什么是「分布式」：没有哪一台机器装得下全世界域名；它由许多服务器分层协作管理（为第 4 节四类角色埋伏笔）
  - 普通人不用满世界查：身边的**递归解析器**替我们代问——通常由运营商/本地网络提供，也可手动换成公共 DNS（如 `223.5.5.5`、`1.1.1.1`）
  - 本节只解决「DNS 干嘛的 + 该找谁问」，接力细节放第 4 节
- **素材引用**：CF1, CF2, AL, DS
- **写作要点**：
  - 类比：电话簿/总机。DNS = 电话簿，但它是「很多人共同维护、还在不断更新」的版本；递归解析器 = 你身边的查号台前台，你报名字、它去跑腿。
  - Callout 位置：
    - `> [!tip] 大白话`：你把域名报给 DNS，它把 IP 报给你——中间谁去跑腿你不用管。
    - `> [!note]`：公共 DNS 是「别人帮你开的查号台」，换它可能更快/更稳，但非本笔记重点。
    - `> [!warning] 易错点`：DNS 不是一个网站，一次查询也不是只问一台机器。
  - 易错点：以为 DNS 是单一服务器；以为「设置了域名」网站就能开（还要有服务器 + 记录，见第 5 节）。
  - 是否含表格：无（角色表留给第 4 节）。

## 第四节：输入网址后发生了什么？一次「问路」接力

- **篇幅**：约 1500–1800 字
- **覆盖要点**：
  - 冷缓存完整链路：浏览器 → 递归解析器 → 根服务器 → TLD 服务器 → 权威服务器 → 把 IP 带回浏览器
  - 四类角色各司其职：**根服务器只指路、不存具体域名**，返回对应 TLD 服务器地址；**TLD 服务器**管末段（如 `.com`），返回该域名的权威服务器地址；**权威服务器是最后一站**，手里才有真实记录，只凭自身数据作答
  - 正文写「解析器向上游共问 3 轮路」，不写死精确步数（各资料口径 6/8/10 步不一，属叙述差异非事实冲突）
  - 递归 vs 迭代一句话：递归 = 代你问到底；迭代 = 指路、你自己接着问
  - 缓存与「第二次更快」：解析器缓存答案，命中后直接回 IP，跳过后续询问；缓存还分层存在浏览器、操作系统、运营商解析器
  - 解析器省事捷径：缓存过 NS 记录就直接找权威、缓存过 TLD 信息就跳过根（提一句即可）
  - 可选实操提示（须标注「因路由器型号而定」）：部分路由器也会做 DNS 缓存
- **素材引用**：CF1, CF2, AL, DS
- **写作要点**：
  - 类比：接力问路——你要去一栋楼，先问保安（根）管这片的是谁，再问街道办（TLD）这栋楼归谁管，最后问物业（权威）具体门牌/IP。
  - 链路呈现：用「缩进 + 有序列表」文字版逐步串讲（Obsidian 中比 Mermaid 稳、不依赖插件）；每一步写清「问了谁、拿到什么」。在此埋一句「每条记录还带 TTL 保质期，第 6 节细说」的钩子。
  - Callout 位置：
    - `> [!tip] 大白话`：DNS 查询像接力问路——每一站不亲自带你去，只告诉你下一站找谁。
    - `> [!example]`：冷缓存完整链路小例子（带缩进的步骤列表）。
    - `> [!note]`：第二次为什么快？查号台把答案贴在自己桌上（缓存），不用再出门问。
    - `> [!warning] 易错点`：别背「8 步/10 步」——重点是问几轮、每轮谁回答；根服务器不存具体域名。
    - 若写路由器缓存：`> [!note]` 标注「部分路由器也会缓存，视型号而定」。
  - 易错点：把根服务器当成存所有域名的大数据库（其实只指路）；以为每次上网都完整走一遍（其实缓存很常见）。
  - 是否含表格：有 —— 四类角色速览表（角色 / 手里有什么 / 职责 / 一句话比喻）。示例链路用列表不用表。

## 第五节：域名背后的「记录」是啥？A / AAAA / CNAME / MX / TXT / NS 速查

- **篇幅**：约 1300–1550 字
- **覆盖要点**：
  - 域名背后不只有一条记录：权威服务器里存多种「记录」，各回答不同问题
  - A：域名 → IPv4（点分十进制）；AAAA：域名 → IPv6（十六进制）
  - CNAME：把一个名字「别名」到另一个域名；限制：不能放根域（apex），也不能与同主机名的其它记录共存；根域想要类似效果一般用 ALIAS/ANAME（一句带过）
  - MX：邮件路由，带优先级数字，**数字越小越优先**
  - TXT：任意文本，常见于 SPF 反垃圾与所有权验证
  - NS：把某个子域的解析委派给其它 DNS 服务器
  - 大白话目标：读完能看懂解析控制台里一排排记录是干嘛的
- **素材引用**：gcp, AL（A/AAAA/MX/CNAME 以 gcp 为主；CNAME 根域限制 AL 佐证；TXT/NS 以 AL 为主）
- **写作要点**：
  - 表现手法：主线 = 一张**速查表**，每行 = 记录类型 + 大白话一句 + 典型用途 + 值长啥样；表后用 2–3 个高亮点讲最易踩的 CNAME 限制。
  - Callout 位置：
    - `> [!tip] 大白话`：DNS 记录像这个域名下的一排电话分机——不同业务拨不同分机。
    - `> [!warning] 易错点`：CNAME 不能放根域（如 `example.com` 本身），也不能和同名其它记录挤在一起。
    - `> [!note]`：根域想要「CNAME 效果」可用 ALIAS/ANAME，是否支持看解析服务商。
    - `> [!example]`：每个类型给一行「值长啥样」示例（如 A 记录 `→ 93.184.216.34`）。
  - 易错点：把 CNAME 当谁都能用（根域受限）；把 AAAA 当 A 的升级版（它是 IPv6、二者并行）；以为 MX 数字越大越优先（实际越小越优先）。
  - 是否含表格：有 —— 6 行速查表为核心。

## 第六节：改完解析多久生效？TTL 与「传播」的真相

- **篇幅**：约 1150–1400 字
- **覆盖要点**：
  - TTL = 递归服务器/缓存「允许保存这份结果的最长时间」，到期删除、下次重查
  - TTL 越小 → 改动生效越快，但解析器回来问得更勤；TTL 越大 → 更省查询，但生效慢
  - 点破「DNS 传播」误解：改记录后没有全球同步广播，而是各缓存按各自旧 TTL 过期、下次重查才拿到新值
  - 因此有「新旧并存」的生效窗口：同一时刻不同用户可能看到旧 IP / 新 IP
  - 运营商可能不严格守 TTL、缓存更久，进一步拉长生效时间
  - 实用建议（写作时标注为「建议」而非事实）：改解析前先调低 TTL（如 60 秒）并等旧 TTL 过期，可缩短生效窗口
- **素材引用**：AL, gcp, CF1, ibm
- **写作要点**：
  - 类比：便签/记事本「有效期」。TTL 就像贴在桌上的便签写着「这号码 300 秒内有效」，到点撕掉重查。
  - Callout 位置：
    - `> [!tip] 大白话`：TTL 是缓存便签的保质期——保质期内直接照抄，过期就重新问。
    - `> [!warning] 易错点`：把「DNS 传播」理解成主动广播。真相：没有广播，只是各家等自己的旧便签过期。
    - `> [!note]`：想缩短生效窗口？改之前先调低 TTL、等旧 TTL 过期再改——这是建议不是包票，运营商缓存仍可能拖时间。
    - `> [!example]`：小场景——改 IP 后，小明 5 分钟看到新地址，小红因缓存未过期仍看到旧地址。
  - 易错点：以为改完立刻全世界生效；以为「传播」是主动推送。
  - 是否含表格：无（TTL 大/小权衡用两行 bullets 或一句对比即可）。

## 学习路径说明（写作参考 · 元信息，不属于笔记正文）

### 前置要求
- 无硬性前置：会用浏览器打开网址即可；不需要懂网络协议、命令行或任何代码。

### 学完能做什么
- 能讲清域名与 IP / URL / 网站的区别，不再三词混用
- 能看懂任意网址的分层结构，并解释 TLD / 二级域 / 子域
- 能大致复述「输入网址到打开页面」之间 DNS 做了什么（问几轮路、每轮谁回答）
- 在解析服务商控制台看到 A / AAAA / CNAME / MX / TXT / NS 时不慌，知道各自用途与 CNAME 的根域限制
- 理解「改了解析为什么不是马上生效」以及 TTL 大小取舍
- 知道买域名 / 备案 / HTTPS / 反代等实战内容该去哪里深入（[[域名完全上手]]）

### 建议学习顺序（面向读者的时间参考）
- 按第 1→7 节顺序精读一遍约 40–60 分钟；第 4、5 节信息密度最高，可放慢或分两次读
- 读完本笔记后跳 [[域名完全上手]] 时，本笔记第 1、3、5、6 节可作为概念底子对照阅读
