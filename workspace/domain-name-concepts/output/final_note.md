# 域名概念入门：零基础搞懂域名与 DNS

> 面向零基础的概念笔记：看懂「域名是什么、DNS 怎么把名字翻译成地址、背后的记录与 TTL」。纯概念，不含选购注册、ICP 备案、HTTPS/反代等实战（见文末出口）。

## 第一节 域名是啥？一句话——它是给人看的「门牌号」

你也许没注意过：自己其实很少在地址栏里「背」网址，更多是点收藏、搜一下，或只记得住那几个天天见的名字。可这些天天见的名字——`taobao.com`、`google.com`——到底是什么？这一节只回答这一个问题，顺便把总被混着说的「域名 / IP / URL / 网站」四个词一次分清。

### 机器靠数字相认，人靠名字相认

先想一个每天都在发生的场景：手机通讯录。你给家人存的备注是「老妈」，而不是那串 11 位手机号。拨电话时你喊「老妈」，手机替你拨出真正的号码。你记不住号码没关系，**通讯录记得住**。

互联网上的机器也一样。两台计算机要互相访问，认的是一串数字地址，叫 **IP 地址**（现在有 IPv4、IPv6 两种写法，零基础不必细究，记住它是「一串数字」就够）。机器之间用数字最省事，可这串数字对人类太不友好——`203.0.113.10` 和 `203.0.113.11` 看着几乎一样，谁能记得住哪个是哪个？人脑天生不擅长记这种无规律的数字串，这正是后面所有故事的起点。

于是人们发明了**域名**：一个**给人看、好记的文本地址**。就像通讯录把「老妈」绑到手机号上，域名把 `example.com` 这样一个好记的名字，绑到某台机器的 IP 地址上。说得更直白些：机器只认数字、人只认名字，两边本来谁也听不懂谁，域名就是横在中间的一块「翻译面板」——正面写的是人看得懂的名字，背面贴的是机器认得出的数字。

> [!tip] 大白话
> 域名是给人看的「昵称」，IP 是机器用的「号码」，DNS 是替你翻通讯录的「帮手」——你报昵称，帮手去查号码。这个帮手具体怎么干活，先不用管，记住分工即可。

域名还常和 IP、URL、网站这几个词混着用，其实四者分工不同、谁也代替不了谁。先放一张表，把关系钉死：

| 词 | 是什么 | 主要给谁看 | 一个例子 |
|---|---|---|---|
| 域名 | 好记的文本地址，用来找到某台机器 | 人 | `example.com` |
| IP 地址 | 机器之间真正使用的数字地址 | 机器 | `203.0.113.10`（示意） |
| URL | 完整访问串：协议 + 域名 + 具体路径 | 人和浏览器 | `https://www.example.com/page` |
| 网站 | 域名背后真正跑起来的网页与内容 | 人 | 一个能打开的页面 |

> [!note]
> 域名 ≠ 网站。域名只是一个「名字」；要让人能打开你的页面，名字背后还得有台服务器真的跑着网站内容。光注册一个域名，不会凭空变出网站。

> [!warning] 易错点
> 地址栏里那一整串——`https://www.example.com/page`——是 URL，不全是域名。它除了域名，还带着 `https://` 协议和 `/page` 路径。别把整串都喊成「域名」。

所以第一节只需带走一层心智：**域名解决的是「让人好记地找到一台机器」。**可浏览器是机器，它只认数字、不认名字。谁来把域名翻译成 IP？这个翻译官叫 DNS，正是后面几节的主角。一句话复习：**报名字是人的事，查号码是 DNS 的事。**记住这个分工，下一节就来看看：域名这串「名字」本身长什么样。

## 第二节 域名长啥样？从右往左一层层读

第一节说域名是「给人看、好记的名字」，可光知道名字还不够——你得会**读**它，才分得清 `www.google.co.uk`、`developer.mozilla.org` 里到底谁是谁。这一节讲域名这串字符的内部结构。先记住全文最重要的一个阅读习惯：**域名要像读地址一样，从右往左读。**

域名的书写规则看起来平平无奇：用点 `.` 把几段字符串起来，例如 `example.com`。难点从来不在写，而在读的方向。

试试拿寄快递来类比。寄一个国际包裹，地址要从大写到小：**国家 → 城市 → 街道 → 门牌号**。门牌号最具体，但你先得知道它在哪个国家、哪个城市。域名其实也是一层套一层的地址，只是它横着排时方向刚好相反：从左往右念 `www.google.co.uk`，开头是最具体的 `www`，越往右越笼统，到 `uk` 直接是「国家」级别。所以读域名要反过来，从最「大」的单位（最右边）往最「小」的单位（最左边）读。

> [!tip] 大白话
> 域名像一长串寄快递的地址：先写国家，再写城市，一层层具体到门牌号。它只是把这串「从大到小」的地址横过来写成一行，所以要**从右往左**读，才正好是从「国家」一路读到「门牌」。

**最右边一段，叫顶级域名（英文简称 TLD），管的是「类别」和「地区」。**看一眼 TLD，基本能猜出域名属性：

- `.com` `.org` `.net`：最常见的通用顶级域，谁都能注册；
- `.cn` `.uk`：国家或地区顶级域，对应某个国家/地区；
- `.gov` `.edu`：有用途限制，不能随便申请；
- `.xyz` `.top` 等：近年新增的一批通用顶级域，让名字的选择更多。

> [!note]
> `.cn`、`.uk` 这类是国家/地区顶级域，代表某个国家或地区；`.gov`、`.edu` 这类看着眼熟，但申请有门槛，多数情况下前者面向政府机构、后者面向教育机构。

TLD 往左，就是越来越具体的层次。**多数人第一次注册拿到的，是 TLD 左边那段位置的名字**——例如 `example.com` 里的 `example`。它常被叫作**二级域名**，更通俗的叫法是**主域**：这是你花钱注册、对外代表招牌的那一段。**主域再往左，都可以叫子域**，网站想细分内容时就自己加。比如 `developer.mozilla.org`：`org` 是 TLD，`mozilla` 是主域，`developer` 是 Mozilla 自己开的子域，专门放开发文档。一个域名没有规定必须刚好几段——有人只有两段，有人还会再加更多层，也不要求一定带 `www`。

有的国家顶级域下面还多套了一层分类，英国就是典型：人们一般在 `.uk` 之下的 `.co.uk` 里注册。于是 `www.google.co.uk` 拆开是这样：

> [!example]
> 拆 `www.google.co.uk`：`uk` 是顶级域名，`co` 是它下面的二级分类，`google` 才是主域（真正注册、代表品牌的那段），`www` 只是 Google 给某台服务器起的一个主机名。

| 位置（从右往左） | 例子 | 名称 | 作用 |
|---|---|---|---|
| 第 1 段（最右） | `uk` | 顶级域名 TLD | 标识国家/地区：英国 |
| 第 2 段 | `co` | 二级域名（分类标签） | 英国域名体系里的「商业」分类，注册时基本固定 |
| 第 3 段 | `google` | 主域 | 实际注册、代表品牌的名字 |
| 第 4 段（最左） | `www` | 子域 / 主机名 | 某台服务器的名字，删掉通常也能访问 |

每段字符（技术上叫**标签**，label）自己还有些书写规矩：长度 1 到 63 个字符；只能由字母、数字和连字符 `-` 组成；连字符不能放在段首或段尾；大小写不敏感，`Example.COM` 和 `example.com` 是同一个域名——不过习惯上大家都写小写。

> [!warning] 易错点
> `www.` 不是网址的语法必需品，它只是很常见的一个子域/主机名。`google.co.uk` 不带 `www` 照样能用；带不带 `www`，取决于网站管理员怎么配置，而不是语法规定。

### 顺带：域名是「租」的，不是「买」的

看到「注册」，你可能想问：花钱买了域名，这名字算我的吗？答案是——**你不是买，是租。**

域名世界大致有三个角色：

- **注册局（registry）**：管着某个顶级域背后那本「总账本」，比如谁负责维护所有 `.com` 的名单。它把「对外出租」的权限委托给注册商。
- **注册商（registrar）**：面向普通人和公司零售，你就是在它的网站上搜名字、下单、付款。
- **注册人（registrant）**：也就是你。你按年付费，租用这个名字，到期前可以续费。

关键要记牢的是：**你拿到的是使用权，不是所有权。**只要停止续费，名字就会被收回，别人之后就能注册走。另外，域名注册信息是公开的：通过 WHOIS 可以查到某个域名注册了没有、归谁所有；不想暴露个人信息，可以开启注册商提供的隐私保护，把联系方式藏起来。

## 第三节 DNS 是啥？一本全世界一起维护的「电话簿」

前两节我们认识了域名——它是给人看、好记的文本名字。可电脑不认名字，只认数字 IP。两者之间缺一个「翻译」：负责把域名翻成 IP 的这套系统，就是 DNS（Domain Name System，域名系统）。

把整个互联网想象成一座巨大的城市：域名像人名，IP 像电话号码，DNS 就是这座城市的电话簿——你报上名字，它翻出号码。但它跟我们手边那本纸质电话簿有一个关键区别：它不是某个地方印好、从此一成不变的书，而是由全世界无数台服务器一起维护、还在不断更新的「活电话簿」。

那为什么不干脆造一台超级电脑，把全世界域名都塞进去？因为域名数量实在太大、还在每天增长，任何单一组织都存不下，也扛不住所有人同时来查。于是 DNS 换了一种思路：把整本电话簿拆散，交给许多台服务器分工保管、分层协作。某一台出问题，还有别人能顶上。这种「不靠单点、大家一起扛」的设计，术语叫**分布式**。

> [!tip] 大白话
> 你把域名报给 DNS，它把 IP 报给你——至于它背后有多少台机器在接力、怎么查到的，你都不用管。它是一本「很多人共同维护、随时更新」的电话簿，不是某个藏在角落的单一网站。

普通人上网时，需要自己满世界去翻这本电话簿吗？不用。你身边就有一个现成的「查号台前台」，术语叫**递归解析器**。它通常由你的宽带运营商或本地网络自动配好，不需要你动手；你只管把域名报给它，它会替你把路跑完，再把 IP 告诉你。

> [!note]
> 除了运营商默认的解析器，你也能手动把设备的 DNS 换成「公共 DNS」——也就是公司或机构免费开给大家用的查号台，例如 `223.5.5.5`、`1.1.1.1`。换它有时更快或更稳，但这不是本笔记的重点，知道有这回事就好。

到这里，「DNS 是干嘛的」和「平时该找谁问」已经清楚了。至于递归解析器替你跑腿时，路上会遇到哪些角色、每个人手里有什么，下一节我们跟着它完整走一趟。

> [!warning] 易错点
> DNS 不是一个网站，也不是某一台电脑；一次查询往往要很多台服务器接力完成。另外要记得：光「设置了域名」，网站并不会凭空出现——域名背后还得有一台真正的服务器，并配上对应的解析记录，这部分到第五节再展开。

## 第四节 输入网址后发生了什么？一次「问路」接力

上一节，我们把「翻译域名」这单活儿交给了身边的递归解析器，并叫它查号台前台。但前台也不是全知全能——当它手头没有现成答案时，它得替你出门，一路问过去。这一节我们就跟着它走一趟，看它怎样把 IP 一步步带回来。

### 四类角色：接力问路里的每一站

这趟路会遇到四类角色，先记一张速览表：

| 角色 | 手里有什么 | 职责 | 一句话比喻 |
| --- | --- | --- | --- |
| 递归解析器 | 以前查过的旧答案（缓存） | 收下你的查询，替你把最终 IP 找回来 | 替你跑腿的查号台前台 |
| 根服务器 | 「顶级域名的服务器在哪儿」名单 | 只指路：告诉你去问哪台 TLD 服务器 | 只认大片区、不记门牌的保安 |
| TLD 服务器 | 该后缀下「每个域名归谁管」的索引 | 只指路：告诉你去问哪台权威服务器 | 管一个后缀的街道办 |
| 权威服务器 | 域名真正的记录（域名 → IP） | 最后一站，翻记录直接作答 | 手握登记册的物业 |

理解这套流程，最好用的类比是「接力问路」：你想去一栋楼但不知道门牌，便让前台（递归解析器）去打听。前台先问路口只认大片区、不记门牌的保安（根服务器），保安指了街道办；再去问街道办（TLD 服务器），街道办又指了物业；最后找到物业（权威服务器），物业翻出登记册报出门牌。全程每一站都不亲自带路，只说「下一站找谁」。

> [!tip] 大白话
> DNS 查询就像接力问路——每一站都不亲自带你去，只告诉你下一站该找谁，直到最后一站才给出真答案。

### 冷缓存：完整走一遍

「冷缓存」的意思是：各处都还没有记过这个域名，递归解析器没有旧答案可用，只能老老实实出门问。假设你第一次访问 `example.com`：

> [!example] 冷缓存下的完整链路
> 1. 浏览器把 `example.com` 交给身边的递归解析器：「帮我查它的 IP。」
> 2. 递归解析器先问根服务器。根服务器不存任何具体域名，只回答：「`.com` 的 TLD 服务器在哪。」于是它拿到 TLD 服务器的地址。
> 3. 递归解析器再问 TLD 服务器。它也不存 `example.com`，只回答：「`example.com` 的权威服务器是哪台。」于是它拿到权威服务器的地址。
> 4. 递归解析器最后问权威服务器。这次不再被指路——权威服务器翻出自己的记录本，直接回答：「`example.com` 的 IP 是 `93.184.216.34`。」
> 5. 递归解析器把 IP 带回浏览器。浏览器这才拿着 IP 去连接那台服务器，网页开始加载。

数一数会发现，递归解析器真正向上游问路，只问了 **3 轮**：根、TLD、权威各一轮。网上「DNS 要 8 步、10 步」的说法，多半是把浏览器和每一轮往返都数了进去，属叙述口径不同，不是事实冲突。你只需记住三句：问 3 轮路；前两轮只指路、不存具体域名；最后一站才给真答案。

> [!warning] 易错点
> 别去背「8 步 / 10 步」这种精确数字，重点是问了几轮、每轮谁在回答。最容易误解的是根服务器——它并不存全世界的域名，只是拿着一张「顶级域名服务器名单」，专职指路。

这里还能顺带分清两个常听到的词：**递归**和**迭代**。递归解析器对你是「递归」——代你问到底，你坐等结果；它往上游问那 3 轮时则是「迭代」——每站只告诉它下一站是谁，它再自己去问。一句话记法：递归 = 代你问到底；迭代 = 指路、自己接着问。

### 第二次为什么快：缓存

刚才走的是完全没有现成答案的最坏情况。现实中，递归解析器问完并不会把答案扔掉，而是记在自己桌上。等下次再有人问同一个域名，它一翻桌上有答案，直接把 IP 交出去，连门都不用出，上游那 3 轮全部省掉。

> [!note]
> 第二次为什么快？因为查号台把答案贴在了自己桌上（这就是缓存），下次直接照抄，不用再出门问。

不过它不会永远留着这张便签：每条记录都自带一个「保质期」，术语叫 **TTL**，到点就撕掉、重新去问。这里先按下不表，第六节细说。

缓存也不止解析器这一层。浏览器、操作系统、运营商的解析器都会各留一份；查询时通常从离你最近的那份翻起——浏览器没有就问操作系统，再没有才轮到递归解析器出门跑全程。所以多数时候，你根本感觉不到背后有这么多环节，不是每次上网都会完整走一遍。

递归解析器还有省事捷径：缓存过这个域名的 NS 记录（即知道权威服务器是谁），就跳过前两轮直接去问权威；缓存过 TLD 那层信息，连根都不用问。这些是提速细节，理解大意即可。

> [!note] 实操提示
> 部分路由器也会做 DNS 缓存，视型号而定。如果你改了某些网络设置却感觉「半天不生效」，路由器里那份旧缓存有时也是原因之一——背后的道理同样是缓存还没过期，到第六节一起说清。

这一节我们走完了全程：四类角色接力、向上游共问 3 轮路、权威服务器给出真答案，再靠缓存让第二次变快。下一节我们走进权威服务器，看看记录本里「域名背后的记录」长什么样——A、CNAME、MX 这些名字，分别都在干嘛。

## 第五节 域名背后的「记录」是啥？A / AAAA / CNAME / MX / TXT / NS 速查

上一节我们跟着一次解析走到了最后一站：权威服务器。它是整条链路上唯一「手里有真货」的角色，但你有没有想过，它手里握着的其实不是孤零零一条答案，而是一整排记录？域名背后从来不只一条记录。本节就把这排记录里最常用的 6 种讲清楚，让你以后在解析服务商的控制台看到表格不犯怵。

> [!tip] 大白话
> 把 DNS 记录想成这个域名名下的一排电话分机：访客打电话进来，「找网站」转 1 号分机，「发邮件」转 2 号分机，「确认这确实是你的店」转 3 号分机。每个分机各管一种问题、互不抢线。

记录类型有几十种，但零基础阶段先认这 6 种就够用了。下面一张速查表全部讲清，每行回答四个问题：它是谁、用大白话怎么理解、一般拿来干嘛、值长什么样。

| 记录类型 | 大白话一句 | 典型用途 | 值长啥样 |
| --- | --- | --- | --- |
| A | 把域名翻译成服务器的 IPv4 地址 | 让网站能被找到的最基础主记录 | `93.184.216.34`，点分十进制，四组 0–255 的数字 |
| AAAA | 把域名翻译成 IPv6 地址（读作 quad-A） | 网站启用 IPv6 时使用；与 A 并行，不是 A 的升级版 | `2606:2800:220:1:248:1893:25c8:1946`，十六进制、长得多 |
| CNAME | 给这个域名起别名，指向另一个域名 | 让 `www.example.com` 和主域指向同一处 | 一条域名而不是 IP，如 `example.com` |
| MX | 告诉全世界：寄往这个域的邮件交给谁收 | 邮件路由；多个时数字小的优先 | `10 mail.example.com`，优先级 + 邮件服务器域名 |
| TXT | 存一段任意说明文字 | SPF 反垃圾邮件、证明域名归你所有 | `"v=spf1 include:_spf.example.com ~all"`，一段文本 |
| NS | 把某个（子）域的解析外包给其它 DNS 服务器 | 子域委派、把解析交给别人管 | `ns1.example.com`，一台 DNS 服务器的域名 |

> [!example]
> 在控制台里，一行记录通常长这样：主机记录 `www` · 类型 `A` · 记录值 `93.184.216.34` · TTL `600`。「主机记录」告诉你是哪个名字，「类型」回答这是什么问题，「记录值」是答案，「TTL」是答案的保质期（下一节细说）。看懂这四个要素，就等于看懂了一行记录。

表里其它几类都比较直白，唯独 **CNAME** 最容易被误用，值得单独拎出来讲三点。

第一，CNAME 自己不给答案，只给「别名」。它的值永远指向另一个域名，而不是一串数字——意思是「别问我，去问那个名字要地址」，而且别名可以指向完全不同的域名。

第二，CNAME 有两条硬限制：一是**不能放在根域（apex）**，也就是 `example.com` 这种不带任何前缀的名字本身；二是**一旦某个主机名设了 CNAME，它就不能再和同名其它记录共存**——同一个名字下，不能又当别名、又自己定义 A、MX 之类的答案。原因也顺理成章：既然这个名的答案全由另一个名字说了算，自然不能再自己另立答案。

第三，那根域真想要「别名」效果怎么办？用 ALIAS / ANAME 这类记录。它不是 DNS 标准里的官方类型，而是解析服务商自己实现的变通，所以支持与否要看服务商。

> [!warning] 易错点
> CNAME 不是谁都能用：不能放根域（如 `example.com` 本身），也不能和同主机名的其它记录（A、AAAA、MX、TXT 等）挤在一起。

> [!note]
> 根域想要「CNAME 效果」时，一般改用 ALIAS / ANAME，由解析服务商提供，是否支持以服务商为准。

到这里，域名背后这「一排记录」你已经认得大半。下一节回答一个更实际的问题：把 A 记录的值一改，为什么全世界不是马上变？

## 第六节 改完解析多久生效？TTL 与「传播」的真相

上一节末尾的问题，答案就藏在「缓存」和「TTL」这对组合里——也是第四节埋下的钩子。先给结论：你改动记录本身是瞬时的，慢的是散落在世界各地的缓存。

回想第四节：解析器拿到答案后，会把它像便签一样贴在自己桌上，下次直接照抄，不再出门问。问题来了：它总不能永远照抄，万一你后来改了记录呢？所以每张便签上都写了一个「保质期」，这就是 **TTL（Time to Live，存活时间）**。TTL 是递归服务器、缓存「允许保存这份结果的最长时间」：保质期内直接照抄；一到点就撕掉，下次再有人问，就重新出门问权威服务器。

> [!tip] 大白话
> TTL 是缓存便签的保质期——保质期内直接照抄答案，过期就撕掉重问。

保质期设多长，是一笔交易：

- TTL 调小（比如 60 秒）：便签很快过期，你改动后别人很快就能拿到新值；代价是解析器隔一会儿就要回来重问一次，查询更频繁。
- TTL 调大（比如 86400 秒，即一天）：绝大多数查询直接照抄、又省又快；代价是你改了什么，别人最长要等一整天才知道。

所以大多数域名默认用较大的 TTL——「稳定优先、极少改动」，这对日常网站是合理的权衡。

弄懂了 TTL，就能拆穿一个流传很广的说法。很多人把「改完解析要等一会儿才生效」叫作 **DNS 传播（propagation）**，听起来像是新记录会像广播一样被主动推送到全世界每一台服务器。真相不是这样。

你改的，只是权威服务器上那一条主记录。散布在各处的缓存并不知道你改了，它们只是各自守着旧便签、按旧 TTL 过日子。真正发生的不是「传播」，而是「等待过期」：每一处缓存按自己那份旧 TTL 到期之后，下一次查询才会去拿新值。所以生效时间不是一个固定的「多久」，而是取决于各个缓存还剩多少保质期。

> [!warning] 易错点
> 把「DNS 传播」理解成主动广播是错的。真相：没有广播、没有推送，只是各家缓存等自己的旧便签过期，下次重查才看到新值。

正因为「等过期」是各等各的，就出现了一个新旧并存的生效窗口：

> [!example]
> 上午 10:00 你把 `example.com` 的 A 记录从旧服务器改成新服务器。小明的解析器便签恰好 10:02 到期，重查后立刻看到新 IP，打开的是新网站；小红的解析器便签要到 10:30 才到期，这半小时里她反复刷新，看到的仍是旧服务器。于是 10:00–10:30 之间，新旧两个版本在互联网上并存——不同用户、甚至同一用户的不同设备，看到的可能不一样。

还要留个心眼：贴便签的不只是解析器。浏览器、操作系统、运营商的递归解析器，都可能各贴一张。更要留意的是，运营商提供的解析器未必严格遵守 TTL——有些为了省事会把结果多留一会儿，相当于在便签保质期上又擅自加了几小时。这也是为什么偶尔你等了远超 TTL 的时间，某些网络里仍是旧地址。

> [!note]
> 想让生效窗口尽量短，可参考这套做法（是建议、不是保证）：动手改解析之前，先把 TTL 调低到比如 60 秒，等一段时间让各处旧便签按旧 TTL 自然过期，再把真正的新值写上去。这样新值散开后，各地便签很快又会到期重查。若运营商缓存不守 TTL，生效仍可能被拖长。

小结一下：记录存在权威服务器上，改动本身即时完成；慢的从来不是「改」，而是散落全球的旧便签一一过期。TTL 越短，生效窗口越短、但查询越勤；TTL 越长越省事、但改动见效越慢。下次在控制台看到 TTL 输入框，你就知道它是在给便签写保质期了。

## 第七节 收尾：三句话带走

- **域名**是给人看的分层地址，从右往左读：`.com` 在最右，越往左越具体。
- **DNS** 是一本全世界一起维护的「电话簿」：你报名字，它靠 根 → TLD → 权威 接力问路、再靠缓存让第二次更快，把 IP 报给你。
- **记录与 TTL**：域名背后是一排排记录（A / AAAA / CNAME / MX / TXT / NS…），每条还带 TTL 保质期——所以改了解析不是立刻全球生效，而是各家等自己的旧便签过期。
