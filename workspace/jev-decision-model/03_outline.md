### 第三章：三原语与一次最小调用

### 第四章：读结果——probability、confidence 与阈值设计
- **篇幅**：长
- **覆盖要点**：
  - 三条硬结论逐条展开（三·D）：
    1. **probability ≠ confidence**：前者是「陈述为真 / 事件发生的概率」，后者是把分布形状压成 0–1、可直接阈值的统计量（`g2-8` + `g1-27` + `g1-28`）；`g2-8` 明确 `probability` 不是「对答案的置信度」
    2. **confidence 只出现在 Choice 与 Score 上，Noul 没有**（`g1-27` 官方括号原话 + `g2-9` 独立印证）
    3. **`confidence` 是答案对象自己的属性**（`g1-27` 措辞 + `g1-19`/`g2-20`/`g2-21` 三个响应示例）；AI SDK 在 `providerMetadata.typesafe.confidence` 重新暴露属**平台层显影**，非另一套语义（`g2-9`、四·C4）
  - 分布语义：分布越平坦置信越低；Choice 低置信常意味着没有明显胜出选项（`g1-30`）
  - `confidence` ≠ 最高选项概率：官方示例中 0.78 vs 0.85（`g1-19`）
  - 官方把 confidence 定位为「适配多数用例的便利度量」，不锁定用户自定义定义（`g1-29`）
  - 阈值设计：官方明确**没有普适阈值**，需按领域自测标定（`g1-33`）；示例起点为置信度 ≥0.6 且选中项概率 ≥0.7（`g2-10`）；按动作风险上调——只读动作约 0.7、破坏性动作接近 0.9 以上（`g2-11`）；低置信时**不执行动作**，转人工 / 请求澄清 / 降级到其他系统（`g1-32`）；官方示例中的 0.5 下限（`g1-34`）
- **素材引用**：#三·D（g1-19, g1-26 至 g1-30, g2-8, g2-9, g2-20, g2-21）、#三·E（g1-32, g1-33, g1-34, g2-10, g2-11）；`G1a`、`S07`、`S06`、`S08`；#四·C4、#四·C7；#五·3–4
- **代码示例**：无
- **⚠ 注意事项**：`G1a` 页的阈值示例代码在抓取时**比较运算符丢失**（页面只剩 `if confidence  0.5:`），故本章只引散文句、**不引阈值代码**；如需代码请回官网原页（三·E 注）
- **未解标注（本章必须如实并列）**：第一方矛盾 **C7** 仍未解 —— `S01`（官方博客）称「All answers are accompanied with calibrated probabilities and confidence scores」「Always communicates confidence and uncertainty with every output」（`g1-5`、`g1-9`），而 `G1a`（官方 `/confidence` 页）写「(Noul answers don't carry one.)」（`g1-27`）。**同一厂商两页互相矛盾，本轮无第三份官方材料可裁决**：并列两个官方页面原文、标注未解，不替厂商圆场（四·C7、六·1）

### 第六章：独立实测——三方数据与它们各自的口径
- **篇幅**：中
- **覆盖要点**：
  - `S11` 品玩实测（50 条中文客服题、紧急度/售前概率/类别/严重度四项全对才算对，`g3-1`）：与便宜小模型组同组（`g3-2`），平均 32～32.6 分、完整准确率约 64%～65.2%、组内第二（`g3-3`），每题约 0.73～0.75 秒、50 题约 $0.002、两项均为该测试最低（`g3-4`）；跨组参照 MiniMax M3 约 38 分、多花约 $0.0035（`g3-5`、`g3-6`）；失分集中在阈值附近（`g3-7`）；15 次重复有 3 题通过与失分交替（`g3-8`）；作者自述样本与题集不足以代表全部任务、也不验证概率校准（`g3-9`、`g3-11`）；结论是「一组具体取舍」而非「更聪明」（`g3-12`）

## 学习路径说明

### 前置要求
- 会调用 LLM API，理解 request/response 与 token 计费的基本概念
- 了解 Agent 分层架构的常见说法（慢思考模型 + 快模型 + 确定性代码 + 调度）
- 知道 JSON Schema / 结构化输出与「约束解码」要解决的问题
- 不需要任何 Jev 或 TypeSafe 背景

### 学完能做什么
- 说清 Jev 与 LLM 的本质差异：输出空间从词表换成预定义类型，以及「零幻觉」的确切边界
- 写出一次可运行的最小调用：`state` + 三个原语问题，并读懂 `probabilities` 与 `confidence` 的分工
- 为具体场景设定置信度/概率阈值，并给出低置信时的回退策略（转人工、澄清、降级）
- 按官方三种模式（投机性多问 / 置信度门控路由 / 多维合成分）设计一次接入，并控制输入 token 成本
- 判断哪些任务不该交给 Jev（算术、日期比较、计数、超大选项集、否定式），并把它们挪回代码或 frontier 模型
- 正确引述三方实测数据的口径与成立条件，不把厂商自报数字或被刻意限制的基线当作结论

### 建议学习顺序
1. 第一章 → 第二章（建立概念与厂商口径，约 15 分钟）
2. 第三章 → 第四章（一次调用与读结果，本篇核心，约 40 分钟；第三章代码需回官网核对）
3. 第五章（接入与设计模式，约 20 分钟）
