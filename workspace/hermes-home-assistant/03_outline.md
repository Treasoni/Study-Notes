### 类型说明与混合理由

**为什么是混合型**：本主题的核心问题不是「怎么点一个按钮」，而是**同一个能力存在多条实现路线，且各路线在覆盖范围、权限强度、成本上差异很大**。

- 纯**实战**写法会退化成路线复述——接入步骤用户已完成，重复写没有增量。
- 纯**对比**写法会停在表格——用户明确要求「每个能力给出可落地写法」，只给判据不给产物不算完成。

因此采用**「对比定方向 → 实战给产物」双段结构**：

| 段落 | 章 | 作用 |
|---|---|---|
| 对比段 | 第 1–3 章 | 建立判据，产出「能力缺口清单」「任务→路线判据表」「路线选型决策表」 |
| 实战段 | 第 4–7 章 | 按选定路线给可抄产物：`mcp_servers` 配置、`platforms.homeassistant.extra` 片段、安全清单 |
| 收口段 | 第 8–9 章 + 附录 C | 风险与失配：文档/代码不一致、成本与可靠性、延伸阅读索引 |

**对实战类标准模式（环境搭建 → 核心功能 → 进阶优化 → 部署）的替换**：用户起点非零（接入已完成），「环境搭建」段无内容可写，替换为「起点盘点与天花板」；「部署」段替换为「安全收口」，因为本主题的主要失败模式是权限与成本失控，不是装不上。

### 组织规则（本册遵循）

1. **顶级章节对应一个落点产物**：每章收敛到一份具体产物（清单 / 判据表 / 配置片段 / 决策表），同一落点的子主题收进该章 `###` 子节，不升格为平级章。第 4、5 章虽同属 MCP 路线，但因**产物不同**（社区模板 YAML vs 官方路径拼接 YAML）且鉴权行为相反，保持为两章。
2. **不重讲已有笔记**：凡笔记 06 已覆盖的内容，只做「引用 + 加深」，并在章末显式标注分工。
3. **素材性质随章标注**：标为「拼接」「未验证」「源码级推论」「子代理采集」的条目，在正文中保留该性质，不得升格为「官方口径」。

### 第三章：路线选型——自建 skill / MCP server / 自定义 plugin 何时用

- **落点产物**：一张路线选型决策表（能力需求 × 三条路线 × 成本 × 权限）
- **篇幅**：中
- **章内子节**：3.1 三条路线互补而非替代 ｜ 3.2 为什么自建 SKILL.md 补不了能力 ｜ 3.3 MCP 接线的硬规则 ｜ 3.4 自定义 plugin 的适用面 ｜ 3.5 落点决策表
- **覆盖要点**：
  - 三条路线是**互补而非替代**，不是三选一的优劣排序
  - 关键否定结论：自建 SKILL.md **表达不了新能力**——它只能教 agent 怎么调已有工具，而 HA 场景不存在可调的 `ha` CLI；只有当能力已由别的方式（如 REST）提供后，SKILL.md 才有意义
  - MCP 与内置 toolset **同名叠加、不遮蔽**
  - MCP 注册名的硬规则：`mcp__<server>__<tool>`（**源码定论**）、`-`/`.` → `_`、超 64 字符截断 + 8 位 sha256 后缀
  - `tools.include` / `tools.exclude` 用**原始 MCP 工具名**（非注册名），`include` 优先
  - `trust` 的 fail-closed 语义：未识别值按 `untrusted` 处理；无 `readOnlyHint: true` 的写工具都需审批
  - `readOnlyHint` 的性质：**服务端自报**的提示（引用官方原句说明它最多能做什么、不能做什么）
  - CLI 与会话内操作：`hermes mcp add/login/test`、`/reload-mcp`
  - 排错陷阱：`hermes mcp test` 打印的是**原生工具名**，不能用来验证注册名前缀
  - 自定义 plugin 的适用面（精确执行 / 二进制或流式 / 必须走审批面的原生工具），plugins **默认 opt-in**

### 第七章：安全与限界——LLT 权限真相、暴露列表的真实效力、最小化清单

- **落点产物**：一份可勾选的 8 步安全最小化操作清单
- **篇幅**：长
- **章内子节**：7.1 LLT 权限模型的真相 ｜ 7.2 细粒度只读怎么做 ｜ 7.3 暴露列表：设计意图 ≠ 运行期边界 ｜ 7.4 MCP 侧审批面与白名单 ｜ 7.5 已知误报与事故机理 ｜ 7.6 落点清单
- **覆盖要点**：
  - LLT **不带 scope claim**，权限来自**用户上下文** → 标记为「**源码级推论**，HA 文档从未明文写」
  - LLT 有效期与吊销语义：吊销 refresh token 会**立即连带撤销**其签发的全部 access token
  - non-admin 也能创建 LLT（接口用的是普通用户校验，非 admin 校验）
  - 细粒度只读只能靠**受限用户/组**（entity / domain / area / device 粒度）——关键点：这是**用户属性，不是 token 属性**
  - Assist 暴露粒度 = 逐实体 + 多选批量，**无** domain / area 批量
  - `/api/mcp/assist` 恒可用；其他 API ID 的要求随版本变化（交叉引用第 5 章）
  - **「暴露列表是安全边界」的真相**：官方设计意图 ≠ 运行期强制边界。三方证据并列：官方设计意图原文 / 官方 issue 记录的穿透实例（`not_planned` 关闭、无维护者解释）/ 第三方作者自陈「难以校验查询是否只用了已暴露实体」，而另有第三方项目把它当安全保证来陈述
  - ha-mcp 的实体作用域 `Everything in Home Assistant` vs 官方内建 `Only entities exposed to Assist`——官方明文的路线差异
  - 已修补的历史缺陷须写成「**已修补**」：无 area 的已暴露实体被 area 过滤静默漏掉，issue 已 closed as `completed`（2026-09-08），**不得当作当前行为**
  - MCP 审批面：`trust` 从严格侧起步、不信 `readOnlyHint`、**白名单优于黑名单**
  - 误报与事故机理（四个已知形态）：只读询问触发写动作 / brightness 单位不一致 / 模型不支持 tools 却输出 JSON / 标签覆写导致 entity registry 损坏
