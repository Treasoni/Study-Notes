## 第一章：Ventoy 是什么——先搞懂原理再动手

动手前先弄清一个问题：Ventoy 和 Rufus 这类烧录工具到底有什么本质不同？为什么到处都说它「装一次，之后全靠拷贝」？这一章把 Ventoy 的双分区结构和引导原理讲清楚，后面每一章的操作你都能知道「这一步在改什么、为什么这样改」。

### 1.1 传统烧录的痛点：刻一个镜像，重烧一次

用过 Rufus 或 balenaEtcher 的读者都熟悉这套流程：插上 U 盘、选一个 ISO、点开始，等镜像被「刻」进 U 盘。结果是**一块 U 盘等于一个镜像的启动盘**。今天装 Windows，明天想装 Ubuntu，就得重新烧录一次，U 盘里的旧镜像连同数据一起被清掉。

Ventoy 换了个思路：**先在 U 盘上装一次引导器，之后把镜像当普通文件「拷」进去**。一块盘里可以同时放几十个 ISO，开机时自己选要启动哪一个 [^c1-1]。

> [!tip] 大白话
> 传统烧录像把一本「系统书」整本印到 U 盘上——换书就得把纸全擦掉重印。Ventoy 像给 U 盘装了个「书架 + 点菜单」：书（ISO）随时往书架上摆，开机时从菜单里点一本读。

### 1.2 核心原理：引导管理器，不是烧录工具

Ventoy 的本质是**引导管理器（boot manager）**。它不修改镜像，也不把镜像展开到磁盘；安装 Ventoy 只是在 U 盘上部署一套引导程序。每次开机选择从 U 盘启动时，这套程序会**递归扫描数据分区各目录里的镜像文件、按字母排序，现场生成一份启动菜单** [^c1-1][^c1-3]。你选中哪个镜像，Ventoy 再用兼容的方式引导它加载。

所以「拷镜像」不是把文件塞进某个固定格式，而是把镜像放进一个 Ventoy 随时能发现的位置——这正是它与烧录工具的分水岭。

### 1.3 磁盘分区结构：三件套各司其职

安装 Ventoy 后，一块 U 盘在磁盘层面被改造成这样的布局 [^c1-2]：

```text
┌─────────────────────────────────────────────┐
│ 分区 1：镜像数据区（默认 exFAT）            │ ← 占绝大部分空间，镜像直接拷这里
│   可改 FAT32 / NTFS / UDF / XFS / Ext 等     │   剩余空间也能当普通 U 盘存文件
├─────────────────────────────────────────────┤
│ 分区 2：VTOYEFI（32 MB，FAT）               │ ← EFI 引导分区，存放 UEFI 引导文件
├─────────────────────────────────────────────┤
│ MBR 间隙（约 1 MB，不建分区）               │ ← Legacy BIOS 启动文件藏在这里
└─────────────────────────────────────────────┘
```

三个部分各司其职 [^c1-1][^c1-2]：

- **分区 1（镜像数据区）**：平时在资源管理器里看到的那个盘。镜像、普通文件都放这里；文件系统安装后想换也能换（普通 U 盘建议 exFAT，详见第五章）。
- **分区 2（VTOYEFI）**：32MB 的 EFI 引导分区，藏着 UEFI 引导文件。日后「升级 Ventoy」其实只更新这一小块。
- **MBR 间隙（约 1MB）**：不占分区表，用来放老式 Legacy BIOS 的启动文件。

### 1.4 为什么引导分区故意放在第二位

这不是随手排的，而是刻意设计 [^c1-2]：UEFI 规范要求 EFI 分区必须是 FAT 文件系统；而早期 Windows 只会挂载 U 盘的**第一个分区**。Ventoy 把真正重要的 VTOYEFI 放到第二位、把用户日常使用的数据区排第一位，既满足规范，又能防止用户随手把引导分区当成普通盘格式化——引导区一旦被误删，U 盘就无法启动了。

### 1.5 能引导什么：平台与镜像格式

官方 FAQ 给出的支持范围 [^c1-3]：

| 维度 | 支持范围 |
|------|----------|
| 固件平台 | x86 Legacy BIOS；IA32 / x86_64 / ARM64 / MIPS64EL UEFI |
| 镜像格式 | ISO、WIM、VHD(x)、EFI 等，直接拷贝即可 |

### 1.6 关键认知：启动模式由主板说了算

**Legacy 还是 UEFI，由主板 BIOS 决定，Ventoy 不能自行切换**，它只能「适应」[^c1-3]。判断当前机器到底用哪种模式启动，看 Ventoy 启动菜单**左下角的模式标识**：`BIOS` = Legacy 模式；`UEFI` / `IA32` / `AA64` / `MIPS` = 对应架构的 UEFI 模式。排错时（第六章）这个标识能帮你快速定位问题在哪一层。

> [!tip] 大白话
> Legacy / UEFI 是主板两套「开机暗号」。哪台机器用哪套暗号是主板的出厂设定，Ventoy 两套都听得懂，但「用哪套」由不得它挑。菜单左下角的小字就是告诉你：这次开机，主板用的是哪套暗号。

### 1.7 与 Rufus / balenaEtcher 的取舍

| 维度 | Ventoy | Rufus / balenaEtcher |
|------|--------|----------------------|
| 核心用法 | 装一次引导器，之后拷镜像 | 每刻一个镜像，烧录一次 |
| 多镜像共存 | 一盘几十个镜像，菜单选择 | 不行，一块盘一个镜像 |
| 更换镜像 | 删旧文件、拷新文件 | 重新烧录（清空 U 盘） |
| 镜像格式 | ISO/WIM/VHD(x)/EFI 直接拷贝 | 以 ISO 写盘为主 |
| 兼作普通 U 盘 | 可以，数据区随意存文件 | 一般不这么用 |
| 特殊兼容性 | 个别老机器 / Legacy 有限制 | 兼容细节打磨更久，单一场景更稳 |

**怎么选**：要常备多个系统镜像、经常更新、做装机维修盘，选 Ventoy；只是偶尔刻一个系统盘、或遇到老机器特殊兼容问题，传统烧录工具更直接（Rufus 的兼容选项也更细）。

> [!tip] 大白话
> Ventoy 像「活页夹」：活页（镜像）随时抽换，一夹多页。Rufus 像「一次性订书机」：订死一本是一本，想换内容得拆掉重订。需要多页常翻就选活页夹，只偶尔订一本、还讲究订得牢，就用订书机。

### 1.8 适用场景小结

- **多系统装机**：一块 U 盘放下 Windows + 多个 Linux 发行版，装机现场不再翻找一堆盘。
- **系统维修 PE 盘**：塞几个 PE / 救援镜像，系统进不去时随时启动救援。
- **随身工具盘**：镜像占一部分空间，剩余空间当普通 U 盘用，互不干扰。

---

**本章小结**

- Ventoy 是引导管理器而非烧录工具：引导器只装一次，之后镜像靠「复制文件」增删 [^c1-1]。
- 磁盘三件套：镜像数据区（默认 exFAT，可改格式）+ 32MB VTOYEFI 引导分区 + 1MB MBR 间隙（Legacy 启动文件）[^c1-2]。
- VTOYEFI 排第二位是刻意设计：满足 UEFI 的 FAT 要求，也防被误格式化 [^c1-2]。
- 启动模式（Legacy/UEFI）由主板决定，Ventoy 不能切换；认准菜单左下角标识 [^c1-3]。
- 多镜像、常更新选 Ventoy；单镜像或特殊兼容需求，Rufus 类工具仍值得保留。
