## 第一章：Ventoy 是什么——先搞懂原理再动手

动手前先弄清一个问题：Ventoy 和 Rufus 这类烧录工具到底有什么本质不同？为什么到处都说它「装一次，之后全靠拷贝」？这一章把 Ventoy 的双分区结构和引导原理讲清楚，后面每一章的操作你都能知道「这一步在改什么、为什么这样改」。

### 1.1 传统烧录的痛点：刻一个镜像，重烧一次

用过 Rufus 或 balenaEtcher 的读者都熟悉这套流程：插上 U 盘、选一个 ISO、点开始，等镜像被「刻」进 U 盘。结果是**一块 U 盘等于一个镜像的启动盘**。今天装 Windows，明天想装 Ubuntu，就得重新烧录一次，U 盘里的旧镜像连同数据一起被清掉。

Ventoy 换了个思路：**先在 U 盘上装一次引导器，之后把镜像当普通文件「拷」进去**。一块盘里可以同时放几十个 ISO，开机时自己选要启动哪一个 [^c1-1]。

> [!tip] 大白话
> 传统烧录像把一本「系统书」整本印到 U 盘上——换书就得把纸全擦掉重印。Ventoy 像给 U 盘装了个「书架 + 点菜单」：书（ISO）随时往书架上摆，开机时从菜单里点一本读。

### 1.2 核心原理：引导管理器，不是烧录工具

Ventoy 的本质是**引导管理器（boot manager）**。它不修改镜像，也不把镜像展开到磁盘；安装 Ventoy 只是在 U 盘上部署一套引导程序。每次开机选择从 U 盘启动时，这套程序会**递归扫描数据分区各目录里的镜像文件、按字母排序，现场生成一份启动菜单** [^c1-1][^c1-3]。你选中哪个镜像，Ventoy 再用兼容的方式引导它加载。

所以「拷镜像」不是把文件塞进某个固定格式，而是把镜像放进一个 Ventoy 随时能发现的位置——这正是它与烧录工具的分水岭。

### 1.3 磁盘分区结构：三件套各司其职

安装 Ventoy 后，一块 U 盘在磁盘层面被改造成这样的布局 [^c1-2]：

```text
┌─────────────────────────────────────────────┐
│ 分区 1：镜像数据区（默认 exFAT）            │ ← 占绝大部分空间，镜像直接拷这里
│   可改 FAT32 / NTFS / UDF / XFS / Ext 等     │   剩余空间也能当普通 U 盘存文件
├─────────────────────────────────────────────┤
│ 分区 2：VTOYEFI（32 MB，FAT）               │ ← EFI 引导分区，存放 UEFI 引导文件
├─────────────────────────────────────────────┤
│ MBR 间隙（约 1 MB，不建分区）               │ ← Legacy BIOS 启动文件藏在这里
└─────────────────────────────────────────────┘
```

三个部分各司其职 [^c1-1][^c1-2]：

- **分区 1（镜像数据区）**：平时在资源管理器里看到的那个盘。镜像、普通文件都放这里；文件系统安装后想换也能换（普通 U 盘建议 exFAT，详见第五章）。
- **分区 2（VTOYEFI）**：32MB 的 EFI 引导分区，藏着 UEFI 引导文件。日后「升级 Ventoy」其实只更新这一小块。
- **MBR 间隙（约 1MB）**：不占分区表，用来放老式 Legacy BIOS 的启动文件。

### 1.4 为什么引导分区故意放在第二位

这不是随手排的，而是刻意设计 [^c1-2]：UEFI 规范要求 EFI 分区必须是 FAT 文件系统；而早期 Windows 只会挂载 U 盘的**第一个分区**。Ventoy 把真正重要的 VTOYEFI 放到第二位、把用户日常使用的数据区排第一位，既满足规范，又能防止用户随手把引导分区当成普通盘格式化——引导区一旦被误删，U 盘就无法启动了。

### 1.5 能引导什么：平台与镜像格式

官方 FAQ 给出的支持范围 [^c1-3]：

| 维度 | 支持范围 |
|------|----------|
| 固件平台 | x86 Legacy BIOS；IA32 / x86_64 / ARM64 / MIPS64EL UEFI |
| 镜像格式 | ISO、WIM、VHD(x)、EFI 等，直接拷贝即可 |

### 1.6 关键认知：启动模式由主板说了算

**Legacy 还是 UEFI，由主板 BIOS 决定，Ventoy 不能自行切换**，它只能「适应」[^c1-3]。判断当前机器到底用哪种模式启动，看 Ventoy 启动菜单**左下角的模式标识**：`BIOS` = Legacy 模式；`UEFI` / `IA32` / `AA64` / `MIPS` = 对应架构的 UEFI 模式。排错时（第六章）这个标识能帮你快速定位问题在哪一层。

> [!tip] 大白话
> Legacy / UEFI 是主板两套「开机暗号」。哪台机器用哪套暗号是主板的出厂设定，Ventoy 两套都听得懂，但「用哪套」由不得它挑。菜单左下角的小字就是告诉你：这次开机，主板用的是哪套暗号。

### 1.7 与 Rufus / balenaEtcher 的取舍

| 维度 | Ventoy | Rufus / balenaEtcher |
|------|--------|----------------------|
| 核心用法 | 装一次引导器，之后拷镜像 | 每刻一个镜像，烧录一次 |
| 多镜像共存 | 一盘几十个镜像，菜单选择 | 不行，一块盘一个镜像 |
| 更换镜像 | 删旧文件、拷新文件 | 重新烧录（清空 U 盘） |
| 镜像格式 | ISO/WIM/VHD(x)/EFI 直接拷贝 | 以 ISO 写盘为主 |
| 兼作普通 U 盘 | 可以，数据区随意存文件 | 一般不这么用 |
| 特殊兼容性 | 个别老机器 / Legacy 有限制 | 兼容细节打磨更久，单一场景更稳 |

**怎么选**：要常备多个系统镜像、经常更新、做装机维修盘，选 Ventoy；只是偶尔刻一个系统盘、或遇到老机器特殊兼容问题，传统烧录工具更直接（Rufus 的兼容选项也更细）。

> [!tip] 大白话
> Ventoy 像「活页夹」：活页（镜像）随时抽换，一夹多页。Rufus 像「一次性订书机」：订死一本是一本，想换内容得拆掉重订。需要多页常翻就选活页夹，只偶尔订一本、还讲究订得牢，就用订书机。

### 1.8 适用场景小结

- **多系统装机**：一块 U 盘放下 Windows + 多个 Linux 发行版，装机现场不再翻找一堆盘。
- **系统维修 PE 盘**：塞几个 PE / 救援镜像，系统进不去时随时启动救援。
- **随身工具盘**：镜像占一部分空间，剩余空间当普通 U 盘用，互不干扰。

---

**本章小结**

- Ventoy 是引导管理器而非烧录工具：引导器只装一次，之后镜像靠「复制文件」增删 [^c1-1]。
- 磁盘三件套：镜像数据区（默认 exFAT，可改格式）+ 32MB VTOYEFI 引导分区 + 1MB MBR 间隙（Legacy 启动文件）[^c1-2]。
- VTOYEFI 排第二位是刻意设计：满足 UEFI 的 FAT 要求，也防被误格式化 [^c1-2]。
- 启动模式（Legacy/UEFI）由主板决定，Ventoy 不能切换；认准菜单左下角标识 [^c1-3]。
- 多镜像、常更新选 Ventoy；单镜像或特殊兼容需求，Rufus 类工具仍值得保留。

下一章开始动手：去官方渠道下载合适的 Ventoy 版本、挑一块 U 盘并先把数据备份好——为第一次「装引导器」做足准备。

## 第二章：开工前的准备——下载、U 盘与备份

原理清楚后，动手前还要备齐三样东西：官方渠道下载的安装包、一块合适的 U 盘、以及被清空前的数据备份。安装是这条主路径上唯一一次会「整盘清空」的操作，把准备做扎实，后面就不会翻车。

### 2.1 下载 Ventoy：认准 GitHub Releases

Ventoy 安装包统一发布在 GitHub Releases 官方页，按平台分两种，命名固定为 `ventoy-<版本>-windows.zip` / `ventoy-<版本>-linux.tar.gz` [^c2-1]。写作时最新稳定版是 **v1.1.17（发布于 2026-07-24）** [^c2-2]；你读到时若有更新，认准标着 Latest 的最新稳定版即可。

| 你的系统 | 下载文件（以 v1.1.17 为例） | 解压后关键文件 |
| --- | --- | --- |
| Windows | `ventoy-1.1.17-windows.zip` | `Ventoy2Disk.exe`（图形界面） |
| Linux | `ventoy-1.1.17-linux.tar.gz` | `Ventoy2Disk.sh`（命令行脚本） |

### 2.2 解压后装包里有什么

Windows 包顶层就是 `Ventoy2Disk.exe`——默认的图形安装器。它本身是 32 位程序，但兼容最常见的 32/64 位 Windows，直接用即可；包内 `altexe` 子目录另有 `Ventoy2Disk_X64.exe` / `Ventoy2Disk_ARM64.exe` 等备用版本，需要时拷到与 `Ventoy2Disk.exe` 同层再运行 [^c2-1]。

Linux 包解压后执行入口是 `Ventoy2Disk.sh`，两条硬规矩：**必须 root 权限**（加 `sudo`），且**必须先 `cd` 进解压目录再执行** [^c2-1]。

### 2.3 U 盘选型

按三条来选：

- **容量 ≥ 镜像总和再留余量**：一个 Windows ISO 常约 5 GB，装三五个就是几十 GB，先估算再买盘。
- **接口 USB 3.0 起步**：大镜像拷贝和启动加载都快得多，USB 2.0 会等到怀疑人生。
- **避开扩容/劣质盘**：标称 64 GB 实际只有 16 GB 的假盘并不少见。买正规品牌，到手先用工具实测容量。

> [!tip] 大白话
> 把扩容盘想成「注水猪肉」：标签写 64 GB，实际能装的只有 16 GB。等你拷到后半段才发现装不下、启动还失败，前面全白干。U 盘是地基，这里别省钱。

### 2.4 先备份，再谈安装

> [!warning] 安装 = 整盘清空
> Ventoy 首次安装会把目标磁盘格式化、清空全部数据，且不可反悔 [^c2-1]。无论 Windows 还是 Linux 路径都一样。动手前，把 U 盘里任何还想留的文件复制到电脑或其他盘，并确认接下来要操作的确实是这块 U 盘、不是系统盘。

### 2.5（可选）校验下载完整性

下载可能拿到「能解压但已损坏」的包。SHA-256 校验能确认文件与官方发布一致 [^c2-3]：在发布页找到对应文件的 SHA-256 值，本地算一次同样的值，一致即通过。

Linux 用 `sha256sum`：

```bash
# 先 cd 到下载目录；文件名按实际下载替换
sha256sum ventoy-1.1.17-linux.tar.gz
# 输出示例：d2b1…0f3e  ventoy-1.1.17-linux.tar.gz  （以发布页公布值为准）
```

Windows 用 `certutil`：

```bat
:: 先切到下载目录
certutil -hashfile ventoy-1.1.17-windows.zip SHA256
:: 输出含一行 64 位十六进制，与发布页公布值比对
```

> [!tip] 大白话
> SHA-256 像文件的「指纹」：内容差一个字节，指纹就完全不同。本地指纹与官方指纹对得上，就说明你下载的包和官方原版一模一样，没下残、没被改。

---

**本章小结**

- 下载认准 GitHub Releases：Windows 选 `ventoy-*-windows.zip`，Linux 选 `ventoy-*-linux.tar.gz`；锚点 v1.1.17（2026-07-24）[^c2-2]。
- Windows 关键文件是 `Ventoy2Disk.exe`（`altexe` 下有备用架构版）；Linux 是 `Ventoy2Disk.sh`，需 root 且要先 `cd` 进解压目录 [^c2-1]。
- U 盘三原则：容量留余量、USB 3.0+、认正品避开扩容盘。
- 首次安装会格式化整盘，动手前务必备份并核对目标盘 [^c2-1]。
- 可选：用 `sha256sum` / `certutil` 校验 SHA-256，与发布页公布值比对 [^c2-3]。

一切就绪，下一步就是把 Ventoy 真正装到这块 U 盘上——先从多数读者走的 Windows 图形界面路径开始。

## 第三章：Windows 制作——图形界面走一遍（多数读者的主路径）

准备好了 U 盘、下载好了 `ventoy-1.1.17-windows.zip`（写作时官方最新稳定版）之后，这一章就把 U 盘真正变成 Ventoy 启动盘。整章走 Ventoy 官方 Windows 图形安装器 `Ventoy2Disk.exe`，鼠标点击为主，是多数读者上手的主路径 [^c3-1]。全章只需要记一条铁律：**首次安装会格式化整块磁盘、清空所有数据**，所以选盘和备份比后面任何一步都重要 [^c3-1]。

### 3.1 解压并启动 Ventoy2Disk.exe

1. 从 GitHub Releases 拿到 Windows 版压缩包，文件名形如 `ventoy-1.1.17-windows.zip`；若官方已发布更新版本，取最新的 `*-windows.zip` 即可 [^c3-5]。
2. 用系统自带解压（或 7-Zip 等工具）把 zip 解压到任意文件夹。
3. 进入解压后的目录，找到 **`Ventoy2Disk.exe`**——这就是 Ventoy 的 Windows 图形安装器，本章全部操作都由它完成 [^c3-1]。
4. 右键 `Ventoy2Disk.exe` → **以管理员身份运行**，弹出 UAC 提示时选「是」。

> [!tip] 大白话
> 把 Ventoy2Disk 当成装修施工队：格式化 U 盘等于给磁盘「动结构」，Windows 平时只允许普通用户参观、不允许施工。右键「以管理员身份运行」就是亮门禁卡；不亮这张卡，工具连磁盘都碰不到，装到一半就会报错。

启动后，主窗口会列出它识别到的磁盘，并提供「安装 / 升级」等操作按钮。先别急着点，下一步是全程最容易翻车的地方。

### 3.2 关键安全步骤：确认目标磁盘

- 窗口默认**只列出 U 盘**，这是 Ventoy 的保护设计。找到你的 U 盘，核对列表里的容量和你插入的那块一致 [^c3-1]。
- 如果 U 盘没出现，先检查是否被占用或重新插拔，不要急着勾选项。
- 高风险点：只有勾选「配置选项 → 显示所有设备」后，系统盘等**所有磁盘**才会被列出来。一旦勾上并选错，安装会把系统盘整块格式化，电脑直接无法启动 [^c3-1] [^c3-3]。

> [!warning] 安装前确认清单
> 点「安装」之前，逐条核对：
>
> - [ ] 列表里选中的磁盘，容量与你插入的 U 盘一致
> - [ ] 该磁盘**不是**系统盘（不是 C: 所在的那块磁盘）
> - [ ] U 盘内的所有重要数据已备份到别处
> - [ ] Ventoy 来自官方渠道（GitHub Releases 或官网）[^c3-5]
>
> 首次安装会**格式化整块磁盘、清空全部数据** [^c3-1]，这一步没有后悔药。

> [!tip] 大白话
> 默认「只显示 U 盘」相当于物业只给你一把空置房的钥匙，想碰错都难。勾选「显示所有设备」等于把整栋楼的钥匙都塞给你，系统盘也暴露出来，手一抖整块盘就没了。对绝大多数人来说，**永远不需要勾它**。

### 3.3 安装前的可选配置

下面两项按需调整，不调整、保持默认也完全能用：

- **Secure Boot Support**：在菜单栏「Option / 配置选项」里。Secure Boot 是现代电脑 UEFI 固件的一项安全特性，Ventoy 自 1.0.76 起默认支持 [^c3-4]。如果这块盘将来要在 BIOS 里开着 Secure Boot 的电脑上启动，就保持勾选，首次在那台机器引导时再按其提示操作；若完全用不到 Secure Boot 的机器，也可不勾。
- **分区设置 / 保留空间**：可指定在磁盘末尾预留一段空间（留给以后自建分区）。注意保留空间**只在安装时生效**——Ventoy 装好后形成的两个分区（镜像数据分区 + 32MB VTOYEFI 引导分区）不能移动或改大小 [^c3-2]。普通 U 盘用户保持默认即可。

### 3.4 执行首次安装（会清空数据）

1. 再次核对列表里选中的确实是你那块 U 盘。
2. 点击「**安装**」按钮 [^c3-1]。
3. 弹出二次确认，明确提示将格式化磁盘、清空全部数据——这是最后一道闸门。确认已备份后点「确定 / 继续」。
4. 等待进度条走完，看到安装成功提示后再拔 U 盘；中途不要拔盘、不要关窗口。

> [!warning] 这一步真的会清空磁盘
> 前面所有警告都在这一下兑现：点「确定」后，U 盘会被重新分区并格式化，**原有数据全部消失** [^c3-1]。别在存有重要数据的盘上抱着「先装上试试」的侥幸心理。

故障速查：如果 Ventoy2Disk 提示找不到 U 盘或安装失败，通常是某些软件占用了磁盘，先关闭 Paragon ExtFS、DokanMounter、ext2fsd、DiskGenius、Intel DSA 这类工具再重试 [^c3-3]。

### 3.5 安装完成后的首次验证

1. 打开 U 盘上那个容量最大、新出现的分区（即**数据分区**），它现在就像一个普通 U 盘。
2. 把一个系统 ISO 镜像复制进去，放根目录或任意子文件夹都行。Ventoy 会递归搜索数据分区里的镜像，并按文件名排序生成启动菜单 [^c3-1] [^c3-3]。
3. 复制完成后，在系统里安全弹出 U 盘。
4. 重启电脑，进入 BIOS/UEFI 的启动菜单（不同主板按键不同，通常开机时按 Del / F2 / F12 等），选择从 U 盘启动。
5. 屏幕上应出现 Ventoy 的图形化启动菜单，并列出你刚放入的 ISO。选中它回车，若能正常进入对应系统的安装 / 引导界面，就说明这块多系统启动盘制作成功。

这条流程在中文社区大量 Windows 实操帖中反复印证，步骤基本一致 [^c3-8]。

### 3.6 两个重要的「之后」

- **以后更新 Ventoy 用「升级」按钮，不要重新「安装」**。重装会再次格式化、清空镜像；而「升级」只覆盖 32MB VTOYEFI 引导分区里的文件，镜像分区原封不动，镜像不会丢，文件系统也不会被改回默认 [^c3-1]。记住「升级 ≠ 重装」，这是日后最常被混淆的一对操作。
- **Windows 命令行安装模式**：Ventoy 官方同样提供 Windows 命令行安装方式，供有脚本化 / 自动化需求的读者使用；本实战笔记以图形界面为主线，不展开命令行细节 [^c3-1]。

### 本章小结

- Windows 制作全流程 = 解压 → 以管理员身份运行 `Ventoy2Disk.exe` → 选对盘 → 点「安装」。
- 最高风险点是选盘：默认只显示 U 盘是保护机制；勾选「显示所有设备」后务必看清，绝不能选系统盘。
- 首次安装会格式化整盘，点「确定」前对照「安装前确认清单」逐条打勾。
- 装完把 ISO 复制进数据分区即可，重启从 U 盘引导，看到 Ventoy 启动菜单即成功。
- Ventoy 本体以后一律用「升级」，不丢镜像；只有「安装」才会清空数据。

图形界面这条路走通后，你在任何一台 Windows 电脑上都能独立做出一块多系统启动盘。Linux 用户则可以用等价的命令行完成同一件事——操作方式不同，但背后的原理和注意事项完全一致。

## 第四章：Linux 制作——命令行参数一次讲清

Windows 有图形界面点几下就行，Linux 下更常用的是官方那条命令行工具 `Ventoy2Disk.sh`。别被一长串参数吓到——它真正常用的只有安装、升级两个动作，其余参数都是「按需加」的选项。这一章把「下载解压 → 认清设备 → 安装」的主路径走一遍，再用一张速查表把每个参数一次讲清。

### 4.1 下载解压并进入目录：为什么必须先 `cd`

先在 GitHub Releases 下载 Linux 版压缩包并解压（写作时最新稳定版为 v1.1.17）[^c4-1][^c4-2]：

```bash
# 1. 下载 linux 版（文件名带版本号，按实际版本替换）
wget https://github.com/ventoy/Ventoy/releases/download/v1.1.17/ventoy-1.1.17-linux.tar.gz

# 2. 解压
tar -xzf ventoy-1.1.17-linux.tar.gz

# 3. 进入解压出来的目录（关键一步，见下方说明）
cd ventoy-1.1.17
```

解压后目录里能看到 `Ventoy2Disk.sh`、`boot/`、`plugin/` 等文件。**执行前必须 `cd` 进这个目录**，因为 `Ventoy2Disk.sh` 是靠「相对路径」去调同目录下的引导文件——人站在别的目录直接执行，脚本就找不到搭档，装出来是坏的 [^c4-1][^c4-2]。

> [!tip] 大白话
> 把脚本和 `boot/` 引导文件想成一支装修队和堆在同一个房间里的材料。你必须站在这间房里喊「开工」，工人才能顺手拿到材料；站到楼道里喊，工人两手空空，活儿干不成。`cd` 就是「走进那间房」。

### 4.2 先认清目标设备：`lsblk` / `fdisk -l`

安装会格式化整块目标盘，**选错盘的代价是清空一块好盘**。Ventoy 不校验你给的是 U 盘还是系统盘——它只认你给的设备名 [^c4-1]。所以动手前必须先用下面命令看清设备：

```bash
# 列出所有块设备：看容量和挂载点，辨认哪块是 U 盘
lsblk

# 或更传统的方式（需要 root）
sudo fdisk -l
```

`lsblk` 输出示意（不同机器略有差异）：

```text
NAME   MAJ:MIN RM   SIZE RO TYPE MOUNTPOINT
sda      8:0    0 238.5G  0 disk            ← 系统盘（NVMe/SSD/机械），绝对别碰
├─sda1   8:1    0   512M  0 part /boot/efi
└─sda2   8:2    0   238G  0 part /
sdb      8:16   1  28.7G  0 disk            ← 目标 U 盘（RM=1 表示可移动）
└─sdb1   8:17   1  28.7G  0 part
```

判断要点：**看容量**（和你的 U 盘标称容量对上）、**看 `RM` 列是否为 1**（1 表示可移动设备，通常就是 U 盘），系统盘一般挂载在 `/` 上。确认出目标是 `sdb`（这只是示意，以你机器实际输出为准）后，下一步的 `/dev/sdX` 就替换成 `/dev/sdb`。

> [!warning] 高危警告
> 把设备名写错成系统盘（如 `/dev/sda`）并回车，整块系统盘会被清空，没有后悔药。核对标准只有一条：**用 `lsblk` 自己确认过**，不要凭记忆、不要照抄网上的 `sdb`。

> [!tip] 大白话
> 把设备名想成停车场的车位编号。Ventoy 不会先问「这是不是你的车」，你报哪个车位它就拆哪个车位——报错车位，拆的就是别人的车。所以掏钥匙前，先绕到车位前看一眼车牌。

### 4.3 执行首次安装：`sudo sh Ventoy2Disk.sh -i /dev/sdX`

确认设备无误后执行首次安装（把 `sdb` 换成你实际确认的设备名）[^c4-1][^c4-2]：

```bash
# -i = install：首次把 Ventoy 装进 /dev/sdb
# 注意：这会格式化整块盘、清空所有数据，执行前确认已备份
sudo sh Ventoy2Disk.sh -i /dev/sdb
```

脚本执行时会弹出警告要求确认，**趁这个最后的机会再核对一遍设备名**。确认后脚本完成这些事：格式化磁盘、写入引导文件，并把磁盘改造成第一章讲过的「数据区 + VTOYEFI」双分区结构 [^c4-3]。跑完把 U 盘拔插一次，在文件管理器里应能看到一个新的数据分区，把它当普通盘用即可。

### 4.4 参数速查表

`Ventoy2Disk.sh` 的完整参数如下 [^c4-1][^c4-2]：

| 参数 | 含义 | 说明 |
|------|------|------|
| `-i` | 安装（install） | 首次制作启动盘，格式化整盘、清空数据 |
| `-I` | 强制重装 | 即使盘上已装过 Ventoy 也重新装，同样清空数据，慎用 |
| `-u` | 升级（update） | 只更新 VTOYEFI 引导分区，**不碰镜像、不丢数据** |
| `-l` | 列出设备 | 让 Ventoy 列出它识别到的磁盘，方便核对设备名 |
| `-r SIZE_MB` | 保留空间 | 在磁盘末尾预留 `SIZE_MB` 的未分区空间；**只在安装时生效** |
| `-s` | Secure Boot 支持 | 默认关闭；开启后生成的引导文件才支持 Secure Boot |
| `-g` | 使用 GPT | 默认 MBR 分区表；需要 GPT 时加此参数 |
| `-L` | 设置卷标 | 给数据分区设一个卷标，方便在文件管理器里认出这块盘 |

几个容易记混的点：**`-i` 和 `-u` 的区别**是「安装清空」vs「升级保数据」，日常更新永远用 `-u`；**`-s` 默认关**，只有要在开 Secure Boot 的电脑上启动才加；**`-r` 只在安装那一刻生效**，装完再想留保留空间就得重装，而且装好后分区 1/2 不能移动或改大小 [^c4-3]。

### 4.5 典型组合：Secure Boot、GPT 与卷标

单参数理解后，看两个真实场景的拼法：

```bash
# 场景 A：要在开启 Secure Boot 的电脑上启动 —— 加 -s
sudo sh Ventoy2Disk.sh -s -i /dev/sdb
```

Secure Boot 开启时，主板只信任带合法签名的引导程序。Ventoy 默认生成的引导不带 Secure Boot 支持（`-s` 默认关），所以这类机器要在安装时加上 `-s`，首次启动时再按界面指引注册一次 key [^c4-1][^c4-2]。

```bash
# 场景 B：大容量移动硬盘 / SSD —— 换 GPT + 设卷标，装完把数据区格成 NTFS
sudo sh Ventoy2Disk.sh -g -L VentoyData -i /dev/sdc

# 装完后数据区是 /dev/sdc1；大容量盘建议格成 NTFS（Windows/Linux 都认）：
# （可选，需系统装有 ntfs-3g；普通 U 盘保持默认 exFAT 即可）
sudo mkfs.ntfs -f -L VentoyData /dev/sdc1
```

关于分区格式的经验法则 [^c4-3]：普通 U 盘保持默认 **exFAT** 最省心；**大容量移动硬盘/SSD 建议 NTFS**（Windows 也能读写、大文件更稳）；XFS/Ext 系列只在纯 Linux 环境可见，Windows 不认。注意上一条 `-r` 保留空间与自建分区属于进阶玩法，这里不展开。

> [!tip] 大白话
> `-s`、`-g`、`-L` 这些参数像点餐时的「加料」：主食永远是 `-i /dev/sdX`，口味需求（要过 Secure Boot 的门禁、要 GPT 的桌型、要给盘子贴标签）才需要额外勾选。不勾就上默认套餐。

### 4.6 日常升级：`-u` 只动引导分区

Ventoy 出新版后，升级流程与安装几乎一样，只是把 `-i` 换成 `-u`：

```bash
# 下载新版、解压、cd 进新版目录后执行升级：
sudo sh Ventoy2Disk.sh -u /dev/sdb
```

`-u` 只覆盖那 32MB 的 VTOYEFI 引导分区，**镜像分区原封不动**——盘里的 ISO、普通文件都在，文件系统也不会被改回 exFAT [^c4-1]。这是「升级」与「重装（`-i`/`-I`）」最本质的差别：升级是日常操作，随时可以做；重装会清空一切，只在想彻底重来时用。

> [!tip] 大白话
> 装 Ventoy 像给房子做整体装修，家具得先搬空；升级像只换门锁芯——屋里东西原样不动，只把门锁换成新型号。所以日常「换锁芯」（`-u`）很安全，别手滑选了「砸墙重装」（`-i`）。

### 4.7 一句补充：Linux 下也有图形/网页配置入口

命令行是 Linux 下的主路径，但官方也提供图形化界面与网页版配置工具（如 VentoyPlugson），适合想可视化调整插件、主题的读者。本笔记以命令行主线为主，需要时再去翻官方文档即可。

- Linux 制作 = 解压 `linux.tar.gz` → **`cd` 进解压目录** → `sudo sh Ventoy2Disk.sh -i /dev/sdX` [^c4-1][^c4-2]。
- 先 `lsblk` / `fdisk -l` 认清设备；**Ventoy 不校验设备类型，选错盘会清空整块盘** [^c4-1]。
- 参数速查：`-i` 安装 / `-I` 强制重装 / `-u` 升级 / `-l` 列设备 / `-r` 保留空间 / `-s` Secure Boot（默认关）/ `-g` GPT（默认 MBR）/ `-L` 卷标。
- 日常更新永远用 `-u`：只覆盖引导分区，镜像不丢、文件系统不变 [^c4-1]。
- Secure Boot 电脑安装时加 `-s`；普通 U 盘用 exFAT，大容量移动硬盘/SSD 建议 NTFS [^c4-3]。

装好并验证能出现 Ventoy 启动菜单后，这块 U 盘就进入「镜像靠复制文件增删」的日常模式——往数据分区里拖 ISO 就是添加系统，删文件就是移除系统，再也不用重烧。

## 第五章：日常使用与升级——把 U 盘用顺手

装好 Ventoy 之后，日常维护其实只剩四件事：加镜像、删镜像、升级 Ventoy 本体、以及让启动菜单出得快一点。本章把这些操作全部归到「复制/删除文件」和「按一个按钮」的层面，你会发现这块 U 盘用起来和普通 U 盘没什么两样。

### 增删镜像：复制与删除文件

Ventoy 的核心承诺是「引导器只装一次，之后镜像即拷即用」[^c5-1]。它支持 ISO、WIM、IMG、VHD/VHDX 以及 EFI 启动文件。想加一个系统镜像，就把文件直接拖进数据分区（分区 1）的任意目录；想删，直接删除文件即可。全程不需要重新烧录，也不需要重装 Ventoy。

```text
你的 U 盘（Ventoy）
└── iso/                      ← 目录可自己新建、随意命名
    ├── Win11_24H2.iso
    ├── ubuntu-24.04-desktop.iso
    └── WePE_64_V2.3.iso
```

复制完成后无需任何「刷新」操作，下次开机进入 Ventoy 启动菜单，新镜像就会出现在列表里。

> [!tip] 大白话：把 Ventoy 想成「装好的点菜机」
> 传统烧录好比把一道菜刻进一只盘子，换菜就得换盘子；Ventoy 则是菜单已经装好，你往「菜柜」（数据分区）放进或拿出镜像文件，开机菜单就自动加菜、撤菜。所以「加镜像 = 拷贝文件，删镜像 = 删除文件」。

### 启动菜单规则：递归搜索 + 字母排序

Ventoy 默认**递归搜索分区 1 的所有目录和子目录**，把找到的镜像按**字母序**显示在启动菜单上[^c5-1][^c5-3]。也就是说，镜像放在多深的子目录里都能被找到，你不需要把所有镜像堆在根目录。

这个规则带来的直观后果有两个：

- **方便**：可以按用途建 `iso/windows`、`iso/linux`、`iso/pe` 之类的分类目录，自己好找。
- **代价**：Ventoy 开机时要遍历这些目录生成菜单，文件总量越大、目录越深，扫描就越慢（对应 5.6 的卡顿处理）。

### 兼作普通 U 盘

镜像分区的剩余空间可以随意存放任意文件——文档、驱动、常用软件安装包都可以，不影响 Ventoy 的启动功能[^c5-1]。建议把镜像集中在少数几个目录里，普通文件放另一处：平时它就是一块普通移动存储，只有开机时才会「变身」成启动菜单。这样既方便查找，也能减少开机扫描的负担。

### 安全升级：只动引导分区，别选「重装」

Ventoy 会持续更新，但日常升级不需要重做 U 盘：

- **Windows**：打开 `Ventoy2Disk.exe`，选中 U 盘后点「升级」按钮。
- **Linux**：在解压目录里执行 `-u` 参数升级。

升级操作只覆盖那块 32MB 的 VTOYEFI 引导分区，**不触碰镜像分区**——镜像不会丢失，数据分区的文件系统也不会被改回 exFAT[^c5-1]。

```bash
# 假设已下载新版本并解压，先进入解压目录（必须 cd 进来再执行）
cd ventoy-1.1.17

# -u 表示 upgrade，只更新引导区；镜像与数据原封不动
# 把 /dev/sdb 换成你自己的 U 盘设备名，可用 lsblk 确认
sudo sh Ventoy2Disk.sh -u /dev/sdb
```

> [!warning] 别把「升级」做成「重装」
> 日常更新只点「升级」或用 `-u`。一旦误点「安装」或用 `-i`/`-I`（强制重装），Ventoy 会重新格式化整盘、清空所有镜像。按钮相邻但后果完全不同，点之前看清。

> [!tip] 大白话：升级是「换招牌」，重装是「拆楼」
> 32MB 引导分区像店面招牌，数据分区像店内货物。升级 = 只换一块新招牌，货物原封不动；重装 = 把整栋楼推倒重建，货物自然全没。

### 数据分区文件系统怎么选

Ventoy 装完后分区 1 默认是 exFAT。镜像分区可以在装好之后重新格式化[^c5-1][^c5-2]，按你的使用场景选：

| 文件系统 | 建议场景 | 说明 |
|---|---|---|
| exFAT | 普通 U 盘（默认） | Windows/macOS/Linux 开箱即读，适合放体积大的 ISO |
| NTFS | 大容量移动硬盘 / SSD | Windows 环境全功能，适合在 Windows 下长期使用 |
| XFS / Ext 系列 | 仅纯 Linux 环境 | 只在 Linux 下可见，Windows 不识别，需要跨平台时别用 |

重新格式化只会清空分区 1 里的镜像，不会动 32MB 引导分区，但动手前仍要把需要的文件先拷走。Windows 下可直接右键盘符选「格式化」；Linux 下可用下面的命令：

```bash
# 把数据分区重格为 exFAT（先备份！会清空该分区所有文件）
# /dev/sdb1 = U 盘第一个分区（数据分区），用 lsblk 确认设备名
sudo mkfs.exfat /dev/sdb1
```

### 镜像太多导致开机扫描卡顿

如果开机长时间停在 `Ventoy scanning files, please wait...`，通常是文件太多：Ventoy 启动时要扫一遍分区 1 生成菜单，文件越多越慢[^c5-3]。两种解决办法：

1. **限定搜索路径**：通过全局配置让 Ventoy 只扫描指定目录，而不是整盘。
2. **用 `.ventoyignore` 跳过目录**：在不想被扫描的目录里放一个名为 `.ventoyignore` 的空文件，Ventoy 就会跳过整个目录[^c5-3]。

```text
你的 U 盘（Ventoy）
├── iso/                  ← 镜像集中放这里，正常扫描
│   └── Win11_24H2.iso
└── 软件仓库/             ← 大量普通文件，不想被扫
    └── .ventoyignore     ← 空文件占位，Ventoy 跳过整个目录
```

```bash
# Linux/macOS：进入目标目录后创建一个空占位文件
cd "/media/$USER/Ventoy/软件仓库" && touch .ventoyignore

# Windows：在该目录右键「新建文本文档」，重命名为 .ventoyignore
# 注意：文件名以点开头，且没有 .txt 扩展名
```

效果是开机菜单生成明显变快。要注意：别把 `.ventoyignore` 放进存放镜像的目录，否则里面的镜像会被一起跳过、不出现在菜单里。

> [!tip] 大白话：`.ventoyignore` 像仓库门口挂的「免检牌」
> Ventoy 开机像安检员把整个盘每个房间查一遍。给某个房间挂上「免检」牌（放一个 `.ventoyignore`），安检员就绕过这间，速度自然快；但挂牌房间里的「货」（镜像）也不查了，所以别给放镜像的房间挂牌。

### 本章小结

- 增删镜像 = 复制/删除文件，支持 ISO/WIM/IMG/VHD(X)/EFI，拷贝后下次开机即出现在启动菜单。
- Ventoy 递归搜索分区 1 全部子目录并按字母序展示镜像；镜像目录分类存放，普通文件另放一处。
- 升级 Ventoy 用 Windows「升级」按钮或 Linux `-u`，只更新引导分区、镜像不丢；切勿误用「安装 / 重装」。
- 数据分区可按场景更换文件系统：普通 U 盘用 exFAT，大容量移动硬盘/SSD 用 NTFS，XFS/Ext 系列仅限纯 Linux 环境。
- 文件过多导致开机扫描卡顿时，用搜索路径限定范围，或在目标目录放 `.ventoyignore` 让 Ventoy 跳过。

把 U 盘用顺之后，剩下的变量就是「万一启动不了怎么办」。下一章把最常见的启动失败、安装失败与扫描卡顿整理成一份可以直接照做的排查清单。

## 第六章：常见问题与排错——启动不了怎么办

U 盘做出来了，镜像也拷进去了，重启却发现进不去启动菜单——这是 Ventoy 新手最常卡住的一关。这一章按「先分层定位、再逐项处理」的思路，把最常见的启动失败、安装失败与扫描卡顿问题整理成可照做的检查清单。

> [!tip] 大白话
> 排错就像查漏水：别先拆墙，先确认水是从哪一层进来的。启动问题也分楼层——先看是「主板那层」不认你的盘，还是「盘那层」引导坏了，还是「镜像那层」文件坏了。从上往下查，一次只动一层。

### 6.1 先分层再动手：一张排查决策链

启动失败时按下面四层顺序排查，每层都确认没问题再往下走[^c6-S3]：

| 层级 | 检查什么 | 怎么判断 | 处置 |
|------|----------|----------|------|
| ① 引导模式 | 主板用 Legacy 还是 UEFI 启动 | 看启动菜单左下角标识（见 6.8） | 模式由主板决定，Ventoy 不能切换；U 盘必须在同模式下启动 |
| ② 引导分区 | VTOYEFI/引导文件是否完好 | 换一台机器能否启动？插回电脑看分区是否还在 | VTOYEFI 损坏走 6.7 非破坏安装 |
| ③ 镜像完整性 | ISO 是否拷全、是否损坏 | 重新拷一次；做 checksum 比对 | 换源重新下载/复制 |
| ④ 机器限制 | 扩容假盘、老主板 Legacy 地址限制 | 换一块正规 U 盘试 | 换盘；老机器用 UEFI 或小容量盘 |

### 6.2 Secure Boot：第一次启动的蓝色注册界面

BIOS 开了 Secure Boot 的电脑，第一次用 Ventoy 启动时不会直接进菜单，而是会先进一个**蓝色 key 注册界面**——这是让固件「认识」Ventoy 的签名钥匙，每台电脑只需注册一次[^c6-S4]。

注册步骤：

1. 确认 BIOS 中 Secure Boot 为开启状态，从 U 盘启动；
2. 屏幕出现蓝色 key 注册界面，按提示选择注册/认可该钥匙（不同机器按钮措辞不同，通常选 Enroll / OK / Yes 一类）；
3. 确认后机器会重启，再次从 U 盘启动即可正常进入 Ventoy 菜单；
4. 之后同一台电脑不再需要重复注册。

如果注册时直接出现**错误/失败界面**（官方举例会出现 `Linpus lite` 这类字样），说明当前 Ventoy 的签名方案在这台机器的固件上不兼容[^c6-S4]。处置：进 BIOS **关闭 Secure Boot**，保存退出后重新从 U 盘启动。Ventoy 默认策略本就是「绕过」Secure Boot，关掉后不影响正常使用。

> [!tip] 大白话
> 把注册钥匙想成给 U 盘办一张「临时工牌」：门禁（Secure Boot）认一次工牌，之后每次放行。要是门禁系统太老、连工牌机都不认（报错 Linpus lite），就别跟它耗了——直接跟保安说「今天不查工牌」（关 Secure Boot），照样进门。

### 6.3 Secure Boot 的版本坑：1.1.13+ 与 UEFI CA 2023

如果你用的是 **Ventoy 1.1.13 或更新版本**，以前注册过的旧钥匙可能突然失效——这是 2023 年 UEFI CA（证书颁发机构）更新导致的，需要**重新注册一次新 key**，注册流程同 6.2[^c6-S4]。

另有部分机器的固件默认不信任第三方证书，还需要进 BIOS 把 **`Allow Microsoft 3rd Party UEFI CA`** 选项打开，Ventoy 的钥匙才会被接受[^c6-S4]。升级 Ventoy 后遇到「以前能启动、现在 Secure Boot 报错」的机器，优先按这两条处理。

### 6.4 卡进 grub shell 或直接启动失败

排除 Secure Boot 后仍启动失败，最常见三类原因[^c6-S3]：

1. **扩容/假 U 盘**：实际容量远小于标称值，引导文件或镜像落在「假容量」区域读不出来。换一块正规渠道的 U 盘重做一次即知。
2. **老主板 Legacy BIOS 的访问范围限制**：部分老机器的 Legacy 模式只能访问磁盘前约 **128GB** 空间。镜像放在靠后位置会找不到——把镜像放前面、换小容量盘、或改用 UEFI 模式启动。
3. **镜像损坏**：拷贝中断、源文件本身损坏都会导致启动到一半失败。用发布方给的校验值核对，例如在 Linux 下：

```bash
# 用发布方给的 SHA256 值核对 ISO，输出应完全一致
sha256sum 你的镜像.iso
```

Windows 下可用 `certutil -hashfile 你的镜像.iso SHA256` 核对。

### 6.5 Ventoy2Disk 安装失败：多半是进程占用

在 Windows 上点「安装」报失败、或列表里找不到 U 盘，常是**有程序正占用 U 盘/磁盘**。已知的常见元凶包括：Paragon ExtFS、DokanMounter、ext2fsd、DiskGenius、Intel DSA（Intel 驱动支持助手）等[^c6-S3]。

处理步骤：

1. 关闭上述占用软件（含托盘驻留程序），必要时在任务管理器结束进程；
2. 拔下 U 盘重新插入；
3. 重新以管理员身份运行 `Ventoy2Disk.exe`，再次安装；
4. 仍失败就重启电脑后再试一次（彻底释放句柄）。

### 6.6 卡在 "Ventoy scanning files, please wait..."

启动菜单出现这行字后长时间不动，通常是**数据分区里文件太多**，Ventoy 递归扫描全部目录耗时过长[^c6-S3]。两种解法：

- **限定搜索路径**：用 VentoyPlugson 等配置把扫描范围指向固定的镜像目录，别让它全盘递归；
- **跳过指定目录**：在不希望被扫描的目录里放一个名为 `.ventoyignore` 的空文件，Ventoy 会跳过整个目录。创建方式：

```bash
# Linux：在目标目录里创建空标记文件
touch /挂载点/某个大目录/.ventoyignore
```

```bat
rem Windows：在目标目录里创建空标记文件
type nul > .ventoyignore
```

> [!tip] 大白话
> `.ventoyignore` 就像给文件夹门口挂一块「仓库重地，闲人免进」的牌子——Ventoy 扫到这里看一眼牌子就绕道走，不会进去把每个箱子都翻一遍。

### 6.7 VTOYEFI 引导分区损坏：非破坏安装修复

32MB 的 VTOYEFI 分区（分区 2）被误格式化或损坏后，U 盘会完全无法引导。修复思路是**只重建引导分区、不动镜像数据**，即「非破坏安装（Non-destructive install）」[^c6-S3]：

1. 先删掉损坏的 VTOYEFI 分区，把它腾成空闲空间。可用 DiskGenius 图形操作，也可用 Windows 自带 diskpart：

```bat
diskpart
list disk          rem 确认 U 盘是几号盘，别选错系统盘
select disk 2      rem 换成你的 U 盘编号
list partition
select partition 2 rem 选中损坏的 VTOYEFI 分区
delete partition override
exit
```

2. 回到 `Ventoy2Disk.exe`，选择**非破坏安装（Non-destructive install）**而不是普通安装——它只重建引导分区，不会清空第一分区的镜像文件；
3. 完成后重新拔插 U 盘并测试启动。

> [!tip] 大白话
> 这就像房间（数据分区）里的家具不动，只把坏掉的「门禁读卡器」（VTOYEFI 引导分区）拆下来换个新的。千万别手滑选了普通「安装」——那是把整个房间推倒重装，镜像全没。

### 6.8 看菜单左下角，确认启动模式

Ventoy 启动菜单左下角会显示当前实际引导模式[^c6-S3]：

| 标识 | 含义 |
|------|------|
| `BIOS` | Legacy BIOS 模式 |
| `UEFI` | 64 位 UEFI 模式（最常见） |
| `IA32` | 32 位 UEFI 模式 |
| `AA64` | ARM64 UEFI 模式 |
| `MIPS` | MIPS64EL UEFI 模式 |

排查时先看这个角标，能立刻确认主板到底在用哪种模式启动——很多「为什么这台机器起不来、那台可以」的困惑，根源就是两台机器走了不同模式。

### 本章小结

- 启动失败先分层：引导模式 → 引导分区 → 镜像完整性 → 机器限制，逐层确认再动手。
- Secure Boot 首次启动要进蓝色界面注册 key（每台机器一次）；报错（如 Linpus lite）就去 BIOS 关掉 Secure Boot。
- Ventoy 1.1.13+ 因 UEFI CA 2023 需重新注册 key，部分固件还要开 `Allow Microsoft 3rd Party UEFI CA`。
- 启动失败重点查扩容假盘、老主板 Legacy 约 128GB 限制、镜像损坏（checksum 验证）。
- 安装失败先关占用进程（Paragon ExtFS、DokanMounter、ext2fsd、DiskGenius、Intel DSA）；扫描卡顿用搜索路径或 `.ventoyignore` 限范围。
- VTOYEFI 损坏用 diskgenius/diskpart 删分区后走非破坏安装；左下角标识（`BIOS`/`UEFI`/`IA32`/`AA64`/`MIPS`）用于确认实际启动模式。

走完这章，主线日常使用的坑基本都有了对应解法。至于严格 Secure Boot 策略、插件与持久化等进阶话题，等把这块盘真正用熟之后，再翻阅官方文档也不迟。

## 第七章：（可选）进阶速览——等用熟了再看

用顺了 Ventoy 之后，这几个进阶点值得先知道「有这回事、去哪查」。每节只给概念定位和官方文档入口，不展开操作细节，等真要用到时再按需翻原文。

### 7.1 严格 Secure Boot：从「绕过」到「遵循」

Ventoy 对 Secure Boot 的**默认策略是「完全绕过」**；如果环境（如企业安全策略）要求严格遵循 UEFI 安全启动流程，可通过 **Global Control Plugin** 的 `VTOY_SECURE_BOOT_POLICY` 开关切换 [^c7-1]。概念与入口到此为止，具体取值见[官方插件控制文档](https://www.ventoy.net/cn/plugin_control.html)与 [About Secure Boot](https://www.ventoy.net/en/doc_secure.html)。

### 7.2 插件体系：一切配置落在 ventoy.json

主题、菜单、上述全局控制等高级功能都以**插件**形式提供，实际载体是一个 JSON 配置文件。官方提供可视化配置器 **VentoyPlugson** 帮你生成和修改，不必手写 JSON。文件位置是高频坑：`ventoy.json` 必须放在**第一分区（镜像数据区）的 `\ventoy\ventoy.json`**，不能放进 32MB 的 VTOYEFI [^c7-2]。

> [!tip] 大白话
> 把 VTOYEFI 想成点唱机的内置固件（平时别碰），`ventoy.json` 是放在手边的「歌单设置」——设置当然要放在你够得着的地方，也就是镜像数据区的 `\ventoy\` 文件夹里。

### 7.3 持久化（persistence）

想让 Linux 发行版 Live 启动后，重启仍保留装过的软件、改过的配置，这就是 **persistence（持久化）** 的适用场景。它属于进阶深水区，具体用法见[官方 persistence 文档](https://www.ventoy.net/cn/plugin_persistence.html)。

### 7.4 保留空间与自建分区 3/4

在磁盘末尾预留空间（Windows 安装界面的「分区设置」/ Linux 的 `-r` 参数）有两点关键认知 [^c7-3]：

- **只在安装时生效**：装 Ventoy 那一刻就要决定预留多少，之后不能再改。
- **分区 1/2 不可移动或改大小**：装好后数据分区与 VTOYEFI 的位置、大小都固定了；只能在预留区**自建分区 3、分区 4** 来利用这块空间。

> [!tip] 大白话
> 分区 1/2 是承重墙，装完不能再挪；保留空间像收房时留出的储物区，想隔成几间（分区 3/4）得在装修（安装）前就划好。

### 7.5 Windows 命令行模式

`Ventoy2Disk.exe` 也提供命令行参数版本（官方文档页 `doc_windows_cli`），适合想写脚本批量部署的读者；日常用图形界面即可，需要自动化时再查[对应文档](https://www.ventoy.net/cn/doc_windows_cli.html)。

---

**本章小结**

- 默认「绕过」Secure Boot；要严格遵循时用 Global Control Plugin 的 `VTOY_SECURE_BOOT_POLICY` 切换 [^c7-1]。
- 插件配置载体是 `ventoy.json`：放第一分区 `\ventoy\ventoy.json`，**别放** VTOYEFI；可用 VentoyPlugson 可视化编辑 [^c7-2]。
- persistence 面向「Live 系统重启保留改动」的需求，进阶用法指向官方文档。
- 保留空间只在安装时生效；分区 1/2 固定不可改，预留区可自建分区 3/4 [^c7-3]。
- 批量自动化需求可走 Windows 命令行（doc_windows_cli），日常 GUI 已够用。
