# 虚拟机 vs 容器 vs WSL2：三种「装系统」的思路

上一章我们认识了虚拟机这台「电脑里的电脑」。可同一台电脑上想再开出一套系统，市面上至少有三条路：虚拟机、容器（Docker 是代表）、以及 Windows 自带的 WSL2。它们都做「隔离」，差别在隔离做到哪一层。搞懂这个分水岭，你就不会被「虚拟机太重」「容器不能跨系统」「WSL2 是不是虚拟机」这类讨论绕晕。

## 2.1 核心分水岭：搬一整套「带家具的房子」 vs 只打包自己的行李

沿用第 1 章的出租屋比喻。虚拟机 = 房东（Hypervisor）隔出整套「带家具的房子」：完整 OS 原样搬入，水电各走各表，房子多重虚拟机就多重；想换装修风格（换操作系统）推倒重来也行，且与隔壁租客互不干扰。容器是另一思路：只打包「自己的行李」——应用、依赖库、配置——住进由宿主操作系统管水电的大楼，行李里没有厨房锅炉（没有独立内核），用的是大楼公共水电，也就是宿主的内核服务。[^c2-1][^c2-2][^c2-3]

> [!tip] 大白话：什么是「共享宿主内核」？
> 把宿主操作系统想成大楼总闸，容器是只带随身行李的房客：靠大楼统一水电（宿主内核）生活，入住快、行李少。可大楼一停水停电（内核出问题），全楼房客一起遭殃；虚拟机是带独立厨房的套房，自家水管爆了只淹自己那套。

## 2.2 逐项对比：隔离、体重、启动、更新

VM 与容器最关键的差异有四：[^c2-1][^c2-2][^c2-3]

- **隔离强度**：VM 与宿主、与其他 VM 完全隔离，能构成强安全边界；容器是轻量隔离，比进程级强、但弱于 VM。
- **体重与启动**：VM 自带整套 OS，体积大、吃资源，要引导整个系统；容器共享内核只带应用层，体积小、近乎秒开。
- **更新方式**：VM 要进每台客户机打补丁，换系统版本常等于新建一台 VM；容器改构建文件（Dockerfile）指向新基础镜像 → 重建镜像 → 重新部署即可。
- **异构 OS**：VM 几乎能跑任何操作系统；容器只能跑与宿主同版本体系的操作系统。

「VM 更新重、容器重建即更新」是个钩子，第 8 章选型时我们会回来用它。

| 对比维度 | 虚拟机（VM） | 容器 | WSL2 |
| --- | --- | --- | --- |
| 隔离单位 | 整台「虚拟电脑」（虚拟硬件 + 完整 OS） | 单个应用及其依赖 | 一个 Linux 发行版，底层是微软托管的轻量 VM |
| 内核 | 自带完整内核 | 共享宿主内核，不自带 | 微软提供的真实 Linux 内核 |
| 启动速度 | 慢（要引导完整 OS） | 近乎即时 | 快（后台托管，无需自己配置） |
| 更新方式 | 进每台 VM 打补丁 / 升级系统 | 改 Dockerfile → 重建镜像 → 重新部署 | 内核随 Windows 更新自动推送 |
| 可否跑异构 OS | 几乎可以运行任意 OS | 只能与宿主同 OS | 专为在 Windows 里跑 Linux 设计 |
| 典型场景 | 强隔离、跑异构系统、开发测试 | 同 OS 下打包和编排大量轻量服务 | Windows 里开一个 Linux 环境做开发 |

## 2.3 容器引擎不是 Hypervisor

新手最常见的误会，是把容器说成「一种更轻的虚拟机」。容器引擎（如 Docker）跑在完整操作系统之上，由它提供内核；容器只是往内核上叠应用、依赖和少量运行时，没有属于自己的客户机 OS，也不虚拟化整块硬件——中间没有 hypervisor 那一层。[^c2-1][^c2-2][^c2-3]

> [!tip] 大白话：容器引擎和 Hypervisor 差在哪？
> Hypervisor 是房东把一套房隔成几套独立公寓，每套自带水电（完整系统）；容器引擎更像在一间大开间里拉几道帘子分头办公——帘子隔得开座位，却共用同一套空调和总闸。所以容器隔得开「进程」，隔不开底下那个大家共用的内核。

正因如此，本笔记不采用「容器引擎是专门化的 Type 2 hypervisor」的说法：hypervisor 的职责是切分硬件资源、喂饱多个完整系统，而容器没有第二个系统要喂。[^c2-1]

## 2.4 WSL1（转换层） vs WSL2（微软托管的轻量实用 VM）

WSL 是 Windows Subsystem for Linux 的缩写，是微软官方给 Windows 用户「在 Windows 里跑 Linux」的方案，分两代。[^c2-4]

- **WSL1 不是虚拟机**：它没有 Linux 内核，只用一个转换层把 Linux 程序的系统调用实时翻译成 Windows 内核能懂的调用。跨系统读写文件快，但系统调用兼容不完整，个别 Linux 软件跑不了。
- **WSL2 是微软托管的轻量实用 VM**：后台真跑一台轻量虚拟机，内含微软维护的真实 Linux 内核，系统调用完全兼容；内核随 Windows 更新推送，用户不用自己装系统。这正是 WSL2 是默认版本的原因。WSL1 仅在项目文件必须放 Windows 盘、需跨系统交叉编译等少数场景仍占优。

> [!tip] 大白话：WSL2 算虚拟机吗？
> 把 WSL2 想成托管式公寓：底层确实用了一间「虚拟机套房」，但房东不是你——微软在后台开好、维护好，Windows 更新时顺手换内核。你不用像用 VirtualBox 那样分配内存、装系统，所以体验上不像；但要刨根问底，它底层确实是 VM。

关于 WSL2 与 VirtualBox / Hyper-V 能否共存：早期资料称 WSL2 与 VirtualBox 6+ 有明显兼容问题，如今 7.x 已改善，但请以你当前版本实测为准。[^c2-4]

## 2.5 互补关系：容器常常跑在虚拟机里

最后别把三者当对手。容器和 VM 互补：云厂商的典型做法是先拿 VM 把物理服务器切成相互隔离的租户，再在 VM 里跑容器——容器负责打包应用、快速伸缩，VM 负责强隔离的安全边界。微软官方也指出，许多容器部署以 VM 为宿主 OS，而不是直接跑在裸硬件上，云端尤其如此。[^c2-2]

到这里，VM 的定位已经清楚。下一章钻回虚拟机内部看它的「零件」：这台电脑没有实体硬件，那内存、硬盘从哪来？答案藏在几个配置文件和镜像文件里——这也是后面理解快照与磁盘维护的地基。

## 本章小结

- 分水岭在「隔离到哪一层」：VM 整套 OS 自己带，容器共享宿主内核只带应用层，WSL2 是微软托管的轻量实用 VM。[05][12][13][07]
- VM 强隔离、能跑异构 OS，代价是重、更新慢；容器轻、秒开、更新靠重建镜像，但隔离弱、不能跨 OS。[13]
- 容器引擎不是 hypervisor：容器共享宿主内核、无 hypervisor。[05][12][13]
- WSL1 = 系统调用转换层、非 VM；WSL2 = 托管 VM + 真实 Linux 内核、随 Windows 更新；与 VBox/Hyper-V 共存以当前版本实测为准。[07]
- 三者互补：容器常跑在虚拟机里（云上常见架构）。[13]
