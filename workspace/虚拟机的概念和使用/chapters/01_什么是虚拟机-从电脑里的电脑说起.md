# 什么是虚拟机：从「电脑里的电脑」说起

如果有人告诉你：不用买新电脑，也能在一台电脑里再「开」一台电脑，里面能装另一个操作系统、跑另一套软件，你会不会觉得是魔术？这不是魔术，而是虚拟化（Virtualization）技术。这一章我们从零认识虚拟机：它到底是什么、由哪几个角色组成、分成哪两类，以及普通人常用它来做什么。

## 1.1 一台用软件造出来的「电脑」

虚拟机（Virtual Machine，简称 VM）就是用软件造出来的一台「电脑」。它没有真实的外壳和芯片，却可以像真电脑一样运行操作系统、安装程序、存文件、联网。它跑在哪？跑在真实的物理电脑上——这台出体力活的物理电脑被称为宿主机（host），而虚拟机的全部「零件」都是宿主机上由软件模拟出来的。[^c1-1][^c1-2]

> [!tip] 大白话：什么是虚拟机？
> 把真实电脑想成一套出租屋，虚拟机就是用软件在这套屋里隔出的独立房间。房间里的家具（操作系统、软件）是你自己布置的，水电燃气（CPU、内存、磁盘）仍是房东这套。所以它可以独立开关、随意折腾，却不用真的再买一套房。

从你眼前看，一台运行中的虚拟机通常就是一个窗口，窗口里是一个完整的系统桌面，看起来和真电脑没两样。它的内部结构可以概括成一条纵线：

```text
你的应用软件
   ↓
客户机操作系统（Guest OS，虚拟机里那个系统）
   ↓
Hypervisor（虚拟化管理层）
   ↓
宿主物理硬件（CPU / 内存 / 磁盘 / 网卡）
```

这条纵线值得记住：虚拟机里的一切都在上层，最底下始终是这台真实电脑的硬件。

## 1.2 三个角色正名：宿主机 Host / 客户机 Guest / Hypervisor

要听懂虚拟机的话题，先认三个人。[^c1-2][^c1-3]

- **宿主机（Host）**：装虚拟化软件、提供硬件的那台物理电脑。比如你准备安装 VirtualBox 的那台 Windows 电脑。
- **客户机（Guest）**：跑在虚拟机里面的操作系统；平时也常把这台虚拟机本身叫 guest。同一个宿主上可以同时跑多个 guest，彼此隔离。
- **Hypervisor**：中间那层管理软件，旧名叫虚拟机监视器（Virtual Machine Monitor，VMM）。它的工作是把宿主的 CPU、内存、存储、网络切成一块块「资源池」，再按需分给每个客户机。

> [!tip] 大白话：Hypervisor 是干什么的？
> 把宿主机想成一个大食堂，Hypervisor 就是切菜分餐的师傅：他把整块食材（CPU、内存、磁盘、网络）切成一份份装进不同餐盒，分给各个窗口（客户机）。每个窗口只拿到自己那份，互不串味。

本笔记实操要用的 VirtualBox，就是这样一个跑在宿主机操作系统之上的 Hypervisor。[^c1-2][^c1-3]

## 1.3 Hypervisor 的两种形态：Type 1 与 Type 2

Hypervisor 按「自己住在哪一层」分成两类。[^c1-1][^c1-3]

- **Type 1，裸机型（bare-metal）**：直接装在物理硬件上，不需要先装操作系统，它自己就是最底层。代表产品有 VMware ESXi、Microsoft Hyper-V、KVM、Xen，常见于企业数据中心。
- **Type 2，托管型（hosted）**：像一个普通应用那样，装在已有操作系统之上。代表产品有 Oracle VM VirtualBox、VMware Workstation、QEMU、Parallels Desktop，常见于个人桌面与开发测试。

Type 2 与 Type 1 的目标相同，但中间多了一层宿主操作系统。虚拟机的所有请求都要先经过这个共同的操作系统转发，才碰得到硬件，所以多了一段路径；宿主 OS 也是所有虚拟机共同的关注点——它一旦出问题，跑在它上面的虚拟机都可能受影响。[^c1-3]

> [!tip] 大白话：Type 1 和 Type 2 差在哪？
> Type 1 像一栋专门用来开「虚拟公寓」的楼，一楼就是机房，没有别的住户。Type 2 像你自己住着的房子里再隔出几间出租——租客进出都要经过你家大门（宿主 OS），大门一锁，谁也别想进出。

| 对比维度 | Type 1（裸机型） | Type 2（托管型） |
| --- | --- | --- |
| 部署位置 | 直接装在物理硬件上，不需要底层操作系统 | 作为应用装在宿主操作系统之上 |
| 代表产品 | VMware ESXi、Microsoft Hyper-V、KVM、Xen | VirtualBox、VMware Workstation、QEMU、Parallels Desktop |
| 资源口径 | Hypervisor 直接管理硬件，中间少一层软件 | 一切请求经宿主 OS 转发，多一层路径 |
| 典型用途 | 数据中心、服务器整合、生产环境 | 个人桌面、开发测试、学习实验 |

> 顺便澄清一句：虚拟化 ≠ 云。虚拟化是「把一台物理机拆成多台虚拟电脑」的技术；云是在虚拟化之上，再叠加「按需自助开通、弹性伸缩、按量计费」等能力的服务模式。[^c1-1][^c1-3]

## 1.4 典型用途：普通人为什么需要它

虚拟机最常见的几类用法：[^c1-1][^c1-3]

- **学新系统、随便折腾**：想试试 Linux 又不想动主力电脑，开一台虚拟机随便装、随便玩，玩坏了删掉重建即可。
- **隔离试验**：测试不放心的软件、研究安全问题时，把它关在虚拟机里，不影响宿主机。
- **跑不兼容的旧软件**：有些老软件在新系统上跑不起来，就保留一台旧系统的虚拟机专门运行它。
- **一台当多台用**：一台物理服务器开多个虚拟机承载不同业务；云服务商把服务器分给众多用户（多租户）靠的也是它。

这一章我们建起了「电脑里的电脑」这个画面。下一章要回答一个紧接着的问题：同样是做隔离，虚拟机、容器（Docker）和 WSL2 这三兄弟到底有什么不一样？搞清楚之后，你就知道什么时候该用谁了。

## 本章小结

- 虚拟机 = 用软件造出来的「电脑」，跑在真实物理机上，能装系统、跑软件、存文件、联网。[05]
- 三个角色：宿主机 Host（出硬件）、客户机 Guest（虚拟机里的系统）、Hypervisor（切块分池的管理层，旧名 VMM）。[03][05][11]
- Hypervisor 把宿主 CPU/内存/存储/网络切块分池给客户机；分 Type 1（裸机，如 ESXi / Hyper-V / KVM）和 Type 2（托管，如 VirtualBox / VMware Workstation）。[05][11]
- Type 2 跑在宿主 OS 之上、多一层转发路径，宿主 OS 是共同关注点（措辞已按素材矛盾裁决修正）。[11]
- 典型用途：学新系统、隔离试验、跑旧软件、一台顶多台；虚拟化 ≠ 云。
