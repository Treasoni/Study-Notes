# 常见坑与磁盘维护：从 VT-x 到「越用越胖」的磁盘

这是本笔记的最后一章，我们从「怎么用」切换到「出问题怎么救」。前几章把概念、实操和选型都走完了，但真正让新手放弃虚拟机的，往往是几个特别具体的坑：虚拟化加速开不起来、内存给太多把宿主机拖垮、磁盘文件「只涨不缩」越用越胖。这一章把它们摆成一张坑清单，讲清现象与排查方向，再给一条官方磁盘瘦身流程和一份收尾维护清单。

## 9.1 坑 1：BIOS 没开 VT-x/AMD-V，或被 Windows 抢先占用

Intel VT-x 和 AMD-V 是 CPU 里的硬件虚拟化扩展，作用是给 Hypervisor 提供硬件加速，让虚拟机跑得顺畅。[^c9-2] 服务器基本都默认开启，但桌面电脑经常在 BIOS 里关着，需要手动打开。[^c9-3] 缺少硬件加速时，Type 2 虚拟化软件会退回到「纯软件模拟」，性能损失非常明显。[^c9-2]

- **现象**：新建/启动 64 位客户机时报「VT-x/AMD-V 不可用」之类的错，或虚拟机能启动但慢得明显。
- **排查方向 ①——BIOS/UEFI**：重启进固件设置，找 **Intel Virtualization Technology（VT-x）** 或 AMD 的 **SVM Mode**，改为开启后保存重启。这是第 3、5 章提过的那道「加速开关」。
- **排查方向 ②——Windows 抢占**：BIOS 明明已开，VirtualBox/VMware 却仍报 VT-x 不可用，这在 Windows 上通常指向 Hyper-V 或「内核隔离」常驻占用了硬件虚拟化功能。

> [!tip] 大白话：抢占是什么？
> 把硬件虚拟化功能想成一栋楼里唯一一部货梯。Windows 的 Hyper-V / 内核隔离常驻时，等于有人把货梯长期占用并锁了门；这时 VirtualBox、VMware 再想用同一部货梯，就会被挡在门外——报错或慢到没法用。解决方向就是让 Windows 先「放梯」：关掉 Hyper-V、关掉内核隔离，重启后再试。

关于 Hyper-V / 内核隔离（VBS，即「内存完整性」）与 VirtualBox / VMware 的冲突，目前没有权威的通用专项说明，以上只是**现象 + 排查方向**的经验级提示，请以你当前版本的实测为准。操作入口：`Windows 功能` 里取消勾选 Hyper-V；`Windows 安全中心 → 设备安全性 → 内核隔离` 里关掉内存完整性。两者都要重启才生效。

## 9.2 坑 2：内存/CPU 给太多，宿主先卡死

很多新手觉得「给虚拟机越多越流畅」，结果反被卡死的是宿主机。

- **现象**：虚拟机开着，宿主机鼠标开始发飘、切窗口要等好几秒、硬盘灯常亮不灭。
- **原因**：分给虚拟机的那部分内存，在虚拟机运行期间宿主机就用不到了。[^c9-4] 一旦给得超过你能 spare 的额度，宿主自身内存不够，Windows 会把内存内容不断换到硬盘上的页面文件（swap），整机陷入无穷无尽的「倒腾」，几乎等于假死。[^c9-4]
- **排查方向**：先关掉多余的虚拟机，按第 5 章的铁律重新分配——内存按向导建议值给，同时运行多台虚拟机时要加总预算；处理器数不要超过宿主总线程数的一半。[^c9-4]

> [!tip] 大白话：内存是借来的
> 把宿主机的内存想成你钱包里的现金。借给虚拟机太多，自己剩的钱不够付水电，只能把家当搬去储物间（磁盘换页），取一件都要跑一趟，全家卡在门口排队——这就是宿主卡成 PPT 的原因。所以只借你 spare 得起的额度，别把家底掏空。

## 9.3 坑 3：磁盘越用越胖——稀疏盘「只增不减」

第 3 章讲过「动态增长（稀疏）盘」：镜像文件随客户机使用量增长，而不是一开始就占满。VMware 官方把磁盘分成两类：**预分配盘**的镜像文件大小从一开始就等于磁盘容量；**稀疏盘**的镜像文件大小约等于客户机内的「已用空间」。[^c9-1]

问题出在稀疏盘「只增不减」：在客户机里删除文件后，镜像文件并不会自动缩小。官方列出的典型症状就是：宿主上的 .vmdk 文件体积，明显大于客户机系统里显示的已用空间。[^c9-1]

另外要提醒：VM 目录偏大，不一定都是磁盘镜像的错。整个 VM 目录 = 虚拟磁盘 + **快照** + **挂起状态文件**（如果 VM 被挂起）+ 设置文件 + 日志，官方明确说 VM 目录总是比虚拟磁盘本身大，先看清楚是哪一部分在占空间。[^c9-1]

> [!tip] 大白话：只进不出的储物箱
> 把动态磁盘想成一个只进不出的储物箱：往里放东西，箱子会变大；但往外扔东西，箱子外壳并不会缩回去——空出来的位置只是留在箱子里。镜像文件同理：guest 里删了文件，那些扇区只是被标记成「可覆盖」，宿主上的镜像文件不会自动变小。

## 9.4 磁盘瘦身：VMware 官方三步（有快照先删）

想真正让镜像文件「瘦」回去，用 VMware Workstation 的官方流程最稳妥。它只对**稀疏盘**有效，预分配盘不适用。[^c9-1]

开始前先做两个确认：

1. **确认磁盘类型**：菜单 `Virtual Machine > Settings > Hard Disk`，在 Disk information 里看是稀疏还是预分配。
2. **有快照必须先删**：官方明确说，带快照的磁盘无法收缩，删完快照再继续。[^c9-1]

然后按顺序操作（全程勿中断）：

1. **客户机内碎片整理**：在 Windows 客户机里对磁盘做一次碎片整理，把已用空间整理成连续区域，这是收缩的前提。[^c9-1]
2. **用 VMware Tools 收缩**：对 Workstation 9.x（Windows）及以后版本，收缩动作已并入下一步，VMware Tools 面板里的 Shrink 选项被移除。[^c9-1]
3. **从宿主层清理**：在主菜单执行 `VM > Manage > Clean up Disks`，让 Workstation 把镜像尾部空出来的区域回收掉。[^c9-1]

**红线警告**：收缩过程中不要关闭虚拟机、不要关闭宿主机、更不要手动取消。官方警告说，中断这个流程可能对虚拟磁盘造成**不可修复的损坏**，虚拟机可能再也无法启动。[^c9-1]

VirtualBox 用户请注意：VDI 镜像也有类似体积问题，社区常用 `VBoxManage modifyhd --compact` 压缩，但该命令**没有官方 KB 支撑、属经验级操作**，需关机后自行实测；本笔记只保证 VMware 官方三步的可靠性。

## 9.5 收尾维护清单

养成三个习惯，能少踩 9.3 那种「越用越胖」的坑：

- **定期删不需要的快照**：快照基于差异镜像，会持续占磁盘；留着最新一两个可用即可。牢记第 4 章的结论——快照不是备份。
- **监视 VM 目录大小**：目录明显大于客户机「已用空间」时，先查是不是快照、挂起状态文件或日志在占地方，再决定要不要做一次 9.4 的收缩。
- **重要数据靠备份**：快照只能回滚系统状态，数据安全底线是备份。好消息是第 3 章讲过：虚拟磁盘本质是普通文件，复制一份镜像文件，就是最朴素的整机备份。

到这里，9 章全部走完：从「什么是虚拟机」的概念地图，到 VirtualBox/VMware 两条实操线，再到选型与排障。以后遇到问题不用从头翻——概念卡住看第 1–4 章，操作卡住看第 5–7 章，拿不定主意看第 8 章，跑不起来、磁盘变胖就看这一章。

## 本章小结

- VT-x/AMD-V 是 CPU 的硬件虚拟化加速开关：服务器标配，桌面机常在 BIOS 里关着；缺失时 Type 2 退化为软件模拟、性能明显下降。[06][11][12]
- Windows 下 Hyper-V / 内核隔离抢占硬件虚拟化是经验级排查项：关掉后重启再试，以实测为准。
- 分给虚拟机的内存，运行期间宿主就用不到；给太多会让宿主靠磁盘换页硬撑、整机卡死；CPU 别超过宿主线程数一半。[01]
- 稀疏盘「只增不减」：guest 内删文件镜像不自动缩小；VM 目录大还可能是快照 / 挂起状态文件 / 日志在占空间。[06]
- VMware 瘦身官方流程：仅稀疏盘、先删快照 → 客户机碎片整理 → `VM > Manage > Clean up Disks`；全程勿中断，中断可能毁盘。[06]
