## 第 1 章 什么是虚拟机：从「电脑里的电脑」说起

如果有人告诉你：不用买新电脑，也能在一台电脑里再「开」一台电脑，里面能装另一个操作系统、跑另一套软件，你会不会觉得是魔术？这不是魔术，而是虚拟化（Virtualization）技术。这一章我们从零认识虚拟机：它到底是什么、由哪几个角色组成、分成哪两类，以及普通人常用它来做什么。

### 1.1 一台用软件造出来的「电脑」

虚拟机（Virtual Machine，简称 VM）就是用软件造出来的一台「电脑」。它没有真实的外壳和芯片，却可以像真电脑一样运行操作系统、安装程序、存文件、联网。它跑在哪？跑在真实的物理电脑上——这台出体力活的物理电脑被称为宿主机（host），而虚拟机的全部「零件」都是宿主机上由软件模拟出来的。[^c1-1][^c1-2]

> [!tip] 大白话：什么是虚拟机？
> 把真实电脑想成一套出租屋，虚拟机就是用软件在这套屋里隔出的独立房间。房间里的家具（操作系统、软件）是你自己布置的，水电燃气（CPU、内存、磁盘）仍是房东这套。所以它可以独立开关、随意折腾，却不用真的再买一套房。

从你眼前看，一台运行中的虚拟机通常就是一个窗口，窗口里是一个完整的系统桌面，看起来和真电脑没两样。它的内部结构可以概括成一条纵线：

```text
你的应用软件
   ↓
客户机操作系统（Guest OS，虚拟机里那个系统）
   ↓
Hypervisor（虚拟化管理层）
   ↓
宿主物理硬件（CPU / 内存 / 磁盘 / 网卡）
```

这条纵线值得记住：虚拟机里的一切都在上层，最底下始终是这台真实电脑的硬件。

### 1.2 三个角色正名：宿主机 Host / 客户机 Guest / Hypervisor

要听懂虚拟机的话题，先认三个人。[^c1-2][^c1-3]

- **宿主机（Host）**：装虚拟化软件、提供硬件的那台物理电脑。比如你准备安装 VirtualBox 的那台 Windows 电脑。
- **客户机（Guest）**：跑在虚拟机里面的操作系统；平时也常把这台虚拟机本身叫 guest。同一个宿主上可以同时跑多个 guest，彼此隔离。
- **Hypervisor**：中间那层管理软件，旧名叫虚拟机监视器（Virtual Machine Monitor，VMM）。它的工作是把宿主的 CPU、内存、存储、网络切成一块块「资源池」，再按需分给每个客户机。

> [!tip] 大白话：Hypervisor 是干什么的？
> 把宿主机想成一个大食堂，Hypervisor 就是切菜分餐的师傅：他把整块食材（CPU、内存、磁盘、网络）切成一份份装进不同餐盒，分给各个窗口（客户机）。每个窗口只拿到自己那份，互不串味。

本笔记实操要用的 VirtualBox，就是这样一个跑在宿主机操作系统之上的 Hypervisor。[^c1-2][^c1-3]

### 1.3 Hypervisor 的两种形态：Type 1 与 Type 2

Hypervisor 按「自己住在哪一层」分成两类。[^c1-1][^c1-3]

- **Type 1，裸机型（bare-metal）**：直接装在物理硬件上，不需要先装操作系统，它自己就是最底层。代表产品有 VMware ESXi、Microsoft Hyper-V、KVM、Xen，常见于企业数据中心。
- **Type 2，托管型（hosted）**：像一个普通应用那样，装在已有操作系统之上。代表产品有 Oracle VM VirtualBox、VMware Workstation、QEMU、Parallels Desktop，常见于个人桌面与开发测试。

Type 2 与 Type 1 的目标相同，但中间多了一层宿主操作系统。虚拟机的所有请求都要先经过这个共同的操作系统转发，才碰得到硬件，所以多了一段路径；宿主 OS 也是所有虚拟机共同的关注点——它一旦出问题，跑在它上面的虚拟机都可能受影响。[^c1-3]

> [!tip] 大白话：Type 1 和 Type 2 差在哪？
> Type 1 像一栋专门用来开「虚拟公寓」的楼，一楼就是机房，没有别的住户。Type 2 像你自己住着的房子里再隔出几间出租——租客进出都要经过你家大门（宿主 OS），大门一锁，谁也别想进出。

| 对比维度 | Type 1（裸机型） | Type 2（托管型） |
| --- | --- | --- |
| 部署位置 | 直接装在物理硬件上，不需要底层操作系统 | 作为应用装在宿主操作系统之上 |
| 代表产品 | VMware ESXi、Microsoft Hyper-V、KVM、Xen | VirtualBox、VMware Workstation、QEMU、Parallels Desktop |
| 资源口径 | Hypervisor 直接管理硬件，中间少一层软件 | 一切请求经宿主 OS 转发，多一层路径 |
| 典型用途 | 数据中心、服务器整合、生产环境 | 个人桌面、开发测试、学习实验 |

> 顺便澄清一句：虚拟化 ≠ 云。虚拟化是「把一台物理机拆成多台虚拟电脑」的技术；云是在虚拟化之上，再叠加「按需自助开通、弹性伸缩、按量计费」等能力的服务模式。[^c1-1][^c1-3]

### 1.4 典型用途：普通人为什么需要它

虚拟机最常见的几类用法：[^c1-1][^c1-3]

- **学新系统、随便折腾**：想试试 Linux 又不想动主力电脑，开一台虚拟机随便装、随便玩，玩坏了删掉重建即可。
- **隔离试验**：测试不放心的软件、研究安全问题时，把它关在虚拟机里，不影响宿主机。
- **跑不兼容的旧软件**：有些老软件在新系统上跑不起来，就保留一台旧系统的虚拟机专门运行它。
- **一台当多台用**：一台物理服务器开多个虚拟机承载不同业务；云服务商把服务器分给众多用户（多租户）靠的也是它。

这一章我们建起了「电脑里的电脑」这个画面。下一章要回答一个紧接着的问题：同样是做隔离，虚拟机、容器（Docker）和 WSL2 这三兄弟到底有什么不一样？搞清楚之后，你就知道什么时候该用谁了。

### 本章小结

- 虚拟机 = 用软件造出来的「电脑」，跑在真实物理机上，能装系统、跑软件、存文件、联网。[05]
- 三个角色：宿主机 Host（出硬件）、客户机 Guest（虚拟机里的系统）、Hypervisor（切块分池的管理层，旧名 VMM）。[03][05][11]
- Hypervisor 把宿主 CPU/内存/存储/网络切块分池给客户机；分 Type 1（裸机，如 ESXi / Hyper-V / KVM）和 Type 2（托管，如 VirtualBox / VMware Workstation）。[05][11]
- Type 2 跑在宿主 OS 之上、多一层转发路径，宿主 OS 是共同关注点（措辞已按素材矛盾裁决修正）。[11]
- 典型用途：学新系统、隔离试验、跑旧软件、一台顶多台；虚拟化 ≠ 云。

## 第 2 章 虚拟机 vs 容器 vs WSL2：三种「装系统」的思路

上一章我们认识了虚拟机这台「电脑里的电脑」。可同一台电脑上想再开出一套系统，市面上至少有三条路：虚拟机、容器（Docker 是代表）、以及 Windows 自带的 WSL2。它们都做「隔离」，差别在隔离做到哪一层。搞懂这个分水岭，你就不会被「虚拟机太重」「容器不能跨系统」「WSL2 是不是虚拟机」这类讨论绕晕。

### 2.1 核心分水岭：搬一整套「带家具的房子」 vs 只打包自己的行李

沿用第 1 章的出租屋比喻。虚拟机 = 房东（Hypervisor）隔出整套「带家具的房子」：完整 OS 原样搬入，水电各走各表，房子多重虚拟机就多重；想换装修风格（换操作系统）推倒重来也行，且与隔壁租客互不干扰。容器是另一思路：只打包「自己的行李」——应用、依赖库、配置——住进由宿主操作系统管水电的大楼，行李里没有厨房锅炉（没有独立内核），用的是大楼公共水电，也就是宿主的内核服务。[^c2-1][^c2-2][^c2-3]

> [!tip] 大白话：什么是「共享宿主内核」？
> 把宿主操作系统想成大楼总闸，容器是只带随身行李的房客：靠大楼统一水电（宿主内核）生活，入住快、行李少。可大楼一停水停电（内核出问题），全楼房客一起遭殃；虚拟机是带独立厨房的套房，自家水管爆了只淹自己那套。

### 2.2 逐项对比：隔离、体重、启动、更新

VM 与容器最关键的差异有四：[^c2-1][^c2-2][^c2-3]

- **隔离强度**：VM 与宿主、与其他 VM 完全隔离，能构成强安全边界；容器是轻量隔离，比进程级强、但弱于 VM。
- **体重与启动**：VM 自带整套 OS，体积大、吃资源，要引导整个系统；容器共享内核只带应用层，体积小、近乎秒开。
- **更新方式**：VM 要进每台客户机打补丁，换系统版本常等于新建一台 VM；容器改构建文件（Dockerfile）指向新基础镜像 → 重建镜像 → 重新部署即可。
- **异构 OS**：VM 几乎能跑任何操作系统；容器只能跑与宿主同版本体系的操作系统。

「VM 更新重、容器重建即更新」是个钩子，第 8 章选型时我们会回来用它。

| 对比维度 | 虚拟机（VM） | 容器 | WSL2 |
| --- | --- | --- | --- |
| 隔离单位 | 整台「虚拟电脑」（虚拟硬件 + 完整 OS） | 单个应用及其依赖 | 一个 Linux 发行版，底层是微软托管的轻量 VM |
| 内核 | 自带完整内核 | 共享宿主内核，不自带 | 微软提供的真实 Linux 内核 |
| 启动速度 | 慢（要引导完整 OS） | 近乎即时 | 快（后台托管，无需自己配置） |
| 更新方式 | 进每台 VM 打补丁 / 升级系统 | 改 Dockerfile → 重建镜像 → 重新部署 | 内核随 Windows 更新自动推送 |
| 可否跑异构 OS | 几乎可以运行任意 OS | 只能与宿主同 OS | 专为在 Windows 里跑 Linux 设计 |
| 典型场景 | 强隔离、跑异构系统、开发测试 | 同 OS 下打包和编排大量轻量服务 | Windows 里开一个 Linux 环境做开发 |

### 2.3 容器引擎不是 Hypervisor

新手最常见的误会，是把容器说成「一种更轻的虚拟机」。容器引擎（如 Docker）跑在完整操作系统之上，由它提供内核；容器只是往内核上叠应用、依赖和少量运行时，没有属于自己的客户机 OS，也不虚拟化整块硬件——中间没有 hypervisor 那一层。[^c2-1][^c2-2][^c2-3]

> [!tip] 大白话：容器引擎和 Hypervisor 差在哪？
> Hypervisor 是房东把一套房隔成几套独立公寓，每套自带水电（完整系统）；容器引擎更像在一间大开间里拉几道帘子分头办公——帘子隔得开座位，却共用同一套空调和总闸。所以容器隔得开「进程」，隔不开底下那个大家共用的内核。

正因如此，本笔记不采用「容器引擎是专门化的 Type 2 hypervisor」的说法：hypervisor 的职责是切分硬件资源、喂饱多个完整系统，而容器没有第二个系统要喂。[^c2-1]

### 2.4 WSL1（转换层） vs WSL2（微软托管的轻量实用 VM）

WSL 是 Windows Subsystem for Linux 的缩写，是微软官方给 Windows 用户「在 Windows 里跑 Linux」的方案，分两代。[^c2-4]

- **WSL1 不是虚拟机**：它没有 Linux 内核，只用一个转换层把 Linux 程序的系统调用实时翻译成 Windows 内核能懂的调用。跨系统读写文件快，但系统调用兼容不完整，个别 Linux 软件跑不了。
- **WSL2 是微软托管的轻量实用 VM**：后台真跑一台轻量虚拟机，内含微软维护的真实 Linux 内核，系统调用完全兼容；内核随 Windows 更新推送，用户不用自己装系统。这正是 WSL2 是默认版本的原因。WSL1 仅在项目文件必须放 Windows 盘、需跨系统交叉编译等少数场景仍占优。

> [!tip] 大白话：WSL2 算虚拟机吗？
> 把 WSL2 想成托管式公寓：底层确实用了一间「虚拟机套房」，但房东不是你——微软在后台开好、维护好，Windows 更新时顺手换内核。你不用像用 VirtualBox 那样分配内存、装系统，所以体验上不像；但要刨根问底，它底层确实是 VM。

关于 WSL2 与 VirtualBox / Hyper-V 能否共存：早期资料称 WSL2 与 VirtualBox 6+ 有明显兼容问题，如今 7.x 已改善，但请以你当前版本实测为准。[^c2-4]

### 2.5 互补关系：容器常常跑在虚拟机里

最后别把三者当对手。容器和 VM 互补：云厂商的典型做法是先拿 VM 把物理服务器切成相互隔离的租户，再在 VM 里跑容器——容器负责打包应用、快速伸缩，VM 负责强隔离的安全边界。微软官方也指出，许多容器部署以 VM 为宿主 OS，而不是直接跑在裸硬件上，云端尤其如此。[^c2-2]

到这里，VM 的定位已经清楚。下一章钻回虚拟机内部看它的「零件」：这台电脑没有实体硬件，那内存、硬盘从哪来？答案藏在几个配置文件和镜像文件里——这也是后面理解快照与磁盘维护的地基。

### 本章小结

- 分水岭在「隔离到哪一层」：VM 整套 OS 自己带，容器共享宿主内核只带应用层，WSL2 是微软托管的轻量实用 VM。[05][12][13][07]
- VM 强隔离、能跑异构 OS，代价是重、更新慢；容器轻、秒开、更新靠重建镜像，但隔离弱、不能跨 OS。[13]
- 容器引擎不是 hypervisor：容器共享宿主内核、无 hypervisor。[05][12][13]
- WSL1 = 系统调用转换层、非 VM；WSL2 = 托管 VM + 真实 Linux 内核、随 Windows 更新；与 VBox/Hyper-V 共存以当前版本实测为准。[07]
- 三者互补：容器常跑在虚拟机里（云上常见架构）。[13]

## 第 3 章 虚拟硬件与虚拟磁盘：这台「电脑」由哪些文件组成

第 1 章把虚拟机比作「电脑里的电脑」，那这台虚拟电脑到底住在哪儿？答案是：它在宿主机的硬盘上，就是一堆普通文件。这一章我们打开机箱看看——虚拟机的 CPU、内存、网卡、硬盘是怎么「无中生有」的，以及为什么说它真正的硬盘其实是宿主机上的一个镜像文件。想明白这一点，「这台电脑能不能复制、搬走、备份」就不用再问别人了。

### 3.1 VM 的本质是「参数 + 状态」

Oracle VirtualBox 官方手册给过一个非常关键的定义：在软件内部，一台 VM 就是**一组参数（parameters）加状态（state）**。[^c3-1]

- **参数**：描述「这台电脑应该长什么样」的硬件设置，比如分配多少内存、几颗 CPU、用什么网卡、接多大的硬盘。
- **状态**：描述「这台电脑现在处于什么状态」，比如正在运行、已保存（挂起）还是已关机。

这些参数写在宿主机上的**配置文件**里，本身不含你的数据。真正装系统、存文件的地方是另一类体积大得多的文件——**磁盘镜像文件**。所以「一台 VM」落到宿主磁盘上，可以浓缩成一句话：**一小份参数配置文件 + 一大块磁盘镜像文件**。

> [!tip] 大白话：参数 + 状态
> 把 VM 想成一道按菜谱做的菜：「参数」是那张菜谱，写清锅多大、火多旺、装盘用什么；「状态」是菜做到哪一步了（备料、下锅、出锅）。菜谱不会替你把菜做出来，真正的菜在锅里——锅就是镜像文件。所以一台虚拟机在宿主上，不过是「几张纸 + 一口锅」。

### 3.2 虚拟硬件与加速基础：Intel VT-x / AMD-V

虚拟机里的客户机系统并不知道自己是「假的」，它以为自己跑在一块真实主板上。Hypervisor 用软件给它造出一整套**虚拟硬件**：虚拟 CPU、虚拟内存、虚拟网卡、虚拟磁盘。[^c3-2] 这也是第 1 章那张纵线图里「虚拟化把硬件切成资源池再分配」的落地形态。

虚拟硬件毕竟是「翻译」出来的，天然比物理硬件多一层开销。[^c3-2] 为了让它跑得接近原生速度，Intel 和 AMD 从 2000 年代中期开始在 CPU 里内置**硬件虚拟化扩展**：Intel 叫 **VT-x**，AMD 叫 **AMD-V**（也称 SVM）。Hypervisor 有了它，虚拟机指令就能获得 CPU 原生协助，Type 1 / Type 2 都依赖这类加速；服务器基本标配，桌面电脑有时要到 BIOS 里手动开启——这正是第 9 章要排的经典坑之一。[^c3-5]

### 3.3 虚拟磁盘：一个镜像文件，装着一整块「硬盘」

客户机里看到的 C 盘、D 盘，在宿主机上其实只是一个（或几个）文件，叫**虚拟磁盘镜像文件**，后缀常见 `.vdi`、`.vmdk`、`.vhd` 等。[^c3-3] 它的作用是把一整块硬盘的内容（操作系统、程序、数据）全部装进一个文件里。

创建虚拟磁盘时要选一种**分配方式**：

- **动态分配（也叫稀疏盘，sparse）**：文件一开始很小，客户机里越装东西它越大，但不会超过你设的容量上限——镜像文件大小约等于「已用空间」。[^c3-4]
- **固定大小（预分配，pre-allocated）**：创建那一刻就把容量整块划走，文件大小等于整块虚拟盘容量，不管里面装没装东西。[^c3-3][^c3-4]

新手默认用动态分配即可，但先记住一个坑：稀疏盘**只增不减**——你在客户机里删了文件，镜像文件并不会自动变小。这就是「磁盘越用越胖」的雏形，第 9 章专门讲怎么瘦身。[^c3-4]

> [!tip] 大白话：动态分配的磁盘像饭卡
> 动态磁盘像一张饭卡：你告诉食堂额度上限 500 块（容量上限），但今天只吃 15 块就只扣 15 块——所以文件一开始很小，装得越多涨得越大，刷到上限为止。固定磁盘则像一次性包下整年的套餐，不管吃不吃，位置和钱当天就全占了。

### 3.4 磁盘格式只讲「归属」：VDI / VMDK / VHD / VHDX

`.vdi`、`.vmdk`、`.vhd`、`.vhdx` 这些后缀，本质是不同厂家定义的「硬盘包装规格」。它们各有出身和主场的生态，本笔记只讲归属，不做「谁快谁慢」的排序（市面教程对此结论互相矛盾，不采信）。

| 格式 | 全称 | 出身与所属生态 |
| --- | --- | --- |
| VDI | Virtual Disk Image | Oracle VirtualBox 的开源格式 |
| VMDK | Virtual Machine Disk | VMware 定义，2011 年起开放；主战场 VMware Workstation |
| VHD | Virtual Hard Disk | 微软早期虚拟化产品（Virtual PC / Virtual Server）的格式，Hyper-V 仍沿用 |
| VHDX | Virtual Hard Disk v2 | VHD 的继任者，主战场微软 Hyper-V |

一句话概括生态：**VirtualBox 原生认 VDI，VMware 原生认 VMDK，微软 Hyper-V 认 VHD / VHDX**。[^c3-3] 很多镜像也能被非原生的软件打开，或者用各家自带工具互相转换，但转换总会丢一些特性、添一些麻烦。所以实操建议是：**长期使用选宿主原生格式最省心**；只有一次性迁移、跨平台共享时才考虑转换。[^c3-3]

> [!tip] 大白话：镜像格式像充电插头规格
> VDI、VMDK、VHD 就像不同牌子的充电插头：每个牌子的设备原配自己最顺手的插口。临时借用别的插头或许也能充上电，但长期用，还是设备和原装插头配套最省心。

### 3.5 为什么「磁盘文件是普通文件」很重要

因为整台 VM 在宿主机上就是**一个目录里的一堆普通文件**——里面既有参数配置文件，也有磁盘镜像，还可能混着快照、挂起状态文件、日志等。[^c3-4] 「普通文件」三个字意味着它可以被当成文件来对待：

- **复制**：想复制一台电脑？把这个目录复制一份就行。
- **移动 / 迁移**：把目录拷到另一台宿主上就能搬走整台 VM。Google Cloud 明确说 VM 是一个软件包，可以像文件一样在服务器间迁移。[^c3-2]
- **备份**：把目录归档，就是给整台电脑做了备份。

这也是后面两章的认知地基：**快照**（第 4 章）本质是在这个目录里追加「某个时刻的记录和差异文件」；而「越用越胖」的磁盘瘦身（第 9 章），则是把镜像文件里「已经删掉、却仍占着位置」的空间释放出来。

### 本章小结

- 一台 VM 落到磁盘上 = 参数配置文件 + 磁盘镜像文件；官方把它定义为「一组参数 + 状态」。[03][05]
- 客户机看到的是 Hypervisor 模拟的虚拟硬件；Intel VT-x / AMD-V 是让虚拟化接近原生速度的 CPU 硬件扩展，桌面可能要在 BIOS 开启。[11][12]
- 虚拟磁盘 = 宿主机上的镜像文件：动态（稀疏）分配开始小、随用随长、只增不减；固定分配创建即占满。[06][10]
- 磁盘格式只讲归属：VDI→VirtualBox、VMDK→VMware、VHD/VHDX→微软生态；长期使用选宿主原生格式更省心。[10]
- 「磁盘是普通文件」⇒ VM 可复制、移动、备份，也是第 4 章快照与第 9 章「磁盘瘦身」的认知基础。

下一章我们聊虚拟机的「后悔药」——快照。既然这台电脑说到底只是文件，那能不能把它的某一个时刻整个存下来，玩坏了再一键跳回去？第 4 章的「时光机」会告诉你它怎么工作，以及它为什么不是备份。

## 第 4 章 快照：虚拟机的「时光机」

折腾虚拟机最怕系统玩坏回不去。快照（Snapshot）就是虚拟机的「时光机」：改系统前存个档，之后无论怎么折腾，都能一键回到存档那一刻。

### 4.1 快照是什么：整台机器的「存档」

快照把虚拟机某一时刻的完整状态存下来，随时能回去。[^c4-1] 它由三部分组成：

- **设置记录**：一个很小的 XML 文件，记当时的硬件配置，几乎不占空间。
- **磁盘差异镜像（differencing image）**：磁盘不被整份复制，而是新建一个只记「以后改动」的差异文件，原盘不动；恢复时丢掉它，就回到原状。
- **内存状态**（运行中拍摄才有）：连「运行到哪一步」一起存，恢复后从那一瞬继续，代价是占用与内存相当的磁盘。[^c4-1]

> [!tip] 大白话：快照是什么？
> 把快照想成游戏存档：存的是那一刻的整台机器。进大 BOSS 房间前先存档，打不过就回档重来。

拍完快照后的改动都写进差异镜像，用得越久它越大。[^c4-1]

### 4.2 什么时候拍：动手前的「后悔药」

打补丁、装不熟悉的软件、改重要配置之前，都值得先拍一张；刚装好干净系统也拍一张当底子。这样玩砸了能快速撤销，不会比动手前更差。[^c4-1][^c4-2] 典型剧本一句话：**拍快照 → 随便折腾 → 一键恢复**。

### 4.3 恢复 vs 删除：回到过去，还是扔掉存档

- **恢复（Restore）**：整机回滚到拍快照那一刻，之后新建的文件消失、删掉的回来、改动还原，硬件设置一并还原——之后的一切都丢。当前状态还有用，就先补拍一张再恢复。[^c4-1]
- **删除（Delete）**：不动当前状态，只释放快照占的磁盘；可能较慢（要在多个镜像文件间搬数据），有时要求先关机再删。[^c4-1]

> [!tip] 大白话：恢复 ≠ 删除
> 恢复 = 回到存档点继续，存档之后发生的事全部作废；删除 = 只扔掉存档文件腾地方，当前进度不受影响。

### 4.4 两个坑：越拍越胖，且不是备份

**坑一：快照链膨胀。** 官方不限快照数量，只限宿主磁盘空间。[^c4-1] 但每张快照都派生自前一张、只记增量，拍完还继续用只会更大。链越长越占空间、删起来越慢——所以磁盘瘦身的第一步正是「先删快照」。[^c4-3]

**坑二：快照不是备份。** 它只记增量、依赖原磁盘文件，不是独立完整副本，只在「这台虚拟机自己的历史」里保护你。宿主磁盘坏了或整个虚拟机目录被误删，快照救不回来；重要数据要另做真正备份。[^c4-1]

### 本章小结

- 快照 = 设置记录（XML）+ 磁盘差异镜像 +（运行中）内存状态。
- 时机：装软件、打补丁、改配置前；刚装好干净系统后拍一张底子。
- 恢复 = 整机回滚、其后改动全丢；删除 = 只释放磁盘、可能较慢。
- 两个坑：快照链只记增量、越拍越胖（磁盘瘦身前先删）；快照 ≠ 备份。

概念篇到此结束。下一章进入实操篇，用 VirtualBox 建出第一台虚拟机；到第 6 章再亲手试「拍快照 → 故意玩坏 → 一键恢复」，看看这台时光机怎么工作。

## 第 5 章 动手 · VirtualBox（上）：安装、建机、装第一个系统

前四章我们把「虚拟机是什么、磁盘文件、快照」这些概念地图铺好了。这一章开始真正动手：用开源的 VirtualBox 从零建一台虚拟机，装一个 Ubuntu Linux 系统。看完概念却不会建机，等于没学；而建机这第一步里藏着两个新手最容易踩的坑——内存给太多会卡死宿主机、ISO 得自己准备。我们把这两件事一次讲透。

### 5.1 动手前准备：三样东西缺一不可

建机前先备好三样：VirtualBox 软件本身、一份 Ubuntu 系统镜像（ISO 文件）、一台支持硬件虚拟化的电脑。

1. **下载并安装 VirtualBox**
   1. 打开 VirtualBox 官网的 Downloads（下载）页面，选对应你电脑系统的安装包（Windows 用户选 `Windows hosts`）。
   2. 双击安装包，一路 Next / Install。若 Windows 弹出「是否安装此设备软件」的询问，选择安装——VirtualBox 需要装一些驱动程序才能工作。
   3. 完成后打开 VirtualBox Manager（VirtualBox 管理器主界面），你会看到左侧空的「Machines 列表」和上方一排按钮。[截图：VirtualBox 官网下载页] [截图：安装完成后的 VirtualBox Manager 主界面]

2. **备一份 Ubuntu 的 ISO 镜像**
   到 Ubuntu 官网的 Download 页面下载桌面版（Desktop），建议选 LTS（长期支持版），得到一个 `.iso` 文件，记下它存放的路径。[截图：Ubuntu 官网下载页，注意选 LTS]
   VirtualBox 只提供「造电脑」的软件，**不附带任何操作系统，也不提供使用系统所需的许可**——系统镜像必须你自己去各系统官方渠道获取。[^c5-1]

> [!tip] 大白话：ISO 是什么？
> 把 ISO 想成一张「虚拟安装光盘」。真实的系统装机会用光盘/U盘引导，VirtualBox 没有光驱，就直接把这个 `.iso` 文件当成光盘塞给虚拟机。所以你下载的是「一张光盘的完整映像」，不是要双击安装的程序。

3. **检查 VT-x / AMD-V（硬件虚拟化开关）**
   Ubuntu 是 64 位系统，跑得动它需要 CPU 的硬件虚拟化扩展帮忙加速：Intel 的扩展叫 VT-x，AMD 的叫 AMD-V（主板上常写作 SVM Mode）。今天的服务器默认都有，但台式机可能要在 BIOS 里手动打开。[^c5-4]
   在 Windows 上快速看一眼：按 `Ctrl+Shift+Esc` 打开任务管理器 → 性能 → CPU，看右下角「虚拟化」是否为「已启用」。如果是「已禁用」，需要重启电脑，开机时按 `Del`/`F2`（不同主板按键不同）进 BIOS，找到 `Intel Virtualization Technology` 或 `SVM Mode` 设为 Enabled，保存重启。找不到开关也别急，第 9 章会专门讲这个坑怎么排。

### 5.2 New 向导：给这台「电脑」命名、选位置、挂 ISO

在 VirtualBox Manager 主界面点「新建」（New），弹出 New Virtual Machine（新建虚拟机）向导。如果没看到向导而是一整页表单，是「体验级别」被设成了 Expert（专家）模式，切回 Basic（基本）模式即可。[^c5-1]

向导通常有四步，跟着做：

1. **名称和操作系统（Name and Operating System）**
   - **Name（名称）**：给虚拟机起个能看懂的名字，比如 `Ubuntu-学习用`。这个名字既是列表里显示的名字，也会用作磁盘文件的文件名；VirtualBox 还会根据名字自动猜操作系统。[^c5-1]
   - **VM Folder（文件夹）**：虚拟机文件存放的位置。默认在你的用户目录下，建议放到**空间充足**的磁盘分区——尤其你后面要用快照功能时，这个文件夹会越长越大。[^c5-1]
   - **ISO Image（镜像）**：点下拉框，选 5.1 下载好的 Ubuntu ISO。选完后 VirtualBox 一般能自动识别出操作系统类型和版本（Ubuntu 64-bit）。[截图：New 向导的名称/操作系统页]
2. **无人值守，还是手动装？（关键选择）**
   向导里默认勾着「使用无人值守安装」（Install OS Using Unattended Installation）之类的一项。两个方向二选一：
   - **自动（默认）**：勾着它，向导会让你填一个**用户名和密码**，作为系统里的日常账号；官方手册说明，在 Linux 客户机上还会用同一密码创建 root 账号。[^c5-1] 之后 VirtualBox 会替你走完整个安装流程，装完直接进桌面。适合想省事的新手。
   - **手动**：取消勾选。VirtualBox 只把 ISO「塞进虚拟光驱」，剩下点「安装 Ubuntu」、选分区、设账号全由你自己点，更接近真实装机的体验。[截图：无人值守配置页，用户名/密码输入框]
   > 顺带记住：无论自动还是手动，你在系统里建的都是**这台虚拟机的管理员账号**，只管得到虚拟机内部，碰不到宿主机。

3. **虚拟硬件（Virtual Hardware）**：这一步分配内存和 CPU，铁律见 5.3。
4. **虚拟硬盘（Virtual Hard Disk）**：设一个磁盘大小上限（Ubuntu 日常用建议 25–50 GB），保持默认的**动态分配（dynamically allocated）**即可。动态分配意味着这个上限先不真占满，虚拟机实际用多少，磁盘文件才长多少。[^c5-1]

### 5.3 资源分配铁律：内存是借来的

向导会让你填 Base Memory（内存）和 Processors（处理器）。记住两条官方铁律：[^c5-1]

1. **内存是「借」的，不是「分」的。** 你填给虚拟机的内存，在虚拟机运行期间会从宿主机里划走，宿主机自己就少这么多内存可用。VirtualBox 官方特别警告：如果宿主剩余内存不足，系统会拼命把内存换到硬盘（swap），**可能把宿主机拖到近乎死机的程度**。这就是「内存给太多反而卡死真电脑」的真相。[^c5-1]
2. **给多少合适？** 听向导的默认建议值最稳（Ubuntu 一般建议 2048 MB），同时保证给宿主留足余量。举例：宿主机 8 GB 内存，给虚拟机 4 GB，那虚拟机开着时宿主机只剩 4 GB 给其他所有软件。**同时开的虚拟机越多，加起来越要克制。** 处理器同理：官方建议**不要超过宿主机总线程数的一半**。[^c5-1]

> [!tip] 大白话：内存是借来的
> 把宿主内存想成一张工资卡，虚拟机是向你借钱的室友。他借 4000 你只剩 4000，月底他还不上了你还得替他倒贴（系统开始用硬盘硬撑 swap），结果你俩一起卡死。所以别当老好人——按建议值借，给自己留够生活费。

### 5.4 首次启动与 Host key：鼠标「卡」在窗口里了怎么办

向导完成后，虚拟机出现在左侧列表里。选中它，点顶部绿色的「启动」（Start）。[^c5-2]

- 选了**无人值守**：首次启动会自动用之前选好的 ISO 开始安装，全程基本不用管，跟着屏幕提示即可。[^c5-2]
- 选了**手动**：虚拟机会像一台光驱里放着安装盘的真电脑那样启动，你按屏幕提示自己装 Ubuntu。[截图：首次启动、Ubuntu 安装画面]

装的过程里你可能遇到第一个「惊吓」：**鼠标点进虚拟机窗口后「出不来了」，键盘打字也都进了虚拟机。** 这不是坏了，而是虚拟机还没装 Guest Additions（增强功能）时，键盘和鼠标同一时刻只能归一方所有——归了虚拟机，宿主机就抢不回来。[^c5-2]

解决办法是记住一个键：**Host key（宿主键）**。默认是键盘右侧的 `Ctrl`（右 Ctrl），按一下，键盘鼠标的控制权就交还给宿主机。当前 Host key 是什么，永远显示在虚拟机窗口**右下角的状态栏**上，随时可查。[^c5-2]

- 想在虚拟机里按 `Ctrl+Alt+Del`？用 `Host key + Del` 代替。[^c5-2]
- 看到「第二个鼠标指针」？也是正常的——没装 Guest Additions 前的典型现象，第 6 章装完增强功能就消失了。[^c5-2][^c5-3]

等 Ubuntu 装完自动重启进入桌面，你就在 VirtualBox 里拥有了一台真正跑起来的 Linux 电脑。

### 选学：用 VBoxManage 命令行建机（入门可跳过）

向导点按钮的每一步，其实都对应一条命令。想对「建机到底做了什么」有感觉的读者可以看看，完全不想碰命令行的可以直接跳过，不影响后续章节。

```bash
# 创建一台名为 Ubuntu-CLI 的 64 位 Ubuntu 空虚拟机并注册
VBoxManage createvm --name "Ubuntu-CLI" --ostype "Ubuntu_64" --register
# 分配 2048MB 内存、2 个虚拟 CPU
VBoxManage modifyvm "Ubuntu-CLI" --memory 2048 --cpus 2
# 建一块 30GB（30720MB）的动态虚拟硬盘
VBoxManage createhd --filename "Ubuntu-CLI.vdi" --size 30720
```

命令执行后，VirtualBox 会生成一个 XML 配置文件来记录这台虚拟机的硬件参数——这正是第 3 章说的「虚拟机 = 一组参数 + 状态」在文件层面的体现。[^c5-1][^c5-3]

### 本章小结

- 建机前备三样：VirtualBox、Ubuntu ISO、开启 VT-x/AMD-V 的电脑；VirtualBox 不提供操作系统和许可，系统镜像要自己下载。[^c5-1]
- New 向导四步：命名（同时是文件名）、选存放文件夹（快照会占空间）、挂 ISO、选无人值守或手动安装。[^c5-1]
- 无人值守会替你建一个管理员账号并自动装完（Linux 下还用同密码建 root）；手动装则取消勾选、自己点安装器。[^c5-1]
- 资源铁律：内存是「借」的，给太多会把宿主机拖到近死机；按向导建议并给宿主留余量，CPU 不超过宿主线程数一半。[^c5-1]
- 首次启动后鼠标键盘「被抢」是正常现象，按 Host key（默认右 Ctrl）交还；`Host key + Del` = 虚拟机内 `Ctrl+Alt+Del`。[^c5-2]

机器已经跑起来了，但这只是开始：窗口里的鼠标还是双份的、分辨率不跟手、想和宿主机互传文件也还没戏。下一章装 Guest Additions（增强功能），再学三种关机方式、打第一个快照，把网络从 NAT 讲到桥接——一台「好用」的虚拟机才算完工。

## 第 6 章 动手 · VirtualBox（下）：增强功能、关机、快照与网络

上一章用 VirtualBox 建好了虚拟机并装好 Ubuntu。这一章把日常使用要补的四件事讲完：装增强功能、分清三种关闭方式、亲手做一次「拍快照→玩坏→回滚」、搞懂网络模式。

### 6.1 装 Guest Additions：把「遥控器」递给虚拟机

没装增强功能的虚拟机像隔着玻璃操作：鼠标一进窗口就被「困」住、窗口拉大分辨率不变、剪贴板不互通。Guest Additions 是 VirtualBox 附送、但要装进客户机**内部**的驱动工具包，专治这些毛病。[^c6-1]

安装步骤：

1. 启动第 5 章建好的 Ubuntu 虚拟机，登录桌面。
2. 在 VM 窗口菜单栏点 **Devices → Insert Guest Additions CD image…**。VirtualBox 会把自带的驱动镜像像「塞光盘」一样挂载进虚拟机。[截图：Devices 菜单的 Insert Guest Additions CD image]
3. 回到客户机：一般会自动弹出安装提示，Ubuntu 要你输密码授权，一路确认；没弹窗就手动打开挂载的光盘（形如 `VBOXADDITIONS_…`）运行安装程序。
4. 装完按提示**重启虚拟机**。

重启后改善明显：第二个鼠标指针消失，鼠标能自由滑出窗口；窗口拉多大分辨率自动跟着变；剪贴板、拖放、共享文件夹等宿主 ↔ 客户机互传功能也解锁（都以 Guest Additions 为前提，且前两者默认关闭，可在 Devices 菜单打开）。[^c6-1]

> [!tip] 大白话：Guest Additions 是什么？
> 把虚拟机想成刚搬来的邻居，Guest Additions 就是你去送的那把「万能遥控器」。之前调他家电视（分辨率）、给他送东西（剪贴板/文件）都得敲门喊话；有了遥控器，两边直接互通。所以装完系统第一件事就是装它。

### 6.2 三种关闭方式：先别急着点那个 ×

点 VM 窗口右上角的关闭按钮，VirtualBox 不会直接关掉虚拟机，而是弹窗问你想怎么处理（也可按 Host key + Q）。三个选项区别很大：[^c6-2]

| 选项 | 行为 | 何时用 |
| --- | --- | --- |
| **Save State**（保存状态） | 整机「冻结」并把完整状态写入宿主磁盘；下次启动原地续跑，打开的程序和窗口都还在 | 临时走开、想留现场又不占内存，类似笔记本「合盖休眠」 |
| **Shut Down**（关机） | 发 ACPI 关机信号，等同按真实电脑电源键，触发客户机正常关机流程；不保存状态 | 日常真正用完收尾——最接近物理机关机 |
| **Power Off**（断电） | 立刻停止虚拟机，不关机、不保存状态 | 正常情况别用；唯一例外是下节快照回滚场景 |

两句红线：**Save State 不是关机**——只是把状态「冻住存盘」，客户机没走关机流程，下次启动直接回到刚才的桌面，但此时不能改那些要求机器关闭的设置。**Power Off 等于拔电源**，没有关机保护，可能损坏系统盘或触发长时间自检。[^c6-2]

> [!tip] 大白话：Save State、关机、断电差在哪？
> 把没做完的工作想成一桌菜：Save State 是连火候拍照存档、关火走人，回来原样接着炒；Shut Down 是正常关火收拾，下次重来；Power Off 是一脚踹翻灶台——菜没了还可能砸锅。

### 6.3 快照实操：拍一张「后悔药」，然后真的吃一次

第 4 章说过快照是时光机，这里动手验证：拍快照 → 危险操作 → 回滚。

1. **拍快照**：让虚拟机处于「干净可用」状态（如刚装完系统）。点菜单 **Machine → Take Snapshot…**，起名如「刚装好，干净」，点 OK；拍摄瞬间会暂停一两秒。[^c6-3][截图：Take Snapshot 对话框]
2. **做危险操作**：故意在客户机里折腾——删几个文件、乱改系统设置或装个可疑软件，制造「后悔了」的场景。
3. **回滚**，两种走法殊途同归：
   - 走法 A：正常关掉虚拟机，在管理器选中该 VM → 点右侧 **Snapshots** → 选中刚才的快照 → 点工具栏 **Restore** → 确认后重启。[截图：Snapshots 列表点 Restore]
   - 走法 B：虚拟机还在运行就直接关窗口选 **Power Off**。只要这台 VM 有快照，Power Off 就会丢弃自最近快照以来的改动、回到快照状态——这正是 6.2 里 Power Off 那个「唯一例外」的正确用法。[^c6-2][^c6-3]

回滚后，删掉的文件回来了、改坏的设置复原，与拍快照那一刻分毫不差——但快照之后的新改动会**永久丢失**，有不想丢的东西就先再拍一张。不需要的快照选中点 **Delete** 即可，不影响当前状态，只释放磁盘空间。[^c6-3]

### 6.4 网络：默认 NAT 够用，什么时候换模式

新建虚拟机时，VirtualBox 默认启用一张虚拟网卡并设为 **NAT** 模式。对多数人这已足够：客户机想上网浏览、下载、收邮件，无需任何设置。[^c6-4][^c6-5]

> [!tip] 大白话：NAT 是什么？
> 把宿主机想成小区门卫。虚拟机出门上网都走门卫这道，外面看到的只是门卫的地址。好处是安全省事、不用管 IP；坏处是外人想主动进楼找你（访问虚拟机里的服务），门卫默认不放行，除非你专门开一条「访客通道」（端口转发）。

那什么时候改模式？要诀一句话：**只上网用 NAT；给局域网/外网提供服务改 Bridged；只要宿主↔虚拟机互通选 Host-only；只想让几台虚拟机自己互通选 Internal。** 改网络先关机——设置窗口在虚拟机运行或保存（Saved）状态时是禁用的。[^c6-4] 步骤：

1. 用 Shut Down 正常关闭虚拟机。
2. 在管理器选中该 VM，点 **Settings → Network**。
3. 把 Adapter 1 的 **Attached to** 从 NAT 改成目标模式，点 OK。
4. 重启虚拟机生效。[截图：Network 设置页的 Attached to 下拉框]

四种模式（外加 NAT 家族的 NAT Network）怎么记，看速记表：[^c6-5]

| 模式 | 通信范围 | 能否上网 | 用途 |
| --- | --- | --- | --- |
| **NAT**（默认） | 虚拟机单向发起出网；外部/宿主默认连不进虚拟机 | 能（借宿主网络） | 虚拟机只当「上网客户端」，零配置 |
| **NAT Network** | 同一 NAT 网络的多台虚拟机可互访，且都能出外网 | 能（经宿主） | 多台虚拟机既要互访又要一起上网的实验环境 |
| **Bridged**（桥接） | 虚拟机直接挂到宿主所在局域网，相当于局域网内一台独立主机，双向可达 | 能（用局域网真实 IP） | 在虚拟机里跑服务、给局域网/外部设备访问 |
| **Host-only**（仅主机） | 仅宿主机 ↔ 虚拟机及同网虚拟机之间 | 否（默认不通外网） | 只要宿主和虚拟机私密互通，不需要外网 |
| **Internal**（内部网络） | 仅选中的虚拟机之间；宿主和外部都看不见 | 否 | 纯虚拟机之间的私密通信演练 |

> NAT 默认形态下外部连不进虚拟机内的服务；想让宿主机或外网访问 VM 内某端口（如 Web 服务）需配置 **NAT 端口转发（port forwarding）**——进阶操作，本章不展开。

### 本章小结

- Guest Additions 装进客户机内部：消除第二鼠标指针、窗口自适应、解锁剪贴板/拖放/共享文件夹，装完重启。[02][03]
- Save State = 冻结续跑（不是关机）；Shut Down = ACPI 正常关机（首选）；Power Off = 拔电源，仅在要回滚快照时用。[02]
- 快照「拍→玩坏→回滚」：Restore 丢快照后的改动；Delete 只释放磁盘；有快照时 Power Off 会回到快照状态。[02]
- 默认 NAT 上网零配置；对外服务换 Bridged；Host-only 仅宿主↔VM；Internal 仅 VM 间；改网络先关机。[02][04]

## 第 7 章 动手 · VMware Workstation：给 Windows 11 建一台虚拟机

前面几章用 VirtualBox 建过 Ubuntu，但若想在虚拟机里装 Windows 11，会发现 VBox 建机向导没有 vTPM 这一步，而 Windows 11 对可信平台模块有硬性要求，直接装容易卡在硬件检查。这章换同为 Type 2 的商业选手 VMware Workstation，把「Windows 11 + vTPM」这条 VBox 缺源的路线走通。

### 7.1 VMware Workstation：商业 Type 2，为什么需要它

VMware Workstation 是 VMware 出品的桌面虚拟化软件，与 VirtualBox 一样是 Type 2 托管型 Hypervisor：它作为普通应用装在宿主操作系统之上，而不是直接装在硬件上。[^c7-2]

- **Workstation Player**：免费版，界面精简，够建机、跑系统。
- **Workstation Pro**：付费版，功能更全（快照、克隆、高级网络等）。
- 2023 年 Broadcom 收购 VMware 后，授权与价格常有调整，具体**以官网为准**。

已有 VirtualBox 为何还要单独开这章？VirtualBox 开源免费、适合入门（第 5 章 Ubuntu 就是它装的）；VMware 则在 Windows 11 场景有官方路径——创建 Windows 11 客户机时，Workstation 会自动添加 vTPM（虚拟可信平台模块），让 Win11 通过安装检查。[^c7-1]

> [!tip] 大白话：vTPM 是什么？
> 把 TPM 想成主板上的一把「硬件锁」，系统开机先对暗号，确认机器没被掉包。真电脑装 Win11 需要这把锁；VMware 就在虚拟机里用软件造一把虚拟锁（vTPM），Win11 看见锁在，就肯继续装了。

### 7.2 Typical 向导建机，逐步入

流程和第 5 章大同小异，跟「新建虚拟机」向导的 Typical（典型）配置走即可；它适合大多数情况，只有要改硬件兼容版本、磁盘类型等细节时才选 Custom（自定义）。[^c7-1]

1. **选 ISO**：启动「新建虚拟机」向导，配置类型选「典型」；客户机操作系统来源选「安装程序光盘映像文件 (ISO)」，指向准备好的 Windows 11 镜像。[截图：新建虚拟机向导 - 选择 ISO]
2. **选系统**：客户机操作系统类型选 `Windows 11 x64`，下一步——这正是向导自动添加 vTPM 的触发条件。[^c7-1][截图：客户机操作系统 - Windows 11 x64]
3. **命名与目录**：输入虚拟机名称与存放目录，下一步；所在磁盘留足空间，这个文件夹以后会越变越大。[截图：命名与位置]
4. **加密与 vTPM**：选加密类型、设密码。加密范围二选一：加密全部文件，或「仅加密支持 vTPM 设备所需的最小文件数」——日常学习选最小加密即可，更快也满足要求。[^c7-1][截图：选择加密范围]
5. **磁盘**：设置虚拟磁盘大小（典型配置还会问是否拆成多个文件）。沿用第 5 章铁律：够用即可，别把宿主磁盘塞满。
6. **Customize Hardware（可选）**：想调内存、CPU、固件可以点开改，创建后再改也行，这步可直接跳过。[^c7-1]
7. **创建**：勾选「创建后开启此虚拟机」并完成，向导随即开机进入 Windows 11 安装。[截图：向导完成]

> [!tip] 大白话：为什么加密和 vTPM 绑在一起？
> 加密是给虚拟机文件上「保险箱锁」，没密码谁也打不开；vTPM 是保险箱里那把「硬件锁」。Windows 11 要两者配合才肯干活，所以向导把它俩放在同一步，你只输一次密码。

### 7.3 Windows 11 特例：装完别删加密和 vTPM

- **自动加 vTPM**：选 Windows 11 x64 后，Workstation 会自动把 vTPM 加进虚拟机，这是安装能通过硬件检查的关键。[^c7-1]
- **装后不要移除**：官方手册建议，装完 Windows 11 后，不要为了「更流畅」把加密或 vTPM 从虚拟机中移除，否则会影响 Windows 11 的使用体验。[^c7-1]
- **远程 VM 不支持**：Workstation 不支持在远程虚拟机上创建 Windows 11 客户机，想装 Win11 要在本机建。[^c7-1]

### 7.4 与 VirtualBox 的异同小结

拉回第 3 章那张「虚拟机 = 参数 + 文件」的地图：两者同为 Type 2，都由配置文件加虚拟磁盘镜像描述一台机器，建机都走向导。差异集中在授权、开源和 Windows 11 路径上：

| 对比维度 | VMware Workstation | Oracle VirtualBox |
| --- | --- | --- |
| 许可证 | Player 免费、Pro 付费（商业软件，以官网为准） | 开源免费 |
| 是否开源 | 否（闭源商业） | 是 |
| Win11 + vTPM 路径 | 向导自动加 vTPM 并要求加密（官方手册路径） | 建机向导无 vTPM 步骤，装 Win11 需自行处理（本笔记不展开） |
| 图形化完整度 | 社区认为最完善，克隆/快照/网络配置一键完成 | 社区认为功能完整、操作逻辑简单 |
| 适合人群 | 愿付费、需 Win11 场景与丰富教程的开发者 | 零成本入门、开源爱好者、基础练习 |

表中「图形化完整度」两行转述自博客园的社区对比，属个人经验、无基准测试，以本机实测为准。[^c7-2]

### 本章小结

- VMware Workstation 是商业 Type 2 托管型 Hypervisor：Player 免费、Pro 付费；Broadcom 收购后授权与价格以官网为准。
- 建 Windows 11 客户机时，Workstation 自动添加 vTPM 并要求加密；选「仅加密最小文件」即可满足日常学习。
- Typical 向导路径：选 ISO → Windows 11 x64 → 命名/目录 → 加密/vTPM → 磁盘 →（可选）Customize Hardware → 创建。
- 两条官方红线：装完 Win11 后不要移除加密或 vTPM；远程虚拟机不支持创建 Windows 11 客户机。
- 与 VirtualBox 同为 Type 2，主要差别在许可证、开源性与 Win11 + vTPM 支持路径。

免费与商业工具都试过以后，下一章把镜头拉远：什么时候真的该用虚拟机？Windows 桌面的 WSL2、Hyper-V、VMware、VirtualBox 四套方案怎么选？我们给一张决策地图。

## 第 8 章 选型：什么时候该用虚拟机？桌面四方案怎么选

前几章你已经把 VirtualBox、VMware 都动手走通了，现在停下来想一个更根本的问题：这些「电脑里的电脑」到底什么时候才该用？如果只是想在这台 Windows 里跑跑 Linux 命令，是不是有更轻的办法？这一章给你两把尺子：第一把判断「用虚拟机还是容器」，第二把在 Windows 桌面常见的四套方案里挑一个。

### 8.1 用虚拟机的信号：要一整套「带锁的独立房间」

回想第 2 章的分水岭：虚拟机自带完整操作系统（含内核），是系统级隔离；容器共享宿主内核，只打包应用和运行时所需的少量系统服务，且容器引擎不是 Hypervisor。[^c8-1][^c8-2] 所以出现下面这些信号时，虚拟机更合适：

- **需要强隔离的安全边界**：比如在同一台电脑上托管两个互不信任的应用，要它们彻底隔开、互不影响。
- **要跑异构操作系统**：宿主是 Windows，客户机却想装 Linux、老版本 Windows 或别的系统。
- **需要完整内核兼容**：要运行对内核敏感的软件，甚至加载内核模块。
- **能接受「整机式维护」**：每台虚拟机都带完整系统，补丁和升级得在每一台里单独做，虚拟机一多就很耗时。[^c8-1]

> [!tip] 大白话：什么信号该用虚拟机？
> 把虚拟机想成一间「带独立大门和全套家具的房间」——水电、装修、钥匙全归你管，锁上门谁也进不来。所以当你要「和别人彻底隔离」「另配一套家具（操作系统）」「造出楼里没有的户型」时，就选它；代价是每间房都要单独打扫（打补丁、升级），费时费力。

### 8.2 用容器的信号：同一栋楼里轻装快跑

反过来，这些信号指向容器（Docker 这类）：客户机和宿主是同一个操作系统家族、版本兼容（容器基本不能跨 OS 跑）；想要轻和快，因为容器只带应用和少量用户态服务，资源占用更小、启动更快；更新靠「重建镜像」而不是「逐台打补丁」，改一行镜像配置、重新生成再部署，比重装虚拟机快得多。[^c8-1][^c8-2] 官方口径汇成一张判断清单：

| 判断清单 | 用虚拟机（VM） | 用容器 |
| --- | --- | --- |
| 隔离需求 | 强隔离、安全边界至关重要 | 轻型隔离即可 |
| 操作系统 | 可跑异构 OS、要完整内核 | 需与宿主同 OS 家族/版本 |
| 体量与启动 | 重、慢、吃资源 | 轻、快、省资源 |
| 更新方式 | 每台 VM 单独下载安装更新或另建新 VM | 改镜像 → 重建 → 重新部署 |
| 一句话信号 | 「要一整套独立房间」 | 「同楼轻装、频繁重装」 |

> 补充一句：容器和虚拟机不是二选一的敌人——容器经常跑在虚拟机里，云上尤其常见，二者互补。[^c8-1][^c8-2]

### 8.3 桌面四方案一句话定位

落到 Windows 桌面，最常见的候选就是 WSL2、Hyper-V、VMware Workstation、VirtualBox。架构类型你在第 1、2 章认过，这里并成一张表。下表排序来自博客园作者的社区经验、无基准测试，快慢以你机器上的实测为准。[^c8-3]

| 方案 | 一句话定位 | 是否免费 | 适用人群 |
| --- | --- | --- | --- |
| WSL2 | Windows 内置的「轻量实用 VM」子系统：后台托管、跑真 Linux 内核，主为命令行与开发工具设计 | 免费（系统自带） | 想在 Windows 里直接用 Linux 命令/工具的开发者 |
| Hyper-V | Windows 原生内置的 Type 1 系统级组件：直接调度硬件，适合多台独立节点 | 免费（系统内置，需在 Windows 功能里开启） | 搭多节点/集群、追求低损耗的进阶用户 |
| VMware Workstation | 商业 Type 2：图形化功能最全、兼容性与教程资源丰富 | Player 有免费版，Pro 付费（以官网为准） | 要丰富图形化操作、全场景虚拟化的用户 |
| VirtualBox | 开源免费 Type 2：操作逻辑简单、图形化完整 | 免费（开源） | 零基础入门、零成本练手 |

> 排序声明：以上「最轻 / 损耗小 / 图形化最全 / 免费但高负载略逊」均出自社区经验、无基准测试，以实测为准。[^c8-3]

给零基础的决策树：

```text
第 1 问：你只要 Linux 命令行/开发工具，还是要一整个图形系统？
  ├─ 只要命令行与开发工具 → WSL2（Windows 里一键开启，最省事）
  └─ 要完整系统/图形桌面/异构 OS → 进入第 2 问
第 2 问：你的目标是「入门折腾」还是「搭多节点集群」？
  ├─ 零基础入门、零成本 → VirtualBox（跟着第 5、6 章做）
  ├─ 已明确要多节点/集群、要低损耗 → Hyper-V 或 VMware Workstation
  └─ 拿不准 → 先用 VirtualBox，不够再换
```

> [!tip] 大白话：四方案怎么记？
> 把四套方案想成四种「住法」：WSL2 是酒店式托管公寓（拎包入住、维修归物业）；Hyper-V 是整栋自建楼（底层直接管硬件，入住门槛高）；VMware 是设施齐全的高档小区（什么都有、可能要花钱）；VirtualBox 是免费青年公寓（该有的都有，够你折腾）。入门别贪心——先住青年公寓，不够再搬。

### 8.4 默认推荐：入门用 VirtualBox，尝鲜用 WSL2

落到具体的人，本笔记的默认建议有两条：

- **零基础入门、想看见完整图形系统随便折腾 → VirtualBox**：免费开源，跟着第 5、6 章就能走通，玩坏了删掉重建即可。
- **想在这台 Windows 里一键体验 Linux 命令行/开发工具 → WSL2**：它是微软后台托管的轻量实用 VM，内核由 Windows 更新维护，不用自己建机、配硬件，几乎零门槛。[^c8-4]

最后埋一个第 9 章的伏笔：Hyper-V 虽是 Type 1，但在桌面上它只是 Windows 的一个可选功能——在「启用或关闭 Windows 功能」里勾选开启。一旦开启就占用 CPU 的硬件虚拟化能力，可能和 VirtualBox/VMware 需要的 VT-x、Windows 的「内核隔离」抢资源；WSL2 与 VirtualBox 能否共存也随版本变化，以当前版本实测为准。[^c8-3][^c8-4]

> [!tip] 大白话：Hyper-V 为什么「明明是 Type 1 却像个开关」？
> 把 Hyper-V 想成整栋楼的「中央机房」——它在硬件之上直接管资源，所以是 Type 1；但对普通台式机来说，这个机房只是 Windows 附带的一个「可勾选设施」。你一勾选启用，它就接管了 CPU 的虚拟化开关，其他想用同一把开关的住户（VirtualBox、VMware）就可能被挤出去。这就是第 9 章要排的坑。

### 本章小结

- 用虚拟机的信号：强隔离安全边界、异构 OS、完整内核兼容；代价是每台单独更新、更重更慢。[13][05]
- 用容器的信号：与宿主同 OS、要轻快、频繁重建更新；隔离弱于 VM，容器引擎无 Hypervisor。[13][05]
- Windows 桌面四方案：WSL2（内置轻量 VM）、Hyper-V（内置 Type 1）、VMware Workstation（商业 Type 2）、VirtualBox（开源 Type 2）。[08]
- 默认推荐：入门选 VirtualBox，Windows 内一键体验 Linux 选 WSL2；决策树见 8.3。[08]
- 四方案排序是社区经验、无基准测试，以实测为准；Hyper-V 开启会占用硬件虚拟化能力，与 VT-x 的冲突留到第 9 章。[08][07]

## 第 9 章 常见坑与磁盘维护：从 VT-x 到「越用越胖」的磁盘

这是本笔记的最后一章，我们从「怎么用」切换到「出问题怎么救」。前几章把概念、实操和选型都走完了，但真正让新手放弃虚拟机的，往往是几个特别具体的坑：虚拟化加速开不起来、内存给太多把宿主机拖垮、磁盘文件「只涨不缩」越用越胖。这一章把它们摆成一张坑清单，讲清现象与排查方向，再给一条官方磁盘瘦身流程和一份收尾维护清单。

### 9.1 坑 1：BIOS 没开 VT-x/AMD-V，或被 Windows 抢先占用

Intel VT-x 和 AMD-V 是 CPU 里的硬件虚拟化扩展，作用是给 Hypervisor 提供硬件加速，让虚拟机跑得顺畅。[^c9-2] 服务器基本都默认开启，但桌面电脑经常在 BIOS 里关着，需要手动打开。[^c9-3] 缺少硬件加速时，Type 2 虚拟化软件会退回到「纯软件模拟」，性能损失非常明显。[^c9-2]

- **现象**：新建/启动 64 位客户机时报「VT-x/AMD-V 不可用」之类的错，或虚拟机能启动但慢得明显。
- **排查方向 ①——BIOS/UEFI**：重启进固件设置，找 **Intel Virtualization Technology（VT-x）** 或 AMD 的 **SVM Mode**，改为开启后保存重启。这是第 3、5 章提过的那道「加速开关」。
- **排查方向 ②——Windows 抢占**：BIOS 明明已开，VirtualBox/VMware 却仍报 VT-x 不可用，这在 Windows 上通常指向 Hyper-V 或「内核隔离」常驻占用了硬件虚拟化功能。

> [!tip] 大白话：抢占是什么？
> 把硬件虚拟化功能想成一栋楼里唯一一部货梯。Windows 的 Hyper-V / 内核隔离常驻时，等于有人把货梯长期占用并锁了门；这时 VirtualBox、VMware 再想用同一部货梯，就会被挡在门外——报错或慢到没法用。解决方向就是让 Windows 先「放梯」：关掉 Hyper-V、关掉内核隔离，重启后再试。

关于 Hyper-V / 内核隔离（VBS，即「内存完整性」）与 VirtualBox / VMware 的冲突，目前没有权威的通用专项说明，以上只是**现象 + 排查方向**的经验级提示，请以你当前版本的实测为准。操作入口：`Windows 功能` 里取消勾选 Hyper-V；`Windows 安全中心 → 设备安全性 → 内核隔离` 里关掉内存完整性。两者都要重启才生效。

### 9.2 坑 2：内存/CPU 给太多，宿主先卡死

很多新手觉得「给虚拟机越多越流畅」，结果反被卡死的是宿主机。

- **现象**：虚拟机开着，宿主机鼠标开始发飘、切窗口要等好几秒、硬盘灯常亮不灭。
- **原因**：分给虚拟机的那部分内存，在虚拟机运行期间宿主机就用不到了。[^c9-4] 一旦给得超过你能 spare 的额度，宿主自身内存不够，Windows 会把内存内容不断换到硬盘上的页面文件（swap），整机陷入无穷无尽的「倒腾」，几乎等于假死。[^c9-4]
- **排查方向**：先关掉多余的虚拟机，按第 5 章的铁律重新分配——内存按向导建议值给，同时运行多台虚拟机时要加总预算；处理器数不要超过宿主总线程数的一半。[^c9-4]

> [!tip] 大白话：内存是借来的
> 把宿主机的内存想成你钱包里的现金。借给虚拟机太多，自己剩的钱不够付水电，只能把家当搬去储物间（磁盘换页），取一件都要跑一趟，全家卡在门口排队——这就是宿主卡成 PPT 的原因。所以只借你 spare 得起的额度，别把家底掏空。

### 9.3 坑 3：磁盘越用越胖——稀疏盘「只增不减」

第 3 章讲过「动态增长（稀疏）盘」：镜像文件随客户机使用量增长，而不是一开始就占满。VMware 官方把磁盘分成两类：**预分配盘**的镜像文件大小从一开始就等于磁盘容量；**稀疏盘**的镜像文件大小约等于客户机内的「已用空间」。[^c9-1]

问题出在稀疏盘「只增不减」：在客户机里删除文件后，镜像文件并不会自动缩小。官方列出的典型症状就是：宿主上的 .vmdk 文件体积，明显大于客户机系统里显示的已用空间。[^c9-1]

另外要提醒：VM 目录偏大，不一定都是磁盘镜像的错。整个 VM 目录 = 虚拟磁盘 + **快照** + **挂起状态文件**（如果 VM 被挂起）+ 设置文件 + 日志，官方明确说 VM 目录总是比虚拟磁盘本身大，先看清楚是哪一部分在占空间。[^c9-1]

> [!tip] 大白话：只进不出的储物箱
> 把动态磁盘想成一个只进不出的储物箱：往里放东西，箱子会变大；但往外扔东西，箱子外壳并不会缩回去——空出来的位置只是留在箱子里。镜像文件同理：guest 里删了文件，那些扇区只是被标记成「可覆盖」，宿主上的镜像文件不会自动变小。

### 9.4 磁盘瘦身：VMware 官方三步（有快照先删）

想真正让镜像文件「瘦」回去，用 VMware Workstation 的官方流程最稳妥。它只对**稀疏盘**有效，预分配盘不适用。[^c9-1]

开始前先做两个确认：

1. **确认磁盘类型**：菜单 `Virtual Machine > Settings > Hard Disk`，在 Disk information 里看是稀疏还是预分配。
2. **有快照必须先删**：官方明确说，带快照的磁盘无法收缩，删完快照再继续。[^c9-1]

然后按顺序操作（全程勿中断）：

1. **客户机内碎片整理**：在 Windows 客户机里对磁盘做一次碎片整理，把已用空间整理成连续区域，这是收缩的前提。[^c9-1]
2. **用 VMware Tools 收缩**：对 Workstation 9.x（Windows）及以后版本，收缩动作已并入下一步，VMware Tools 面板里的 Shrink 选项被移除。[^c9-1]
3. **从宿主层清理**：在主菜单执行 `VM > Manage > Clean up Disks`，让 Workstation 把镜像尾部空出来的区域回收掉。[^c9-1]

**红线警告**：收缩过程中不要关闭虚拟机、不要关闭宿主机、更不要手动取消。官方警告说，中断这个流程可能对虚拟磁盘造成**不可修复的损坏**，虚拟机可能再也无法启动。[^c9-1]

VirtualBox 用户请注意：VDI 镜像也有类似体积问题，社区常用 `VBoxManage modifyhd --compact` 压缩，但该命令**没有官方 KB 支撑、属经验级操作**，需关机后自行实测；本笔记只保证 VMware 官方三步的可靠性。

### 9.5 收尾维护清单

养成三个习惯，能少踩 9.3 那种「越用越胖」的坑：

- **定期删不需要的快照**：快照基于差异镜像，会持续占磁盘；留着最新一两个可用即可。牢记第 4 章的结论——快照不是备份。
- **监视 VM 目录大小**：目录明显大于客户机「已用空间」时，先查是不是快照、挂起状态文件或日志在占地方，再决定要不要做一次 9.4 的收缩。
- **重要数据靠备份**：快照只能回滚系统状态，数据安全底线是备份。好消息是第 3 章讲过：虚拟磁盘本质是普通文件，复制一份镜像文件，就是最朴素的整机备份。

### 本章小结

- VT-x/AMD-V 是 CPU 的硬件虚拟化加速开关：服务器标配，桌面机常在 BIOS 里关着；缺失时 Type 2 退化为软件模拟、性能明显下降。[06][11][12]
- Windows 下 Hyper-V / 内核隔离抢占硬件虚拟化是经验级排查项：关掉后重启再试，以实测为准。
- 分给虚拟机的内存，运行期间宿主就用不到；给太多会让宿主靠磁盘换页硬撑、整机卡死；CPU 别超过宿主线程数一半。[01]
- 稀疏盘「只增不减」：guest 内删文件镜像不自动缩小；VM 目录大还可能是快照 / 挂起状态文件 / 日志在占空间。[06]
- VMware 瘦身官方流程：仅稀疏盘、先删快照 → 客户机碎片整理 → `VM > Manage > Clean up Disks`；全程勿中断，中断可能毁盘。[06]
