## 学习路径（前置 → 产出 → 顺序）

**学完能做什么**

### 第 1 章 什么是虚拟机：从"电脑里的电脑"说起

- **定位**：概念篇 · 开篇
- **篇幅**：中，约 800–1200 字（读 5–8 分钟）
- **素材引用**：`05_cloud_google_com.md`、`03_docs_oracle_com.md`、`11_www_techtarget_com.md`
- **需要元素**：一张文字版分层示意（应用 → 客户机 OS → Hypervisor → 宿主硬件，用等宽文本或后续配图）；无代码/CLI
- **覆盖要点**：
  - 用生活比喻引出 VM：一台用软件"模拟"出来的计算机，跑在真电脑里，有自己的系统/程序/网络
  - 三个角色正名：宿主机 Host、客户机 Guest、虚拟机监视器 Hypervisor（旧名 VMM）
  - Type 1（裸机型）与 Type 2（托管型）一句话定义 + 代表产品（ESXi/Hyper-V/KVM vs VirtualBox/VMware Workstation）
  - 典型用途：学新系统、隔离试验、跑不兼容旧软件、一台机器当多台用
- **必讲要点（红线/不可漏）**：
  - Host/Guest/Hypervisor 三角色必须配实例讲，这是全文术语地基
  - Hypervisor 把宿主 CPU/内存/存储/网络"切块分池"给 Guest——用资源池比喻
  - **红线（Type 2 措辞）**：不得写 TechTarget 的"Type 2 比 Type 1 更小更快、占用资源更少、单机可承载更多"；统一改为"Type 2 跑在宿主 OS 之上、多一层转发路径；宿主 OS 是共同关注点"。本点来源见 `02_deep_research.md` §四.1
  - 明确"虚拟化不等于云"，一句话带过，避免读者把两者画等号

### 第 2 章 虚拟机 vs 容器 vs WSL2：三种"装系统"的思路

- **定位**：概念篇 · 横向对比
- **篇幅**：中，约 900–1300 字（读 6–9 分钟）
- **素材引用**：`05_cloud_google_com.md`、`12_baeldung_cn.md`、`13_learn_microsoft_com.md`、`07_learn_microsoft_com.md`
- **需要元素**：一张 VM/容器/WSL2 对比表（隔离单位、内核、启动速度、更新方式、典型场景）；无代码
- **覆盖要点**：
  - 核心分水岭：VM 自带完整 OS + 虚拟化整块硬件；容器共享宿主内核、只打包应用与运行时
  - 逐项对比（隔离强弱 / 重量 / 启动 / 更新 / 是否可跑异构 OS），讲清"不是谁取代谁"
  - 二者互补关系：容器经常跑在虚拟机里（云上常见架构）
  - WSL2 特殊位：WSL1 是系统调用转换层（非 VM）；WSL2 是微软托管的轻量实用 VM，跑真 Linux 内核、免运维
- **必讲要点（红线/不可漏）**：
  - **红线（容器无 Hypervisor）**：TechTarget 称容器引擎是"专门化 Type 2 hypervisor"，本笔记不采用；统一口径=容器共享宿主内核、没有 hypervisor（Google/Baeldung/Microsoft 三方一致）
  - 零基础比喻必须到位：VM = 搬一整套带家具的房子；容器 = 只打包自己的行李、住进别人的房子（共享水电内核）
  - WSL2 与 VirtualBox/Hyper-V 能否共存：注明"来源结论较旧，以当前版本实测为准"（对应 `02_deep_research.md` §四.5）
  - 更新对比（13）：VM 补丁重、容器重建镜像即更新——这是选型章的重要伏笔

### 第 3 章 虚拟硬件与虚拟磁盘：这台"电脑"由哪些文件组成

- **定位**：概念篇 · 拆解构造
- **篇幅**：中，约 800–1200 字（读 5–8 分钟）
- **素材引用**：`05_cloud_google_com.md`、`03_docs_oracle_com.md`、`10_www_makeuseof_com.md`、`06_knowledge_broadcom_com.md`
- **需要元素**：一张"VM = 一组参数 + 文件状态"清单（虚拟 CPU/内存/网卡 + 磁盘镜像文件 + 运行状态）；虚拟磁盘格式归属对照表（VDI / VMDK / VHD·VHDX）
- **覆盖要点**：
  - VM 本质是"参数 + 状态"：硬件设置（内存/CPU/网卡/虚拟磁盘）记录在配置文件，真正的"硬盘"是一个镜像文件
  - 虚拟磁盘 = 宿主上的镜像文件；动态增长（稀疏）vs 固定大小两种分配方式一句话区分
  - 磁盘格式归属：VDI=VirtualBox 开源、VMDK=VMware、VHD/VHDX=微软生态
  - "磁盘越用越胖"伏笔：稀疏盘"只增不减"，删文件不会自动缩小（第 9 章展开处理）
- **必讲要点（红线/不可漏）**：
  - **红线（磁盘格式措辞）**：格式对比只写"归属与生态"，不写"XX 性能比 XX 好/差"的绝对排序（MakeUseOf 自相矛盾，`02_deep_research.md` §四.3）；可给可操作建议"长期用选宿主原生格式更省心"
  - 动态 vs 固定大小用"饭卡"式比喻：动态=用多少扣多少但会涨，固定=提前划好一块
  - 每个概念给"是什么 / 为什么用 / 一个坑"三件套（素材 §七.3 要求）
  - 虚拟磁盘文件就是普通文件——所以可以复制/移动/备份，这是后面快照、瘦身的认知基础

### 第 4 章 快照：虚拟机的"时光机"

- **定位**：概念篇 · 收尾（为实操第 6 章铺路）
- **篇幅**：短，约 400–700 字（读 3–5 分钟）
- **素材引用**：`02_docs_oracle_com.md`、`12_baeldung_cn.md`、`06_knowledge_broadcom_com.md`
- **需要元素**：无代码；一段"改动前拍快照 → 玩坏 → 一键回滚"的示意流程
- **覆盖要点**：
  - 快照是什么：记录虚拟机设置 + 磁盘差异镜像（differencing image），运行中拍摄还会存内存状态
  - 什么时候用：给系统打补丁、装软件、改配置前拍一张，当"后悔药"
  - 恢复与删除的语义差异：恢复=整机回滚、其后改动丢失；删除快照只释放磁盘、可能较慢
  - 一个坑：快照链会让磁盘越来越占空间（差异镜像只记增量）；快照 ≠ 备份
- **必讲要点（红线/不可漏）**：
  - "快照基于差异镜像、只记变化"一句话解释膨胀机理即可，不深入 delta 链实现（`02_deep_research.md` §六.4 inline 处置）
  - 必须写明"快照不是备份"：镜像损坏时快照救不了你
  - 范围声明：**克隆（Clone）** 本批素材未收集实操步骤，本入门笔记不展开，避免写无源步骤；如需加需补源
  - 埋钩子：第 6 章会有一次真实"拍快照 → 回滚"演示

### 第 6 章 动手 · VirtualBox（下）：增强功能、关机、快照与网络

- **定位**：实操篇 · 第一条完整动手线（下）
- **篇幅**：中，约 1000–1500 字（步骤密集，读+做 10–15 分钟）
- **素材引用**：`02_docs_oracle_com.md`、`03_docs_oracle_com.md`、`04_docs_oracle_com.md`
- **需要元素**：菜单路径文字步骤（Devices → Insert Guest Additions CD image…、Machine → Take Snapshot…）；三种关闭方式对照；网络模式速记表（NAT / Bridged / Host-only / Internal）；关机后改网络的提醒
- **覆盖要点**：
  - Guest Additions 增强功能：消除第二个鼠标指针、窗口自适应分辨率、共享文件夹/剪贴板
  - 三种关闭方式：Save State（冻结续跑）/ Shut Down（ACPI 正常关机）/ Power Off（=拔电源，日常不用，有快照时可用来回滚到快照状态）
  - 快照实操：Machine → Take Snapshot 拍照 → 做危险操作 → 恢复快照演示回滚
  - 网络：默认 NAT 上网够用；要对外提供服务才改 Bridged；Host-only 仅宿主↔VM；Internal 仅 VM 之间；改网络需先关机
- **必讲要点（红线/不可漏）**：
  - "Save State 不是关机"——初学者最常把两者混为一谈，续跑后磁盘/时间状态要讲清
  - Power Off 要给出正确使用场景（配合快照回滚），而不是一句"别用"
  - **开放问题 2 处理（NAT 端口转发）**：本笔记**只写一句概念**"端口转发可让宿主机访问 VM 内服务"，**不展开步骤（defer）**；若用户要实操需先补 VirtualBox 官方网络手册源（见待确认问题 C）
  - 网络选择用"速记口诀"收尾，方便零基础日后回来查

### 第 8 章 选型：什么时候该用虚拟机？桌面四方案怎么选

- **定位**：选型避坑篇 · 决策
- **篇幅**：中，约 900–1300 字（读 6–9 分钟）
- **素材引用**：`13_learn_microsoft_com.md`、`08_www_cnblogs_com.md`、`07_learn_microsoft_com.md`、`05_cloud_google_com.md`
- **需要元素**：一张"何时用 VM / 何时用容器"判断清单；桌面四方案速查表（WSL2 / Hyper-V / VMware Workstation / VirtualBox）
- **覆盖要点**：
  - 用 VM 的信号：需要强隔离安全边界、跑异构 OS、要完整内核兼容；更新成本高是它的代价
  - 用容器的信号：同 OS、要轻快、要频繁更新重建；隔离弱、不能跨 OS
  - 桌面四方案一句话定位：WSL2=轻量开发/一键/免费；Hyper-V=Windows 内置 Type1/适合多虚拟机；VMware=图形化功能全/商业；VirtualBox=开源免费/入门首选
  - 给零基础的决策树：先问"要不要图形界面/异构 OS/多台"→ 再落到具体方案
- **必讲要点（红线/不可漏）**：
  - 四方案排序来自 cnblogs **社区经验，无基准测试**，全章标注"经验结论、以实测为准"（`02_deep_research.md` §四.6 / §六）
  - 容器/VM 判断用官方口径（13/05），避免把社区观点当权威写
  - 明确"虚拟化选型没有唯一答案"，给出"默认推荐 VirtualBox 入门、要 Windows 内一键体验试 WSL2"的可操作建议
  - Hyper-V 是 Type1 但桌面版开关在 Windows 功能里——为第 9 章 VT-x/Hyper-V 冲突埋线
