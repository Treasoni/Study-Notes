# 抓包与协议分析基础

前面九章我们一直在用各种命令"读"网络信息——读路由表、读连接状态、读 DNS 记录。但有一个更本质的方式：**直接看网线上跑的数据包**。这就是抓包（packet capture）。

比起读统计数据，看原始报文能让你看到更底层的东西——某次连接到底有没有握手成功？哪个包丢了？重传了几次？对方回了什么标志位？这些在 `ss` 或 `ping` 的输出里看不到，但在 `tcpdump` 的输出里一清二楚。

> 说白了：ss 告诉你"连没连上"，tcpdump 告诉你"是怎么连的"。

本章的主角是 `tcpdump`——Linux 上最经典的命令行抓包工具。它没有 Wireshark 的图形界面，但正因为是命令行，它更适合在服务器上做快速诊断。学完本章，你应该能从一条原始报文输出里读出"这是一个 TCP SYN 包，从哪个端口发到哪个端口，序列号是多少"。

---

## 1. tcpdump 基础用法

### 安装确认

多数发行版默认不装 tcpdump，但包名很统一：

```bash
# Debian/Ubuntu
sudo apt install tcpdump -y

# Arch Linux
sudo pacman -S tcpdump --noconfirm

# RHEL/Fedora
sudo dnf install tcpdump -y
```

安装后验证：

```bash
tcpdump --version
# tcpdump version 4.99.4
# libpcap version 1.10.5
```

---

### 选择接口：`-i`

如果不指定接口，tcpdump 会选系统中编号最小的活跃接口（通常是 eth0 或 enp0s3）。**但强烈建议显式指定**，避免抓到不想要的流量。

```bash
# 查看可用接口
tcpdump -D
# 1.eth0 [Up, Running]
# 2.lo [Up, Running, Loopback]
# 3.any (Pseudo-device that captures on all interfaces)

# 监听特定接口
sudo tcpdump -i eth0

# 监听所有接口（虚拟设备 any）
sudo tcpdump -i any
```

> [!tip] `-i any` 的特殊性
> `any` 是一个伪接口，同时抓取所有接口的流量。但注意它默认**不抓回环接口（lo）的流量**——如果需要抓 lo 上的流量，必须单独 `-i lo`。

---

### 抓取数量：`-c`

如果不加 `-c`，tcpdump 会一直抓直到你按 `Ctrl+C`。用 `-c` 指定抓取数量后，tcpdump 会在抓到指定数量的包后自动退出——适合做"抓 10 个包看看"的快速诊断。

```bash
# 抓 5 个包后退出
sudo tcpdump -i eth0 -c 5
# tcpdump: verbose output suppressed, use -v[v]... for full protocol decode
# listening on eth0, link-type EN10MB (Ethernet), snapshot length 262144 bytes
# 12:34:56.123456 IP 192.168.1.100.54321 > 93.184.216.34.80: Flags [S], seq 12345, win 65535, ...
# ...（5 行后自动退出）
```

---

### 关闭域名解析：`-n` 和 `-nn`

`-n` 是最常用的优化选项之一。不加 `-n` 时，tcpdump 会尝试反解 IP 为域名、端口为服务名——这需要 DNS 查询，速度变慢，而且输出里到处是 `http`、`ssh` 之类，反而不利于看清端口号。

```bash
# 不反解 IP（显示 192.168.1.1 而非 router.local）
sudo tcpdump -i eth0 -c 5 -n

# 不反解 IP 和端口（显示 80 而非 http，443 而非 https）
sudo tcpdump -i eth0 -c 5 -nn
```

对比：

```
不加 -nn: 12:34:56 IP 192.168.1.100.54321 > 93.184.216.34.http: Flags [S], ...
加 -nn:  12:34:56 IP 192.168.1.100.54321 > 93.184.216.34.80: Flags [S], ...
```

> [!note] 实战习惯
> 大部分排查场景**始终加 `-nn`**。只有在需要确认服务名而非端口号时才考虑去掉。

---

### 详细信息：`-v`、`-vv`、`-vvv`

默认输出已经包含主要字段，但有时需要看更底层的信息（如 TTL、IP 头部总长度、校验和、TCP 选项）。

```bash
# -v：显示 TTL、IP ID、总长度
sudo tcpdump -i eth0 -c 3 -nn -v
# 12:34:56.123456 IP (tos 0x0, ttl 64, id 54321, offset 0, flags [DF], proto TCP (6), length 60)

# -vv：显示更多细节（如 TCP 选项）
sudo tcpdump -i eth0 -c 3 -nn -vv

# -vvv：最详细级别的输出
sudo tcpdump -i eth0 -c 3 -nn -vvv
```

---

### 最常用的组合

```bash
# 轻量诊断：看有什么流量经过
sudo tcpdump -i any -c 100 -nn

# 看得更细：带上 IP 层细节
sudo tcpdump -i eth0 -c 50 -nn -v

# 永不停机：滚动监控（不接 -c）
sudo tcpdump -i eth0 -nn
```

## 2. BPF 过滤表达式

如果只抓不滤，屏幕上会刷过海量无关数据包。BPF（Berkeley Packet Filter）是 tcpdump 的过滤语言，能让你精确指定"只要某某流量"。

BPF 表达式的基本格式是 `[方向] [类型] [值]`，可以用 `and` / `or` / `not` 组合。

### 按 IP 过滤

```bash
# 匹配源或目标为 192.168.1.1 的包
sudo tcpdump -i eth0 -nn host 192.168.1.1

# 只匹配源 IP（发出来的包）
sudo tcpdump -i eth0 -nn src host 192.168.1.1

# 只匹配目标 IP（收到的包）
sudo tcpdump -i eth0 -nn dst host 192.168.1.1

# 匹配网段
sudo tcpdump -i eth0 -nn net 192.168.1.0/24
sudo tcpdump -i eth0 -nn src net 10.0.0.0/8
```

### 按端口过滤

```bash
# 匹配源或目标端口为 80
sudo tcpdump -i eth0 -nn port 80

# 只匹配源端口
sudo tcpdump -i eth0 -nn src port 80

# 只匹配目标端口
sudo tcpdump -i eth0 -nn dst port 80

# 端口范围（大于 1024）
sudo tcpdump -i eth0 -nn portrange 1024-65535
```

### 按协议过滤

```bash
# 只抓 TCP
sudo tcpdump -i eth0 -nn tcp

# 只抓 UDP
sudo tcpdump -i eth0 -nn udp

# 只抓 ICMP（即 ping 和 traceroute 的底层协议）
sudo tcpdump -i eth0 -nn icmp

# 只抓 ARP（链路层地址解析）
sudo tcpdump -i eth0 -nn arp
```

### 复合条件：and / or / not

```bash
# DNS 查询和响应（UDP 且端口 53）
sudo tcpdump -i eth0 -nn udp and port 53

# 来自 192.168.1.100 的 HTTP 流量
sudo tcpdump -i eth0 -nn src host 192.168.1.100 and tcp port 80

# 排除 SSH 连接（避免被自己的 SSH 会话干扰）
sudo tcpdump -i eth0 -nn not port 22

# 复杂组合：来自 10.0.0.0/8 且非 SSH 的 TCP 流量
sudo tcpdump -i eth0 -nn src net 10.0.0.0/8 and tcp and not port 22
```

> [!warning] 表达式组织的顺序
> tcpdump 的 BPF 引擎有优先级：`not` > `and` > `or`。复杂的表达式建议用引号括起来，并用括号明确分组：
> ```bash
> sudo tcpdump -i eth0 -nn 'tcp and (port 80 or port 443) and not host 192.168.1.1'
> ```
> 不加括号时，`tcp and port 80 or port 443` 会被解释为 `(tcp and port 80) or port 443`，含义完全不同。

## 3. 抓包存储与读取

### 写入文件：`-w`

抓包最常犯的错误是"抓完了才想起来要存"。用 `-w` 直接把原始报文写入 pcap（packet capture）文件，不占用屏幕输出，效率最高。

```bash
# 抓 10000 个包存文件
sudo tcpdump -i eth0 -c 10000 -nn -w capture.pcap
# tcpdump: listening on eth0, link-type EN10MB (Ethernet), capture size 262144 bytes
# 10000 packets captured

# 写入时彻底关闭屏幕输出（-q 静默模式也可省去）
sudo tcpdump -i eth0 -w capture.pcap
```

生成的 `.pcap` 文件可以用 Wireshark 打开，也可以在另一台机器上用 `tcpdump -r` 慢慢分析。

> [!tip] 文件扩展名
> tcpdump 不强制扩展名，但社区惯例用 `.pcap` 或 `.pcapng`。Wireshark 两者都支持。

### 读取文件：`-r`

写好的 pcap 文件用 `-r` 读回来分析，读取时仍然可以加过滤表达式——等于**对已经抓完的包再过滤**，比抓包时反复猜测条件有用得多。

```bash
# 读取全部
tcpdump -r capture.pcap -nn

# 读取时只显示 TCP 流量
tcpdump -r capture.pcap -nn tcp

# 读取时只显示与 192.168.1.1 相关的包
tcpdump -r capture.pcap -nn host 192.168.1.1

# 读取时显示详细信息
tcpdump -r capture.pcap -nn -vv
```

典型流程：

```bash
# 第一步：在服务器上抓包存文件，不浪费时间现场分析
sudo tcpdump -i eth0 -c 50000 -w problem.pcap
#（抓完了传给本地机器）

# 第二步：在本地慢慢分析
tcpdump -r problem.pcap -nn | head -50         # 快速看一眼
tcpdump -r problem.pcap -nn 'tcp and port 80'  # 过滤出感兴趣的
tcpdump -r problem.pcap -nn -X | less           # 看十六进制内容
```

### 文件轮转：`-C` + `-W`

在生产环境长期抓包时，单个文件会越来越大，不方便传输和分析。tcpdump 支持自动轮转——达到一定大小后自动切到下一个文件。

```bash
# 每 100MB 切一个文件，最多保留 20 个，文件名前缀为 trace
sudo tcpdump -i eth0 -nn -C 100 -W 20 -w trace.pcap
# 生成文件：trace.pcap0, trace.pcap1, trace.pcap2, ... trace.pcap19
```

参数含义：

| 参数 | 含义 | 说明 |
|------|------|------|
| `-C 100` | 每个文件最大 100 MB | 达到上限后自动创建新文件 |
| `-W 20` | 最多轮转 20 个文件 | 达到 20 个后覆盖最旧的文件 |
| `-w trace.pcap` | 文件名模板 | 实际生成 `trace.pcap0`、`trace.pcap1`... |

> [!note] 轮转的工作原理
> tcpdump 会监控当前文件大小，当超过 `-C` 指定的值（单位 MB）时，关闭当前文件并创建下一个。`-W` 控制环形缓冲区大小——例如 `-C 100 -W 10` 相当于用 10 个 100MB 的文件形成一个 1GB 的环形缓冲区，始终保留最近的 1GB 数据。

### 写入时的缓冲区问题

按 `Ctrl+C` 停止抓包时，tcpdump 会正常刷缓冲区退出。但如果系统突然崩溃，最后几秒的数据可能丢失。要强制每条记录立即写入：

```bash
# 每条记录立即写入（-U 模式）
sudo tcpdump -i eth0 -nn -U -w capture.pcap
```

`-U`（packet-buffered）让 tcpdump 每收到一个包就写入文件，而不是攒满缓冲区再写。代价是磁盘 I/O 增加，适合对实时性要求高、不丢包更重要的场景。

## 4. 报文输出逐字段解读

tcpdump 的默认输出行虽然密集，但每个字段都有明确的含义。学会解读一行报文，是网络排查的基本功。

### 标准 TCP 报文行

```
12:34:56.789012 IP 192.168.1.100.54321 > 93.184.216.34.80: Flags [S], seq 12345, ack 0, win 65535, options [mss 1460], length 0
```

从前往后拆解：

| 字段 | 示例值 | 含义 |
|------|--------|------|
| `12:34:56.789012` | 时间戳 | 发生时间，精确到微秒（本地时区） |
| `IP` | IP | 网络层协议，可能是 `IP6` |
| `192.168.1.100.54321` | 源 IP.源端口 | 点号分隔 IP 和端口，左边是 IP 右边是端口 |
| `>` | 方向 | 箭头从源指向目标 |
| `93.184.216.34.80` | 目标 IP.目标端口 | 同上 |
| `Flags [S]` | 标志位 | TCP 控制标志，详见下方 |
| `seq 12345` | 序列号 | 本段数据的起始序列号 |
| `ack 0` | 确认号 | 期望收到的下一个序列号 |
| `win 65535` | 窗口大小 | 接收窗口剩余空间（流量控制） |
| `options [mss 1460]` | TCP 选项 | 如 MSS、时间戳、SACK |
| `length 0` | 净载荷长度 | 不含 TCP 头部的数据字节数 |

### 标志位（Flags）详解

Flags 是 TCP 报文最重要的字段之一，表示"这个包是干什么用的"：

| 缩写 | 全称 | 含义 | 典型场景 |
|------|------|------|---------|
| `S` | SYN | 同步序号，发起连接 | 三次握手的第一个包 |
| `.` | ACK | 确认号有效 | 除了 SYN 和 FIN，几乎所有包都带 ACK |
| `F` | FIN | 结束连接 | 四次挥手的第一个包 |
| `P` | PSH | 推送数据 | 告诉接收方"立即处理，不要等缓冲区满" |
| `R` | RST | 重置连接 | 连接被拒绝或异常中断 |
| `[S.]` | SYN-ACK | SYN + ACK 同时置位 | 三次握手的第二个包 |
| `[F.]` | FIN-ACK | FIN + ACK 同时置位 | 四次挥手的第三、四个包 |

```
# 三次握手的完整报文
12:34:56.000001 IP 192.168.1.100.50001 > 93.184.216.34.80: Flags [S], seq 1000, ...     ← 客户端发 SYN
12:34:56.000120 IP 93.184.216.34.80 > 192.168.1.100.50001: Flags [S.], seq 2000, ack 1001, ... ← 服务器回 SYN-ACK
12:34:56.000150 IP 192.168.1.100.50001 > 93.184.216.34.80: Flags [.], ack 2001, ...       ← 客户端回 ACK，完成握手
```

> 注意 `seq` 和 `ack` 的变化：第一次握手 seq=1000，第二次握手 ack=1001（表示"收到了 1000 之前的全部字节，期待 1001"），第三次握手 ack=2001。

### 常见报文解读示例

**HTTP GET 请求**：

```
12:34:56.100001 IP 192.168.1.100.50001 > 93.184.216.34.80: Flags [P.], seq 1:100, ack 1, win 65535, length 99
```

解读：客户端向 80 端口发送 99 字节数据（P 标志指立即推送），这 99 字节就是 HTTP 请求行 + 头部。

**ICMP Echo（ping）**：

```
12:34:56.200001 IP 192.168.1.100 > 93.184.216.34: ICMP echo request, id 12345, seq 1, length 64
12:34:56.200050 IP 93.184.216.34 > 192.168.1.100: ICMP echo reply, id 12345, seq 1, length 64
```

ICMP 没有端口号，通过 id 和 seq 匹配请求和回复。

**DNS 查询（UDP）**：

```
12:34:56.300001 IP 192.168.1.100.54321 > 8.8.8.8.53: 12345+ A? baidu.com. (28)
```

解读：从临时端口 54321 发往 8.8.8.8 的 53 端口，查询 baidu.com 的 A 记录，查询 ID 为 12345，`+` 表示启用 DNSSEC，括号里的 28 是 DNS 消息长度。

## 5. 实用过滤场景

### 场景一：只看 TCP 三次握手（只抓 SYN）

有时你只想知道"有没有人试图连某个端口"，所有已建立的连接不关心。SYN 包就是"连接请求"的代号。

```bash
# 只抓 SYN 包（连接请求）
sudo tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-syn != 0 and tcp[tcpflags] & tcp-ack == 0'
```

解释一下：
- `tcp[tcpflags]` 是 BPF 的原始字节偏移写法，读取 TCP 头部第 13 字节（flags 字段）
- `& tcp-syn != 0`：SYN 标志位置 1
- `& tcp-ack == 0`：ACK 标志位为 0（排除 SYN-ACK）

> 更简单的写法（tcpdump 新版支持）：`tcp[tcpflags] == tcp-syn`

**只抓 SYN-ACK（服务器对连接请求的应答）**：

```bash
sudo tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-syn != 0 and tcp[tcpflags] & tcp-ack != 0'
```

### 场景二：只抓 DNS 查询

DNS 通常是 UDP 53，但也有 TCP 53（大查询或 DNSSEC）：

```bash
# UDP DNS（最常见的查询）
sudo tcpdump -i eth0 -nn udp port 53

# 同时抓 UDP 和 TCP 的 DNS
sudo tcpdump -i eth0 -nn 'port 53'

# 只看发出的 DNS 查询（源端口随机，目标端口 53）
sudo tcpdump -i eth0 -nn udp dst port 53

# 只看收到的 DNS 回复（源端口 53）
sudo tcpdump -i eth0 -nn udp src port 53
```

### 场景三：抓特定对话（单向或双向）

有时两侧 IP 都是已知的，比如查"客户端 192.168.1.100 和服务器 10.0.0.5 之间的交互"：

```bash
# 两个 IP 之间的全部流量
sudo tcpdump -i eth0 -nn host 192.168.1.100 and host 10.0.0.5

# 加上端口限制（比如只关心 HTTP）
sudo tcpdump -i eth0 -nn host 192.168.1.100 and host 10.0.0.5 and tcp port 80
```

### 场景四：找重传和丢包

TCP 重传包在 tcpdump 默认输出中没有显式标记，但可以通过观察 seq 是否重复来判断。更可靠的方式是用 Wireshark 分析 pcap 文件。tcpdump 可以用 `-e` 显示以太网帧头的重传位（不精确），更好的做法是：

```bash
# 抓包存文件，然后用 Wireshark 的 Analyze → Expert Info 分析重传
sudo tcpdump -i eth0 -nn -w capture.pcap
```

### 场景五：排除自己的 SSH 流量

如果你通过 SSH 连到服务器上抓包，自己输入的 SSH 命令也会产生大量流量。排除 SSH 端口：

```bash
sudo tcpdump -i eth0 -nn not port 22
```

> 但注意如果你抓的是 `-i any`，SSH 流量可能从 eth0 进来、从 eth0 出去——过滤 `not port 22` 是安全的。

## 6. 权限说明

tcpdump 需要进入"混杂模式"（promiscuous mode）才能看到所有经过网卡的包，这不是普通用户权限能做的事。

### 为什么需要 root？

抓包涉及两个关键操作：
1. **打开原始套接字（raw socket）**：需要 `CAP_NET_RAW` 能力
2. **设置网卡为混杂模式**：需要 `CAP_NET_ADMIN` 能力

这两个能力默认只有 root 才有，所以直接运行会报：

```bash
$ tcpdump -i eth0
# tcpdump: eth0: You don't have permission to capture on that device
# (socket: Operation not permitted)
```

### 三种解决方案

**方案一：sudo（最简单，推荐临时使用）**

```bash
sudo tcpdump -i eth0 -nn
```

适合临时诊断，安全性由 sudo 的密码保护控制。

**方案二：设置 CAP_NET_RAW 能力（适合日常免 root 使用）**

Linux capabilities 机制允许将特定特权赋予可执行文件，无需完整 root：

```bash
sudo setcap cap_net_raw,cap_net_admin+eip $(which tcpdump)
```

执行后，普通用户可直接运行 tcpdump：

```bash
# 不再需要 sudo
tcpdump -i eth0 -nn -c 10
```

查看能力是否设置成功：

```bash
getcap $(which tcpdump)
# /usr/sbin/tcpdump cap_net_admin,cap_net_raw=eip
```

> [!warning] capabilities 的安全风险
> 设置了 `cap_net_raw` 的 tcpdump 可以在**所有接口**上抓包。如果系统上有其他用户能访问这台机器，他们也能用 tcpdump 抓取经过网卡的所有流量（包括其他人的 SSH 密码等敏感信息）。**生产环境建议仅在诊断期间临时开放，用完后移除**：
> ```bash
> sudo setcap -r $(which tcpdump)
> ```

**方案三：将用户加入 wireshark 组**

某些发行版（如 Debian/Ubuntu）提供了专门的抓包组：

```bash
sudo usermod -a -G wireshark $USER
# 重新登录后生效
```

原理是该组下的用户通过 udev 规则获得了访问 `/usr/bin/dumpcap` 的权限，而 dumpcap 本身被赋予了抓包能力。

## 7. 与其他工具的配合

### tcpdump + Wireshark

这是最经典的工作流：**tcpdump 负责在服务器上抓包存文件，Wireshark 负责在本地图形化分析**。

```bash
# 服务器端：抓包存文件
sudo tcpdump -i eth0 -c 100000 -nn -w problem.pcap

# 将文件传到本地（用 scp）
scp user@server:/path/to/problem.pcap .

# 本地：用 Wireshark 打开分析
wireshark problem.pcap
```

Wireshark 的图形界面可以轻松做到 tcpdump 命令行比较困难的事：
- 着色标记重传包
- 追踪 TCP 流（右键 → Follow → TCP Stream）
- 查看协议层次统计
- 用 Wireshark 的显示过滤（比 BPF 更强）

### tcpdump + ngrep

`ngrep`（network grep）在抓包基础上加了"按包内容匹配"的能力，适合快速查找包含特定字符串的包：

```bash
# 搜索 HTTP 包中的关键字
sudo ngrep -d eth0 -q 'GET /api' port 80

# 搜索包中是否包含 "password"
sudo ngrep -d eth0 -q 'password' tcp
```

### tcpdump + tshark

`tshark`（Wireshark 的命令行版本）比 tcpdump 的输出更结构化，适合复杂分析：

```bash
# 列出每个包的协议层级
tshark -r capture.pcap -T fields -e frame.number -e ip.src -e tcp.srcport -e http.request.uri

# 显示 HTTP 请求的 URL
tshark -r capture.pcap -Y 'http.request' -T fields -e http.host -e http.request.uri
```

### tcpdump + tcpick

`tcpick` 能从 pcap 文件中重组 TCP 流，直接提取传输的文件内容：

```bash
# 从抓包中还原 HTTP 传输的文件
sudo tcpick -r capture.pcap -C
```

## 本章小结

- **tcpdump 是命令行抓包的工业标准**，前后端通用，适合在服务器上快速诊断
- **基础三参数必记**：`-i` 指定接口、`-c` 限制数量、`-nn` 禁用域名解析（加 `-nn` 几乎从不后悔）
- **BPF 过滤表达式**是精准定位流量的关键，格式为 `[方向] [类型] [值]`，用 `and`/`or`/`not` 组合
- **抓包三段式**：本地 `-w` 写文件 → 传文件 → `-r` 读取分析，比边抓边分析更少出错
- **报文输出解读是基本功**：重点看 `Flags`（标志位）、`seq`（序列号）、`ack`（确认号），三次握手的 SYN → SYN-ACK → ACK 是最经典的跟踪练习
- **权限要求**：需要 root 或 `CAP_NET_RAW` + `CAP_NET_ADMIN`；生产环境用 sudo 即可，capabilities 适合需要频繁抓包但不想提权的场景
- **联合使用**：tcpdump 是"采集器"角色，配合 Wireshark、tshark、ngrep 等工具能覆盖从采集到分析的完整链路
