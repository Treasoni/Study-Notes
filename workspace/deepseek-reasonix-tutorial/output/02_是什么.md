# DeepSeek-Reasonix 是什么

> [!info] 文档定位
> 本页是入门篇第一篇，回答三个问题：DeepSeek-Reasonix 是什么、为什么值得关注、和你正在用的 Claude Code 是什么关系。读完你应建立正确的心智模型。装、配、跑见 [[DeepSeek-Reasonix 使用指南]]，成本与缓存深挖见 [[DeepSeek-Reasonix 前缀缓存与成本优化]]。

## 一、产品定位：DeepSeek 原生的终端 AI 编程 agent

DeepSeek-Reasonix 是 **DeepSeek 原生的终端 AI 编程 agent**：MIT 开源，核心是一个**单 Go 静态二进制**（`CGO_ENABLED=0` 构建，无动态依赖），定位是「可以一直开着跑的编码 Agent」。

- **一套本地引擎，四个入口**：终端（TUI）、桌面端（dmg/exe/deb）、浏览器、ACP 编辑器（VS Code 扩展走本地 `reasonix acp` 后端）。无论从哪个入口进，跑的都是同一个引擎。
- **仓库**：https://github.com/esengine/DeepSeek-Reasonix（素材收集时 33.6k stars / 2.2k forks）。
- **内核不做模型硬编码**：provider 是**插件式声明**——在 `reasonix.toml` 里声明 OpenAI/Anthropic 兼容端点即可接入其他后端。官方文档未出现「不支持非 DeepSeek 后端」的断言，教程以 provider 声明机制为准，不做绝对断言。配置示意（摘自官方 `reasonix.example.toml`）：

```toml
default_model = "deepseek"           # provider 名或 "provider/model"
```

> [!tip] 大白话
> 把 Reasonix 想成「一个只装 DeepSeek 引擎的工地包工头」：你交代一个任务，它自己拆解、自己动手改代码、自己验证。它不像 ChatGPT 问一句答一句，而是能一口气跑很久，像雇了个能连续加班的员工。四入口则是「同一台机器，四种遥控器」——终端、桌面、浏览器、编辑器，怎么顺手怎么开。

## 二、设计哲学：长时自治 + 逐轮可撤销

Reasonix 的核心场景是**长时自治运行**——让 agent 自己跑完一个复杂、多步骤、可能跨很多轮的任务。但「自治」不等于「失控」，它用四件事保证整个运行**可读、可撤销**：

1. **计划模式（plan）**：先规划后执行，只读研究，不直接改文件。
2. **权限（permissions）**：写文件、跑命令前按规则审批（ask / auto / yolo 等 6 种模式，详见权限模式章节）。
3. **工作区沙箱（sandbox）**：把 agent 的读写限定在工作区范围内（macOS 用 Seatbelt、Linux 用 bubblewrap；Windows 无 OS 级沙箱）。
4. **逐轮 checkpoint**：每一步决策留检查点，出问题可回滚/恢复。

> [!tip] 大白话
> 把「自治 agent」想成「请了个远程实习生」。计划模式 = 先交方案给你看再动手；权限 = 每次动关键文件先问你「可以吗」；工作区沙箱 = 只许他在工位上干活，不许翻你抽屉；checkpoint = 每做一步存个档，随时回退。四样凑齐，你才敢让他跑一整天。

## 三、前缀缓存原理（概览）

DeepSeek 的 API 自带**自动前缀缓存**，而 Reasonix 是围绕它深度调优的。核心机制（据官方 ARCHITECTURE.md）：

- **精确字节前缀匹配**：只有当上一请求的**精确字节前缀**完全匹配时缓存才生效；前缀内任何早期改动都会让缓存失效。
- **命中按未命中的 ~10% 计费**：缓存命中的输入 token 只按未命中价格约 1/10 计费——这是成本优势的来源。
- **无纪律 agent 命中率 <20%**：如果 agent 每轮重排上下文、重写旧日志、注入时间戳，缓存几乎必 miss，实测无纪律循环命中率低于 20%。

Reasonix 用**三区上下文设计**（CacheFirstLoop）对抗这种「自己打自己」：

| 区域 | 内容 | 行为 |
|------|------|------|
| IMMUTABLE PREFIX 不可变前缀 | system + tool_specs + few_shots | 会话内固定，每会话算一次并钉住 |
| APPEND-ONLY LOG 只追加日志 | assistant / 工具调用序列 | 单调追加，绝不重写 |
| VOLATILE SCRATCH 易变草稿 | R1 思维、临时计划 | 每轮重置，先蒸馏再折叠进日志 |

> [!tip] 大白话
> 把前缀缓存想成「同一份长文档反复修改」：每次都从同一段开头接着写，系统记得开头，只收你新增部分的钱；但如果你每次把前面整段删掉重写，系统就得全部重算，价格回到原价。Reasonix 的工程目标就一句话——**保证开头永远不变**。

详细命中率公式、缓存友好实践与实测数据在 [[DeepSeek-Reasonix 前缀缓存与成本优化]] 展开。

## 四、与 Claude Code 的关系：同类工具，非替代品

Reasonix 和 Claude Code 是**同类工具**——都是终端里的 AI 编程 agent——但不是替代品：

- **核心差异一句话**：Claude Code 是通用多模型闭源 harness；Reasonix 是围绕 DeepSeek 前缀缓存深度调优的 DeepSeek 原生实现。
- **交互层大量对齐**：命令（`claude`↔`reasonix`、`-p`/`run`、`--allowed-tools`、`--permission-mode` 等）、picker 方向键 / Vim / Ctrl+P/N 等交互均与 Claude Code 对齐（见 [PR #6431](https://github.com/esengine/DeepSeek-Reasonix/pull/6431)）。
- **不是「只能连 DeepSeek」**：provider 为插件式声明，可在 `reasonix.toml` 声明其他兼容端点，官方文档无「不支持非 DeepSeek」的绝对断言。

> [!warning] 别被「对齐」误导
> 「命令对齐」只是交互层体验一致，**不代表内核相同**。Reasonix 的杀手锏是缓存友好工程（三区设计、Tool-Call Repair），这是围绕 DeepSeek 计费模型专门做的，不是换皮 Claude Code。

## 五、选型判断框架：何时用 Reasonix，何时留 Claude Code

| 场景 | 建议 |
|------|------|
| 重度用 DeepSeek、成本敏感 | 值得试：缓存优化 + 长会话输入成本约 1/5（实测口径见成本章节） |
| 需要长时自治跑多步骤任务 | 值得试：计划 + 权限 + 沙箱 + checkpoint 正是为此设计 |
| 依赖 Claude 生态 / 特定闭源模型 | 留 Claude Code，或按需声明 Anthropic 兼容端点 |
| 已在 Claude Code 上跑顺工作流 | 先读 [[从 Claude Code 迁移到 DeepSeek-Reasonix]] 再决定，不必盲目切换 |

> [!note] 一句话结论
> 最适合：已会用 Claude Code、想压低长会话成本、或想要「能一直开着跑」的自治 agent 的用户。最不适合：只在终端问零散问题、不跑长会话的用户——缓存优势基本用不上。

## 常见问题

**Q: Reasonix 只能连 DeepSeek 吗？**
A: 不是。provider 是插件式声明，`reasonix.toml` 中可声明 OpenAI/Anthropic 兼容端点；官方文档未出现「不支持非 DeepSeek 后端」的断言。只是默认配置与优化都围绕 DeepSeek 展开。

**Q: 它和 Claude Code 能共存吗？**
A: 可以。两者是同类但可并存的工具，命令与交互层已对齐（PR #6431），可在同一工作区切换试用。

**Q: 前缀缓存是自动生效的吗？**
A: 缓存本身是 DeepSeek API 侧的自动机制；Reasonix 做的是「缓存友好」工程（三区上下文、Tool-Call Repair）来提高命中率。命中率逐轮显示在 TUI 顶栏缓存单元格。
