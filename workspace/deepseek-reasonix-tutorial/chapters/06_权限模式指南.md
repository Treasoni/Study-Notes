# DeepSeek-Reasonix 权限模式指南

> [!info] 文档定位
> 这是基础功能篇第 6 章，负责「权限语义」这一整块：6 种权限模式分别是什么、会话里怎么切换、命令行与配置文件怎么控制、无头模式为什么默认 fail-closed、以及最容易被误用的 `--allowed-tools` 与 `deny` 优先级。CLI 参数写法见 [[DeepSeek-Reasonix CLI 完整参考]]，`[permissions]` 字段的书写位置见 [[reasonix.toml 配置详解]]，沙箱与凭据保护见 [[DeepSeek-Reasonix 沙箱与安全]]。

本章面向已熟悉 Claude Code 的用户：默认审批、`--permission-mode`、plan 模式在这里都能找到对应物，差别集中在交互切换与 fail-closed 行为。先建立「为什么需要权限模式」的模型，再逐项过 6 种模式。

## 一、权限模型总览

Reasonix 的定位是「可以一直开着跑的编码 Agent」——长时自治运行意味着它会在你不在键盘前时连续调用工具。权限模型存在的意义，就是让这种自治**可读、可撤销**：

- 每个工具调用在真正执行前都要过一道**权限检查**；
- 权限模式决定这道检查的结果：自动放行、弹审批、还是直接拒绝；
- 配合逐轮 checkpoint，放行后的每一步操作都能回看、能撤销。

这与 Claude Code 的权限体系高度对齐（PR #6431）：交互里 `Shift+Tab` 循环模式、`--permission-mode`、plan 模式都是同源概念；区别在于 Reasonix 把「plan 只读」与「YOLO」都纳入了同一套 6 种模式，且非交互场景默认 fail-closed。

> [!tip] 大白话
> 把权限模式想成「公司门禁的三种门卫态度」：Ask 是每个房间都拦下问你「进不进」；Auto 是普通房间直接放行、敏感房间才问；YOLO 是给你一把万能钥匙，所有门都直接开。门禁不是为了不让你干活，而是保证「每扇门是谁开的一查就有记录」——这就是长时自治可撤销的前提。

> [!note] 与 Claude Code 对齐
> 工具审批在 Reasonix 的本地 TUI 里走键盘循环，但在编辑器/IDE 集成（ACP）场景里走协议层：`session/set_config_option` 设置 `tool_approval`（ask/auto/yolo）、`session/request_permission` 发审批请求。形态不同、语义同源，ACP 细节见第 11 章。

## 二、6 种权限模式

`--permission-mode` 接受 6 种取值，逐个说明：

| 模式 | 行为 | 典型场景 |
|------|------|---------|
| `manual/ask` | 每个操作弹审批，人工确认后才执行 | 默认模式；不熟悉的项目、涉及生产环境 |
| `auto` | 自动批准普通操作 | 可信的本地开发，想减少按键 |
| `acceptEdits` | 只放行文件编辑，其他操作仍需审批 | 只想让 agent 改代码，不想让它跑任意命令 |
| `dontAsk` | 拒绝但**不弹窗** | 显式禁止某类操作，又不想被反复打扰 |
| `plan` | 只读 Plan，不做任何写入 | 先让 agent 出方案，看完再动手 |
| `bypassPermissions`（YOLO） | 跳过权限，全自动执行 | 完全信任、追求无人值守速度 |

几个关键区别：

- `auto` 与 `acceptEdits` 都减少审批，但 `auto` 放行「普通操作」（含常规命令），`acceptEdits` 只对文件编辑放行，更保守。
- `dontAsk` 与 `manual/ask` 正好相反：`ask` 是「做之前问你」，`dontAsk` 是「直接拒绝、也不弹窗打扰你」。
- `plan` 是只读档，进入后 agent 只读文件、只出计划，不做任何写入。
- `bypassPermissions` 的别名就是 `--yolo`，名字即行为——跳过权限检查。

> [!tip] 大白话
> 把 6 种模式想成给临时工的六种工牌权限：`ask` 是每进一间房都要打卡审批；`auto` 是普通区域畅行、机房才审批；`acceptEdits` 是只能改文档、不能碰机器；`dontAsk` 是把某些区域划为禁区、保安直接挡回也不解释；`plan` 是只让他在门口画图纸、不许进场；`yolo` 是全场万能卡随便造。

## 三、交互切换

TUI 里不需要退出重开就能切模式（快捷键与 Claude Code 对齐，PR #6431）：

| 快捷键 | 作用 |
|--------|------|
| `Shift+Tab` | 循环切换 Ask → Auto → Plan |
| `Ctrl+Y` | 独立切换 YOLO（bypassPermissions） |
| `y` / `a` / `p` / `n`（可带数字） | 审批动作键，按字母语义对应：y 批准、a 放行、p 计划、n 拒绝（精确行为以 `/help` 为准） |
| `y` / `n` | 编辑门控：接受 / 丢弃待定编辑 |
| `u` | 撤销最近自动应用的编辑批次 |

要点：

- `Shift+Tab` 只在 Ask / Auto / Plan 三者间循环，`Ctrl+Y` 是**独立的** YOLO 开关——不是循环的一环，按一下直接进入绕过权限状态，再按切回。
- `u` 是自动批次的「后悔药」：Auto 模式下一次自动应用了一整批编辑，按 `u` 可以把最近这批整体撤销。
- 会话内 v1 还提供 `/mode review|auto|yolo` 与 `/permissions` 命令；main-v2 下以应用内 `/help` 为实时权威（版本差异见[[DeepSeek-Reasonix 会话与交互]]）。

> [!tip] 大白话
> `Shift+Tab` 像手电筒的档位循环（常亮 / 自动 / 省电），在 Ask / Auto / Plan 之间转；`Ctrl+Y` 则是独立的「紧急直通开关」，一按直接进入 YOLO。日常建议保持 Ask，需要批量放行再临时切 Auto。

## 四、启动参数

权限相关的启动参数共四个维度：

```bash
# 显式指定 6 种权限模式之一
reasonix code --permission-mode plan

# YOLO：bypassPermissions 的别名
reasonix code --yolo

# auto 别名（无人值守常用）
reasonix run --auto "把 main.go 的 TODO 实现掉"
# 等价：reasonix run -y "..."  /  reasonix run --permission-mode auto "..."
```

| 参数 | 作用 |
|------|------|
| `--permission-mode MODE` | 指定权限模式：ask/auto/acceptEdits/dontAsk/plan/bypassPermissions |
| `--yolo` | `bypassPermissions` 别名 |
| `--auto` / `-y` | `auto` 别名；**不能与显式 `--permission-mode` 组合** |
| `--allowed-tools RULES` | 仅本次会话放行指定工具（可重复） |

> [!warning] 坑点：`--auto` 与 `--permission-mode` 互斥
> `--auto` 本身就是 `permission-mode auto` 的别名，再显式写一个 `--permission-mode` 属于重复指定同一件事，两者不能组合。

`--allowed-tools` 是最容易被误解的参数：**它是权限覆盖，不是 schema 过滤**。它只决定「这次会话放行哪些工具」，并不改变可用工具集合——工具都还在，只是这次没放行。而且，配置文件里的 `deny` 永远压过 CLI 的 `allow`（含 `--allowed-tools`）。

> [!tip] 大白话
> `--allowed-tools` 像「临时门禁卡」：只给这次会话发一张卡，能进哪几扇门说得清清楚楚；但它不拆门——工具都还在，只是这次没放行。所以它是权限放行，不是删除工具。

## 五、配置文件 [permissions]

`reasonix.toml` 的 `[permissions]` 节是权限的持久化兜底（字段书写位置见[[reasonix.toml 配置详解]]）：

```toml
[permissions]
mode = "ask"                         # ask|allow|deny 兜底
deny  = ["Bash(rm -rf*)", "Bash(git push*)"]   # 黑名单：永远禁止
allow = ["Bash(go test:*)"]          # 白名单：放行
```

三层要点：

1. **`mode` 是配置层的三态兜底（`ask|allow|deny`）**，与交互/CLI 的「6 种权限模式」是两层概念：`--permission-mode` 的 6 种面向运行时交互，`[permissions] mode` 面向会话默认纪律。命令行 flag 优先级最高，会覆盖配置兜底。
2. **`deny` 黑名单永远压过 `allow` / `--allowed-tools`**：哪怕命令行临时放行了某个工具，配置里的 `deny` 照样拦截。这是权限里优先级最高的一层。
3. **fail-closed 原则**：默认 `ask/manual` 下，无法交互确认的显式 Ask 决定与普通写操作都会被拒绝（关门而不是放行）。

> [!tip] 大白话
> 把 `[permissions]` 想成「门禁的规则白皮书」：`mode` 是默认规矩（进门要刷卡审批），`deny` 是黑名单（这几扇门永远进不去），`allow` 是白名单（这几扇门刷脸就进）。黑名单永远压过白名单——就算你临时让门卫（CLI）放行，黑名单上的门照样进不去。

## 六、无头模式权限

`reasonix run "<task>"` 是无头一次性执行，没有人坐在键盘前按审批键。因此：

- **默认 fail-closed**：没有显式放行时，`ask/manual` 下需要人工确认的决策与普通写操作会被拒绝——宁可任务失败，也不在无人值守时乱放行。
- **必须显式放行**：无人值守需要 `reasonix run --auto` / `-y` / `--permission-mode auto`，否则写操作会卡在审批上或直接被拒。
- **YOLO 也有底线**：`bypassPermissions` 跳过的是「权限模式」这一层，但仍遵守 `deny` 规则、工作区沙箱，以及需要人工审批的工具。

> [!warning] 坑点：无人值守忘写 `--auto`
> 在 CI 或脚本里跑 `reasonix run` 而忘记 `--auto`，任务会因为 fail-closed 被拒绝写操作。第一反应不是「工具坏了」，而是「权限没放行」。

> [!tip] 大白话
> fail-closed 像「没人值班的工地默认锁门」：你不在场，所有装修活动默认被叫停，而不是默认放行。所以无人值守时你要主动交代「今天放行普通操作」（`--auto`），否则工地就停工给你看。

## 七、常见坑

1. **`--auto` 不能与显式 `--permission-mode` 组合**：`--auto` 就是 auto 的别名，重复指定会报错，二选一即可。
2. **`--allowed-tools` 是权限覆盖不是 schema 过滤**：它不改变可用工具集合，只决定本次会话放行范围。
3. **`deny` 优先级最高**：配置 `deny` 永远压过 `allow` / `--allowed-tools`，黑名单无法被命令行绕过。
4. **无人值守必须 `--auto`**：无头模式默认 fail-closed，不显式放行就会拒绝写操作。
5. **版本差异**：v1 提供 `/mode review|auto|yolo`、`/permissions` 等命令，main-v2 命令列表可能不同；遇到「命令不存在」先敲应用内 `/help`。
6. **YOLO 不是万能**：`bypassPermissions` 仍遵守 `deny`、沙箱与需人工审批的工具，别以为 YOLO 能穿透一切边界（沙箱细节见[[DeepSeek-Reasonix 沙箱与安全]]）。

## 常见问题

**Q：`--permission-mode` 的 6 种模式和配置里 `[permissions] mode` 是一回事吗？**
A：不是同一层。`--permission-mode` 是运行时交互/CLI 的 6 种模式（ask/auto/acceptEdits/dontAsk/plan/bypassPermissions）；`[permissions] mode` 是配置文件里更简单的三态兜底（ask|allow|deny）。命令行 flag 优先级最高，会覆盖配置兜底。

**Q：无人值守跑 `reasonix run`，写文件被拒是怎么回事？**
A：无头模式默认 fail-closed。需要加 `--auto`（或 `-y`、`--permission-mode auto`）显式放行普通操作。

**Q：我在命令行用 `--allowed-tools` 放行了某个工具，为什么还是被拦？**
A：因为 `--allowed-tools` 是权限覆盖不是 schema 过滤，而且配置文件里的 `deny` 黑名单永远压过 CLI 的 allow。去 `[permissions] deny` 里查一下是不是命中黑名单规则。

**Q：`Ctrl+Y` 和 `Shift+Tab` 是什么关系？**
A：`Shift+Tab` 只在 Ask / Auto / Plan 之间循环；`Ctrl+Y` 是独立的 YOLO 开关，不是循环的一部分，按一下直接进入绕过权限状态。
