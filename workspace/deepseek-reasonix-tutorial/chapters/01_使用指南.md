## 一、安装：4 条路径 + 源码构建

Reasonix 是一套本地引擎、四个入口共用，四条安装路径**任选一条即可**。下表整理自官方安装文档 [DeepSeek-Reasonix README](https://github.com/esengine/DeepSeek-Reasonix)。

| 路径 | 命令 / 操作 | 前置要求 | 适用场景 |
|------|------------|---------|---------|
| A1. CLI（npm） | `npm i -g reasonix` | Node/npm | 任意系统，自动拉平台原生二进制 |
| A2. CLI（brew） | `brew install esengine/reasonix/reasonix` | Homebrew | macOS |
| B. 免安装（npx） | `npx reasonix code` | Node≥22 + API Key | 临时用，每次自动拉最新版 |
| C. 桌面端 | 官方下载页 `reasonix.io/?download=desktop` | — | macOS `.dmg`，Windows `.exe`，Linux `.deb` |
| D. VS Code 扩展 | Marketplace / Open VSX 安装 `SivanLiu.reasonix-agent` | **先装 CLI** | VS Code / VSCodium |
| E. 源码构建 | `git clone` + `make build` | Go 工具链 | 定制构建（可选） |

### A. CLI：npm 或 brew（推荐）

```bash
# 任选一条
npm install -g reasonix                          # 任意系统
brew install esengine/reasonix/reasonix          # macOS

reasonix --version                               # 验证安装
```

### B. npx 免安装（临时用）

```bash
npx reasonix code
```

> [!tip] 大白话：npx 像「临时工牌」
> 把 npx 想成**临时工牌**——不用办入职（全局安装），刷卡（自动拉最新版）就能进场干活。所以它适合临时体验，但要求 Node≥22、每次都要重新拉取，正式用还是建议装 CLI。

### C. 桌面端 / D. VS Code 扩展

桌面端到官方下载页 `reasonix.io/?download=desktop` 取对应安装包。VS Code 扩展需要**先装好 CLI**——扩展本身只是前端，启动的是本地 `reasonix acp` 后端，装好 CLI 才有引擎可连 [DeepSeek-Reasonix README](https://github.com/esengine/DeepSeek-Reasonix)。

### E. 源码构建（可选）

```bash
git clone https://github.com/esengine/DeepSeek-Reasonix
cd DeepSeek-Reasonix
make build          # 产物在 bin/reasonix
```

> [!note] 补充
> `make cross` 可跨 6 平台交叉构建，需要 Go 工具链。一般用户不需要走这条路。

## 二、首次配置：`reasonix setup`

安装后第一件事是跑配置向导 [GUIDE.zh-CN（setup）](https://github.com/esengine/DeepSeek-Reasonix/blob/main-v2/docs/GUIDE.zh-CN.md)：

```bash
reasonix setup
```

向导统一管理 provider、模型列表、凭据、连接测试，并设定默认模型。要点如下：

- **修改是「暂存」的**：向导里的改动不立刻生效，全部改完选「保存并退出」才统一写入；中途退出等于没改。向导也会同步维护桌面端的 provider access。
- **API Key 存全局 `.env`**：配置文件只存**变量名**（如 `api_key_env = "DEEPSEEK_API_KEY"`），真实密钥写在全局 `<Reasonix home>/.env`（macOS/Linux 为 `~/.reasonix/`，Windows 为 `%AppData%\reasonix\`）。
- **项目 `.env` 不导入 provider key**：项目里的 `.env` 只作 MCP/plugin 的 `${VAR}` 展开来源，不会把 provider 密钥带进项目。

> [!tip] 大白话：config 是保险箱的位置，不是密码
> 把真实 API Key 想成**保险箱里的现金**，config 只写了一张「保险箱在 `~/.reasonix/.env`」的便条。项目里别人看到 config 也拿不到密钥，密钥始终锁在你主目录的保险箱里。

> [!note] 补充
> setup 生成的配置结构、字段优先级与全部字段解释，见 [[reasonix.toml 配置详解]]。

## 三、第一个会话

配置完就能跑。进入项目目录，启动交互式代码模式 [CLI.zh-CN](https://github.com/esengine/DeepSeek-Reasonix/blob/main-v2/docs/CLI.zh-CN.md)：

```bash
cd /path/to/your-project
reasonix code .
```

- 进入 TUI 后先运行 `/init`，生成项目记忆文件 `REASONIX.md` / `AGENTS.md`——相当于 Claude Code 的 `CLAUDE.md`，让 agent 了解项目规范与偏好。
- 然后直接下任务，例如「把 main.go 里的 TODO 实现掉」。
- 用 `/status` 查看会话状态，用 `/cost` 查看 token 消耗与费用。

> [!tip] 大白话：/init 是给 agent 立家规
> `/init` 想成**入职时发的员工手册**——把项目规矩（技术栈、目录约定、禁止事项）写进 `REASONIX.md`，agent 每次干活前先读它，才不乱来。

> [!warning] 版本差异
> `/cost` 等命令在 v1 与 main-v2 文档的收录情况不同，实际以应用内 `/help` 为实时权威（详见 [[DeepSeek-Reasonix CLI 完整参考]]）。

## 四、日常速查表

### 核心命令

| 命令 | 用途 |
|------|------|
| `reasonix code [dir]` | 交互式代码模式 TUI（默认） |
| `reasonix chat` | 纯聊天，无文件系统 / shell |
| `reasonix run "<task>"` | 无头一次性执行，CI 友好 |
| `reasonix setup` | 配置向导 |
| `reasonix doctor` | 健康检查（API / 配置 / hooks / 项目） |
| `reasonix upgrade`（别名 `update`） | 升级 |

### 常用斜杠命令

| 命令 | 用途 |
|------|------|
| `/init` | 生成 REASONIX.md / AGENTS.md |
| `/status` | 会话状态 |
| `/cost` | token 消耗与费用（v1） |
| `/model` / `/provider` | 切换模型 / provider |
| `/help` | 实时命令列表 |

### 常用快捷键

| 快捷键 | 作用 |
|--------|------|
| `Shift+Tab` | 循环切换权限模式 Ask → Auto → Plan |
| `Ctrl+Y` | 独立切换 YOLO |
| `y/a/p/n` | 审批动作 |
| `u` | 撤销最近自动应用批次 |

> 完整命令、启动参数、快捷键见 [[DeepSeek-Reasonix CLI 完整参考]]。

## 五、常见坑

1. **npx 需要 Node≥22**：npx 免装路径前置要求 Node≥22 + API Key，否则跑不起来 [DeepSeek-Reasonix README](https://github.com/esengine/DeepSeek-Reasonix)。
2. **Windows 沙箱强制关闭**：Reasonix 不在 Windows 提供 OS 级 Bash 沙箱，配置里 `bash = "enforce"` 也会被解析为 off。需要隔离时在容器 / CI 中运行。
3. **API Key 未配置**：首次跑报认证错误时，先确认全局 `<Reasonix home>/.env` 里有密钥、config 里的 `api_key_env` 变量名对得上。
4. **第一次跑不起来**：先跑 `reasonix doctor` 做健康检查（API / 配置 / hooks / 项目），按输出逐项排查。

> [!tip] 大白话：Windows 沙箱 off 像「没有围墙的施工现场」
> 沙箱想成**工地围挡**——macOS/Linux 有围挡（Seatbelt / bubblewrap），Windows 没配围挡，于是「要求围挡」的 `enforce` 开关在 Windows 上会被自动忽略，等于默认露天施工。需要隔离就自己把工地搬进容器里。

## 常见问题（FAQ）

**Q：npx 装和全局装有什么区别？**
A：npx 免安装、每次拉最新版，适合临时体验；正式使用建议 `npm i -g reasonix`。

**Q：`upgrade` 和 `update` 有什么区别？**
A：同一个命令的别名。

**Q：API Key 一定要放全局 `.env` 吗？**
A：是。config 只存变量名，真实值放全局 `<Reasonix home>/.env`；项目 `.env` 不导入 provider key。

**Q：Windows 上沙箱配置不生效？**
A：正常。Windows 无 OS 级 Bash 沙箱，`bash = "enforce"` 解析为 off。
