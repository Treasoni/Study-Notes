# 第 1 章 工具体系总览与配置入口

如果模型是 Hermes 的"大脑"，那工具就是它的"双手"。大脑负责思考和决策，双手负责把想法落到现实——搜索一条新闻、跑一段代码、改一个文件、点开一个网页。上一册《上手实战》带你用 Docker 把 Hermes 跑起来、配好模型和密钥，但从那以后你可能一直有个疑问：**Hermes 到底带了多少工具？我想让它搜网页、跑命令、开浏览器，它们默认开着吗？在哪里开关？**

这正是本册要解决的问题。这一章先建立全局地图：tool 是什么、和 skill 有什么区别、内置工具体系长什么样、配置分散在哪些入口，以及 Docker 场景下你真正需要动手改哪几个文件。看完你会清楚一件事：**要配一个工具，应该去改 `config.yaml`、写 `.env`，还是跑 `hermes tools`。** 后续章节都是在这张地图上逐块展开：

- **第 2 章**：内置工具与 toolsets 全解，重点讲 terminal 后端与 Docker；
- **第 3 章**：Nous Portal Tool Gateway 接入与审批权限；
- **第 4 章**：自定义工具开发与注册；
- **第 5 章**：MCP 服务器接入与排错；
- **第 6 章**：Skills 与工具关系收束、安全基线。

所以第 1 章是最值得认真读的一章——它是后面所有操作的地基。

## 1.1 tool 是什么：可执行能力，与 skill 程序性知识的边界

先厘清最容易被混的两个词：tool 和 skill。它们都会被模型"使用"，但本质完全不同。

- **tool 是「一段可执行的能力」**。它注册在 Hermes 的工具注册表里，是一个有明确输入输出的函数。模型判断"需要搜网页"，就调用 `web_search`；需要跑命令，就调用 `terminal`。工具由 Hermes 核心、插件或 MCP 服务器实现，返回结构化结果（通常是 JSON 字符串）。（来源 S1）
- **skill 是「一份程序性知识的文档」**。它是一个 SKILL.md 文件，用自然语言写清楚"完成某类任务的具体步骤"。模型不是直接调用 skill，而是把这份文档读进上下文，照着步骤用**现有的工具**去执行。skills 记录的是 how-to，本身不产生新能力。（来源 S6, S9）

一个直觉的区分：tool 提供"能力"，skill 提供"方法"。Docker 管理、git 提交流程这类事，用 `terminal` 工具就能表达，所以做成 skill（教你一步步怎么跑命令）；而浏览器自动化、TTS 这类需要端到端鉴权、处理二进制或流式数据的能力，现有工具表达不了，才值得做成新 tool。（来源 S6）

举个对比：**arXiv 论文下载**做成 skill 就够——它本质是"用 `terminal` 跑 `git clone`/`curl`，再用 `read_file` 看结果"，模型照着步骤走就能完成；但 **Browserbase 云浏览器**必须做成 tool——它需要端到端 API key、管理远程浏览器会话、处理实时页面快照，这些逻辑无法靠几行指令稳定复现，必须封装成一个精确执行的函数。（来源 S6）

> [!warning] 易错点
> 判断"该写 skill 还是 tool"时，官方贡献指南的优先级很明确：**多数能力应该做成 skill，新 tool rarely needed**。先问"这事能不能用指令 + shell + 现有工具表达"，能就别造新工具——自定义 tool 意味着你要写注册表、维护 handler、跟进工具命名规范，成本高一个数量级。这个决策流程会在第 4 章完整展开。

> [!tip] 大白话
> 把 tool 想成**临时工**：你招它来"搜一下""跑个命令"，它干完活交结果就走，活是它亲手干的。把 skill 想成**操作手册**：手册自己不干活，它写着"第一步查资料、第二步写方案、第三步自测"，模型照着手册一步步调派临时工。临时工解决"能做吗"，手册解决"该怎么做"。

本册与《上手实战》第 5 章《技能体系》分工明确：第 5 章讲 skill 是什么、SKILL.md 生命周期、怎么写怎么测；本册专讲 tool 怎么配、怎么接。两者的边界会在第 6 章再收束一次。需要复习 skill 概念时，回到 [[Hermes Agent 上手实战/05-技能体系|第 5 章《技能体系》]] 即可，本册不重复其正文。

## 1.2 内置工具体系速览：约 86 个工具与 toolset 分组

Hermes 内置约 86 个工具，可用性随平台、凭据、启用的 toolset 变化（来源 S2）。这么多工具不能平铺直叙，它们按**逻辑 toolset（工具集）**分组，方便你按需成组开关。常用 toolset 包括（来源 S1）：

`web`、`search`、`terminal`、`file`、`browser`、`vision`、`image_gen`、`skills`、`tts`、`todo`、`memory`、`session_search`、`cronjob`、`code_execution`、`delegation`、`clarify`、`homeassistant`、`messaging`、`spotify`、`discord`、`discord_admin`、`debugging`、`safe`

从类别看，这 86 个工具大致落在九个功能区（来源 S1）：

| 类别 | 代表工具 | 干什么 |
| --- | --- | --- |
| Web | `web_search`, `web_extract` | 搜索网页、抓取页面正文 |
| X Search | `x_search` | 搜索 X（Twitter）帖子，默认关闭，需 xAI 凭据 |
| Terminal & Files | `terminal`, `process`, `read_file`, `patch` | 执行命令、管理进程、读写文件 |
| Browser | `browser_navigate`, `browser_snapshot`, `browser_vision` | 交互式浏览器自动化，含视觉 |
| Media | `vision_analyze`, `image_generate`, `text_to_speech` | 多模态分析与生成 |
| Agent 编排 | `todo`, `clarify`, `execute_code`, `delegate_task` | 规划、澄清、执行代码、子代理委派 |
| Memory & recall | `memory`, `session_search` | 持久记忆与会话搜索 |
| Automation | `cronjob` | 定时任务 |
| Integrations | `ha_*`, MCP 工具 | Home Assistant 与 MCP 集成 |

三个值得注意的动态来源：

- **平台预设 toolset**：如 `hermes-cli`、`hermes-telegram`，`hermes tools` 会按你当前平台给出预选项。
- **MCP 动态 toolset**：接入的 MCP 服务器只要贡献至少一个工具，就自动生成 `mcp-<server>` 这个 runtime toolset，工具命名形如 `mcp__<server>__<tool>`。（来源 S1, S4）
- **凭据门控**：有些工具（如 `x_search`）只有配好对应凭据才会出现在模型面前，也就是 check_fn 门控。默认关闭的 `x_search`，在 `hermes tools` 里选中 "X (Twitter) Search" 项开启。（来源 S1, S2）

这两点直接决定了你看到的工具列表：同样是 `hermes tools`，在 CLI 平台、Telegram 网关、桌面上列出的预设不同；同一个 `web_search`，装了 EXA 的 key 和装了 Tavily 的 key，背后走的 provider 不同但模型侧看到的工具名一样。所以排查"工具不出现"时，先别急着怀疑配置，按顺序看：**是否在当前平台预设里 → 是否被 `--toolsets` 或 `disabled_toolsets` 挡住 → 是否缺了对应凭据**。这三问能解决绝大多数"工具消失"问题。（来源 S1, S2）

> [!tip] 大白话
> 把 toolset 想成**工具箱**：`web` 是一个箱子，里面装着搜网页、抓正文几样工具；`file` 是另一个箱子，装着读文件、改文件。你按需把整个箱子提给模型用，而不是一个工具一个工具地登记。箱子还能被平台预设（CLI 一套、Telegram 一套）和 MCP 服务器（接一个服务器多一个箱子）动态扩展。

## 1.3 三层配置入口：config.yaml（行为）/ .env（密钥）/ 运行时选择

配工具不只有一种姿势。Hermes 的所有设置都集中在 `~/.hermes/` 目录，工具相关配置分散在**三层**（来源 S5, S11）：

1. **`~/.hermes/config.yaml`** —— 非机密的行为配置。terminal 后端、toolset 开关、输出截断、`agent.disabled_toolsets` 等都在这里。
2. **`~/.hermes/.env`** —— 密钥。API key、bot token、OAuth secret、SSH 凭据。官方约定"用户管理的机密只进这里"。
3. **运行时选择** —— `hermes tools` 交互式开关、`hermes chat --toolsets "..."` 临时指定、`hermes config set` 命令行写入。它们最终落盘到前两层，但提供了不手动编辑 YAML 的路径。

关键规则：**`config.yaml` 优先于 `.env`**。整体解析顺序是：CLI 参数 > `config.yaml` > `.env` > 内置默认。也就是说，同一个非机密设置如果两处都写了，config.yaml 的值生效；`.env` 主要承担"config.yaml 里没有对应键"的回落，以及机密的唯一居所。（来源 S11）

`hermes config set` 是个省心入口：它会自动判断值该进哪个文件——API key 存进 `.env`，其余写进 `config.yaml`（来源 S11）。配套命令还有 `hermes config get KEY` 读值、`hermes config unset KEY` 删值、`hermes config edit` 打开编辑器、`hermes config check` 检查缺失项（来源 S11）。

那么实际配一个工具时该从哪层下手？给一个简化的决策流程：

- **要的是"行为开关"**（开哪个 toolset、切后端、调超时）→ 优先 `hermes tools`（有交互界面，不记键名）或 `hermes config set`（写一行命令）。
- **要的是"密钥"**（EXA/FAL/OpenAI key、SSH 凭据、bot token）→ 写 `~/.hermes/.env`，或 `hermes config set` 让它自动落盘 `.env`。
- **要的是"本次会话临时变通"**（这轮想多带几个工具、不想污染持久配置）→ `hermes chat --toolsets "..."`。
- **要的是"全局一票否决"**（某工具任何平台都不许用）→ `agent.disabled_toolsets`。

> [!tip] 大白话
> 把 config.yaml 想成**设置面板**（所有开关和参数），`.env` 想成**保险箱**（只放钥匙和密码），`hermes tools` 想成**遥控器**（对着面板按开关，改完自动写回面板）。规矩是：面板上有的，以面板为准；面板上没有的，才去保险箱找。`hermes config set` 则是一个智能管家——你把值丢给它，它自己决定是送面板还是送保险箱。

> [!warning] 易错点
> 不要图省事把 API key 写进 config.yaml。密钥只放 `~/.hermes/.env`（或经 `hermes config set` 自动落盘）。config.yaml 常被备份、进日志、给脚本读取，把密钥放进去等于把保险箱钥匙贴在大门上。

## 1.4 实操：启用与禁用 toolset

工具默认不全开。下面按「交互 → 临时 → 持久 → 全局禁用」四种粒度走一遍。

### 交互式：`hermes tools` 逐项开关（按平台预设）

`hermes tools` 是交互式配置入口，列出所有可用 toolset，按当前平台预设逐项开关，改动落盘到 config.yaml 的 `platform_toolsets`（不同平台各自保存一份）：

```bash
hermes tools      # 交互式列出/开关各 toolset（按平台）
```

需要 xAI 凭据的 `x_search` 默认关，就在这个界面里开启。（来源 S1）

界面里每个 toolset 会显示当前开/关状态；改完直接落盘到 `platform_toolsets`，不需要再手动编辑 YAML。开完可以顺手 `hermes config get terminal.backend` 这类命令验证值已经写进去。（来源 S11）

### 临时：`hermes chat --toolsets "web,terminal,file"`

不想改配置、只对当前这次会话生效，用 `--toolsets` 传一个逗号分隔列表：

```bash
hermes chat --toolsets "web,terminal,file"
```

这是最高优先级的 CLI 参数（排在 config.yaml 之上），只影响这一次调用，会话结束即回到配置状态。（来源 S1）

> [!warning] 易错点
> `--toolsets` 是"临时工模式"：这次会话开完就结束，不会写进 config.yaml。如果你在 `hermes tools` 里明明开了 terminal，却发现下次启动又没了，先确认是不是每次都用 `--toolsets` 覆盖了持久配置。

### 持久：`hermes config set` 与全局 `agent.disabled_toolsets`

长期有效有两个方向。

**开（按配置键写值）**：`hermes config set` 直接把值写进 config.yaml。比如把 terminal 后端切到 docker：

```bash
hermes config set terminal.backend docker
hermes config set terminal.timeout 180
```

配置文件里等价于：

```yaml
# ~/.hermes/config.yaml
terminal:
  backend: docker    # local | docker | ssh | singularity | modal | daytona | vercel_sandbox
  timeout: 180       # 单条命令超时（秒）
```

**关（全局禁用某个 toolset）**：`hermes tools` 的开关按平台分别保存，但如果想"无论哪个平台、任何配置都彻底不用某几个 toolset"，用 `agent.disabled_toolsets`：

```yaml
# ~/.hermes/config.yaml
agent:
  disabled_toolsets:
    - memory       # 隐藏 memory 工具 + MEMORY_GUIDANCE 注入
    - web          # 任何平台都没有 web_search / web_extract
```

它**在 `platform_toolsets` 之后生效**——即使某平台的保存配置里仍列着 `web`，只要出现在这里就一定会被移除。空列表或省略该键等于不启用。（来源 S11）

> [!tip] 大白话
> `hermes tools` 是按平台分别记的"各屋的电灯开关"；`agent.disabled_toolsets` 是"总电闸"。哪怕某个屋子的开关还开着，总闸一拉，全屋断电。想把某个工具"在世界范围内禁掉"，拉总闸最省事，不用去 15 个平台的开关面板逐个关。

> [!example] 一个完整示例
> 假设你希望 Hermes 能搜网页、能跑命令、能读写文件，但绝对不许动记忆和定时任务：
>
> ```bash
> hermes tools                                    # 交互里开启 web、terminal、file（按平台）
> hermes chat --toolsets "web,terminal,file"     # 本次会话立即生效
> ```
>
> 同时把 `agent.disabled_toolsets` 配成 `[memory, cronjob]`，就能保证任何平台都不会出现这两类工具。

## 1.5 Docker 场景：配置文件落在哪（宿主机 `~/.hermes` 挂载视角）

如果你照《上手实战》第 2 章用 Docker 跑 Hermes，容器用 `-v ~/.hermes:/opt/data` 挂载了数据卷，那么**宿主机 `~/.hermes/` 与容器内 `/opt/data/` 是同一个目录**。容器内的 Hermes 实际读的就是你宿主机上的文件：

```text
宿主机 ~/.hermes/         容器内 /opt/data/
├── config.yaml      ←→   /opt/data/config.yaml
├── .env             ←→   /opt/data/.env
├── auth.json        ←→   /opt/data/auth.json
├── SOUL.md          ←→   /opt/data/SOUL.md
├── memories/        ←→   /opt/data/memories/
├── skills/          ←→   /opt/data/skills/
├── cron/            ←→   /opt/data/cron/
├── sessions/        ←→   /opt/data/sessions/
└── logs/            ←→   /opt/data/logs/   （errors.log、gateway.log）
```

（目录结构见来源 S11。）

这对配工具有一个直接推论：**所有工具配置都在宿主机上改，改完即对容器内生效，不需要进容器。** 官方 Docker 镜像默认把 `HERMES_HOME=/opt/data` 与 `HERMES_WRITE_SAFE_ROOT=/opt/data` 一起设置，让 agent 无法逃出挂载的数据卷（来源 S5）。所以你只需要在宿主机编辑 `~/.hermes/config.yaml` 和 `~/.hermes/.env`，或在本机装有 CLI 时跑 `hermes` 命令完成写入。

> [!warning] 易错点
> 别 `docker exec` 进容器去改 `/opt/data/config.yaml`——它和宿主机 `~/.hermes/config.yaml` 是同一份文件，改了等于改宿主机那份，只是多绕一层路。反过来，如果你改了宿主机 config.yaml 而容器内不生效，先检查挂载参数是不是 `-v ~/.hermes:/opt/data`、路径有没有写错。

> [!tip] 大白话
> 把挂载想成**同一张写字台从两面看**：宿主机这面写着 `~/.hermes`，容器那面写着 `/opt/data`，但桌子只有一张。你不需要进容器"再从抽屉里拿文件"，在宿主机这面改，容器那面看到的就是改完的样子。

## 1.6 版本锚定与排错入口：hermes doctor 与 errors.log

配置文档和实际行为会随版本漂移，本册所有键名、默认值锚定 **v0.20.x**（本文撰写时最新补丁为 v0.20.6）。你在自己机器上排查时，一切以 `hermes doctor` 的输出为准——它逐项检查配置、依赖与后端可用性，是判断"某个工具为什么没起来"的第一站（来源 S11）。

一个典型例子是 tool-call 迭代上限：每次对话里模型最多能连续调用多少次工具的**迭代预算**由 `HERMES_MAX_ITERATIONS` 控制，**默认 500**。这是 v0.20.0 "The Herald Release" 起从 **90 提升到 500** 的结果——长自主运行任务不再被 90 圈的上限早早卡死（来源 S5, S8）。

```bash
hermes doctor            # 检查配置/依赖/后端，以其输出为准
# 排错时再看日志
# ~/.hermes/logs/errors.log    # 运行期错误，密钥自动打码
```

`.env` 里设置（默认已是 500，一般无需改）：

```bash
# ~/.hermes/.env
HERMES_MAX_ITERATIONS=500
```

日志目录 `~/.hermes/logs/` 下的 `errors.log` 记录运行期错误，且自动对密钥打码（来源 S11）。遇到"工具不出现""后端连不上""权限被拒"，排查顺序总是：`hermes doctor` 查配置 → `errors.log` 看报错 → 回到本章三层入口核对值写没写对地方。

举个例子：你配好了 `terminal.backend: docker`，但模型每次跑命令都报"terminal tool disabled"。此时不要先去翻 config.yaml——先跑 `hermes doctor`，它会直接告诉你 Docker 后端缺什么（比如 Docker daemon 没起来，或本地没装 docker）。如果 doctor 显示一切正常而 terminal 仍不可用，再去 `errors.log` 里 grep `terminal` 看运行期真实报错，最后回头确认是不是被 `agent.disabled_toolsets` 或某个平台的保存配置移除了。这个"先 doctor、再日志、最后核对入口"的顺序，后面每一章排错都会复用。

> [!warning] 易错点
> `HERMES_MAX_ITERATIONS` 是"每次对话的 tool-call 迭代预算"，不是"总 token 预算"，也不是某个具体工具的配额。设太小时复杂任务会在没干完前被叫停；设太大时一个失控循环会烧掉大量 API 调用。默认 500 适合绝大多数场景，改前先想清楚。

## 本章小结

- tool 是「可执行能力」（注册的函数），skill 是「程序性知识文档」（SKILL.md 教模型怎么做）；本册专讲前者，skill 生命周期见 [[Hermes Agent 上手实战/05-技能体系|第 5 章《技能体系》]]。
- Hermes 内置约 86 个工具，按 toolset 分组（web、terminal、file、browser 等）；平台预设与 MCP 服务器会动态增减 toolset。
- 配置分三层：config.yaml 管非机密行为、`.env` 管密钥、`hermes tools` / `--toolsets` / `hermes config set` 管运行时选择；**config.yaml 优先于 `.env`**。
- 开关 toolset 四粒度：`hermes tools` 交互持久、`--toolsets` 临时、`hermes config set` 写配置键持久、`agent.disabled_toolsets` 全局强制移除。
- Docker 场景下宿主机 `~/.hermes/` 与容器 `/opt/data/` 是同一目录，配工具只在宿主机改 config.yaml 与 .env。
- 本册锚定 v0.20.x；`HERMES_MAX_ITERATIONS` 默认 500（v0.20.0 起 90→500）；排错先 `hermes doctor`，再看 `~/.hermes/logs/errors.log`。
