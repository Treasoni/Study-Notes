# 第五章：常见坑与速查

最后一章作为日常速查：坑清单、命令速查、DeepSeek V4 协议坑、生态资源与下一步。

## 5.1 坑清单

| 类别 | 坑 | 处理 |
|---|---|---|
| 安装 | Web 端口被占 | `dsh web --port <空闲端口>` |
| 安装 | npm peer 冲突（ERESOLVE） | 加 `--legacy-peer-deps` |
| 安装 | Windows 多插件重复注册 `ctx.bash` | 报 "service bash has been registered" 启动失败，避免重复注册 |
| 配置 | `MISSING_CREDENTIAL` | 未配 key，检查凭据解析顺序 |
| 配置 | `UNKNOWN_MODEL` | 模型未配置，检查 provider models |
| 配置 | 模型发现返回 401 | 检查 key；发现逻辑调 OpenAI 兼容 `GET /models` |
| 升级 | developer preview 破坏性变更 | 升级前留意 README 变更 |
| 生态 | 同名第三方包 | 认准 `@deepseek-ai/dsh` 与 `deepseek-harness-sdk` |

## 5.2 命令速查表

| 命令 | 用途 |
|---|---|
| `dsh web` | 启动 Web UI（`--profile web` 硬编码别名） |
| `dsh web --port <端口>` | 端口被占时换端口 |
| `dsh --profile headless "任务"` | 一次性任务，退出码 0/1，适合 CI |
| `dsh plugin --profile <name> add <package>` | 安装插件 |
| `dsh --profile web --dump-config` | 打印合成配置，排查用 |
| `dsh --help` / `-V` / `--version` | 帮助/版本 |

**launcher 规则**：标志必须在 app 参数之前；launcher 解析器消费一个 `--`（app 参数要字面 `--` 需写 `-- --`）；launcher 标志在第一个无法识别的 token 处结束。[1]

**热重载与关闭**：profile 启动时监听 profile 与 home 两个 `cordis.patch.yml` 的编辑并事务性重放；进程关闭给插件树最多 5 秒清理，首个 SIGINT/SIGTERM 触发优雅排空（SIGTERM 退出码 0，SIGINT 报 130），第二个信号强制立即退出。

## 5.3 DeepSeek V4 协议坑

（第三方整理，迁移时规避）：[1]

- **thinking 默认开启**，会烧 token；
- 多轮对话必须回传 `reasoning_content`，否则 HTTP 400；
- 必须设 `max_tokens`（否则 reasoning 流可达 26KB/84s 撑爆客户端）；
- thinking 模式下 `tool_choice` 只能 `auto`。

> **大白话**：V4 的 thinking 像「默认开了录音」——每次都先烧一段思考 token；多轮对话不把上次的思考笔记还回去，服务端就直接拒绝（HTTP 400）。
