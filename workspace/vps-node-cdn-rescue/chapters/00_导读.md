# 导读：节点被墙之后，还有第二条路

节点不通时，最容易想到的动作是「换 IP」。但如果问题不在 IP，换 IP 只是把同一件事重来一遍。这篇讲的是另一条路：把节点藏到 CDN 后面，让封锁方「看得见」的目标不再是你服务器的地址（据视频章节推断，视频 9:22 起讨论被墙风险，10:00 起讨论加速问题）。

这是一篇**深水区**笔记。它的前提是你已经有一个能跑通的自建节点；它要回答的不是「怎么装面板、怎么建节点」，而是「CDN 凭什么能救被墙节点、代价是什么、边界在哪」。

> [!note] 关于主来源视频
> 本篇的写作主线取自一期视频的章节骨架（CDN 是什么 → 获取 CDN → 解析域名 → 安装面板 → 搭建节点 → 被墙风险 → 加速问题）。该视频**无字幕**（已两次独立核验），因此凡涉及视频口播的判断，正文一律写「据视频章节推断」，不伪装成视频原话；所有可核验的事实性内容，一律以 Cloudflare / Xray / 3x-ui 官方文档与一手论文为准（来源：00_intent.md | 主来源）。

## 0.1 三个场景先分清

在动手之前，先把「不通」拆成三种互不相同的处境，因为它们的解法不一样：

1. **IP 被墙**：你的服务器 IP 本身在封锁名单里，请求发出去就被丢。此时换 IP 有效，套 CDN 也可能有效。
2. **域名被污染**：域名解析被投毒，查询根本返回不到 Cloudflare。这种情形下，套 CDN 救不了你（详见第二章 2.5）。
3. **只是配错了**：域名、代理状态、端口、TLS 模式、WebSocket 任一层填错。这与封锁无关，属于配置问题，靠第六章的报错码速查。

这三类的判别方法本身**没有官方标准**，Cloudflare / Xray / 3x-ui 官方均未给出节点被墙的判定流程；可用的只是分类排除的经验方法（来源：02_deep_research.md | §四-缺口 1）。

### 本章小结

- 不通分三种：IP 被墙、域名被污染、配置填错；三者解法不同（来源：00_intent.md | 差异化定位表）。
- 节点被墙的判定无官方方法，本篇只写分类排除的经验方法（来源：02_deep_research.md | §四-缺口 1）。
- 本篇不复述装面板、建节点与域名解析填法，只补 CDN 的原理、约束与排错（来源：00_intent.md | 差异化定位表）。
- 主来源视频无字幕，视频结论一律标注「据视频章节推断」，事实以官方文档为准（来源：00_intent.md | 主来源）。
