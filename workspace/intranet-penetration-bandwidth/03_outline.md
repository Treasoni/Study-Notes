## 第一章：内网穿透的带宽从哪来——P2P 直连 vs 服务器中转

- **篇幅**：中
- **覆盖要点**：两类架构（P2P/中继）决定带宽来源、Mbps 与吞吐量/上行/下行概念、商业套餐两种计费模型、上行带宽是隐形瓶颈
- **素材引用**：#S06, #S02, #S03, #G02, #G07, #S05, #G01
- **代码示例**：无（纯概念）

### 1.1 两类架构决定带宽来源
- P2P（NAT 打洞）：节点间直连，流量不经过厂商服务器；带宽上限 = 两端物理链路 + 两端 CPU/加解密能力（S06）
- 中继（Relay）：流量经服务器转发；带宽上限 = 中转服务器带宽/线路 + 限速策略 + 两端物理链路（S02/S03/G02）
- 量化差距：RustDesk 实测 P2P 直连可达 850Mbps，服务器中继受限于家宽上行（典型 30Mbps）；打洞失败自动回退中继

### 1.2 理解 Mbps：带宽、吞吐量、上行与下行
- 为什么商业套餐用固定 Mbps 标注（每映射固定带宽 + 映射数 + 并发数，S05）
- 穿透流量大量消耗**本端上行**；家庭宽带下行 100-1000Mbps 但上行常仅 30-50Mbps，国内有运营商限速到 5Mbps 的报道（S02/G07）

### 1.3 商业套餐的两种计费模型
- 带宽包：稳定低速、不限流量（花生壳 2/3/5/7 Mbps，S05）
- 流量包：不限速、按量计费（ngrok 免费 1GB/月、超额 $0.10/GB，G01）
- 两种模型如何影响"某个带宽能干什么"的判断

## 第二章：固定带宽套餐能干什么——2/4/8（及 2/3/5/7）Mbps 场景对照

- **篇幅**：长
- **覆盖要点**：场景带宽需求总表、2Mbps/4Mbps/8Mbps 分别能跑什么场景、国内 2/3/5/7 档位映射、延迟对体验的影响
- **素材引用**：#S04, #G03, #G04, #G02, #S05
- **代码示例**：无（表格为主）

### 2.1 各场景带宽需求总表
- 总表：场景 | 推荐带宽 | 来源 | 2Mbps | 4Mbps | 8Mbps
  - 远程桌面轻量 1.5 / 中度 3 / 重度 5 / 4K 15（S04）
  - 视频会议 720p 1.2-2.6 / 1080p 3.8 / 1080p60 12.8（G03）
  - 网页/API <1、NAS 文件传输 ≥5（G02）、1080p 串流 ≈6-15、4K 串流 ≥25（G04）、纯语音 60-100kbps（G03）
- 表内数字前提：30fps、丢包 <0.1%（S04）

### 2.2 2 Mbps 能干什么
- ✅ 轻量远程桌面（文字/办公 1.5Mbps）、网页浏览/API、纯语音通话
- ⚠️ 中度远程桌面（3Mbps）勉强；❌ 重度远程桌面、1080p 会议、NAS 大文件

### 2.3 4 Mbps 能干什么
- ✅ 中度远程桌面（3Mbps）、720p 会议（2.6Mbps）
- ⚠️ 重度远程桌面（5Mbps）、1080p 会议（3.8Mbps）勉强
- ❌ 4K 远程桌面、1080p60 会议（12.8Mbps）、4K 串流

### 2.4 8 Mbps 能干什么
- ✅ 重度远程桌面/1080p、1080p 会议、轻度文件传输
- ⚠️ 1080p60（12.8）、4K 远程桌面（15）、NAS 大文件仍偏慢
- ❌ 4K 媒体串流（≥25Mbps）

### 2.5 国内 2/3/5/7 Mbps 档位怎么对应
- 花生壳实际档位：测试号 3Mbps / 专业 2Mbps / 商业 3Mbps / 旗舰 5Mbps / 铂金 7Mbps（S05）
- "4/8" 并非国内主流档位；结论是**档位因厂商而异，评估方法一致**

### 2.6 别忘了延迟：带宽够 ≠ 体验好
- 远程桌面对 RTT 敏感（RTT ≤20ms 为辅助技术目标，S04）
- 延迟、丢包对远程桌面/串流体验的影响大于带宽本身

## 第三章：ZeroTier / Tailscale 的带宽怎么看——直连、中继与实测

- **篇幅**：中
- **覆盖要点**：为什么这类方案没有套餐带宽数字、直连 vs 中继（DERP/root）带宽来源差异、用户态 vs 内核态实测差距、如何判断走直连还是中继
- **素材引用**：#S06, #S02, #S03, #S07, #G05, #G06
- **代码示例**：有（`tailscale ping` 判断 via DERP）

### 3.1 为什么这类方案没有套餐带宽数字
- ZeroTier 官方：直连不限速、不能读加密包内容，速度取决于两端 CPU 与加解密能力（S06）
- 免费版限制：ZeroTier 免费 10 设备/1 网络、Tailscale Personal 6 用户/不限设备；各档均无带宽上限声明（G05/G06）
- 结论：带宽评估 = 实测，不是看套餐页

### 3.2 直连与中继：带宽来源完全不同
- Tailscale DERP：共享 TCP 中继（TLS/443），fair usage 限速吞吐；丢包时 TCP 重传延迟比纯 UDP 更糟（S03）
- 实测数字：跨洋（印度→美国）共享 DERP ~2.2 Mbps，启用自建 peer relay 后 27-35 Mbps（约 12.5 倍），延迟 452ms→298ms（S02）
- ZeroTier root 中继：只增加延迟、官方声明不限速（暂无量化限速数据，S06）

### 3.3 用户态 vs 内核态：实测吞吐差距
- 同一千兆交换链路：直连 754 / Netmaker（内核 WireGuard）852 / ZeroTier 546 / Tailscale 268 Mbps（S07）
- Tailscale 低吞吐来自 userspace 实现 + 重传，并非中继限速（S07）

### 3.4 怎么"看"自家带宽
- `tailscale ping <节点>` 输出是否 `via DERP` → 判断走直连还是中继（S02）
- 结合 iPerf3 端到端实测（详见第四章）

## 第四章：实战——用 iPerf3 测自家隧道带宽并选型

- **篇幅**：长
- **覆盖要点**：iPerf3 测速配方与关键参数、判断直连/中继、测速结果对照场景表、按自家场景的选型决策流程
- **素材引用**：#S01, #S07, #S02, #G02
- **代码示例**：有（iperf3 服务端/上行/下行/UDP 命令、tailscale ping）

### 4.1 iPerf3 测速配方
- 四组命令：服务端启动、上行（-P 4）、下行（-R -P 4）、UDP 丢包/抖动（-u -b 20M）（S01）
- 关键参数：`-P` 多流（仅 CPU 受限场景提升）、`-R` 反向、`-b` UDP 必须显式、`-O` 跳过 TCP 慢启动、`-t` ≥30s、默认端口 5201（S01）

### 4.2 判断走直连还是中继
- `tailscale ping` 是否 `via DERP`；ZeroTier 走 root 的观察方式（S02）
- 测速结果与第二章场景表对照：远程桌面看单流（`-P 1`）结果（S07/S02）

### 4.3 按自家场景选型
- 先测家宽上行（speedtest/iPerf3）——穿透流量大部分消耗本端上行（G07）
- 决策流程：明确场景需求 → 实测隧道吞吐 → 判断够用 → 选商业固定带宽 or 免费 P2P/自建方案
- 参考阈值：2Mbps≈轻量办公、4Mbps≈中度远程桌面/720p、8Mbps≈重度远程桌面/1080p；4K 串流/NAS 大文件需 ≥15-25Mbps 或自建

## 第五章：常见坑、FAQ 与进阶方向

- **篇幅**：中
- **覆盖要点**：五个常见坑（回退中继/上行受限/用户态加密/套餐带宽虚标/TCP 中继拥塞）、FAQ、进阶资源
- **素材引用**：#S02, #S03, #G07, #G02, #S07
- **代码示例**：无

### 5.1 常见坑
- 打洞失败回退中继：对称 NAT/CGNAT 破坏 UDP 打洞 → 自动走 DERP/root → 带宽断崖（S02）
- 家庭宽带上行被限：千兆下行但上行 30-50Mbps 甚至 5Mbps（G07）
- 用户态加密开销：Tailscale 直连 268Mbps 低于内核态 852Mbps（S07）
- 商业套餐"带宽"≠实际吞吐：共享带宽、QoS、单线程限制拉低（G02）
- TCP 中继拥塞：DERP 跨洋 2.2Mbps，丢包时重传惩罚；frp 需调大 TCP 窗口/缓冲（S02/S03/G02）

### 5.2 FAQ
- 为什么我买的 8Mbps 套餐跑不到 8Mbps？
- ZeroTier 和 Tailscale 谁更快？
- 4K 串流 / NAS 大文件传输到底要多少带宽？
- 打洞失败、带宽骤降怎么办？

### 5.3 进阶方向
- 自建 Moon / DERP / peer relay 节点缓解中继瓶颈（S02）
- MTU 调优、多线程传输、frp TCP 窗口/缓冲调优（G02）

## 学习路径说明

### 前置要求
- 了解内网穿透大概原理，对 NAT、公网 IP、端口映射有概念（用户已具备）
- 有一台可作为隧道服务端的设备（NAS / 旧电脑 / 云服务器）更佳，便于动手实测
- 会用命令行（Windows CMD/PowerShell 或 Linux 终端），能运行 iperf3 命令

### 学完能做什么
- 能解释内网穿透的带宽来自哪里（P2P 直连 vs 服务器中转），以及为什么商业套餐按固定 Mbps 卖
- 能根据场景判断 2/4/8（及 2/3/5/7）Mbps 各能跑什么、不够时缺多少
- 能看懂 ZeroTier/Tailscale 为什么没有套餐带宽，并用 `tailscale ping` + iPerf3 实测自家隧道带宽，判断是直连还是中继
- 能根据自家场景（远程桌面/文件/串流/会议）选择商业套餐或免费 P2P 方案，并知道常见瓶颈怎么排查

### 建议学习顺序
- 第 1 → 2 章：先建立"带宽从哪来"的概念，再看"某个数字能干什么"（约 40-60 分钟阅读）
- 第 3 章：理解 ZeroTier/Tailscale 的带宽评估逻辑（约 20-30 分钟）
- 第 4 章：动手实测自家隧道，边测边对照第二章场景表（约 30-45 分钟，需两端设备）
- 第 5 章：排错与 FAQ，遇到问题时可随时回查（约 20 分钟）
- 总计约 2-3 小时（含动手实测）
