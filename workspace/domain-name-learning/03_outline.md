### 第一章：域名与 DNS 原理——从「电话簿」到一次完整解析

- **篇幅**：长
- **覆盖要点**：域名层级、DNS 四类服务器与递归/迭代、缓存跳步、记录类型速查表、CNAME 根域限制与泛解析坑、TTL 与传播真相、IDN/中文域名简介、dig 基础用法
- **素材引用**：A1, A2, A3, A4, A5, A6
- **代码示例**：有（`dig` 系列命令）

小节结构与写作要点：

- **1.1 域名是什么与层级**：点分标号序列，`.com`=TLD、`aliyun.com`=二级/主域、`www.aliyun.com`=三级/子域（A3/A4）
- **1.2 DNS 是什么**：域名↔IP 的分布式电话簿；公网/内网、权威/递归两类角色划分（A2/A4）
- **1.3 一次未缓存的解析**：递归解析器 → 根 → TLD → 权威四类服务器与典型 8 步；「未缓存 / 缓存命中」两条路径画成流程图并列说明（A2/A4；呼应冲突表「先查根 vs 缓存可跳步」）
- **1.4 TTL、各级缓存与「DNS 传播」真相**：TTL 即缓存刷新间隔；传播≠全球同步，而是缓存按 TTL 过期；标注「秒级生效」属商业宣传，给通用经验值「数小时到数天」（A1/A4/A5）
- **1.5 记录类型速查表与两个经典坑**：A/AAAA/CNAME/MX/TXT/NS/SOA/SRV/PTR/CAA 一览；**CNAME 不能用于根域/apex**、根域要 CNAME 效果用 ALIAS/ANAME；主机记录 `@`=主域、`*`=泛解析及其风险（A1/A4）
- **1.6 用 dig 看一次真实解析**：`dig example.com`、`dig +trace` 走完根→TLD→权威整条委托链、`dig @1.1.1.1`、RCODE 含义（NOERROR/NXDOMAIN/SERVFAIL/REFUSED）（A6）
- **1.7 IDN/中文域名简介**：Punycode/A-label、通用接受 UA 是现实障碍；Punycode 编码细节与同形攻击属开放问题，浅覆盖即可（A3）

### 第三章：实名与 ICP 备案——大陆上线的硬门槛

- **篇幅**：中
- **覆盖要点**：备案判定（源站物理位置）、实名认证与四要素、Serverhold、备案硬性前置（批复后缀/到期>45 天）、大陆备案流程与接入备案、境外免备案对照
- **素材引用**：B1, B2, B3, C10
- **代码示例**：无（流程性内容，可给材料清单而非命令）

小节结构与写作要点：

- **3.1 先判场景：要不要备案**：备案看**源站服务器物理位置**而非域名注册地/前端 CDN；解析到大陆服务器必须备案，放境外服务器免备案（B2；呼应写作要点第 1 条）
- **3.2 域名实名认证**：个人=身份证彩色件、企业=营业执照且联系人填个人；实名四要素须与备案主体一致；实名失败会进 **Serverhold（暂停解析）**，通过后约 48h 恢复（B3）
- **3.3 备案前置条件清单**：后缀须工信部批复、注册商须为批复机构、主域到期须 **>45 天**、实名信息一致；阿里云国际站域名须转入内地注册商并实名（B1）
- **3.4 大陆备案流程概览**：非经营性备案制 vs 经营性 ICP 证；只备主域名、子域免额外备案；换接入商需「接入备案」；阿里云代备案不支持 IP 备案（B1/B2）
- **3.5 不备案的路径：境外部署对照**：海外/香港服务器免备案，代价是大陆访问延迟与 QoS 波动（C10/C11 交叉，简述、详述在第 7 章）
- **3.6 「套 CDN 免备案」误区提示**：大陆源站套境外 CDN 仍触碰政策红线——一句话给结论，细节放第 7 章合规速查（C10）

### 第四章：解析托管、NS 委派与域名安全

- **篇幅**：中
- **覆盖要点**：注册商与解析商分离、切 NS 托管、子域 NS 委派、改动生效排查（dig 三步 + TTL 调低）、域名转移规则、安全基线（MFA/禁止转移锁/注册局锁/DNSSEC）
- **素材引用**：A4, A6, B4, B5, B6, B9
- **代码示例**：有（`dig`/`nslookup` 排查命令）

小节结构与写作要点：

- **4.1 域名与解析分离**：域名留在注册商 A、DNS 托管交给 B（Cloudflare/DNSPod/阿里云）是常态；各自职责边界（A4/B4）
- **4.2 切换解析托管与子域委派**：改 NS 到目标解析商的步骤；子域可加 **NS 记录独立委派**到另一解析商，用 TXT 记录做归属校验；子域解析优先于主域同名记录、子域不支持 URL 转发（B4）
- **4.3 改动生效排查（动手验证）**：**上线前先把 TTL 调低（如 60s）**；改完用 `dig @1.1.1.1` 与默认对比判断「本地缓存旧 vs 真没生效」、`dig +trace` 看委托链、`dig @权威` 看最终事实；Windows 用 nslookup 对照（A6；呼应写作要点，承接 1.6 的入门）
- **4.4 域名转移规则**：注册满 60 天且近 60 天未转出、转出须解锁 + 授权码（EPP）、gTLD 转移顺延 1 年；Cloudflare Registrar 按成本价（B5）
- **4.5 安全基线**：账户 MFA → 注册商禁止转移锁/禁止更新锁 → 注册局安全锁（serverDelete/Transfer/UpdateProhibited）→ DNSSEC；个人基线=MFA + 禁止转移锁，核心域加注册局锁 + DNSSEC；**已开 DNSSEC 时改 NS 前须先关并等 TTL 过期（约 24–48h）**；DNSSEC 启用=解析商出 DS → 注册商加 DS（B5/B6/B9）
- **4.6 补充提示**：2FA 只保护登录、转移流程未必二次验证——来自社区经验（B8 附注），标注「未经官方原文复核」，写作时不作定论

### 第五章：把域名接上 HTTPS——Caddy 与 Nginx+certbot 反向代理实战

- **篇幅**：中
- **覆盖要点**：HTTPS/ACME 背景、Caddy 最小反向代理 Caddyfile 与自动 HTTPS、通配符与 DNS-01、staging 防限流、certbot 三种签发方式、续期与 deploy-hook
- **素材引用**：C1, C5, C6, C7
- **代码示例**：有（Caddyfile 片段、certbot 命令）

小节结构与写作要点：

- **5.1 场景判断**：本方案面向「有公网 IP + 自有域名」；无公网 IP 读者可直接跳到第 6 章（C1）
- **5.2 HTTPS 与证书背景（简）**：Let's Encrypt/ACME、HTTP-01(80)/TLS-ALPN(443) vs DNS-01（通配符唯一途径）；Caddy 对公网域自动签 LE/ZeroSSL、对本地名用本地 CA，自动续期与 80→443 跳转（C1）
- **5.3 Caddy 最小反代**：可复制 Caddyfile `example.com { reverse_proxy 127.0.0.1:端口 }`；触发自动 HTTPS 的条件（A/AAAA 指向本机 + 80/443 公网可达 + 配置含域名）（C1）
- **5.4 通配符与 staging**：通配证书 LE 强制 DNS-01 且需 DNS 商凭据；**测试/反复续期务必切 LE staging 否则封禁最长一周**（C1）
- **5.5 Nginx + certbot 签发**：`certbot --nginx`（自动签发并装入、可 rollback）；`certonly --webroot -w <根> -d 域`（免停机）；`--standalone` 需独占 80；证书在 `/etc/letsencrypt/live/<cert>/`（C5/C6/C7）
- **5.6 续期机制**：`certbot renew` 只续临期证书（阈值 <1/3 寿命）；判断「真续期」用 `--deploy-hook` 重载服务；dns 插件是通配唯一途径、`--manual` 不自动续期（C6）

### 第六章：没有公网 IP 也能用域名——Cloudflare Tunnel / frp+Caddy / Tailscale Funnel

- **篇幅**：长
- **覆盖要点**：三方案原理与选型、Cloudflare Tunnel 接入、frp vhostHTTPPort + Caddy TLS 终止组合、Tailscale Funnel 边界、方案对比表
- **素材引用**：C1, C2, C3, C4, C9
- **代码示例**：有（cloudflared 配置/命令、frps/frpc.toml、Caddyfile、`tailscale funnel` 命令）

小节结构与写作要点：

- **6.1 场景与三方案概览**：无公网 IP / 有 IP 但不便开入站端口；先给对比表（需要自有域名？需要自建 VPS？大陆访问与合规差异？）（C2/C3/C4）
- **6.2 Cloudflare Tunnel**：cloudflared 出站-only 连 CF 边缘、零入站端口；公网主机名映射本地 HTTP/TCP 服务；前提=域名托管在 CF；CDN/WAF/DDoS 自动生效；给最小接入配置（C2）
- **6.3 frp + Caddy TLS 终止（自建 VPS 组合）**：frps 开 `vhostHTTPPort` + frpc `type="http"` + `customDomains`，一个端口按 Host 路由多子域；**frp 不做 TLS 终止**——暴露本地 HTTP 需 https2http 插件，或用 Caddy 在 VPS 前做 `*.域` DNS-01 通配证书 → reverse_proxy 到 vhostHTTPPort（C4/C9；衔接 5.4）
- **6.4 Tailscale Funnel**：`tailscale funnel 3000` 一行得到公网 HTTPS URL；**仅能绑 ts.net 域、不能绑自有域名**；仅 443/8443/10000、带宽受限；前置 MagicDNS + HTTPS（C3）
- **6.5 选型与边界提醒**：有自有域名且愿托管 CF → Tunnel；想保留自建 VPS 控制面 → frp+Caddy；临时演示/内部工具 → Funnel；并提示 Tunnel「零攻击面」的功能承诺与大陆访问慢/合规现实的张力（C2/C3/C9）

小节结构与写作要点：

- **7.1 合规决策速查表**：以「源站放哪」为第一分叉——大陆源站=备案+国内 CDN/京东云 CF 中国版；免备案+海外快=海外/香港服务器+CF 全球版（代价是大陆延迟）；**「套 CF 免备案」是误区**（C10/C11）

## 学习路径说明

### 前置要求

- 对 Docker、Nginx、反向代理、内网穿透有操作经验（第 5、6 章直接复用，不从头讲）
- 域名/DNS 术语零基础即可，无需前置
- 动手练习需要：一台能跑服务的机器（VPS/Docker 均可）、一个待注册或已有的域名；做大陆路径需准备实名材料（身份证/营业执照）
- 本机装有 `dig`/`nslookup`（macOS/Linux 自带或 brew/apt 安装）；可选 `cloudflared`/`frp`/`tailscale`

### 学完能做什么

- 能讲清 DNS 从递归器到权威的完整解析链，读懂 `dig` 输出并独立排查「改了解析为什么不生效」
- 能避开续费陷阱选到合适域名，完成注册与实名
- 能判断自己的部署要不要 ICP 备案，走通或绕开大陆备案路径
- 能把解析托管到 Cloudflare/DNSPod、做子域 NS 委派，并按基线加固域名安全
- 能用 Caddy 或 Nginx+certbot 给自己的服务一键上 HTTPS 并处理续期
- 在无公网 IP 时，能用 Cloudflare Tunnel / frp+Caddy / Tailscale Funnel 把服务暴露到 HTTPS 域名
- 上线前能对照合规速查表自查，避免「套 CF 免备案」这类红线误区

### 建议学习顺序

- **标准顺序**：第 1 → 2 → 3 → 4 → 5 → 6 → 7 章。第 1 章概念是后续所有操作的地基；第 5 章的 Caddy/证书知识是第 6 章 frp+Caddy 组合的前置。
- **已有网络基础、想快点上手**：第 1 章可只精读 1.4/1.5/1.6（TTL、记录类型、dig），跳过或速读 1.1–1.3。
- **只做境外/海外项目**：第 3 章可速读（重点看 3.1 判定 + 3.5 对照），不必记备案流程细节。
- **没有公网 IP 的读者**：第 5 章学完 5.2/5.3（Caddy 与自动 HTTPS 心智模型）即可进入第 6 章；5.5/5.6 的 certbot 细节按需回头补。
- **时间预估（粗略）**：第 1 章约 2h；第 2 章约 30min；第 3 章约 1h；第 4 章约 1h；第 5 章约 1–1.5h（含实操）；第 6 章约 1.5–2h（含实操）；第 7 章约 30min。不含等待备案/解析传播的真实时间。
