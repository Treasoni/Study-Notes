## 第一章 Windows 文件系统——数据到底放在哪

导读里我们把文件系统比作"仓库"：卷是库房，目录是货架，文件是箱子。这一章要把这个比喻落到能动手的程度——先看清仓库的三层命名规则，再摸清 C 盘里那些眼熟的文件夹各自是什么，最后学会几条真正能用的命令。学完这一章，你应该能回答三个问题：为什么有的路径会写错？C 盘里的 `WinSxS`、`AppData`、`ProgramData` 到底是什么？为什么复制文件时"看起来成功了"其实可能出过错？

本章的写法统一按一个套路：先用中文人话讲直觉，再给官方术语，最后说清"它到底指什么"。

### 1.1 三个基本名词：卷、目录、文件

#### 1.1.1 官方定义

Windows 支持的所有文件系统共用三个存储组件，官方给的定义是：**卷**是"目录和文件的集合"，**目录**是"目录和文件的分层集合"，**文件**是"相关数据的逻辑分组"；组织层级中最高的一级是卷，文件系统"驻留在卷上" [A1]。

翻译成人话：**卷**是一整块可以存放东西的区域（平时你叫它"C 盘""D 盘"）；**目录**是卷里的分层货架，货架还能挂货架，这就是"分层"；**文件**是最后放在货架上的箱子，存的是"相关数据"。你双击进文件夹、复制粘贴、看 C 盘还剩多少空间，全都是在跟这三层打交道。

#### 1.1.2 一个反直觉点：目录本身也是"文件"

很多人以为"目录"和"文件"是两种完全不同的东西。但在文件系统层面，**目录本身就是一种"具有特殊属性的文件"**，所以"必须像常规文件一样遵循所有命名规则" [A1][A2]。

这句话的后果很实际：下一节讲的"文件名不能包含哪些字符""不能叫 `NUL`""不能以句点结尾"，**对目录名同样生效**。你要是以为目录可以随便起名，就会在 1.2 节踩坑。

#### 1.1.3 NTFS 是什么，为什么新版 Windows 默认用它

**NTFS** 是 Windows 的一种文件系统格式，也是新版 Windows 的默认选择，它提供"安全描述符、加密、磁盘配额和支持丰富的元数据" [A14]。用中文说：它除了存数据，还额外记住"谁能访问这个文件"（安全描述符）、"怎么把内容加密"（加密）、"每个用户能占多少空间"（磁盘配额），以及一堆额外的说明信息（元数据）。

> [!tip] 大白话
> 把文件系统想成仓库的"货架制度"。FAT32 是最老的那套制度，只记"哪箱东西放在哪格"；NTFS 是新制度，除了位置，还记每箱的**钥匙权限、封条编号、占用额度**。所以同样一栋库房，换成 NTFS 这套制度后就能管权限、管加密、管配额。

> [!note] 这里不需要知道的事
> 官方文档在讲文件系统时，会写到"文件系统由一个或多个驱动程序和动态链接库组成"，还会出现 `CreateFile`、I/O 系统这类开发接口名 [A1]。这些是写给写驱动的程序员看的。对你来说，只需要记住一句话：**Windows 靠一组后台程序 + 系统文件来读写硬盘，你不需要知道它们在哪、叫什么名字。**

### 1.2 命名规则与路径规则（全章第一坑区）

这一节是整章最容易出错的地方。坑不在命令难，而在"你想当然的写法，和 Windows 实际的理解不一样"。

#### 1.2.1 九个保留字符 + NUL

文件（以及目录）名里**不能出现**这九个字符：`< > : " / \ | ? *`，外加整数值 0，也就是 NUL 字符 [A2]。其中**反斜杠 `\`** 的身份最特殊：它的作用是"把名称分隔成组件的保留字符" [A2]——也就是说，它不是名字的一部分，而是名字之间的分隔符。所以 `C:\a\b.txt` 里的两个 `\` 划出了 `C:`、`a`、`b.txt` 三个组件。

#### 1.2.2 保留设备名：`NUL.txt` 等于 `NUL`

有一批名字属于"操作系统自己要用"的，**不能拿来当文件名**：`CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9` [A2]。这些名字来自早年 DOS 时代的设备概念。

坑在于官方还补了一句："另请避免这些名称紧跟扩展名" [A2]。也就是说，**`NUL.txt` 和 `NUL` 是等效的**，你并不会得到一个叫"NUL.txt"的普通文件。顺带一个冷门但有用的事实：字符码 **1–31 在备用数据流中允许使用**——流的命名规则和文件不一样（1.5 节会讲什么是流）[A2]。

> [!warning] `NUL.txt` 不是普通文件；8.3 短名也不能假设存在
> 文件名一旦撞上保留设备名（哪怕加了扩展名），行为就不是"创建了一个文件"那么简单 [A2]。另外，和短名相关的假设也要小心：8.3 短名**可以被禁用**，所以**不要假设某个文件一定有 `T97B4~1.TXT` 这样的短名** [A2]。

#### 1.2.3 别用空格或句点结尾；大小写不敏感

文件或目录名**不要以空格或句点结尾**，因为"Windows Shell 和用户界面不支持" [A2]。你也许能用底层接口造出这样的名字，但资源管理器不会好好显示它。

另一条：Windows 文件名**大小写不敏感**。官方原话是把名称 `OSCAR`、`Oscar` 和 `oscar` 视为相同；驱动器号同理，`D:\` 与 `d:\` 指的是同一个卷 [A2]。这对用惯了 Linux 的人是个反向冲击——在 Linux 上这是三个不同文件，在 Windows 上它们是同一个。

#### 1.2.4 8.3 短名：`T97B4~1.TXT`

为了兼容老程序，Windows 会给长文件名另外生成一个 "8.3 短名"，形如 `T97B4~1.TXT` [A2]。但官方给了一句关键提醒：**不要假设磁盘上已经存在 8.3 别名**——它可能被禁用 [A2]。

这个"不一定存在"的性质，会在 1.8 节变成一个真实风险：`dir` 的星号通配符**始终使用短文件名映射**，如果短名被启用，`dir t97\*` 会同时匹配到 `t97.txt` 和 `t.txt2` [A12]。这个坑留到 1.8 节展开。

#### 1.2.5 绝对路径、相对路径、UNC——以及 `C:tmp.txt` 这个陷阱

官方对路径的解释方式是这样的："如果文件名不以下列项之一开头，则其与当前目录相对应"，而 UNC 路径、`C:\` 这种带盘符加反斜杠的、以及单独一个 `\` 开头的，都是例外 [A2]。

| 写法 | 官方含义 | 你的直觉对不对 |
|---|---|---|
| `tmp.txt` | 当前目录下的文件 | 对 |
| `C:\tmp.txt` | C 盘**根目录**下的文件 | 对 |
| `C:tmp.txt` | **C 盘当前目录**下的文件 | **错——很多人以为等于 `C:\tmp.txt`** |
| `\tmp.txt` | 当前盘根目录下 | 对 |
| `\\server\share\x.txt` | UNC 路径（网络共享） | 对 |

第三行是全章第一坑。官方明说：`C:tmp.txt` 指"驱动器 C 上当前目录中"的文件，**与 `C:\tmp.txt` 不同** [A2]。差别在于：`C:\` 带反斜杠，是"根目录"；`C:` 不带反斜杠，是"C 盘**当前的**目录"，会跟着你在 C 盘里 `cd` 到哪而改变。另外 `.` 表示当前目录、`..` 表示父目录 [A2]。

> 环境：cmd ｜ 版本：全版本适用 ｜ 权限：无需管理员

```cmd
# 假设当前目录是 C:\Users\Public
type C:tmp.txt    # 实际打开的是 C:\Users\Public\tmp.txt（C 盘的“当前目录”）
type C:\tmp.txt   # 打开 C 盘根目录下的 tmp.txt —— 完全是另一个文件
```

> [!warning] 把 `C:tmp.txt` 当成 `C:\tmp.txt`，会打开（或覆盖）另一个文件
> 这两个写法在资源管理器里看不出区别，在脚本里却指向不同位置。写路径时**盘符后面一律补上反斜杠**，能避开绝大多数"明明文件在，程序却说找不到"的问题 [A2]。

#### 1.2.6 路径开头的两个字符，决定 Windows 用哪套规则

官方把 `\\?\` 描述为：告诉 Windows API "禁用所有字符串分析，并将其后面的字符串直接发送到文件系统"；把 `\\.\` 描述为进入 Win32 设备命名空间，是"直接访问物理磁盘和卷的方式，而无需通过文件系统" [A2]。

用中文人话说：

- `\\?\C:\很长的路径\...`——这是给程序用的**"别自作聪明"开关**。平时 Windows 会对你的路径字符串做各种处理（补全、解析 `.` 和 `..`、判断长度），加上这个前缀就一律跳过，原样交给文件系统。
- `\\.\C:`——这是**直接对着设备说话**的入口，绕过文件系统这一层。日常基本用不到。

官方还提到，在更底层的 NT 命名空间里，Win32 看到的 `C:` 其实只是"指向 `HarddiskVolume1` 的符号链接" [A2]。这层属于写驱动的人关心的内容，**本章不展开**——你只要记住"**路径开头的两个字符决定了 Windows 用哪套规则理解它**"这一个直觉就够了。

#### 1.2.7 MAX_PATH = 260 与"扩展长度路径"

传统的路径长度上限是 **MAX_PATH = 260 个字符**，它的构成是"驱动器号、冒号、反斜杠、用反斜杠分隔的名称组件和终止 null 字符" [A3]。也就是说，这 260 里还包含了 `C:\` 和一个看不见的结尾字符，**实际能用的字符比 260 少**。

加上 `\\?\` 前缀后，可以使用"扩展长度路径，最大约 32,767 个字符"（UNC 路径要写成 `\\?\UNC\` 的形式）；官方明确说这个数字是**近似值** [A3]。但 `\\?\` 有代价：**不能用正斜杠 `/` 作分隔符，不能用 `.` 表示当前目录，也不能用 `..` 表示父目录** [A3]。另外两条细节：相对路径的总字符数始终不能超过 MAX_PATH；用 API 创建目录时，**目录名不能超过 MAX_PATH 减 12**（要留出 8.3 短名的空间）[A3]。

还有一个容易被忽略的分界：**Shell（资源管理器）和文件系统不是一套标准**。官方原话是"可以使用 Shell 用户界面无法正确解释的 Windows API 来创建路径" [A3]——换句话说，**资源管理器打不开的路径，在文件系统里可能真的存在**。

#### 1.2.8 长路径开关：一个注册表值 + 程序自己声明

从 Windows 10 版本 1607 起，许多 Win32 文件/目录函数移除了 MAX_PATH 限制，但**应用必须显式选择支持**。要同时满足两个条件 [A3]：

1. 注册表 `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem` 下的 `LongPathsEnabled` 值为 `1`；
2. 应用程序的清单里包含 `longPathAware` 声明。

**二者缺一不可。** 官方还提到这个值"按进程缓存"，因此"可能需要重新启动" [A3]。

> 环境：PowerShell ｜ 版本：5.1 & 7 ｜ 权限：需要提升的特权（管理员）

```powershell
# 打开“长路径支持”这个开关（写入 HKLM，所以需要管理员权限）
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" `
  -Name "LongPathsEnabled" -Value 1 -PropertyType DWORD -Force
```

> [!tip] 大白话
> 把这个开关想成**仓库新装的一扇加宽门**：门装好了，不代表所有送货的人都会走它。**老程序不一定认这个开关**——它必须自己在清单里声明"我支持长路径"，才会走那道宽门。所以改完注册表还会遇到"某些老工具照样报路径太长"，这不是你没改对，而是它没表态。

> [!note] 留个心眼：本章的两个空白点
> 官方素材本轮**没有覆盖**两个问题：一是文件/目录三种时间戳（创建、访问、修改）的完整官方说明；二是 ReFS 与 NTFS 的区别。这两处本章不写结论，需要时另行查证。

### 1.3 盘符、卷、装入点与分区

#### 1.3.1 盘符和卷不是一回事

你平时说"C 盘"，说的是**盘符**（一个字母）。但盘符只是卷的一个"外号"——卷本身有自己的名字。官方给出的卷名语法是 `\\?\volume\{GUID}\`，其中**花括号不能省** [A11]。

#### 1.3.2 卷装入点：不给盘符也能挂载

**卷装入点**允许"链接卷，而无需驱动器号"，但它必须建立在"现有 NTFS 目录"上 [A11]。好处官方说得很直白：可以用"单个驱动器号（如 `C:`）访问所有本地卷"，"无需记住哪个卷对应于哪个驱动器号" [A11]。

> [!tip] 大白话
> 盘符像**给仓库单独开一扇大门并挂上字母门牌**（C、D、E……）。装入点则是**在已有走廊里开一道内门**：你不用新门牌，走 `C:\sysmount` 这扇内门，就进了另一间库房。字母只有 26 个，内门却可以随便开。

#### 1.3.3 `mountvol` 常用参数

`mountvol` 是管理卷装入点的命令行工具，常用参数有 `/l`、`/d`、`/p`、`/n`、`/e`、`/s` [A11]。其中 `/p` 的行为要特别知道：它会"卸载基本卷，使基本卷脱机，使其不可装载"，而且"**如果其他进程正在使用该卷，则 mountvol 会在卸载卷之前关闭所有打开的句柄**" [A11]。

> [!note] "关闭句柄"是什么意思
> 官方用"句柄"来描述"某个程序正开着这个卷"。翻译成人话：**别人正在用这个卷时，强卸载会先断开他们的连接**——正在往里写数据的程序可能因此报错。

> 环境：cmd ｜ 版本：全版本适用 ｜ 权限：官方未说明

```cmd
# 不带参数：列出当前卷与卷名（卷名里的花括号不能省）
mountvol

# 把一个卷挂到已存在的空目录 \sysmount（免盘符访问）
mountvol \sysmount \\?\volume{2eca078d-5cbc-43d3-aff8-7e8511f60d0e}\

# /d 删除装入点；/p 卸载卷并使其脱机（会先断开正在使用它的程序）
mountvol \sysmount /d
mountvol X: /p
```

#### 1.3.4 `diskpart` 的焦点模型

`diskpart` 是分区管理工具，官方明确要求："您必须在本地**管理员**组或具有类似权限的组中才能运行 diskpart。"[A15]

它的核心心智模型是**焦点（focus）**：官方说"必须先列出一个对象，然后选择一个对象以使其处于焦点状态。对象具有焦点后，键入的任何 diskpart 命令都将对该对象执行操作"，而且焦点会**自动转移**——"创建新分区时，焦点会自动切换到新分区" [A15]。

> [!warning] diskpart 最容易出错的地方：你以为在改 A，其实改的是 B
> 因为焦点是"隐式记住"的，连着敲命令时很容易忘记当前焦点停在哪。**每做一步破坏性操作前，先 `list` 一次确认对象**，是最省事的自保方式 [A15]。

> 环境：cmd（进入 diskpart 交互子环境）｜ 版本：全版本适用 ｜ 权限：必须属于本地管理员组

```cmd
# 进入 diskpart 交互子环境（需要管理员）
diskpart

# 以下命令在 diskpart> 提示符下输入
list disk                    # 先列出对象
select disk 1                # 选中后，它成为“焦点”
create partition primary     # 焦点会自动转移到新建的分区
format fs=ntfs label=Backup quick   # 快速格式化为 NTFS，卷标 Backup
```

#### 1.3.5 冷知识：NTFS 卷能有多大

NTFS 卷的上限**不是固定值，而取决于"群集大小"这个设置** [A14]。在本章的入门阶段你只需要记住一个直觉：**群集大小越大，单个卷能支持的容量越大**。具体数字放到这个冷知识框里：

| 群集大小 | 卷上限（官方数据） |
|---|---|
| 4 KB（默认） | 16 TB |
| 64 KB | 256 TB |
| 2048 KB（最大） | 8 PB |

另外官方补了一条：使用依赖卷影复制服务（VSS）快照的"以前版本"功能或备份程序时，**最大支持的卷大小为 64 TB** [A14]。（装载了超过上限的群集大小的卷时，系统会报 `STATUS_UNRECOGNIZED_VOLUME`，也就是"认不出这个卷" [A14]。）

### 1.4 系统目录地图：C:\Windows、Program Files、Users、ProgramData、AppData

这一节回答"我 C 盘里那些文件夹到底是干什么的"。先看一张全景图：

```text
C:\
├─ Windows\              ← %windir%
│  ├─ System32\
│  ├─ SysWOW64\          ← 仅 64 位系统上有
│  └─ WinSxS\            ← 本章只说明它存在
├─ Program Files\        ← %ProgramFiles%
├─ Program Files (x86)\  ← 仅 64 位系统上有
├─ ProgramData\          ← %ALLUSERSPROFILE%
└─ Users\
   ├─ <用户名>\          ← %USERPROFILE%
   │  └─ AppData\
   │     ├─ Roaming\     ← %APPDATA%
   │     ├─ Local\       ← %LOCALAPPDATA%
   │     └─ LocalLow\
   └─ Public\            ← %PUBLIC%
```

#### 1.4.1 `AppData` 三兄弟

用户配置文件目录 `%USERPROFILE%` 等于 `%SystemDrive%\Users\%USERNAME%`；它下面的 **`AppData` 分成三个子目录** [A6]：

- **`Roaming`**（`%APPDATA%`）——官方定义是"用作应用程序特定数据的通用存储库" [A6]。它叫"漫游"，意思是可以跟着账户配置一起同步。
- **`Local`**（`%LOCALAPPDATA%`）——官方定义是"充当本地非漫游应用程序的数据存储库" [A6]。也就是"只属于这台机器，不跟着走"。
- **`LocalLow`**——路径是 `%USERPROFILE%\AppData\LocalLow`，官方只给出路径和一句"**没有 CSIDL 等效项**" [A6]。

这三个文件夹的类型都是 **PERUSER**，也就是"**每个用户各有一份**" [A6][A7]。

> [!warning] `AppData\LocalLow` 的用途，官方未说明
> 素材里能查到的只有它的**路径**和"无 CSIDL 等效项"这一句 [A6]。网上常见的"低完整性级别进程使用"这类说法，本轮**没有任何官方来源支撑**，因此本节不写用途，只写它存在 [A6]。

#### 1.4.2 全机器共用的两个目录

- **`ProgramData`**（`%ALLUSERSPROFILE%`，典型路径 `C:\ProgramData`）——官方定义是"包含所有用户的应用程序数据的文件系统目录"；XP 时代的旧路径是 `%ALLUSERSPROFILE%\Application Data` [A6][A7]。
- **`Public`**（`%PUBLIC%`，典型路径 `C:\Users\Public`）——官方标注它是"Windows Vista 新增功能"，同样"无 CSIDL 等效项"；下面按类型分成 `Documents`、`Desktop`、`Music`、`Pictures`、`Videos`、`Favorites` [A6][A7]。

这两个目录的类型是 **FIXED**，也就是"**全机器共用一份**" [A6]。

> [!tip] 大白话
> 把 `AppData` 和 `ProgramData` 的区别想成**员工抽屉和公共储物柜**：`Roaming` 是你可以带走的抽屉，`Local` 是锁在这间办公室的抽屉，`LocalLow` 是一只官方没贴标签的抽屉；而 `ProgramData` 和 `Users\Public` 是走廊里的公共储物柜，全机器共用一份 [A6][A7]。

#### 1.4.3 `C:\Windows` 与 `System32`、`SysWOW64`

`C:\Windows` 由 `%windir%` 指向；`System32` 位于 `%windir%\system32`。关键的一点是：**在 64 位系统上，`FOLDERID_SystemX86` 解析到的其实是 `%windir%\syswow64`** [A6][A7]。

> [!warning] 关于 `System32` / `WinSxS`：本章只说明它们存在
> 网上常说这些目录"不可手动删除"。本轮素材**没有找到这个说法的官方依据**，所以本节**只描述它们存在**，不写"不可删"这类断言。要动这些目录前，请先自己查权威来源。

#### 1.4.4 `Program Files` 与 `Program Files (x86)`

`Program Files` 对应 `%ProgramFiles%`，典型路径 `%SystemDrive%\Program Files` [A6]。而 `Program Files (x86)` 有一条必须记住的规则：**它只存在于 64 位系统** [A6]。官方给出的对照是：

| 系统位数 | `FOLDERID_ProgramFiles` | `FOLDERID_ProgramFilesX86` |
|---|---|---|
| 32 位 | `Program Files` | `Program Files`（**同一个**） |
| 64 位 | `Program Files` | `Program Files (x86)` |

所以，**32 位系统上两个常量指向同一路径**，"`Program Files (x86)` 一定存在"是错误直觉 [A6]。另外两条附带规则：在 64 位系统上运行 **32 位**应用时，`FOLDERID_ProgramFiles` 也会被解析到 `Program Files (x86)`；而 `FOLDERID_ProgramFilesX64` 在"任一情况下使用都会导致错误" [A6]。

> [!warning] "`Program Files (x86)` 一定存在"是错误直觉
> 32 位系统上根本没有这个目录。写脚本时**不要假设它存在**，先判断系统位数或先检查目录是否存在 [A6]。（官方同一页面上对 `ProgramFilesX86` 默认路径的表述存在前后不一致，本节只采用"64 位系统上为 `Program Files (x86)`"这一结论 [A6]。）

### 1.5 NTFS 的四个特色功能：备用数据流、压缩、加密、稀疏文件

这四个功能都是"NTFS 有、老的 FAT32 没有"的能力。它们不是日常必用，但经常出现在"为什么这个文件删不干净""为什么复制后大小对不上"这类问题里。

#### 1.5.1 备用数据流（ADS）：文件身上的"隐藏附加文件"

**备用数据流**（官方的叫法是"流"）是这么定义的：NTFS 中"流包含写入文件的数据，并提供有关文件的详细信息，而不是属性"（例如搜索关键字、创建者身份）[A8]。

关键在于：**每个流有自己的分配大小、实际大小，并"维护自己的压缩、加密和稀疏状态"**；而且**流没有自己的文件时间**——"更新文件中的任何流时，文件的文件时间将更新" [A8]。

> [!tip] 大白话
> 把文件想成一个**文件夹**：平时你只看到里面那份"主文件"，但 NTFS 允许它**再挂几个隐藏的附件**。这些附件有自己的大小、自己的压缩/加密状态，却**没有自己的时间戳**——你动附件，文件的修改时间照样会变。想知道一个文件身上挂了几份附件，用 `dir /r`。

#### 1.5.2 观察 ADS 的入口：`dir /r`

流的命令行全名格式是"`文件名:流名称:流类型`"（例如 `myfile.dat:stream1:$DATA`）；默认数据流是未命名的，所以 `文件名::$DATA` 等价于 `文件名` [A8]。

几条命名规则要知道：流名称只能用文件名的合法字符（**含空格**）；**用户无法创建新的流类型**；流类型"始终以美元符号（$）符号开头" [A8]。另外，单字符文件名必须写成全限定路径或加 `.\`，因为"Windows 将单个字符文件名视为驱动器号" [A8]。

> [!note] 进阶附录：额外流类型
> 官方还给出了一组"目录本身也是流"的等价写法（如 `DirName::$INDEX_ALLOCATION`），以及 EFS 使用 `$EFS`、事务性 NTFS 使用 `$TXF_DATA` 这类流类型 [A8]。它们属于进阶内容，本章不展开。

#### 1.5.3 NTFS 压缩：`compact`

`compact` 是"NTFS 文件系统压缩功能的命令行版本" [A13]。有一个非常容易误解的点：**目录的压缩状态表示的是"将文件添加到目录时是否自动压缩"，而"设置目录的压缩状态不一定更改目录中已存在文件的压缩状态"** [A13]。也就是说，你把一个目录标成"压缩"，里面**已经存在**的文件不会自动变小。

另外**不能压缩 FAT 或 FAT32 分区** [A13]。（`/EXE` 参数下的 `XPRESS4K`、`XPRESS8K`、`XPRESS16K`、`LZX` 等算法名属于进阶内容，本章不展开 [A13]。）

> 环境：cmd ｜ 版本：全版本适用 ｜ 权限：官方未说明

```cmd
# 压缩整个卷（需在卷根目录执行）；/i 表示遇到错误继续处理
compact /c /i /s:\

# 只压缩指定扩展名，不改目录本身的压缩属性
compact /c /s:\tmp *.bmp

# 查询 / 设置系统级“紧凑 OS”状态
compact /CompactOs:query
compact /CompactOs:always
```

#### 1.5.4 EFS 加密：`cipher`

EFS"使用公钥系统为 NTFS 文件系统卷上的单个文件提供加密保护" [A21]。`cipher` 是最常用的查看/设置工具，输出里 **`E` 表示已加密、`U` 表示未加密** [A16]。

官方留下了一个经典坑，原文是："**如果未加密父目录，则修改文件时，加密文件可能会解密。因此，加密文件时，还应加密父目录。**" [A16]

> [!warning] 加密了单个文件，改一次就可能自动变回明文
> 只加密文件本身、不管父目录，会出现"改一下就解密"的情况。**加密时把父目录一起加密**，是官方明确给出的做法 [A16]。`cipher /w:<directory>` 则用于"从整个卷上可用未使用的磁盘空间中删除数据" [A16]。

> 环境：cmd ｜ 版本：全版本适用 ｜ 权限：官方未说明

```cmd
# 查看当前目录下每个文件的加密状态：E=已加密，U=未加密
cipher

# 加密一个目录（务必连同它的父目录一起加密，见上方警告）
cipher /e C:\Users\Public\Secret

# 擦除卷上“已删除文件”留下的残留数据
cipher /w:C:\

# 导出 EFS 证书与密钥 —— 加密后一定要备份，丢了就打不开
cipher /x C:\Users\Public\Secret\a.txt
```

#### 1.5.5 EFS 与压缩：只验证了单向

官方明确列出 EFS **无法加密**的对象：**压缩文件**、系统文件、系统目录、根目录、交易 [A21]。但紧接着又说明：**可以加密稀疏文件** [A21]。

> [!warning] 只说一个方向：无法加密"已压缩"的文件
> 已有的官方证据是"**无法加密已压缩的文件**"这一条 [A21]。**反向结论（"加密后能否再压缩"）本轮没有验证**，所以本章**不写成"两者互斥"**，只写这一个方向 [A21]。

#### 1.5.6 稀疏文件：看起来占空间，其实没占

稀疏文件的原理是：程序"将这些未分配的区域视为包含值为零的字节，但没有使用磁盘空间来表示这些零" [A17]。也就是"内容全是零的部分不占地方，但读起来仍然是零"。

有两条限制要知道：应用必须**显式声明**文件为稀疏（对应一个叫 `FSCTL_SET_SPARSE` 的控制码），并"由应用程序负责"维持稀疏性；此外"**只有压缩文件或稀疏文件才能具有操作系统已知的清零范围**" [A17][A20]。

> 环境：cmd ｜ 版本：全版本适用 ｜ 权限：**必须以管理员或管理员组成员身份登录** [A18]

```cmd
# 把文件标记为稀疏文件
fsutil sparse setflag C:\temp\sample.txt

# 查询是否已标记为稀疏
fsutil sparse queryflag C:\temp\sample.txt

# 扫描文件里哪些区间是非零数据
fsutil sparse queryrange C:\temp\sample.txt

# 用零填充一段区间：从偏移 0 开始、长度 1048576 字节
fsutil sparse setrange C:\temp\sample.txt 0 1048576
```

> [!warning] `fsutil` 主页有信息缺口
> 素材显示 `fsutil` 主页面的**部分子命令描述在抓取结果中为空**，因此涉及 `fsutil fsinfo`、`fsutil volume` 的子命令本章**不展开** [A18]。

> [!warning] `compact` / `cipher` 要不要管理员？官方未说明
> 本轮官方页面**完全没有提到** `compact`、`cipher`、`mountvol`、`robocopy` 是否需要管理员权限 [A13][A16][A11][A10]。本节一律标注"官方未说明"，不替你推断。**唯一的例外是 `fsutil`**，它的官方页面明确写了"必须以管理员或管理员组成员身份登录" [A18]。

### 1.6 链接三兄弟：硬链接、符号链接、交接点

官方原话是："NTFS 文件系统支持三种类型的文件链接：硬链接、交接点和符号链接。" [A19]

| 类型 | 指向什么 | 能否跨卷 | 能否指目录 | `mklink` 参数 |
|---|---|---|---|---|
| **硬链接** | 同一卷上的**同一个文件** | **否** | **否** | `/h` |
| **符号链接** | 文件或目录（默认是文件） | 是 | 是（用 `/d`） | 默认 / `/d` |
| **交接点** | 一个**单独的目录** | 只限同一台机器的不同本地卷 | 是（只能是目录） | `/j` |

具体一点：硬链接是"文件的文件系统表示形式，其中多个路径引用同一卷中的单个文件"，它**不能引用目录，也不能引用不同卷上的文件** [A19]。交接点"引用的存储对象是单独的目录"，"还可以链接位于同一计算机上的不同本地卷上的目录"，它靠**重分析点**实现 [A19]。

> [!tip] 大白话
> 把链接想成 Windows 里的一种**"指针文件"**：硬链接是**给同一个箱子贴了第二个标签**（箱子还是一个）；符号链接和交接点更像**一张写着"东西在那边"的纸条**。最重要的一句话：**删链接 ≠ 删原文件**——你撕掉纸条，箱子还在原地。

#### 1.6.1 反直觉细节与删除语义

官方提到一个很容易看懵的细节：硬链接的"目录条目大小和文件属性信息**仅在进行更改的链接处**明显更新"——在一个链接上清掉只读标志，**其他链接仍显示只读** [A19]。

删除语义则是另一条关键规则：每个文件"可视为至少有一个硬链接"，"**只有在删除了指向某一文件的所有链接之后，才会从文件系统中删除该文件**" [A18]。

#### 1.6.2 `mklink` 的四种形态

`mklink` 默认创建**文件符号链接**，`/d` 创建目录符号链接，`/h` 创建硬链接，`/j` 创建**目录交接点**；删除链接用普通命令即可——`rd` 删目录符号链接、`del` 删硬链接 [A5]。

> 环境：cmd ｜ 版本：全版本适用 ｜ 权限：**官方未说明**

```cmd
# 目录符号链接（/d）—— 像快捷方式，但发生在文件系统层
mklink /d \MyFolder \Users\User1\Documents

# 硬链接（/h）—— 同一卷内，两个名字指向同一个文件
mklink /h \MyFile.file \Users\User1\Documents\example.file

# 目录交接点（/j）—— 官方叫“目录联接”，只能指向目录
mklink /j C:\LinkToData D:\Data
```

> 环境：cmd ｜ 版本：全版本适用 ｜ 权限：无需管理员

```cmd
# 删除链接用普通命令；删掉的只是“这个名字”，原文件仍在
rd C:\LinkToData
del C:\MyFile.file
```

> [!warning] `/j` 是"目录联接"，不是"目录硬链接"
> 社区里常把 `mklink /j` 叫成"目录硬链接"，但官方参数表的定义是"**目录联接**"（英文 junction）[A5]。以官方参数表为准 [A19]。硬链接**根本不能指向目录**，所以"目录硬链接"这个说法在概念上就站不住。

> [!warning] `mklink /F` 这个参数不存在
> 官方参数表里只有 `/d`、`/h`、`/j`、`/?` 四种 [A5]。网上流传的 `mklink /F` 是错误信息，敲下去只会得到"参数无效"。

> [!warning] `mklink /d` 要不要管理员？官方文档未明确说明
> 创建符号链接**可能需要提升权限，但官方文档没有明确说明这一点** [A5]。如果你执行时遇到"拒绝访问"，最务实的做法是以管理员身份重试一次——但请注意，这是操作建议，不是官方结论。

### 1.7 查看与修改元数据：文件属性（attrib）与权限（icacls）

#### 1.7.1 文件属性：`attrib`

`attrib` 可设置的属性字母包括：`r` 只读、`a` 存档、`s` 系统、`h` 隐藏、`o` 脱机、`i` 非内容索引、`x` 清理、`p` 固定、`u` 未固定、`b` SMR Blob [A9]。常用的三个开关是：`/s` 递归子目录、`/d` 作用于目录、`/l` 作用于符号链接**本身**而不是它指向的目标 [A9]。

> 环境：cmd ｜ 版本：全版本适用 ｜ 权限：无需管理员

```cmd
# 查看单个文件的属性
attrib news86

# 加上 / 去掉只读属性
attrib +r report.txt
attrib -r b:\public\*.* /s
```

> [!warning] `attrib` 有一条操作顺序说法，仅有一条官方来源、未实测
> 官方写到：文件若设了**系统属性或隐藏属性**，"必须清除该属性，然后才能更改文件的任何其他属性" [A9]。本轮**只有这一条来源，且未实际验证**，所以你按这个顺序操作**可能得不到预期结果**。遇到"改了没反应"时，先把 `s` / `h` 清掉再改一次试试。

#### 1.7.2 `icacls`：看权限和改权限

`icacls` 的作用是"显示或修改指定文件中的任意访问控制列表（DACL）"，并取代已弃用的 `cacls` [A4]。这里有两个新名词：

- **DACL**：可以理解成"**这张通行名单**"——谁被允许、谁被拒绝，都在里面。
- **SID**：账户的**内部编号**，形如 `S-1-5-21-...`，**不是用户名** [A4]。

官方还说明，ACE（名单里的每一条）有**固定的规范顺序**：显式拒绝 → 显式授予 → 继承的拒绝 → 继承的授予 [A4]。

简单权限字母不用加括号：`N` 无法访问、`F` 完全访问、`M` 修改、`RX` 读取和执行、`R` 只读、`W` 只写、`D` 删除 [A4]。而**高级权限和继承标志必须写在括号里**：例如 `(DE)` 删除、`(WDAC)` 更改权限、`(WO)` 获取所有权、`(RD)` 读取数据/列出目录、`(X)` 执行/遍历；继承标志有 `(I)` 继承、`(OI)` 对象继承（仅目录）、`(CI)` 容器继承（仅目录）、`(IO)` 仅继承、`(NP)` 不传播继承 [A4]。

一条极易忽略的区别：`/grant:r` 是"权限**替换**以前授予的显式权限"，不带 `:r` 则是"**添加**到任何先前授予的显式权限中" [A4]。

> 环境：cmd ｜ 版本：全版本适用 ｜ 权限：无需管理员（改系统目录等位置需要相应权限）

```cmd
# 查看一个路径的权限（列出的就是 DACL 里的各条 ACE）
icacls C:\Users\Public\demo.txt
```

> 环境：cmd ｜ 版本：全版本适用 ｜ 权限：无需管理员（视目标位置而定）

```cmd
# 给用户 User1 授予“删除 + 更改权限”
icacls test1 /grant User1:(d,wdac)

# 用数字 SID 时前面要加星号（*）—— S-1-1-0 是 Everyone
icacls test1 /grant *S-1-1-0:(d,wdac)

# 权限改坏了：/reset 替换为所有匹配文件的“默认继承 ACL”
icacls C:\Users\Public\demo.txt /reset

# 批量备份 / 还原 ACL（/t 递归）
icacls c:\windows\* /save aclfile /t
icacls c:\windows\ /restore aclfile
```

（继承行为还可以用 `/inheritancelevel:e|d|r` 控制：`e` 启用、`d` 禁用、`r` 移除继承的权限 [A4]。）

### 1.8 列目录与看隐藏内容：`dir` 的三个开关与星号坑

#### 1.8.1 三个开关

`dir` 的默认行为是**不显示隐藏文件和系统文件**。官方的说明是：加 `/a` 但不指定具体属性时，才会"显示所有文件的名称，包括隐藏文件和系统文件" [A12]。另外两个开关：`/r` 可以"显示文件的备用数据流"，`/x` 显示 8.3 短名 [A12]。

> 环境：cmd ｜ 版本：全版本适用 ｜ 权限：无需管理员

```cmd
# 默认：隐藏 / 系统文件不出现
dir C:\Users\Public

# /a 不带属性值 = 显示全部（含隐藏、系统文件）
dir /a C:\Users\Public

# /r = 显示备用数据流（1.5 节讲的 ADS）
dir /r C:\Users\Public

# /x = 显示 8.3 短名
dir /x C:\Users\Public
```

#### 1.8.2 星号通配符的坑：它走的是短名映射

官方 Remarks 里写着：星号"始终使用短文件名映射" [A12]。后果是：`dir t97\*` 会**同时返回** `t97.txt` 和 `t.txt2`（后者的短名是 `T97B4~1.TXT`）；而 `del t97\*` 会**把两个文件都删掉** [A12]。

> 环境：cmd ｜ 版本：全版本适用 ｜ 权限：无需管理员

```cmd
# 危险演示：星号会走“短名映射”，匹配范围比你想的宽
dir t97\*     # 同时列出 t97.txt 和 t.txt2
del t97\*     # 会把两个文件都删掉
```

> [!warning] 星号通配符 + 短名映射 = 误删风险
> 你以为 `t97\*` 只匹配"以 t97 开头的文件"，实际它会**通过短名匹配到更多文件** [A12]。搭配 `del` 使用时尤其危险。**批量删除前，先用 `dir` 看一遍匹配结果**，这是最省事的一道保险。

### 1.9 复制与备份：`robocopy` 的默认值有多危险

`robocopy` 的语法是 `robocopy <source> <destination> [<file>] [<options>]`，不指定文件时默认处理 `*.*` [A10]。

#### 1.9.1 `/s` 与 `/e` 的区别

`/s` 复制子目录但"自动排除空目录"，`/e` 则"自动包括空目录" [A10]。想做完整备份，用 `/e`。

#### 1.9.2 `/mir` 是最危险的参数

官方明确：**`/mir` 相当于 `/e` 加 `/purge`**，也就是镜像整个目录树，并**删除目标端源中已不存在的文件和目录** [A10]。

> [!warning] `/mir` 会删除目标端的文件，执行前必须先演练
> 这不是"多复制一份"，而是"让目标端变得和源端一模一样"——**目标端多出来的东西会被删掉** [A10]。执行前先加 `/L` 演练（只列出计划、不实际复制），确认清单无误再真正执行。

#### 1.9.3 默认重试极其激进

官方的默认值是：`/r` 重试 **1,000,000** 次、`/w` 等待 **30** 秒 [A10]。这两个默认值意味着：**网络路径失效时，robocopy 会长时间假死**。官方自己的示例普遍写成 `/R:2 /W:5` [A10]——跟着官方示例加这两个参数，是性价比最高的一条习惯。

> [!warning] 默认 `/r:1000000 /w:30` 会让失效的网络路径长时间假死
> 目标不存在或网络断了时，robocopy 会按默认值反复重试，看起来就像"卡死了" [A10]。**每次都用 `/R:2 /W:5`（或类似的小值）**，能让你在几秒内拿到明确结果，而不是干等。

#### 1.9.4 退出码语义反直觉

`0` 表示"未复制任何文件"（没有失败），`1` 表示"已成功复制所有文件"，而"任何等于或大于 **8** 的值都表示在复制作期间至少发生一次故障" [A10]。

> [!tip] 大白话
> 记住一句话就够：**0 和 1 都算正常，≥8 才是出错。** 别看到 `0` 就以为"出大事了"——它只是说"源和目标完全一样，没什么可复制的" [A10]。

#### 1.9.5 `/copy` 与日志

`/copy` 的默认值是 `DAT`（数据、属性、时间戳）；`/sec` 相当于 `/copy:DATS`；`/copyall` 相当于 `/copy:DATSOU` [A10]。官方"强烈建议"每次运行都加上 `/log:` [A10]。

> 环境：cmd ｜ 版本：全版本适用 ｜ 权限：**官方未说明**

```cmd
# 安全复制：/E 含空目录、/ZB 失败时改用备份模式重试、必带日志
robocopy C:\Users\Admin\Records D:\Backup /E /ZB /LOG:C:\Logs\Backup.log

# 镜像（= /E + /PURGE）：会删除目标端多余文件，破坏性最强
robocopy C:\Users\Admin\Records D:\Backup /MIR /R:2 /W:5 /LOG:C:\Logs\Backup.log

# 多线程复制（/MT:16），适合大量小文件
robocopy C:\Users\Admin\Records D:\Backup /S /E /COPY:DAT /MT:16 /LOG:C:\Logs\Backup.log
```

#### 1.9.6 两个隐藏行为

- **默认会跟随交接点**。官方注明 robocopy 默认包含交接点，要主动用 `/xj`（全部排除）、`/xjd`（排除目录交接点）、`/xjf`（排除文件符号链接）来排除 [A10]。
- **从设备根目录复制时，目标目录会获得"隐藏"和"系统"属性** [A10]。这是官方 Important 级提示，很多人复制完发现目标目录"不见了"，就是这条造成的。

另外：`/sparse` 控制是否保留稀疏状态，不选时默认为 **yes**；`/mt:<n>` 的 `n` 必须为 1–128（默认 8），且"不能与 `/ipg` 和 `/efsraw` 参数一起使用" [A10]。

> 环境：cmd ｜ 版本：全版本适用 ｜ 权限：官方未说明

```cmd
# 演练优先：/L 只列出要做什么，不真的复制
robocopy C:\Users\Admin\Records D:\Backup /MIR /L /LOG:C:\Logs\Plan.log

# 限速 1 MB/s、显示预计完成时间
robocopy C:\Users\Admin\Records D:\Backup /E /iorate:1m /ETA

# 排除交接点（robocopy 默认会跟随它）
robocopy C:\Users\Admin\Records D:\Backup /E /xj
```

### 本章小结

> [!summary] 小结
> - 文件系统分三层：**卷**是"目录和文件的集合"，**目录**是"分层集合"，**文件**是"相关数据的逻辑分组"；**目录本身也是一种"特殊属性的文件"**，所以目录名同样受文件名规则约束 [A1][A2]
> - **命名第一坑**：`C:tmp.txt` 指"C 盘当前目录"，**不等于** `C:\tmp.txt`；保留字符是 `< > : " / \ | ? *` 加 NUL；`NUL.txt` 等同于 `NUL`；8.3 短名**不保证存在** [A2]
> - **路径长度**：传统上限 MAX_PATH = 260；`\\?\` 前缀可用约 32767 字符，但不能用 `/`、`.`、`..`；长路径开关需要"注册表值 + 应用自己声明"两者齐备 [A3]
> - **系统目录**：`%USERPROFILE%\AppData` 分 `Roaming` / `Local` / `LocalLow` 三个（每个用户各一份）；`ProgramData` 和 `Users\Public` 全机器共用；`Program Files (x86)` **只存在于 64 位系统** [A6][A7]
> - **NTFS 四特色**：流（`dir /r` 看）、压缩（`compact`）、加密（`cipher`，加密文件时**要一起加密父目录**；**无法加密已压缩文件**）、稀疏文件（`fsutil sparse setflag`）[A8][A13][A16][A21]
> - **链接三兄弟**：硬链接（不能指目录、不能跨卷）、符号链接（`/d` 可指目录）、交接点（`/j`，官方叫"**目录联接**"）；**删链接 ≠ 删原文件** [A19][A5]
> - **元数据**：`attrib` 看/改属性（`s`/`h` 的操作顺序说法**仅一条来源、未实测**）；`icacls` 看/改/重置权限，`/reset` 是权限改坏后的兜底 [A9][A4]
> - **复制备份**：`robocopy` 的 `/mir` **会删除目标端文件**；默认 `/r:1000000 /w:30` 会让失效网络路径长时间假死；退出码 **0 和 1 都正常，≥8 才是出错** [A10]
> - **官方未说明的位置**（本章一律不推断）：`mklink /d` 的提权要求、`compact` / `cipher` / `mountvol` / `robocopy` 的管理员要求、`AppData\LocalLow` 的用途 [A5][A10][A11][A13][A16][A6]

下一章换一个战场：离开硬盘上的文件，进入 Windows 的"后台登记本"——注册表。它长什么样、五个根键分别管什么、磁盘文件在哪里，以及为什么改它之前**一定要先导出备份**。
