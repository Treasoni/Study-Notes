## 学习笔记大纲：《在 fnOS 中部署小雅（单容器）——飞牛影视能否替代 Emby》

> 笔记类型：实战 + 对比（混合）
> 预计总篇幅：约 26–30 页（4 中 + 2 长 + 1 短）
> 章节数：7 章
> 混合理由：本篇有一条**必须跑通的主线**（单容器部署 + 飞牛影视接入），属于「实战」；而用户的核心疑问是**选型**（不想用 Emby 行不行），必须用「分别介绍 → 逐项对比 → 选型建议」的对比结构回答，两条线无法单独成篇，故混合。结构上：第一、二章走对比（先判断），第三至五章走实战主线（再动手），第六、七章收口为避坑与运维。

### 第二章：选型对比——飞牛影视能不能替代 Emby
- **篇幅**：长
- **覆盖要点**：
  - 结论先行：**不必须 Emby**——没有任何来源断言「必须 Emby」，且已有社区实践是「全家桶除了 Emby」
  - 前端逐项对比表（分别介绍 → 逐项对比 → 选型建议）：**刮削与元数据来源**、**播放链路**、**播放兼容性**、**外网 / 蜂窝网可达性**四个维度，逐项给差异
  - **「单容器 vs 全家桶（Alist + Emby）」对比小节**（作「为什么可以不用 Emby」的反衬）：组成差异 + 资源门槛对比表（仅 AList 1核/512M/512M；Alist+Emby 2核/4G/150G 等），并注明该表是**维护者推荐、非官方硬性**
  - 飞牛影视可作前端的**官方旁证**：MediaWarp 自述「前置于 EmbyServer/Jellyfin/飞牛影视 的反向代理服务器」；fntv-proxy 基于飞牛影视 **0.9.3**
  - 成熟度**并列不合并**：MediaWarp 正文虽列飞牛影视，但 TODO 仍列「适配 飞牛影视」——作「未决项」标注，不写成结论
  - Jellyfin 路线说明：官方 Jellyfin 安装方案**已长久未维护**，全家桶加 Jellyfin 不建议走官方脚本
  - 选型建议落到用户场景：已有飞牛影视 + 不想装 Emby → 单容器（仅 AList）+ 飞牛影视前端

### 第五章：前端接入——让飞牛影视认到小雅
- **篇幅**：中
- **覆盖要点**：
  - 结论先行：**不要**把小雅整个 Alist 直接丢给飞牛影视扫描
  - 播放链路术语首现即解释 + 比喻：STRM 只存 URL 指针（像「快捷方式」），302 直链让流量**不经过**媒体服务器
  - 用 **SmartStrm** 生成 strm（fnOS 应用中心装法 vs Compose 镜像 `cp0204/smartstrm:latest`、`:8024`、`network_mode: host`）；注明应用版**滞后 1~2 个版本**
  - 修 302 与外网可达：**MediaWarp（FNTV 类型）** 或 **fntv-proxy**（飞牛侧播放地址指向代理端口 `:28005`），二选一；注明「能否共存 / 版本矩阵」**无来源**
  - 挂载原则：**只挂小雅下已生成的 strm 子目录**，不挂全部文件夹
  - 实体落点：目录挂载示例、飞牛影视播放地址指向 `:28005` 的截图位 / 配置片段

## 学习路径说明

### 前置要求
- 一台可运行 Docker 的 fnOS（飞牛私有云）设备，能访问阿里云盘
- 了解 Docker 基本概念（镜像、容器、端口映射、卷挂载）——用户已有基础，够用
- 一个阿里云盘账号，且能获取凭据三件套（token / open token / folder id）
- 对 AList 不熟不影响跟做：第一章有名词扫盲表，术语首现处均给大白话
- 建议先建立网盘影视基础认知：可先读 [[网盘影视播放与本地存储的取舍]] 与 [[Strm流文件与302播放详解]]

### 学完能做什么
- 独立判断「不装 Emby、只用飞牛影视」是否适合自己的场景，并说清刮削、播放、外网可达性三处的差异
- 用单容器（官方镜像或 monlor 镜像任选一条）在 fnOS 部署小雅并跑通 WebDAV
- 用 SmartStrm 生成 STRM，并用 MediaWarp / fntv-proxy 修 302，让飞牛影视正常接入与外网播放
- 识别并规避四类常见坑（应用中心版、风控转存、内网地址、UA 绑定）
- 用 xiaoyakeeper 定期清理转存缓存，维持长期可运行

### 建议学习顺序
- 第一步（判断，约 30 分钟）：第一章 → 第二章；若确定走单容器方案再继续
- 第二步（动手，约 30–60 分钟）：第三章（准备清单）→ 第四章（部署）→ 第五章（接入），按序执行，命令集中在各章「动手实践（cmd）」小节
- 第三步（收口，约 20 分钟）：第六章遇问题回查；第七章做长期运维
- 全程预计 1.5–2.5 小时；只想跑通部署的话，第三章至第五章为核心路径
