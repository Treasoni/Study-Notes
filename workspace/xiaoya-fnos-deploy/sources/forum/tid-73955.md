## 主要：两个不同的地址/鉴权边界
**选取《终极对弈》的现有 STRM，限制为 **`Range: bytes=0-0` 进行受控检查，得到：  
 | **现场响应**  |  
| --- |  
|  **STRM 指向的** `xiaoya.host:5678/d/...`  |  `302`到 `127.0.0.1:45678`  | **原 STRM 未带小雅内部签名；小雅 Nginx 配置规定走本机 45678。**  |  
| `127.0.0.1:45678/d/...`  |  `302`到 `cdnfhnfile.115cdn.net`  | **45678 只监听 NAS loopback，内部再访问 AList 的 5234。AList 在这里处理转存/取 115 临时直链。**  |  
|  **同一条 115 CDN 临时链接，**`User-Agent: trim_player`  |  `206`，1 字节；总大小 5,386,279,400 字节  | **NAS 能取到真实媒体。**  |  
|  **同一条** CDN 临时链接，仅把 UA 换成 `Mozilla/5.0`  | `403`  | **CDN 链接不是任意播放器直接可用；请求头条件至少包含 UA。未证明是否还绑定 IP、Cookie 或其他条件。**  |  
**小雅 **`/etc/nginx/http.d/default.conf` 的 `/d/` 规则也证实：缺少内部签名参数时，5678 返回到 `127.0.0.1:45678` 的 302；45678 再代理到 `127.0.0.1:5234/d/`。Emby 的 API 密钥不是此次飞牛播放失败的证据或修复点。
**飞牛服务端通过原 STRM 能探测、读取片段，但飞牛原生 **`/v/api/.../stream` 响应里的 `direct_link_qualities[].url` 仍是 `http://xiaoya.host:5678/...`。手机在蜂窝网络上无法使用 NAS 内部域名；即使把手机直接带到 115 CDN，手机播放器的 UA 与成功请求不同，也可能得到 403。因此“NAS 日志有 206”与“手机报 -99985”可以同时发生。此前只修 hosts 或只转发 115 的 302 都不完整。
