# 第六章 数据与运营（合规向）：官方开放平台 API 与自账号取数

> 本章定位：生产与发布都有工具了，但「复盘自己发的内容到底表现如何」时，你会撞上同一个问题——官方到底给不给你数据？本章回答这个问题，并给出一条合规底座：先分清「官方 API 边界」，再看如何把「官方导出」脚本化。本章对应第一/二层风险，是数据运营里最该优先走通的口径。

## 6.1 抖音开放平台：能力真实存在，但门槛是「会员制」

先说好消息：抖音开放平台确实提供数据接口，不是完全没有。按官方文档，账号授权后可以取两类数据（官方文档，S1）：

- **主页维度**：近 30 天主页数据，含点赞、粉丝、评论、分享、主页访问。
- **视频维度**：指定视频近 30 天数据。

坏消息是，这套接口像「会员制健身房」——公开宣传里有，但进门要先过四道闸：

| 门槛 | 官方口径 | 对运营者的实际含义 |
|---|---|---|
| 粉丝门槛 | 仅粉丝 ≥ 1000 的账号可授权 | 新号、小号拿不到官方数据接口 |
| 数据新鲜度 | 授权次日约 10 点刷新 | T+1 口径，看不到实时，复盘天然滞后一天 |
| 聚合能力 | 无现成聚合能力 | 平台不提供「多作品汇总看板」，需自行分页拉取再本地汇总 |
| 申请方式 | 普通号需在控制台逐项申请；经营号（品牌/员工/合作号）默认授权 | 前置审批 + 权限逐项开通，不是开箱即用 |

[!tip] 大白话
把抖音官方数据接口想成一家「会员制健身房」：不是没有器材，而是没到 1000 粉这档会员，前台不给你门禁卡。就算进了门，器械上的读数也不是实时的，而是「昨天下班前结算好的报表」（授权次日约 10 点刷新）。所以官方口径的复盘，天然是「昨天的账」，不是秒级大屏。

再看「无聚合、需分页自算」这条——官方只给每一条原始流水，不给「本月涨跌」的总账。想在周报里看趋势，得自己写脚本把每页数据拉下来，在 Excel 或数据库里做透视汇总。加上个保法合规要求（取的是本人账号授权数据也要按个保法处理，官方文档，S1），「官方数据分析工具」对中小账号来说，体验上接近空白——这正是第一章识别出的两个显性缺口之一（见第 1.2 节），也解释了为什么数据侧的成熟开源项目大多绕开官方 API，走创作者中心自动化（见 6.3）。

还有一个待核实点：抖音经营号（品牌/员工/合作号）的具体能力范围与 scope，需要登录开放平台后台逐一核对（官方文档，S2?）。本章只引用文档字面口径，实操时以你账号后台实际能申请到的能力为准。

## 6.2 小红书：没有「官方 API」，只有「官方导出」

小红书的现状比抖音更朴素。按第三方数据合规路径综述，个人号 / 专业号**没有自账号批量导出 API**；合规取数只有两条腿（第三方综述，S9）：

| 账号类型 | 可用官方通道 | 说明 |
|---|---|---|
| 个人号 / 专业号 | 创作者中心导出 Excel | 人工在后台点「导出数据」，官方给 Excel |
| 企业专业号 | 专业号后台导出 CSV | 后台自带 CSV 导出能力 |
| 品牌 / 蒲公英 | 蒲公英数据 API | 门槛：品牌近一年消耗 > 500 万或进入白名单（第三方综述，S7） |

蒲公英的数据 API 门槛很高，个人和普通专业号基本无法接入；小红书开放平台入口存在（open.xiaohongshu.com），但登录后实际能申请到哪些能力未核（官方入口，S6?）。

[!warning] 边界说明
小红书《用户协议/社区规范》里禁止爬虫/外挂的具体条款，本次盘点未取得一手原文（第三方综述作者亦标注为 gap，S9?）。因此本章只把「创作者中心导出 Excel / 企业专业号导出 CSV」认定为无争议的官方口径；个人号若想批量拉取自己的数据但不想手动点导出，就落到了下一节工具的范畴——它自动化的是「官方导出按钮」，而非爬公开数据。

## 6.3 xhs_douyin_content：把「官方导出」脚本化

`cwjcw/xhs_douyin_content`（GPL-3.0，约 303★）抓的正是自家抖音 + 小红书**创作者中心**的每作品数据，而不是别人主页。它把 6.2 里「人工点导出」这件事脚本化：Selenium 驱动 Edge 登录创作者中心，自动点「导出数据」，再把下载的 Excel 合并成一张汇总表（项目 README / 源码，X-R）。

抓取指标覆盖了作品维度最常用的口径（字段映射见 `project_config/project.py`）：

- **播放表现**：播放量、完播率、5s 完播率、封面点击率、2s 跳出率、平均播放时长
- **互动表现**：点赞量、分享量、评论量、收藏量
- **账号成长**：主页访问量、粉丝增量
- **基础信息**：所属平台、数据日期、作品名称、发布时间、体裁、审核状态

工作机制一句话：**扫码登录 → cookies 存 pkl 缓存 → 之后每次跑脚本直接加载 pkl 免登录**。pkl 是 Python 的 pickle 序列化文件，放在 `pkl/` 目录，命名规则为 `douyin_*.pkl`、`xhs_*.pkl`（可多账号并存，工具会逐个处理）。

[!tip] 大白话
把 pkl 想成一张「门禁卡」：第一次扫码登录是办卡，之后每次脚本进创作者中心自动刷卡进门，不用再扫。卡会过期（登录态失效），过期就重新扫码补办一张。所以「扫码登录」只在第一次和卡过期时发生，不是每次运行都要扫。

它的风险定位处在第一层与第二层的交界：数据是自家账号的、动作是替人点「官方导出」按钮，在同类工具里合规风险相对最低；但它毕竟是浏览器自动化，创作者中心一改版、XPATH 一点、验证码一加，脚本就会失效，登录态也要人工续期——这是所有「自动点官方按钮」类工具的共同脆弱点（项目源码，X-R）。

## 6.4 实操示例：首次扫码登录与日常导出

下面按「先办卡、后刷卡」两步走。仓库目录结构大致如下（`pkl/` 与 `xlsx_file/` 为空文件夹，需自建）：

```text
xhs_douyin_content/
├─ main.py                  # 入口：依次跑 抖音 → 小红书 → 合并汇总
├─ requirements.txt
├─ project_config/
│  ├─ project.py            # 路径与字段映射（默认即可用）
│  └─ msedgedriver.exe      # Edge 驱动：需自行下载，见步骤 0
├─ spiders/
│  ├─ douyin.py             # 抖音创作者中心：加载 pkl → 点「导出数据」
│  └─ xhs.py                # 小红书创作者中心：加载 pkl → 点「导出数据」
├─ pkl/                     # 扫码登录后的 cookies：douyin_*.pkl / xhs_*.pkl
├─ xlsx_file/
│  ├─ douyin/douyin_汇总数据.xlsx
│  └─ xhs/汇总笔记列表明细表.xlsx
└─ data_processing/         # 二次分析脚本（按天增量对比，可选）
```

**步骤 0：准备依赖、目录与 Edge 驱动**

```bash
# 安装依赖（README 原句是 pip install requirements.txt，漏了 -r，正确如下）
git clone https://github.com/cwjcw/xhs_douyin_content.git
cd xhs_douyin_content
pip install -r requirements.txt
mkdir -p pkl xlsx_file/xhs xlsx_file/douyin
```

项目代码里驱动路径默认指向 `project_config/msedgedriver.exe`（`project_config/project.py`），所以还要下载与本机 Edge 主版本一致的 EdgeDriver 放到该目录；如果仓库里的 requirements.txt 在安装时报编码错误（Windows 上 pip freeze 常产出 UTF-16），先把它转成 UTF-8 再装即可。

**步骤 1：首次扫码登录，生成 pkl 门禁卡**

一个值得注意的坑：README 写「直接运行 main.py 第一次扫码登录」，但当前代码里 `Douyin.run_all()` / `Xhs.run_all()` 在 `pkl/` 目录为空时是直接「未找到任何 cookie 文件，任务终止」退出，并不会自动进入扫码流程。所以首次要先跑下面这段一次性脚本把 pkl 生成好（逻辑对齐 `xhs.py` 里的手动登录保存逻辑）：

```python
# login_first.py —— 首次扫码，运行一次后即可删除本文件
import pickle
from selenium import webdriver
from selenium.webdriver.edge.service import Service

DRIVER = "project_config/msedgedriver.exe"          # 与本机 Edge 版本匹配
HOME = "https://creator.xiaohongshu.com/statistics/data-analysis"
# 若给抖音办卡，把 HOME 换成：https://creator.douyin.com/creator-micro/home

driver = webdriver.Edge(service=Service(DRIVER))
driver.get(HOME)                                    # 打开创作者中心
input("在弹出的浏览器里扫码/登录，成功后回到终端按回车……")

# 小红书保存时会过滤 passport_csrf_token（对齐仓库源码）；抖音可不过滤
cookies = [c for c in driver.get_cookies() if c["name"] != "passport_csrf_token"]
with open("pkl/xhs_我的账号.pkl", "wb") as f:      # 抖音请命名 douyin_我的账号.pkl
    pickle.dump(cookies, f)
print("pkl 已保存，可以删除本脚本，直接跑 main.py")
driver.quit()
```

**步骤 2：日常运行与导出**

之后每天（建议低频，比如早上一次）直接跑入口脚本，它会自动加载 pkl、进创作者中心点「导出数据」、等待下载并把分散的 Excel 合并成汇总文件：

```bash
python main.py
```

预期输出的关键几行：

```text
▶ 开始处理 Douyin 数据
... ✅ 点击导出数据成功
... 📊 已成功导出汇总文件：xlsx_file/douyin/douyin_汇总数据.xlsx
▶ 开始处理 XHS 数据
... ✅ 汇总成功，已保存：xlsx_file/xhs/汇总笔记列表明细表.xlsx
```

README 还提到：如果只是关注单个平台，可以直接跑 `spiders/douyin.py` 或 `spiders/xhs.py`；想要「每天增量」对比，可以先把后台导出的文件命名为 `yesterday.xlsx`，再由 `data_processing/` 下的脚本做清洗对比（X-R）。

## 风险与失效提示

- 本层仍属「自动化」，虽然只是替人点官方导出按钮，但**不要高频并发**——创作者中心是后台，不是公开接口，短时间大量点击同样可能触发验证码或风控。
- pkl 登录态会过期；创作者中心页面一改版，代码里写死的「导出数据」按钮定位（XPATH）就会失效，需要跟进仓库更新或自行修。
- 若要研究他人数据 / 对标竞品，那是第 7 章采集器的范畴（第三层风险，须严守「学习研究」边界）；本章只解决「自己账号的官方口径复盘」。

## 本章小结

- 抖音官方数据接口真实存在（主页/视频近 30 天数据），但有四道门槛：粉丝 ≥ 1000、T+1 刷新、无聚合需分页自算、能力需逐项申请（经营号默认授权）。
- 小红书没有个人/专业号批量导出 API，合规取数靠创作者中心导出 Excel、企业专业号后台导出 CSV；蒲公英数据 API 门槛（年消耗 > 500 万或白名单）把普通账号挡在门外。
- `xhs_douyin_content`（GPL-3.0）把「创作者中心导出」脚本化：扫码登录 → pkl 缓存 → 自动点导出 → 合并 Excel，定位在官方口径与自账号自动化的交界，风险相对最低但依赖后台页面稳定。
- 首次使用要先跑一次性扫码脚本生成 pkl（README 与代码行为不一致：pkl 为空时 `main.py` 直接退出），之后才能低频跑 `python main.py`。
- 本章路径覆盖第一/二层风险，是数据复盘里的合规底座；想看「别人的数据」做对标，请带着第 7 章与第 8 章的红线再行动。

下一章进入数据运营的另一半：研究 / 对标向的采集器与互动管理——以 MediaCrawler 为代表的工具能力很强，但自定义非商用许可与第三层风险，决定了它们只适合标注「学习研究」的场景。
