# 第二章：核心命令组实战 —— core / supervisor / addons

第一章我们认识了 `ha` 的骨架。这一章进入真正的日常高频操作：管 Core、管 Supervisor、管 Addon。这三个命令组几乎覆盖了 80% 的日常运维场景，尤其是看日志、重启、升级。读完这章，你会对"房子"（Core）和"物业公司"（Supervisor）分别能干什么心里有数，也会掌握 addon 的安装、升级与日志查看。

## ha core：管理 Home Assistant 本体

`ha core` 管的是运行自动化、处理实体状态的 Python 应用本体。先看最常用的几个子命令。

### 查版本与状态

```bash
ha core info
```

输出要点：`version`（当前版本）、`version_latest`（最新可用版本）、`update_available`（是否有更新）、`state`（运行状态）。需要脚本解析时加 `--raw-json` 输出原始 JSON。

### 校验配置

改完 `configuration.yaml` 想先验证语法再重启，用 `check`：

```bash
ha core check
```

`check` 只校验配置语法，不重启服务，是"改配置后必跑"的保命命令。任何配置改动，先 `check` 再 `restart`，能避免把系统改到起不来的程度。

### 看日志

```bash
# 看 Core 日志，-f 跟随输出（类似 tail -f）
ha core logs -f
```

日志量很大，通常配合 grep 过滤关键词：

```bash
ha core logs -f | grep -i error
```

### 重启（含安全模式）

```bash
# 普通重启
ha core restart

# 安全模式重启：禁用所有自定义集成，只加载核心，用于排查是哪个集成搞挂系统
ha core restart --safe-mode

# 强制重启
ha core restart --force
```

`-s/--safe-mode` 是排障利器：系统起不来又不知道是哪个集成的问题，就进安全模式。`restart` 还有别名 `reboot`。

### 其他常用子命令

| 子命令 | 用途 | 关键参数 |
|--------|------|---------|
| `ha core start` / `ha core stop` | 手动启动/停止 Core | — |
| `ha core update` | 升级 Core | `--version x.y.z` 指定版本、`--backup` 升级前自动备份 |
| `ha core stats` | CPU/内存/网络/磁盘统计 | — |
| `ha core rebuild` | 重建 Core 容器镜像 | 改某些运行选项后需要 |
| `ha core options` | 运行选项 | `--boot`、`--port`(默认8123)、`--ssl`、`--watchdog` 等 |

注意 `ha core update` 的别名是 `upgrade` / `downgrade`，指定旧版本号即可降级回滚。

## ha supervisor：管理编排层

Supervisor 是管理所有容器的那层，`ha supervisor` 命令组管它自己。

```bash
# 总览：各组件版本、当前 channel（stable/beta/dev）
ha supervisor info

# 看 Supervisor 日志
ha supervisor logs -f

# 轻量重载配置（不需要重启）
ha supervisor reload

# 升级 Supervisor（升级顺序的第一步）
ha supervisor update

# 切换更新渠道
ha supervisor options --channel beta

# 列出所有可用更新
ha supervisor available_updates

# 资源统计 / 重启 / 修复
ha supervisor stats
ha supervisor restart
ha supervisor repair
```

关键点：

- `ha supervisor update` 是整个系统升级流程的**第一步**，必须先升 Supervisor 再升 Core/OS，否则可能出现版本兼容问题。
- `--channel` 可选 `stable` / `beta` / `dev`，日常用 `stable`，追求新功能才切 beta/dev。
- `repair` 用于 Supervisor 自我修复，某些异常状态可用它恢复。

## ha addons：管理附加组件

Addon 是运行在 Supervisor 管理下的独立容器（如 Mosquitto MQTT、SSH、Node-RED）。命令组语法和前面类似，但有个概念要先讲：**slug**。

### 认识 addon slug

slug 是 addon 的唯一标识，很多子命令都要用它。它有两种形态：

| 来源 | slug 形态 | 示例 |
|------|----------|------|
| 官方 addon | `core_` 前缀 | `core_ssh`、`core_mosquitto` |
| 社区 addon | 作者 GitHub ID 前缀 | `a0d7b954_adguard` |

获取某个 addon 的 slug 有三种办法：

1. addon 详情页 URL：`/hassio/addon/<slug>/info` 中间那段就是 slug；
2. `docker ps` 看容器名：容器名是 `addon_<slug>`；
3. 在 Web UI 的 addon 页面点开详情，浏览器地址栏里能看到。

### 安装、升级、卸载

```bash
# 列出已安装 addon
ha addons

# 查看 addon 详情（不加 slug 默认看 self）
ha addons info core_mosquitto

# 安装 addon（只装最新版，不能指定版本）
ha addons install a0d7b954_adguard

# 升级 addon
ha addons update core_ssh

# 升级并自动备份
ha addons update core_ssh --backup

# 卸载
ha addons uninstall core_mosquitto
```

注意 `install` 只能装最新版；要装历史版本得在 Web UI 里操作。`update` 别名 `upgrade` / `up`，**当没有可用更新时，`update` 会返回退出码 1** —— 写脚本判断成败时记得把退出码 1 当"已最新"处理，不要当成失败。

### 生命周期控制与日志

```bash
# 启动 / 停止 / 重启
ha addons start core_mosquitto
ha addons stop core_mosquitto
ha addons restart core_mosquitto

# 看日志（-f 跟随）
ha addons logs core_mosquitto -f

# 只看最近 100 行
ha addons logs core_mosquitto --lines 100

# 资源统计（CPU/内存/网络/磁盘）
ha addons stats core_mosquitto

# 重建容器镜像（addon 内部文件损坏时用）
ha addons rebuild core_mosquitto

# 看更新日志
ha addons changelog core_mosquitto
```

### 综合示例：装一个新 addon 的完整链路

下面演示从安装到看日志的一条龙，以社区 addon AdGuard Home 为例：

```bash
# 1. 安装
ha addons install a0d7b954_adguard

# 2. 确认装上了
ha addons

# 3. 启动它
ha addons start a0d7b954_adguard

# 4. 看它是否健康运行
ha addons stats a0d7b954_adguard

# 5. 有问题就看日志
ha addons logs a0d7b954_adguard -f
```

## 三个命令组的对照记忆

| 操作 | Core | Supervisor | Addon |
|------|------|-----------|-------|
| 看信息 | `ha core info` | `ha supervisor info` | `ha addons info <slug>` |
| 看日志 | `ha core logs -f` | `ha supervisor logs -f` | `ha addons logs <slug> -f` |
| 重启 | `ha core restart` | `ha supervisor restart` | `ha addons restart <slug>` |
| 升级 | `ha core update` | `ha supervisor update` | `ha addons update <slug>` |
| 统计 | `ha core stats` | `ha supervisor stats` | `ha addons stats <slug>` |

规律很清晰：三组的子命令名几乎完全一致，区别只在第一个参数是组名、以及 addon 需要多给一个 slug。记一个组的用法，其余两组自动会了。

## 本章小结

- `ha core` 管 Core 本体：`info` 查版本、`check` 校验配置、`logs -f` 看日志、`restart --safe-mode` 安全重启、`update --version` 升级/降级。
- `ha supervisor` 管编排层：`update` 是升级第一步、`options --channel` 切渠道、`reload` 轻量重载、`repair` 自我修复。
- `ha addons` 管 addon：核心是记住 **slug**（官方 `core_*`、社区 `作者ID_*`），三处可查 slug。
- `ha addons update` 无更新时退出码为 1，脚本判断要区分"已最新"与"真失败"。
- 三组子命令结构高度一致，记一组通三组。
