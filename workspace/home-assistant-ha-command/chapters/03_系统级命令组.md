# 第三章：系统级命令组 —— host / os / network / hardware

第二章讲的是应用层。这一章再往下沉一层，摸到硬件和系统：宿主机（host）的开关机、操作系统（os）的升级与数据盘管理、网络（network）的静态 IP 配置、硬件（hardware）信息查看。这几组命令的权限边界更高，**一旦误操作影响面是整个设备**，所以这一章我会特别标注哪些命令要谨慎。

## ha host：管理宿主机

`ha host` 管理的是这台物理机（树莓派、绿板、NUC 等）本身。

### 重启与关机

```bash
# 立即重启宿主机 —— 执行前先备份、保存手头工作
ha host reboot

# 关机 —— 注意：关了就没人帮你开机，需要手动上电
ha host shutdown
```

这两条命令都是**立即执行**的，没有倒计时。在远程维护时尤其要小心，重启后 SSH 会断开，等系统起来了再重连。

### 宿主机信息与改名

```bash
# 宿主机信息
ha host info

# 修改主机名
ha host options --hostname my-home
```

### 启动日志与磁盘

```bash
# 宿主机启动日志
ha host logs boots

# 磁盘使用情况
ha host disks usage
```

> 版本提示：旧文档里出现过 `ha host update`，但新版本源码已无此子命令。**OS 升级请走 `ha os update`**，不要照旧文档敲 `ha host update`。任何不确定的命令，先 `ha host --help` 确认。

## ha os：管理 HAOS 操作系统

`ha os` 管理的是 Home Assistant 操作系统镜像本身。HAOS 采用 **A/B 双槽（boot slot）** 设计，升级会切到另一个槽，失败自动回退到上一个槽，这也是它相对安全的原因。

### 升级 HAOS

```bash
# 升级到最新版
ha os update

# 指定版本升级
ha os update --version 15.2
```

升级前务必做好备份并保证供电稳定（别在 UPS 没接的情况下降级/升级时断电）。升级走的是双槽切换机制，切过去后如果启动失败会自动回退，但仍建议先备份。

### 查看双槽版本

```bash
ha os info
```

输出要点：当前在跑的 OS 版本、另一个槽的版本、当前活动槽。升级失败回退后，这个命令能帮你确认当前实际运行在哪个版本。

### 数据盘管理（高危）

```bash
# 列出数据盘
ha os datadisk list

# 迁移数据盘（把系统数据迁移到新盘）
ha os datadisk move

# 抹除数据盘 —— 不可逆，全盘数据删除！
ha os datadisk wipe
```

`ha os datadisk wipe` 会删除数据盘上的**所有数据**，且要求输入 `YES` 确认。这条命令是**本地终端专用**，SSH 终端里执行不了，必须用 HAOS 系统控制台（第一章提到的键盘+屏幕直连）操作。执行后如果数据还在，多半是坏盘，需要更换存储介质；部分硬件还要求按实体按钮（如 Yellow+CM4 的红钮、Green 的黑钮）才能真正完成抹除。

### 其他 os 子命令

| 子命令 | 用途 |
|--------|------|
| `ha os import` | 从 USB 导入配置 |
| `ha os config swap options` | 配置 swap（`--swap-size`、`--swappiness` 0-200） |
| `ha os boot_slot` | 查看/切换启动槽 |
| `ha os boards` | 板卡配置 |

## ha network：网络配置

`ha network` 由 NetworkManager 驱动，管网卡的 IP、网关、DNS。最常见的场景是**把设备改成静态 IP**。

### 查看网络状态

```bash
ha network info
```

输出要点：每块网卡的 IP、网关、DNS、获取方式（`auto`/`static`）。注意看 `nameservers: []` —— 空数组意味着 **DNS 未配置**，这是很多"能上外网但域名解析失败"问题的根源。

### 配置静态 IP（完整链路）

以接口 `eth0` 为例，配置静态 IP、网关、双 DNS：

```bash
ha network update eth0 \
  --ipv4-method static \
  --ipv4-address 192.168.1.100/24 \
  --ipv4-gateway 192.168.1.1 \
  --ipv4-nameserver 8.8.8.8,8.8.4.4
```

关键参数说明：

| 参数 | 含义 |
|------|------|
| `--ipv4-method static` | 静态方式；可选 `auto`（DHCP）或 `disabled` |
| `--ipv4-address 192.168.1.100/24` | IP 地址带掩码（**必须带 /24 这样的掩码**，不带会报错） |
| `--ipv4-gateway 192.168.1.1` | 网关 |
| `--ipv4-nameserver 8.8.8.8,8.8.4.4` | DNS，多个用逗号分隔 |

配置完用 `ha network info` 验证，如果没生效，执行 `ha network reload` 重载网络配置（NetworkManager 驱动）：

```bash
ha network reload
ha network info
```

### 其他 network 子命令

```bash
# 扫描可用 WiFi
ha network scan

# 配置 WiFi（连接 WPA2 网络）
ha network update wlan0 --wifi-ssid my-home --wifi-psk yourpassword

# 关闭 mdns / llmnr（某些环境下局域网发现异常时可调）
ha network update eth0 --mdns false --llmnr false

# VLAN 管理
ha network vlan
```

> 坑位提醒：改静态 IP 不生效时，多半是"网关只设在一个主接口上"或没 `reload`。多网卡设备注意网关不要重复配置。

## ha hardware：查看硬件信息

`ha hardware` 提供系统硬件信息，配合 `ha resolution info` 排查兼容性问题。

```bash
# 硬件信息总览（--raw-json 便于脚本解析）
ha hardware info --raw-json

# 音频设备信息
ha hardware audio
```

`ha hardware info` 输出主板、CPU、内存、磁盘控制器等信息；当 Supervisor 报 `unsupported` 或兼容性问题时，它和 `ha resolution info` 是排障的两板斧。

## 本章小结

- `ha host` 管物理机：`reboot` / `shutdown` 立即执行，远程操作要谨慎；旧文档的 `ha host update` 已废弃，升级 OS 走 `ha os update`。
- `ha os` 管 HAOS：`update --version` 升级、`info` 看 A/B 双槽、`datadisk wipe` 全删数据且仅限本地终端，高风险。
- `ha network` 配网络：静态 IP 链路是 `network update eth0 --ipv4-method static ...` → `network info` 验证 → 不生效再 `network reload`；`nameservers: []` 表示 DNS 没配。
- `ha hardware` 查硬件：`info --raw-json` 与 `audio` 两个子命令，配合 `ha resolution info` 排兼容性。

下一章进入诊断面：用 `ha info` 看系统总览、用 `ha jobs` 排查卡住的后台任务、用 `ha resolution` 处理 Supervisor 发现的健康问题。
