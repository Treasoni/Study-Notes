## 显存是什么？GPU 的专属工作台

买电脑时你经常听到「内存 16G」「显存 8G」，它们都带个「存」，却完全不是一回事。这一章要解决一个最基础也最关键的疑问：**显存到底是什么？它和内存有什么区别？为什么显卡离了它就转不动？** 搞懂了这张「专属工作台」，你才能看懂后面几章里「大模型为什么吃显存」「我的显卡能跑多大模型」。

### 1.1 CPU 与 GPU 的分工

在讲显存之前，先分清电脑里两个「干活的人」：CPU 和 GPU。它们的脾气完全不同。

#### 1.1.1 为什么 GPU 需要一块「专属」存储

CPU（中央处理器）是电脑的总指挥，擅长处理**复杂但一步接一步**的任务：打开软件、运行程序、管理文件，都需要它。它像一位总厨，负责统筹全局、处理各种精细活。

GPU（图形处理器）则完全是另一个物种：它擅长**海量、简单、可并行的运算**。一块显卡里有几千个甚至上万个「小计算单元」，能同时算一大片数据。渲染游戏画面、训练和运行大模型，本质上都是「同一套运算对着海量数据重复做无数遍」——这正是 GPU 的主场。它像一支炒锅队，几十口锅同时开火。

> [!tip] 大白话
> 把 CPU 想成餐厅总厨，把 GPU 想成一支炒锅师傅团队。总厨一个人要处理点菜、摆盘、协调等复杂杂事；炒锅队只做一件事——同时翻炒几百份菜。炒锅队火力猛、翻得快，但只会这一件事。

因为 GPU 干活时每一刻都在高速吞吐海量数据，它不能慢悠悠地去跟 CPU 抢系统内存用。如果几十口锅都跑去同一个大仓库取食材，仓库门口立刻堵死。所以 GPU 需要一块**离自己最近、速度最快、谁也抢不走的专属存储**。

#### 1.1.2 显存：焊在显卡上、与 GPU 直连的高速存储

这块专属存储，就是**显存（VRAM，Video Random Access Memory）**。它是专为 GPU 设计、与 GPU 核心直连的高速存储，直接焊在显卡上，是显卡的一部分。你买显卡时看到的「8GB」「12GB」「24GB」，指的就是这块存储的容量。

一句话记住它的地位：**显存是 GPU 的工作台，GPU 只能在工作台上干活。** 后面你会反复看到，这个「只能」是理解大模型部署一切问题的钥匙。

### 1.2 显存 vs 内存：一场「不可互换」的误会

很多人以为显存和内存差不多，缺了显存就加内存条——这是本笔记要纠正的第一个、也是最大的误会。它俩服务对象不同、位置不同、价格不同，**不可互换**。

#### 1.2.1 服务对象 / 容量 / 带宽 / 位置 / 成本对照表

先看一张对照表（带宽的概念 1.3 会细讲，这里先感受数量级）：

| 维度 | 内存（RAM） | 显存（VRAM） |
|------|-------------|--------------|
| 服务对象 | CPU | GPU |
| 物理位置 | 插在主板上，可自行加装升级 | 焊在显卡上，与 GPU 直连 |
| 典型容量 | 大（16 / 32 / 64 GB 常见） | 相对小（消费级常见 8 / 12 / 16 / 24 GB） |
| 带宽量级 | 低（DDR5 约 50-100 GB/s） | 高（GDDR6X/7 约 500-1000 GB/s，HBM3 可达 2-5 TB/s） |
| 设计目标 | 大容量、低延迟、便宜 | 高带宽、高吞吐、贵 |
| 成本 | 低 | 高（HBM 每 GB 成本可达内存的百倍） |

内存是 CPU 的「中央备料台」，容量大、便宜，谁都能用；显存是 GPU 的「猛火灶台」，离炒锅最近、火力最猛，但只给炒锅队用。GPU 求的是高带宽——一秒能灌进多少数据；CPU 求的是低延迟——发出指令后多久能拿到结果。目标不同，造出来的存储自然也不同。

> [!tip] 大白话
> 把内存想成厨房中央的备料台，显存想成每个炒锅师傅手边的猛火灶台。备料台很大、放得下所有食材，但离得远、取料慢；灶台离得近、火又旺，可地方小、只放得下当前要炒的菜。CPU 用备料台，GPU 用灶台，两者不能互相顶替。

#### 1.2.2 为什么「加内存条」救不了显存不足

核心规则只有一句：**GPU 只能读显存里的数据计算，内存再大也只是中转仓库。** 数据先要放到显存里，GPU 才算得动；放在内存里，GPU 够不着。

这就是为什么游戏或 AI 程序报 `CUDA out of memory` 时，你插再多内存条都没用——报错说的是**显存**不够，不是内存不够。举个真实场景：一台 32GB 内存 + 8GB 显存的电脑，加载一个约 14GB 的模型，照样报 CUDA OOM，因为那 14GB 必须装进 8GB 的显存里，32GB 内存帮不上忙。加内存条救不了显存不足，这是本地跑大模型被坑最多的一课。

### 1.3 显存四大参数：容量、频率、位宽、带宽

看显卡参数表，你总会碰到这四个词：**容量（GB）、频率（MHz）、位宽（bit）、带宽（GB/s）**。前三个是「原料」，第四个是「成品」——带宽才是真正决定显卡快慢的核心指标。

> [!tip] 大白话
> 把显存系统想成一座水站。容量 = 水池大小，决定能存多少水；频率 = 进水管的水流速度，决定水跑得多急；位宽 = 水管直径，决定一次能并排进多少水；带宽 = 进水总速度，是最终「每秒能灌进多少水」的合体结果。

#### 1.3.1 带宽 = 频率 × 位宽 ÷ 8

带宽的公式是显存知识里最值得记住的一个式子：

```text
带宽（GB/s）= 频率（MHz） × 位宽（bit） ÷ 8
```

拆开看三个部件：

- **容量（GB）**：工作台能摆多少数据，决定「装不装得下」。
- **频率（MHz）**：显存一秒钟读写多少次，像进水管的水流速度。
- **位宽（bit）**：一个时钟周期能传多少位数据，相当于水管直径或马路宽度。消费级显卡常见位宽梯度是 128 / 192 / 256 / 384 bit。
- **带宽（GB/s）**：最终每秒能传多少数据，是「频率 × 位宽」合起来的效果。

末尾「÷8」是因为 8 bit = 1 Byte，而带宽习惯用字节（GB/s）表示。

> [!tip] 大白话
> 把带宽想成高速公路的车流量。位宽 = 车道数（8 车道比 4 车道能同时跑更多车），频率 = 限速（每辆车跑多快），带宽 = 每小时实际通过的车总数。想多通车，多修车道和提速都有效，缺一不可。

一个常见误区：**显存频率 ≠ GPU 核心频率**，两个「频率」是完全不同的东西。另一个容易忽略的点：位宽一旦缩水，代价很大——位宽从 256 bit 降到 128 bit，显存带宽性能大约下降 32%。

#### 1.3.2 落地例子：RTX 4090 ≈ 1TB/s、RX 7900XTX ≈ 960GB/s

公式背下来之后，看两个真实例子把它落地：

- **RTX 4090**：高频 GDDR6X 显存 × 384 bit 位宽 ÷ 8 ≈ **1 TB/s** 带宽。
- **RX 7900 XTX**：20 Gbps × 384 bit ÷ 8 ≈ **960 GB/s** 带宽。

再对比内存：CPU 的内存位宽常年是 64 bit。位宽差了数倍、频率又低，所以显存带宽能比内存高出**数十倍**——这也是 GPU 必须配专属显存的原因之一。

### 1.4 容量 ≠ 性能：够用即可

容量和带宽，一个管「装不装得下」，一个管「跑得快不快」。**显存大不代表显卡强**，容量和性能并不成正比。

一个经典反例：RTX 3060 有 12GB 显存，RTX 3080 只有 10GB，但 3080 整体性能明显更强——因为它的带宽、核心算力全面占优。反过来，如果容量不足，数据装不下，就会爆显存、掉帧卡顿；容量过剩，多出来的部分也不会让性能再提升。

> [!tip] 大白话
> 把显存容量想成行李箱的大小。箱子大，只代表能装更多东西，不代表你走得快；走得快不快，取决于你的腿脚（带宽）和体力（GPU 核心）。买显卡别只盯着箱子多大。

#### 1.4.1 分辨率参考：1080P ≈ 6GB / 2K ≈ 8GB / 4K ≥ 12GB

不同负载对显存容量的需求差很远。以游戏渲染为例，一个粗略参考：

| 负载 | 显存参考 |
|------|----------|
| 1080P 游戏 | 约 6GB |
| 2K 游戏 | 约 8GB |
| 4K 游戏 | 12GB 起步 |

这是游戏场景的经验参考值：4K 分辨率画面数据量大，需要更大的「工作台」。注意，这仅仅是游戏渲染的参考——**跑大模型是另一套算法**，需要的显存由参数量、精度、上下文长度决定，第 2 章专门讲。

#### 1.4.2 爆显存（崩溃报错）vs 爆内存（整机卡顿）

容量不够时会「爆」，但爆显存和爆内存的症状完全不同，很好区分：

| 情况 | 表现 |
|------|------|
| 爆显存 | 正在跑的程序**中途崩溃、弹报错**（如 `CUDA out of memory`、显存不足），但电脑系统本身还能用 |
| 爆内存 | **整机变卡顿**，系统提示内存不足，其他程序也跟着遭殃 |

记住这个区别，以后看到报错就能立刻判断问题出在显存还是内存，不会一通乱加硬件。

### 1.5 显存家族扫盲：GDDR vs HBM

显存不是一个统一的东西，按用途分两大「家族」：面向普通消费级的 GDDR，和面向数据中心/专业卡的 HBM。

| 家族 | 定位 | 代表型号 | 位宽 | 带宽量级 |
|------|------|----------|------|----------|
| GDDR | 消费级显卡主流 | GDDR5 / 6 / 6X / 7 | 128-384 bit | 约 500-1000 GB/s |
| HBM | 数据中心、专业计算 | HBM2 / HBM3 | 1024 bit 起步 | 可达 2-5 TB/s |

- **GDDR 家族**：靠「高频率 + 大位宽」硬堆带宽，是游戏卡和消费级 AI 卡的绝对主力。代际演进明显：GDDR5 → GDDR6 → GDDR6X → GDDR7，每一代都在提频提速（GDDR7 还引入了 PAM-3 信号技术）。
- **HBM 家族**：采用 3D 堆叠 + 硅通孔（TSV）技术，把多层存储像叠高楼一样叠起来，用极宽的接口取数据，位宽 1024 bit 起步，带宽轻松破 TB/s。代价是贵——每 GB 成本可达内存的百倍，所以几乎只出现在高端专业卡和数据中心。

对我们普通用户，一句话建议：**消费级显卡认准 GDDR 就行，不必纠结 HBM**。如果你的目标是本地跑大模型，入门建议选 **12GB 显存起步**，这正好呼应第 4 章的选卡速查表。

---

**本章小结**

- 显存（VRAM）是焊在显卡上、与 GPU 直连的专属高速存储；GPU 只能读显存里的数据，内存再大也只是中转仓库。
- 显存与内存不可互换：服务对象、位置、带宽、成本都不同，显存带宽可超内存数十倍。
- 显存四大参数：容量、频率、位宽、带宽；核心公式是 **带宽 = 频率 × 位宽 ÷ 8**。
- 容量决定「装不装得下」（1080P ≈ 6GB / 2K ≈ 8GB / 4K ≥ 12GB），带宽决定「快不快」；显存够用即可，不是越大越好。
- 爆显存是程序崩溃报错，爆内存是整机卡顿，两者症状完全不同。
- GDDR 是消费级主流，HBM 是数据中心级；本地跑大模型入门建议 12GB 起步。
