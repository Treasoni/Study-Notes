## 本地部署实战——看显存、选模型、跑起来

前三章我们把概念铺完了：显存是什么、大模型为什么吃显存、量化怎么把模型压缩。这一章全部变成动手操作，目标很具体——**查自己显卡有多少显存 → 判断能跑多大模型 → 用 Ollama 一行命令跑起来 → 遇到显存不足能自己排障**。所有命令都能直接照抄。

### 4.1 动手前：nvidia-smi / GPU-Z 看显存

部署前第一件事，先看清自己手里有什么牌：显卡型号、总显存、现在被占了多少。

NVIDIA 显卡在终端里输入 `nvidia-smi`：

```bash
nvidia-smi
```

输出顶部能看到显卡型号、驱动版本和显存信息，其中关键一行是「Memory-Usage」，格式类似：

```text
| NVIDIA GeForce RTX 4090        |
|    22GB / 24GB                 |
```

- 左边是当前已用显存，右边是总显存。
- 注意：**总显存 ≠ 全部可用**。系统会悄悄占用一部分，比如 24GB 的 4090 实际可用约 22GB。估算模型显存时，别把 24 当满打满算。

Windows 上不想敲命令，也可以用 **GPU-Z** 这类图形工具，第一行直接显示显卡型号和显存大小，适合看入门信息。

> [!tip] 大白话
> 把 `nvidia-smi` 想成显卡的仪表盘。总显存 = 油箱总容量，已用显存 = 当前油量，剩余可用的那格油才是你能跑的。估算前先看看油表，别一上来就按满箱算。

### 4.2 我的显卡能跑多大模型

知道显存后，下一个问题是：它装得下多大的模型？

#### 4.2.1 估算公式：参数量 × 位宽 ÷ 8 × 1.2

实战圈流传一条快速估算公式，把第 2、3 章的知识浓缩成一行：

```text
所需显存（GB）≈ 参数量（B）× 位宽 ÷ 8 × 1.2
```

拆开看：

- **参数量（B）**：模型有多少亿参数，如 7B、14B。
- **位宽**：按精度填，FP16 用 16、INT8 用 8、Q4/INT4 用 4。这就是「每参数字节数」的 bit 表达（÷8 转成字节）。
- **× 1.2**：留约 20% 余量，覆盖 KV Cache、框架开销和安全系数。

动手算三个常见档位：

```text
7B  Q4：7  × 4  ÷ 8 × 1.2 ≈ 4.2GB  → 约 4GB
14B Q4：14 × 4  ÷ 8 × 1.2 ≈ 8.4GB  → 约 8GB
27B Q4：27 × 4  ÷ 8 × 1.2 ≈ 16.2GB → 约 15-16GB
```

一个更快的「心算口诀」：每 10 亿参数，BF16 约 2GB、FP8 约 1GB、INT4 约 0.5GB。记住这个比例，平时不用掏计算器。

#### 4.2.2 8 / 12 / 16 / 24 / 32GB 显存档位速查表

把公式套到常见显卡显存上，得到一张「我的显卡能跑啥」速查表（Q4 量化档为主）：

| 显存 | 参考模型（量化档） | 说明 |
|------|--------------------|------|
| 8GB | Gemma3-4B Q4 ≈ 5GB；Qwen3-8B Q4 ≈ 7.5GB | 入门门槛，只能跑小模型 |
| 12GB | Qwen3-8B Q8 ≈ 11.5GB；Phi-4 14B Q4 ≈ 9.9GB | 跑 7-8B 很从容 |
| 16GB | Qwen3-14B Q4 ≈ 12GB；DeepSeek R1 14B Q8 ≈ 16GB | 多数人的甜点档 |
| 24GB | Qwen3-32B Q4 ≈ 23GB | 可跑 30B 级（如 RTX 4090） |
| 32GB | Qwen3-32B Q8 完整装入 | 27B-32B 从 Q4 升到 Q8，质量更好 |

读这张表的两个要点：

- **16GB 是多数人的甜点档**：能舒服地跑 14B 级模型，兼顾质量和速度。
- **显存够时，优先升量化档，而不是换更大的模型**：32GB 比 24GB 多的价值，主要是让 27B-32B 从 Q4 升到 Q8，而不是硬塞 70B。

> [!tip] 大白话
> 选量化档位就是在选压缩率，和第 3 章的行李打包是同一件事：Q8 是轻压缩、Q4 是高压 zip。显存够用了，就别急着换更大的行李箱（换大模型），先把同箱行李从高压袋换回轻压缩，质量立马上一个台阶。

### 4.3 Ollama 一条命令上手

估算完心里有数，就可以动手跑了。**Ollama** 是目前最省事的一键部署工具：去官网下载对应系统的安装包装好，命令行里两条命令就能拉模型、跑模型。

#### 4.3.1 安装与 pull（注意 tag 带 q4_K_M，避免拉到 FP16）

拉取模型用 `ollama pull`：

```bash
# 基本拉取命令
ollama pull qwen:7b
```

Ollama 的模型用「模型名:标签」表示，**标签里带 `q4_K_M` 的就是 4bit 量化版**。这里有一个新手最容易踩的坑：不指定标签时，部分模型默认拉的是未量化（FP16）原版，7B 直接 14GB，小显存立刻 OOM。所以拉取前先在模型库页面确认带 `q4_K_M` 的标签，格式类似 `模型名:版本-q4_K_M`，再按这个标签拉：

```bash
# 推荐：显式指定带 q4_K_M 的量化版标签
# 具体标签名以模型库页面为准
ollama pull 模型名:版本-q4_K_M
```

> [!tip] 大白话
> Ollama 像点外卖。`ollama pull` 就是下单，系统自动把模型下载、环境、运行依赖一起打包好送到你面前，你只管「吃」。但下单时一定要看清套餐（tag）：不选量化套餐，可能给你上一份 14GB 的「全家桶」，小胃（小显存）直接撑爆。

#### 4.3.2 run 与 ollama ps 看 /GPU 字段

拉下来后运行：

```bash
# 跑起来（如果还没拉过，会自动先拉取）
ollama run qwen:7b
```

进入交互界面后直接打字就能对话。想让模型在后台运行、需要开一个终端查它到底跑在哪，用 `ollama ps`：

```bash
ollama ps
```

输出是一个表格，关键看最后一列**处理器（PROCESSOR）字段**：

- `/GPU`：模型跑在显卡上，正常。
- `/CPU`：模型没跑在显卡上（多半是显存不够被降级到 CPU），速度慢 10-100 倍，需要排查。

> [!note] 提示
> 如果 `ollama ps` 显示 `/CPU`，最常见的三个原因：显存装不下、上下文开太大、tag 拉错了。逐个用下面的三板斧排查。

### 4.4 llama.cpp 进阶路线（可选）

Ollama 底层其实就是 **llama.cpp**。想更精细地控制「模型哪些层放 GPU」，可以直接用 llama.cpp。它通过 `-ngl` 参数控制放进 GPU 的层数。

#### 4.4.1 -ngl 控制 GPU 层数

```bash
# -ngl 后面是放进 GPU 的层数，例如 33
llama-cli -m model.gguf -ngl 33
```

- `-ngl`（全称 `--n-gpu-layers`）告诉引擎「把前 N 层放进 GPU」。
- 显存充足就调大 `-ngl`，让更多层用 GPU 加速；显存不足就调小，把更多层留给 CPU。

#### 4.4.2 offload 到 CPU：慢但能跑

当显存不够时，llama.cpp 不会直接崩溃，而是把放不下的层**卸载（offload）到 CPU 内存**里跑。速度明显变慢，但至少能跑——这是「能跑」和「跑不动」之间的关键缓冲。例如一台 8GB 显存的笔记本，partial offload 也能跑起 32B Q4_K_M，只是速度掉到每秒约 10 个 token 的量级（能对话，但不算流畅）。

### 4.5 OOM 排障三板斧

遇到 `CUDA out of memory` 别慌，这是本地部署最常见的报错。按顺序试三板斧，大部分情况都能解决：**降上下文 → 降量化档 → offload / 换更小模型**。

#### 4.5.1 降上下文（--num-ctx 2048/1024）

第一板斧，也是见效最快的一招：把上下文长度调小。KV Cache 随上下文线性增长（第 2 章讲过），调小它立刻释放一大块显存。

```bash
# Ollama 运行时指定小上下文
ollama run qwen:7b --num-ctx 2048
```

把上下文从默认的大窗口降到 2048，还不够就 1024。Ollama 也可以用环境变量 `OLLAMA_CONTEXT_LENGTH` 统一设置。

> [!tip] 大白话
> 把上下文想成教室里的临时黑板。黑板越大，能同时写的字越多，但占的墙面（显存）也越多。写不下了，就把黑板换小一号——先让课讲起来，黑板大了写得多只是锦上添花。

#### 4.5.2 降量化档位

第二板斧：把模型从高精度换到更低精度。Q8 换成 Q4_K_M，权重显存直接减半；再不行从更大模型换小模型的 Q3 档。Q4_K_M 是质量/体积的平衡点，再往下（如 Q3）质量下降就比较明显了，所以优先在 Q8 和 Q4_K_M 之间切换。

#### 4.5.3 offload / 换更小模型

最后一板斧，两个动作：

- **offload**：用 llama.cpp 的 `-ngl` 减小 GPU 层数，把部分层卸到 CPU（4.4.2）。
- **换更小模型**：14B → 7B → 4B。记住那句口诀——显存不够时先降档、再换小；显存够用时优先升档而不是换大。

三板斧的完整顺序，就是从上到下、从「损失最小」到「损失最大」，每一步都先试试再说。

### 4.6 实战常见坑汇总

把上面散落的坑集中成一张表，排障时对照着看：

| 坑 | 现象 | 解法 |
|----|------|------|
| 内存冒充显存 | 模型被装进 CPU 内存而非显存，慢 10-100 倍 | `ollama ps` 看是否 `/GPU`，不是就排查 |
| 选错量化档位 | `ollama pull` 没指定 tag 拉到 FP16，7B 直接 14GB | 拉带 `q4_K_M` 的标签 |
| 上下文开太大 | 默认大上下文把 12GB 卡撑 OOM | 降 `--num-ctx 2048/1024` |
| 显存被系统吃掉 | 24GB 卡实际可用约 22GB | 估算留余量，别按满显存算 |
| 被 MoE 文件体积骗了 | 16B MoE 下载才 6GB，实际显存要 23GB | MoE 看总参数，别只看下载体积 |
| vLLM + bitsandbytes 不兼容 | 进阶场景报量化加载错 | 设 `VLLM_USE_V1=0`（进阶用到再说）|

最后一条涉及 vLLM，属于第 5 章进阶内容，这里记个印象即可：遇到再回来翻。

---

**本章小结**

- `nvidia-smi` 查显存，注意总显存 ≠ 全部可用（24GB 实际约 22GB）。
- 估算公式：**所需显存 ≈ 参数量 × 位宽 ÷ 8 × 1.2**；7B Q4 ≈ 4GB、14B Q4 ≈ 8GB、27B Q4 ≈ 16GB。
- 显存档位速查表：8GB 跑 4B 级、12GB 跑 7-8B、16GB 是甜点档、24GB 跑 32B Q4、32GB 让 27-32B 升 Q8。
- Ollama 一条命令上手：`ollama pull`（tag 带 `q4_K_M`）→ `ollama run` → `ollama ps` 看 `/GPU`。
- llama.cpp 用 `-ngl` 控制 GPU 层数，显存不足 offload 到 CPU，慢但能跑。
- OOM 排障三板斧：降上下文 → 降量化档 → offload/换更小模型。
