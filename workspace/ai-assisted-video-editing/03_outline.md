## 学习笔记大纲：《AI 助手辅助视频剪辑的方法与工作流》

> 笔记类型：方法与工作流笔记（方法 / 工作流为主，能力边界与工具链为支撑章节）
> 主线：**human-in-the-loop 流水线**（agent 产出提案/粗剪，人保留方向、审美与最终批准）
> 预计总篇幅：中长（约 25–30 页）
> 章节数：7

### 第 1 章：AI 剪视频，到底能帮你做到哪一步

**本章目标**：在动手前建立正确预期 —— agent 是「编排层/操作员」而不是剪辑器；用它之前先判断内容类型。

- **篇幅**：短
- **覆盖要点**：agent 能力画像（无 GUI、无「眼睛」，经沙箱 shell 驱动 ffmpeg/Whisper 等确定性工具）、能稳定接管清单（批量转码/裁剪/拼接、删停顿口误、拆条、字幕识别与烧录、响度格式统一、代理/缩略图）、不能接管清单（节奏/情绪/逐帧精剪/B-roll 判断/品牌与权利审查）、结构性盲区（concat 音画漂移等「静态分析不可见」错误会让 agent 在错误方案内反复调参）、效率真相与适用判断（模板化内容提效显著；创意内容 6 小时改 6 版反例）
- **素材引用**：[S1]、[S3]、[S4]（结构性盲区 14.86s 实测来自 P1 dev.to 线索，非 [S#] 源，**写作期需补源**）
- **代码示例**：无（至多一条「agent 不适合做什么」决策清单）

> 小节建议：
> - 能力画像：agent = 编排层，不是剪辑器
> - 能 / 不能稳定接管的两张清单
> - 结构性盲区：为什么 agent 会「自信地错下去」
> - 效率真相与适用判断：模板化 vs 创意（含 11.2h→10min/40s 与 6h/6 版两个对照案例）

### 第 2 章：素材工程化 —— 让 agent「读」视频，而不是「看」视频

**本章目标**：掌握把视频转成 agent 擅长的「文本 + 时间轴 + 结构化决策」，为后续流水线打底。

- **篇幅**：中
- **覆盖要点**：核心反模式（丢几万帧给 LLM = token 噪音、难复盘）、ASR 逐词时间戳转写（让停顿/口误/笑声/掌声变成可读信号）、多素材汇总成单一 `takes_packed.md` 决策文件、按需视觉化（局部 timeline 合成视图：胶片帧+波形+词标签+静音间隔，而非全片抽帧）、专业版「源时间决策记录」字段（sourceRange / keep-cut / reason / confidence / protectedFrames / narrative role）
- **素材引用**：[S5]、[S6]
- **代码示例**：有（ASR/Whisper 转写命令入口、生成 takes_packed.md 的脚本示意；完整命令参数速查见第 5 章）
- **依赖**：Whisper 等命令细节在第 5 章展开，本章只给「最小可用」命令

> 小节建议：
> - 反模式：把视频堆成 token 只会更糟
> - 转写层：逐词时间戳如何把「废料」变成决策信号
> - 汇总层：takes_packed.md 单一决策文件
> - 视觉层：什么时候才需要「看图」，看图看哪里
> - 专业版：源时间决策记录 = 基于证据的剪辑

### 第 3 章：流水线设计与角色分工 —— 从需求到成片

**本章目标**：给出可复用的阶段化流水线骨架，以及每个环节「人 vs agent」谁负责。

- **代码示例**：有（镜头清单 JSON/CSV 结构示例、EDL 片段示意、流水线各阶段产物清单）

### 第 4 章：安全执行模型 —— 让 agent 批量跑命令不翻车

**本章目标**：建立「默认只读 + 最小写权限 + 可回滚 + 事务式命令」的授权与执行护栏。

- **素材引用**：[S1]、[S2]、[S3]、[S4]、[S5]
- **代码示例**：有（审批/沙箱/权限配置示例、diff 前置校验与幂等 operationId 的伪命令）

> 小节建议：
> - 三条底线：只读源、工作目录边界、最小权限
> - Claude Code / Codex 的权限与审批机制对照

### 第 5 章：工具链速查 —— FFmpeg / Whisper / yt-dlp 的 hard rules

**本章目标**：把支撑流水线的命令级事实收拢成速查，重点是「无损」和「不炸音频」。

- **篇幅**：中
- **覆盖要点**：FFmpeg 无损剪切/拼接（stream copy `-c copy`、concat demuxer、多段先分段抽取再无损 concat 且各片段编码参数一致）、每个剪切点 30ms audio fade 防爆音、字幕滤镜放滤镜链最后、字幕时间用输出时间轴而非素材时间轴、首版不烧录字幕（TTS/字幕从单一锁定脚本生成保关联）、Whisper 转写输出与 yt-dlp 下载的典型组合、产物隔离到独立输出目录（edit/）
- **素材引用**：[S3]、[S6]（无损 concat 前提另见 P1 LensB，非 [S#] 源；ffmpeg/yt-dlp 官方命令页未深读，**写作期补 1–2 篇权威页**）
- **代码示例**：有（ffmpeg 无损剪切/拼接、30ms fade、字幕烧录滤镜、Whisper 转写、yt-dlp 下载命令模板）

> 小节建议：
> - 无损三件套：stream copy、concat demuxer、编码参数一致性
> - 不炸音频规则：30ms fade、不在词中间下刀
> - 字幕的时序与层级：输出时间轴 + 滤镜链最后 + 首版不烧录
> - 素材获取：yt-dlp 下载与 Whisper 转写的最小命令
> - 目录卫生：产物一律进独立输出目录

## 学习路径说明

### 前置要求
- 会用终端，能安装并运行至少一种编码 agent（Codex CLI / Claude Code）
- 有基本视频剪辑概念（时间轴、剪切点、转场、字幕），不一定用过 FFmpeg
- 本机已装 FFmpeg（含 ffprobe）；可选的 Whisper、yt-dlp 在第 2/5 章用到

### 学完能做什么
- 动手前判断一个剪辑任务「该不该交给 agent」（内容类型 + 是否接受精调）
- 把一段视频素材转写、盘点成 agent 可读的「文本 + 时间轴 + 决策记录」工程
- 按第 3 章骨架搭一条「策略提案 → 人审 → 安全执行 → 验证 → 精修」的 human-in-the-loop 流水线
- 写出安全、可回滚、幂等的 FFmpeg / Whisper / yt-dlp 批处理命令，并用 ffprobe 验证产物
- 用第 6 章两层验证门判断「成片 + 可编辑工程」是否达标，并知道在哪一步自己上手精修

### 建议学习顺序
- 主线顺序：第 1 → 2 → 3 → 4 → 5 → 6 → 7（每章依赖前一章）
- 第 5 章工具速查可按需查阅，不必一次背完；第 2/4 章会正向引用它
- 第 7 章可提前浏览建立「避坑直觉」，再回头读主线
- 预估用时：通读约 2–3 小时；跟着第 2/5 章命令跑通一个小样片另加 2–3 小时
