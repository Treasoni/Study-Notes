## 第 6 章：验证门与人工精修 —— 怎么判断「剪完了」

前面几章把流水线推到了「渲染 preview、导出成片」这一步，但这恰是很多自动化剪辑翻车的地方：agent 报告「渲染成功、退出码 0」，不等于视频真的能用。本章回答一个必须由人回答的问题——**凭什么说「剪完了」**：先过两层可命令化的验证门，再逐剪切点自检，最后把「好不好」的终审交回给人。

### 6.1 两层验证门：先验工程，再验成片

第 3 章《流水线设计与角色分工 —— 从需求到成片》定了「成片 + 可编辑工程」双交付，所以「完成」要两个对象分别达标。第一层验工程、第二层验成片，顺序不能反：工程结构错了，重导出多少次都一样（S5）。

> [!tip] 大白话
> 把两层验证想成收房验收：工程验证是查图纸和管线——墙砌没砌、电线走得对不对；视频验证是拎包试住——灯亮不亮、会不会跳闸。agent 说「渲染完成」只等于施工队交了钥匙，两套检查都过了，你才签字收房。

**工程验证 checklist**（S5）：

- [ ] 轨道数量与计划一致
- [ ] 主画面连续、无空洞
- [ ] 片段顺序与时长符合镜头清单
- [ ] 每条字幕都绑定到一段可听见的对应语音
- [ ] 媒体文件已归档进工程包
- [ ] 工程能重新打开
- [ ] 预览首帧能正常显示

**视频验证 checklist**（S5）：

- [ ] 容器与编码正确（如 mp4 / H.264 + AAC）
- [ ] 视频尺寸、时长符合交付简报
- [ ] 整段能完整解码
- [ ] 音频轨存在
- [ ] 字幕、Overlay、效果可见
- [ ] 转场边界无停顿或重复帧
- [ ] 无声道错位与异常静音

第一扇门里最常漏的是「字幕绑定语音」——字幕在、却没有对应声音，是自动化字幕的典型病（S5）；第二扇门里最容易骗过眼睛的是转场边界与声道，这两类恰好要用命令去查。

### 6.2 用 ffprobe 把「看一眼」变成「查一下」

两层验证里凡是能命令化的，都别靠肉眼。下面四条都是标准用法，直接对产物跑，逐条对应 6.1 视频验证项：

```bash
# 1) 容器/编码/尺寸/时长/音轨一览
ffprobe -v error -show_entries \
  format=format_name,duration,size \
  :stream=index,codec_type,codec_name,width,height,r_frame_rate,sample_rate,channels \
  -of default=noprint_wrappers=1 final.mp4

# 2) 完整解码冒烟：全程解码到 null，任何解码错误都会打到 stderr
ffmpeg -v error -i final.mp4 -f null -

# 3) 冻结帧/重复帧检测：转场停顿、重复帧会打印 freeze_start / freeze_end
ffmpeg -i final.mp4 -vf freezedetect=n=-60dB:d=0.4 -map 0:v -f null -

# 4) 异常静音/声道：过长的静音段会打印 silence_start / silence_end
ffmpeg -i final.mp4 -af silencedetect=noise=-40dB:d=0.5 -f null -
```

第 2 条性价比最高：它强制解码每一帧，音画漂移、坏帧这类「静态分析不可见」的问题常在解码阶段现形（呼应第 1 章的结构性盲区）。第 3、4 条专补肉眼容易漏的「转场停顿/重复帧」与「异常静音」。

### 6.3 逐剪切点自检：跳帧、爆音、字幕遮挡

整片指标通过还不够，真正的坑集中在切点附近——这正是第 5 章《工具链速查 —— FFmpeg / Whisper / yt-dlp 的 hard rules》那几条规则（30ms audio fade、不在词中间下刀、字幕滤镜放最后）要防的东西。自检思路：把镜头清单/EDL 里的每个剪切时间点导出来，逐个在切点前后开一个小窗口检查。

```bash
# audit_cuts.sh —— 逐剪切点自检骨架（启发式，最终判断仍靠人眼/人耳）
# 用法: bash audit_cuts.sh final.mp4 cut_times.txt  （cut_times.txt 每行一个切点秒数）
file="$1"; cuts="$2"
while read -r t; do
  s=$(awk -v t="$t" 'BEGIN{printf "%.3f", (t-0.12 < 0 ? 0 : t-0.12)}')
  e=$(awk -v t="$t" 'BEGIN{printf "%.3f", t+0.12}')
  echo "== 剪切点 @ ${t}s =="
  # A. 视频：窗口内实际解码帧数应 ≈ 帧率×0.24s；明显偏少 = 疑似跳帧
  ffprobe -v error -count_frames -select_streams v:0 \
    -read_intervals "${s}+0.24" -show_entries stream=nb_read_frames \
    -of default=noprint_wrappers=1 "$file"
  # B. 音频：解码窗口统计音量，峰值接近 0dB = 疑似爆音/clipping，交耳朵复核
  ffmpeg -i "$file" -ss "$s" -to "$e" -af volumedetect -f null - 2>&1 \
    | grep -E "max_volume|mean_volume"
done < "$cuts"
```

这条脚本只做「数量级」告警（推断的简化方案，阈值需按素材自调）：帧数对不上就去看这一刀是否跳帧，音量顶到 0dB 就去听是否爆音。字幕遮挡命令查不出来，靠源头规则（字幕滤镜放滤镜链最后）防，精修时再到真实平台画幅上逐条看（S6）。

### 6.4 preview 即导出：同一条合成规则

「预览正常、导出坏了」几乎都来自同一根因：预览与导出走了两套合成规则（S5 明说预览走播放路径、导出走独立合成路径时就易出此类问题）。所以流水线立一条纪律：**preview 与最终导出共用同一条渲染命令、同一个滤镜图，只允许码率、分辨率这类显式声明的参数不同**。preview 通过≈导出通过，前提是二者除那几个参数外完全同源（S5/S6）。做不到同源时，最终导出后必须重跑 6.2 全套命令加一次人工抽检，不能拿 preview 结果代替。

### 6.5 人工精修：时机、范围与「谁说了算」

两层验证门保证「工程没坏」，但保证不了「片子好看」——这落在 agent 保留地之外（回看第 1 章两张清单）。

**时机**：preview 通过两层验证之后、锁 master 之前。拿着第 3 章交付的可编辑工程（.timeline / edit 目录）进剪映或 PR，人在这里调整表达与审美（S5/S6）。太早进去是在替 agent 补工程 bug，太晚则改动成本高。

**范围**（S3/S5/S6）：

- **方向与节奏**：hook 成不成立、proof 来得到不到位、CTA 顺不顺；机器只能删停顿、查重复，判断不了情绪转折可不可信。
- **审美**：字幕断行与样式、动画、封面；字幕要到真实平台画幅上看，而不是桌面预览。
- **品牌准确性**：产品颜色、包装版本、是否混入未授权创作者——「长得像」的素材最容易在此翻车。
- **权利审查**：自动化不清权。参考片、音乐、肖像、字体、声音模型的授权记录要人工核对并留存（S3）。

**谁说了算**：agent 产出的镜头清单/EDL 从头到尾只是提案，不是真相（S3/S6）。人在第 3 章镜头清单上批的 review_status 要一路带到交付审计——谁在何时批准了哪一版，是可追溯的批准链，而不是一句「AI 剪的」。

### 6.6 剪映草稿互操作：保守策略

若目标是「让 agent 直接产出可编辑的剪映草稿」，这是全流程版本敏感度最高的一环（S3）。剪映官方功能页确认了智能分割、配音、多轨等能力，但**没有可供第三方稳定依赖的公开官方草稿 schema**（S3）；社区里改草稿的脚本普遍撞版本墙（模板与导出版本各自受限——推断，需按你所用版本实测）。保守做法三条：

1. **adapter 与核心清单分离**：剪映适配只放在最外层，核心镜头清单/EDL 保持工具无关（S3），换工具不重建。
2. **先备份、后测试**：每次剪映更新后，先复制工程、在一次性草稿上验证 adapter，再用于真实项目。
3. **不把「能导进去」当「schema 稳定」**：能成功一次，不等于下个版本还能成功。

### 本章小结

- 「剪完了」由两扇门定义：先过工程验证（结构/字幕绑定/可重开），再过视频验证（容器/解码/转场/声道），顺序不可反。
- 能命令化的验证一律命令化：完整解码冒烟（`ffmpeg -v error -i in -f null -`）性价比最高，freezedetect / silencedetect 补上眼睛易漏的两类问题。
- 逐剪切点自检是第三道网，专查切点附近的跳帧与爆音；字幕遮挡靠「滤镜链最后」从源头防。
- preview 与导出必须同一条合成规则，否则 preview 通过没有意义。
- 人工精修时机在「两层验证后、锁 master 前」，范围是方向、审美、品牌准确性与权利审查；批准权在人，提案权在 agent。
- 剪映草稿互操作是版本敏感区：adapter 与核心清单分离、先备份、一次性草稿测试、不假设 schema 稳定。
