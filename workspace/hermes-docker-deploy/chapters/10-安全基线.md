## 本章要解决的问题

前几章我们把 Hermes 跑成了常驻 gateway，并接入了微信、企微、飞书、QQ。现在这台机器上躺着一堆敏感资产：各平台的 token/secret 明文存在 `~/.hermes/.env`，API Server 可能监听在宿主机端口，甚至被暴露到公网。本章回答一个问题：**这台跑着 Hermes 的机器到底安不安全？** 我们按五层逐层加固：API Server 三件套 → 密钥落盘 → 公网暴露 → Docker 权限 → 平台侧策略（素材：D1 §API env vars / §权限模型、W1、W3、F1、Q1）。

## 10.1 产物 K：API Server 安全三件套

`~/.hermes/.env` 安全版先睹为快：

```bash
# ~/.hermes/.env

# --- API Server ---
API_SERVER_ENABLED=true
API_SERVER_HOST=127.0.0.1   # 仅本机；要外露才改成 0.0.0.0
API_SERVER_KEY=9f3c7a1e...  # openssl rand -hex 32 生成，长度 ≥8 字符

# --- 平台密钥（示例，占位）---
WECOM_BOT_ID=ww1234567890abcdef
WECOM_SECRET=your-wecom-secret
FEISHU_APP_ID=cli_xxxxxxxx
FEISHU_APP_SECRET=your-feishu-secret
QQ_APP_ID=102400000
QQ_CLIENT_SECRET=your-qq-client-secret
```

逐段拆讲（素材：D1 §API env vars）：

- `API_SERVER_ENABLED=true`：打开 Hermes 的 HTTP API Server（dashboard、自定义工具、其他程序都靠它通信）。不需要外部调用的纯聊天部署，可以不设。
- `API_SERVER_HOST=127.0.0.1`：监听在 loopback，**只有本机进程能访问**。只有当你确实需要从局域网或公网调用时，才改成 `0.0.0.0`。
- `API_SERVER_KEY`：访问密钥，官方要求长度 ≥8 字符。别手打密码，用随机命令生成：

```bash
# 终端
openssl rand -hex 32
# 输出 64 位十六进制随机串，例如 9f3c7a1e...，粘到 .env 的 API_SERVER_KEY
```

生成后粘进 `.env`，不要提交到 git，也不要贴到群里或截图发给别人。

[!tip] 大白话
把 API Server 想成**公司前台的门禁**：`ENABLED` 是"这门开不开"，`HOST` 是"这门装在哪面墙"（`127.0.0.1` = 只开在办公室内墙，`0.0.0.0` = 大门开向马路），`KEY` 是访客卡。只给来办事的人发卡、门不开在临街墙，就不会有人浑进来。所以：**外露才设 `0.0.0.0`，设了就一定要配 KEY。**

## 10.2 密钥落盘即泄露面

所有配置过的平台凭证都是**明文**躺在 `~/.hermes/.env` 里（容器视角是 `/opt/data/.env`）。这文件属于数据卷的一部分——换句话说：**数据卷 = 泄露面**。谁拿到 `~/.hermes`，谁就拿到全部平台的 bot 权限（素材：W1、W3）。

[!warning] 易错点
`WECOM_SECRET`（企微 AI Bot 密钥）一旦泄露，攻击者可以**冒充你的企业微信 bot 对外发消息**，比"偷看聊天记录"严重得多——它在别人手里就是一个能替你发言的身份。微信 token、飞书 App Secret、QQ Client Secret 同理，任何一个泄露都是"身份被盗"，不只是"数据泄露"。

应对原则：

- `~/.hermes` 的备份/快照等同密钥备份，必须加密存放；
- 不要把 `.env` 提交进 git（哪怕私有仓库），在仓库根目录加 `.gitignore` 排除；
- 怀疑泄露就**轮换**：到各开放平台重新生成 secret，更新 `.env` 后重启 gateway（素材：W3）。

## 10.3 公网暴露 fail-closed

官方文档没有显式写出 `API_SERVER_HOST` 的默认值，但按实现**默认仅监听本机 loopback**，对外是"关着门"的状态。这是 fail-closed（默认关闭）的设计：**你不主动开，它就不暴露**（素材：D1，注意官方未显式写 `127.0.0.1`，这是按默认行为判断）。

反过来，最危险的配置长这样：

```bash
# ~/.hermes/.env
API_SERVER_ENABLED=true
API_SERVER_HOST=0.0.0.0
# 没有 API_SERVER_KEY！
```

[!warning] 高危
`0.0.0.0` + 无 KEY = 公网裸奔：任何能访问到这台机器 8642 端口的人，都能直接调用 Hermes 的 API。**规则：不配 KEY 就不要开 `0.0.0.0`；配了 KEY 也要确认只有需要的人知道这个 KEY。**

[!tip] 大白话
fail-closed 想成**酒店房门默认锁好**：入住时（`ENABLED=true`）门自动锁上，只有你主动打开（`HOST=0.0.0.0`）才可能有人进来，房卡（KEY）是进门凭证。门可以不锁，但**不锁又把卡挂在门口**，等于请人进来。

## 10.4 Docker 权限最小化

镜像默认把进程降权到 UID 10000（非 root）运行，`/opt/hermes` 安装树是只读的。这是"最小权限"设计：即使容器被攻破，攻击者拿到的也不是 root，能改的只有数据卷（素材：D1 §权限模型）。

两个环境变量的正确用法：

- `HERMES_UID` / `HERMES_GID`：当宿主机 `~/.hermes` 的属主 UID 不是 10000 时，用它对齐宿主机的 uid/gid，避免权限 denied。**这是修权限问题的正路**，而不是 `chmod -R 777`。
- `HERMES_ALLOW_ROOT_GATEWAY`：**不要设**。它允许 gateway 以 root 跑，等于把整套降权设计关掉。只在特殊调试时临时用，日常保持默认不设。

```yaml
# docker-compose.yaml（安全加固片段）
services:
  hermes:
    image: nousresearch/hermes-agent:latest
    environment:
      - HERMES_UID=1000        # 宿主机用户 uid，对齐卷属主
      - HERMES_GID=1000
      # 默认不设 HERMES_ALLOW_ROOT_GATEWAY，保持降权
    read_only: true            # 容器根文件系统只读（可选加固）
```

[!warning] 易错点
遇到 `PermissionError /opt/hermes/.env`，用 `HERMES_UID/GID` 对齐宿主机 uid（或 `chmod -R 755 ~/.hermes`）解决；不要图省事设 `HERMES_ALLOW_ROOT_GATEWAY=1`，那等于亲手拆掉"降权"这层防线（素材：D1 §故障排查 / §权限模型）。

## 10.5 平台侧安全 checklist

密钥之外，每个平台还有一层"谁能跟 bot 说话"的策略。把下面清单逐项勾一遍（素材：W1、W3、F1、Q1、Q4）：

- [ ] **allowlist（白名单）**：飞书 `ALLOWED_USERS`、QQ `QQ_ALLOWED_USERS`、微信 allowlist 策略等，只放行自己人的账号 ID，别用 open/全放行
- [ ] **群策略**：设 `GROUP_POLICY` / `GROUP_ALLOWED_USERS`，明确群里谁能触发 bot
- [ ] **@ 提及**：`REQUIRE_MENTION` / 群@ 触发，避免 bot 在群里被陌生人随意使唤
- [ ] **密钥轮换**：定期（或怀疑泄露时）到各开放平台重新生成 secret，更新 `.env` 后重启
- [ ] **专用号隔离**：尤其是非官方路线（如 NapCat），用一个不绑核心业务的专用 QQ 号 + 白名单 + @触发 + 限流，把风控/封号风险隔离在业务之外（素材：Q4）

[!tip] 大白话
平台侧策略想成**小区门卫**：allowlist 是"只认业主名单"，群策略是"哪个门让谁进"，@提及是"喊我名字我才应"，密钥轮换是"定期换门锁"，专用号隔离是"贵重物品放保险柜、试玩品放仓库"。五件一起上，bot 才不容易被陌生人薅。

## 本章小结

- **API Server 三件套**：`ENABLED=true` + `HOST` 默认本机 + `KEY`（`openssl rand -hex 32` 生成，≥8 字符）；外露才设 `0.0.0.0`。
- **密钥落盘即泄露面**：`.env` 明文落盘，数据卷 = 泄露面；`WECOM_SECRET` 泄露可冒充 bot，怀疑泄露就轮换。
- **公网 fail-closed**：默认仅本机监听；`0.0.0.0` 无 KEY = 公网裸奔，禁止。
- **权限最小化**：UID 10000 降权 + `/opt/hermes` 只读；用 `HERMES_UID/GID` 对齐宿主机，不要开 `HERMES_ALLOW_ROOT_GATEWAY`。
- **平台侧 checklist**：allowlist / 群策略 / @提及 / 密钥轮换 / 专用号隔离。
