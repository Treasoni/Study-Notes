## 第 4 章 登录 VPS（SSH 与 FinalShell）

第 3 章结束时，你手里有一台已开通的 VPS：一串公网 IP，加上服务商给的初始 root 密码（或你自己上传的公钥）。这一章只解决一个问题——把这串 IP 变成你面前的命令行提示符。做完这章，你应该能在本机敲一条 `ssh` 命令、或在图形客户端里点几下就进到服务器 shell；本章不装任何软件、不改任何配置，那些留给第 5 章。

### 4.1 SSH 是什么：一条加密的远程命令行通道

**它是什么、解决什么问题**：SSH 是"把本机的键盘和屏幕安全地接到另一台机器上"的协议。它同时解决两件事：认证（凭什么证明你是这台机器的管理员）和加密（中途被截获也看不出你敲了什么）。

**实体产物**：服务器端的 SSH 由一个叫 `sshd` 的守护进程提供，它读取 `/etc/ssh/sshd_config`。这份文件由 keyword-argument 键值对组成，一行一条，行首为 `#` 的行与空行都按注释处理（来源：C-4 | DESCRIPTION）。它的一小段真实形态就是这样：

```bash
# /etc/ssh/sshd_config（片段）
Port 22
PasswordAuthentication yes
PermitRootLogin prohibit-password
```

**带具体值的例子**：端口方面，`sshd` 默认监听 22 端口（来源：C-4 | KEYWORDS Port）。所以第一次登录只有两种命令形态——把 `<VPS_IP>` 换成第 3 章控制面板里显示的 IPv4 地址：

```bash
# 情形一：服务端仍是默认端口 22
ssh root@<VPS_IP>

# 情形二：服务端改过 SSH 端口（此处假设改成了 2222）
ssh -p 2222 root@<VPS_IP>
```

执行后按提示输入 root 密码（输入过程中不回显，看不到星号属正常）。

| 你的情况 | 用哪条命令 | 命中服务端的哪项配置 |
| --- | --- | --- |
| 端口保持默认 | `ssh root@<VPS_IP>` | `Port 22` |
| 端口被改过 | `ssh -p <PORT> root@<VPS_IP>` | 自定义 `Port` |

> [!tip] 大白话
> 把 SSH 想成"门禁卡 + 对讲机"的组合：门禁卡决定你能不能进门（认证），对讲机保证你说的话外人听不见（加密）。端口 22 就是默认那扇门；门换了编号，你就得在命令里把新编号一起报出来。

### 4.2 图形客户端：FinalShell

不想背命令，可以用图形客户端。以 FinalShell 为例，官网当前标注版本 4.6.3、页面自标更新日期 2025.5.21（来源：B-4 | title）。版本号属易失信息，以观测日 2026-09-23 抓取到的页面为准，请以实际下载页为最终依据。它支持 Windows、macOS、Linux（来源：B-4 | 主要特性）。

按平台选包，注意 CPU 架构别选错（Apple 芯片要选 Arm 版）：

| 平台 | 安装包 |
| --- | --- |
| Windows X64 | `finalshell_windows_x64.exe` |
| macOS Arm（m1/m2/m3） | `finalshell_macos_arm64.pkg` |
| macOS X64（旧款 Intel） | `finalshell_macos_x64.pkg` |
| Linux X64 | `finalshell_linux_x64.deb` |
| Linux Arm64 | `finalshell_linux_arm64.deb` |
| Linux LoongArch64 龙芯 | `finalshell_linux_loong64.deb` |

上表包名与下载地址来源：B-4 | 正文下载地址。Windows 版直链为 `https://dl.hostbuf.com/finalshell3/finalshell_windows_x64.exe`。

> [!warning] 降级表述
> FinalShell 官方只提供下载页与更新日志，**没有官方使用手册**。因此本节的新建连接步骤按通用 SSH 概念组织（依次填 IP、端口、用户名、密码或密钥），不假托官方教程；界面上的按钮文字以你实际下载的版本为准。

客户端自称的特色能力包括云端同步、海外服务器远程桌面加速、ssh 加速、以及带自动补全与命令历史的本地化命令输入框（来源：B-4 | 正文特色功能段）。这些都属于客户端侧的便利，底层走的仍是 4.1 节那条 SSH 通道。

### 4.3 首次登录的高频卡点

1. **密码从哪来**：开通 VPS 后，服务商一般在控制面板与开通邮件里给初始 root 密码；若开通时选了"上传公钥"，则没有密码，改用私钥登录。
2. **端口号**：先按 22 试；若服务商改过端口，控制面板的实例详情里会写明。
3. **首次指纹确认**：第一次连一台新机器，SSH 会打印服务端主机密钥指纹并问你是否信任，核对无误后输入 `yes` 才会继续。若同一 IP 的指纹突然变化（常见于重装系统或换机，详见第 9 章），SSH 会报 `REMOTE HOST IDENTIFICATION HAS CHANGED` 并直接拒绝连接。
4. **连接被拒时先查什么**：`Connection refused` 优先核对 IP、端口、实例是否在运行；`Connection timed out` 通常是连接根本没到服务端，先确认服务商控制面板里实例已启动、SSH 端口已在安全组放行（放行方法见第 5 章）。

> [!note] 本章的边界
> 本章目标只有一个：**能进命令行**。不放行任何端口、不安装任何软件、不改任何系统配置——这些动作全部集中到第 5 章，避免问题排查时无法区分是"进不去"还是"装坏了"。

**本章小结**

- SSH 解决"认证 + 加密"两件事，服务端由 `sshd` 提供，配置在 `/etc/ssh/sshd_config`。
- 默认端口 22；改了端口就用 `ssh -p <PORT> root@<VPS_IP>`。
- 命令行 `ssh` 与图形客户端 FinalShell 走的是同一条通道，只是入口不同。
- 首次连接会核对服务器指纹；指纹突变会导致连接被拒。
- 本章只做到"能进命令行"，不放行端口、不装软件。
