## 笔记定位

- **一句话看懂**：REA（`morluto/rea`，npm 包 `rea-agents`）是一个 **MCP server + CLI**，把「没有源码也把软件拆开看清楚」的逆向能力接给 AI agent；分析在本机跑，结论附证据与局限。
- **目标读者**：逆向零基础、会基本命令行的开发者；想搞清楚「REA 到底是什么、能不能用、怎么几分钟跑通一次」，不要求二进制/汇编背景。
- **读完成果**：能说清 REA 的定位与三层覆盖；认识 22 类可分析目标并知道哪些「零原生引擎」就能跑；能用 `setup` 把 REA 接进自己的 agent；能独立跑通「静态 JS/Electron」与「网站浏览器观测」两条实战；知道 provider/平台限制、安全边界，并能用 CLI 速查表自查。
- **结构主脉**：概念（1–2 章）→ 接入（3 章）→ 实战（4–5 章）→ 进阶与边界（6–7 章）→ 速查收尾（8 章）。

### 第 4 章 实战一：静态 JS/Electron 分析

- **目标**：零原生引擎首跑，端到端跟做「Electron 应用点导出 → 写 CSV」的静态分析，并会读结果。
- **要点**：
  1. 为什么首选：静态 JS 检查只读文件、不运行应用；静态图工作流不执行恢复出的代码。
  2. 场景：点「导出笔记」写 CSV，行为跨 `renderer.js → preload.js → main.js`。
  3. 命令：`analyze-javascript-application <绝对路径> --json`（目录或 `.asar`）。
  4. 期望结果与读法：`literal_channels`/`paired_renderer_transmissions` 等计数在 `normalized_result.summary.ipc`，源码位置在 `normalized_result.graph`。
  5. 大应用注意：完整证据可达数百 MB（例：334 MB 的 Obsidian 证据 → 摘要视图约 10 KB），先落盘再 `inspect-analysis-view` 投影。
  6. 结论链：字面 IPC 调用与唯一匹配的 handler 配对，并识别被暴露的 API；路径由代码推断，运行时捕获可再校验。
- **篇幅**：长（2800–3600 字）
- **素材引用**：§3.7 路径 A（S8:150–151、S8:105–113、S8:155–156、S8:46–48）、S5:23–31、S1:178、S7:303
- **代码示例**：有 —— `npx -y rea-agents@latest analyze-javascript-application /abs/path --json`；`inspect-analysis-view VIEW.json`；小节期望 JSON 输出块（`literal_channels: 1` 等）

### 第 5 章 实战二：网站与浏览器观测

- **目标**：零原生引擎次跑，讲清「点一下发生了什么」的被动观测，并当场划清边界。
- **要点**：
  1. 比喻：像给浏览器装个「行车记录仪」——只记录，不驾驶（不自动化、不远程控制）。
  2. 起远程调试：用独立 profile 起 Chrome，`--remote-debugging-port=9222 --user-data-dir=... <url>`。
  3. 找页面 target：`list-browser-targets http://127.0.0.1:9222 --json`。
  4. 观测窗口：`inspect-web-page <endpoint> TARGET_ID --observation-ms 10000 --include-accessibility-text --include-json-body-shapes --json`。
  5. 期望结果：请求 `GET /examples/notes-web/notes.json`、响应 `200 · application/json`、发起脚本 `export.js`、响应结构 `notes[]`（含 `id`、`title`）→「这次点击请求了 notes.json」。
  6. 边界：这是被动式逆向能力，不是通用浏览器自动化/远程控制面，也不是沙箱或网络隔离；建议用专用 profile、只纳入要检查的 origin。
- **篇幅**：长（2800–3600 字）
- **素材引用**：§3.7 路径 B（S9:57–60、S9:92–93、S9:101–105、S9:121–137、S9:152–162）、§3.8 浏览器边界（S11:9、S11:229）
- **代码示例**：有 —— Chrome 启动命令、`list-browser-targets`、`inspect-web-page`，附期望请求/响应

### 第 6 章 进阶：provider 选择与平台限制

- **目标**：讲清「什么时候需要原生引擎、怎么选、哪些平台支持」，让读者不踩平台坑，且明确这是进阶内容。
- **要点**：
  1. 需不需要引擎：静态 JS 与 .NET 检查只读文件、不运行应用；本章讨论的是需要引擎的目标。
  2. 三类 provider 定位：Hopper（独立商业软件，有自己许可与免费 demo，REA 复用已装 Hopper 并保留）；Ghidra（导入临时库，Linux/macOS 支持只读分析与函数名/入口注释原子修改，Windows P0 仅只读）；IDA（适配既有 IDA MCP server，REA 不安装/升级/激活/授权 IDA）。
  3. IDA 已验证组合：Windows x64 headless 用 IDA 9.3；macOS arm64 用 IDA 9.1；原生 Windows 用 IDA Pro 9.3；其余平台/版本未声称支持。
  4. 选择规则：只有一个可用 provider 时自动选；多个时用 `--provider` 显式指定，`REA_ANALYSIS_PROVIDER` 设默认，MCP 里传 `provider_id`。
  5. 平台限制：进程行为捕获当前需 Linux/macOS 且要有原生 PTY 后端（原生 Windows 不可用）；固件（Binwalk/Unblob）、EVM、部分抓包路径限 Linux。
  6. 自查命令：`doctor --provider ID --json` 诊断引擎就绪，`providers --json` / `capabilities --json` 列能力与 provider。
- **篇幅**：长（2500–3200 字）
- **素材引用**：§3.6（S1:178、S12:3–5、S13:3、S13:143、S13:145、S5:123–131、S17:17–21、S4:310）、§3.5（S5:115–116、S5:143）、§5 未决 #2（Hopper 无独立文档，细节需回 `installation.md#hopper`）
- **代码示例**：有 —— `doctor --provider ID --json`、`providers --json`、`capabilities --json`、`--provider` 示例

### 第 7 章 边界与安全

- **目标**：让读者明确合法用途边界、安全机制，以及「它不是沙箱」这一关键事实。
- **要点**：
  1. 合法用途白名单：安全研究、恶意软件与事件分析、漏洞研究与协调披露、CTF 与教学、互操作性、软件保存，以及对自己拥有或获授权软件的调试/审计。
  2. 明令不帮的用途：绕过 DRM/许可校验/反作弊、外挂与篡改在线服务、未授权绕过认证/机器人防护/访问控制、抄专有软件或复现受保护代码资产、规避 AI 供应商使用政策、转售/共享 AI 账号或 API。
  3. 安全边界机制：Hopper/Ghidra 桥用每会话随机能力令牌，POSIX 走当前用户 Unix socket，令牌经私有会话描述符传递（不走进程参数或环境变量）。
  4. 非沙箱声明：该机制不能防御已以同一操作系统用户身份运行的恶意进程；这些控制只限制意外持久化与资源占用。
  5. 本地性/不上传：REA 在本机分析目标；agent 收到工具结果后，其模型供应商有自己的数据政策。
  6. 浏览器观测呼应：被动、非沙箱、非网络隔离（回链第 5 章）。

## 跨章冻结口径

以下数字与表述全篇必须一致，写作时逐章对齐（同时是并行写作的 dispatch 口径）：

1. **目标类型总数 = 22**（英文 README，S1:153–176）；简体中文表仅 19 行、缺 Go/WASM/SQLite 3 行，以英文为准，不得据此删目标。
2. **「17 client IDs」≠「21 支持客户端」**：21 是 `setup` 可配置的客户端行数（S4:266–288）；17 是 6.4.0 该版本注册表包 dry-run 实际接受的 client ID 数（S4:209–212）。**两者作用域不同，禁止混述为「支持 17/21 个」。**
3. **Node 要求**：`22.x(≥22.19) / 24.x(≥24.11) / 26+`；**23、25 与预发布不支持**（S4:848 / S1:131）。
4. **npm 版本**：`rea-agents 6.4.0`（发布检查日 2026-10-11，S4:207）。持久注册锁定确切版本（S4:811）。
5. **`dsh`（DeepSeek Harness）**：main-only，npm 6.4.0 不含；表述为「main 分支已支持，需等 6.4.0 之后的版本」（S4:290）。
6. **零原生引擎目标集合**：JS/Electron、.NET、Go、Flutter、SQLite（+ 需浏览器的「网站」）。第 2/4/5 章按此口径点名或展开。
