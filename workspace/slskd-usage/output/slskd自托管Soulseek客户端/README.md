## slskd：自托管 Soulseek 客户端实战指南

[slskd](https://github.com/slskd/slskd) 是一个「客户端 + 服务端」形态的 Soulseek 客户端：容器里跑一个常驻进程，你在浏览器里操作它。它把原本必须开着一台 Windows 的桌面客户端，变成了一个可以放在 NAS 或小主机上、用 Web UI 或 API 驱动的自托管服务。

本分册是一份**实战操作指南**，面向已经有 Docker 与自托管应用经验、但没接触过 Soulseek 的读者。目标是走完这条链路：**把容器跑起来 → 能登进 Web UI → 能搜到并下载到文件 → 知道哪些配置会咬人**。

> [!info] 版本锚点
> 本分册的全部配置键名、默认值与行为描述，以 **slskd `0.26.0`**（2026-07 发布）为版本锚点。键名一律以 `src/slskd/Core/Options.cs` 与 `config/slskd.example.yml` 为准——官方文档 `docs/config.md` 在若干处与代码不一致，这些不一致在本分册里被逐条点出，而不是照抄。

### 推荐阅读顺序

**按顺序读 01 → 02 → 03。** 这三章是一条连续的落地线：第 1 章把容器跑起来，第 2 章把账号和共享配好（到此才真正能用），第 3 章把日常操作和配置体系讲透。章内互相引用很多，跳读会碰到不少「见 §x.y」的回指。

**第 4 章可以按需跳到前面读。** 它是一份压缩速览，不是必读：

- **只在家里内网自用**：可以只读 [[04 安全与进阶速览#4.1 默认凭据与远程配置|§4.1 默认凭据与远程配置]]（默认账密与 `remote_configuration`），其余先跳过。
- **准备放到公网**：**先读 [[04 安全与进阶速览#4.8 公网部署最小动作清单|§4.8 公网部署最小动作清单]]**，那张 12 项的清单是发布前的最低要求，每项都指回具体的「为什么」。

### 读之前值得知道的三件事

1. **官方没有 Web UI 操作文档。** 官方 `docs/` 目录下 9 篇正文全是部署、配置、网络与排错，没有任何一篇讲界面怎么点。本分册第 3 章的界面部分因此以**前端源码**为取证依据，正文里按「官方原文（已回源）」「源码可读（已取证）」「源码可读，实际效果需自测」三级标注可信度。
2. **Soulseek 是 P2P 网络，技术之外的责任在你自己。** 本分册只作技术说明：共享什么、下载什么、以及要不要给流量套 VPN，都由使用者自行判断并承担责任。
3. **出处记号怎么读。** 正文里的 `Options.cs:1461`、`docs_config.md:526`、`Dockerfile:107` 是**取证记号**，格式为「文件名:行号」，分别指向 slskd `0.26.0` 的 [`src/slskd/Core/Options.cs`](https://github.com/slskd/slskd/blob/0.26.0/src/slskd/Core/Options.cs)、官方 `docs/config.md`、官方 `Dockerfile`。标了行号的地方都可以按该版本原文逐行核对；M 系列编号（M2–M7）与 O 系列编号在对应的正文小节里就地定义。

> [!tip] 遇到报错先看哪里
> 每一章末尾都有「本章常见坑」一节，按「症状 → 处理 → 出处」组织。启动失败优先查 [[01 部署与运行#1.12 破坏性变更时间线（升级检查清单）|§1.12 破坏性变更时间线]]（旧键名会让应用**直接拒绝启动**，不是报警告）；端口不通查 [[02 账号与共享机制#2.4 入站连接与端口自检|§2.4 入站连接与端口自检]]；「改了没生效」查 [[03 日常使用与配置详解#3.4 配置文件：slskd.yml|§3.4 配置文件]]与 [[03 日常使用与配置详解#3.5 列表合并陷阱（单列一节）|§3.5 列表合并陷阱]]。
