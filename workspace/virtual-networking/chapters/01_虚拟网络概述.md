# 第一章：虚拟网络概述

> 笔记类型：概念笔记 | 篇幅：短 | 代码示例：无

## 本章要回答的问题

物理网络一旦布线完成就难以更改。当我们需要在同一台物理服务器上运行多个应用、多个租户甚至多个操作系统时，传统物理网络暴露出两个根本性问题：**隔离**和**灵活性**。虚拟网络正是为解决这两个问题而生。本章将帮助你建立虚拟网络的整体认知，并预览本系列 10 章笔记的全貌。

---

## 1.1 什么是虚拟网络

### 从物理限制说起

想象一栋办公楼，每个房间只有一根网线接口。如果两个部门要使用不同的 IP 网段、不同的安全策略，物理上唯一的办法是——再拉一根网线。这显然不可扩展。更棘手的是，如果你需要将一台物理服务器同时提供给三个客户使用，每个客户都以为自己独占了一台服务器和它的网络，物理网络本身无法做到这一点。

**虚拟网络的核心思想**：在共享的物理网络基础设施之上，通过软件手段创建出多个相互隔离的逻辑网络。每个逻辑网络有自己的地址空间、转发规则和安全边界，但对使用它的应用或租户来说，它看起来、用起来都和物理网络没有区别。

### 一个类比

> 想象一座城市（物理网络）的街道系统。虚拟网络就像在这座城市上空架设的**高架快速路系统**。不同的车队（租户/应用）可以在高架路上并行飞驰，互不干扰，而它们下方共享同一座城市的道路基础设施。高架路的入口和出口（隧道端点）决定了谁可以进入、从哪里离开。

这个类比中的关键点：
- **共享基础设施**：高架路和地面道路共享同一片土地，就像虚拟网络和物理网络共享同一根网线
- **逻辑隔离**：高架路上的车不会和地面道路的车相撞
- **灵活的路径**：高架路可以随时延伸、改道，无需挖掘地面道路

## 1.2 物理网络 vs 虚拟网络

从几个核心维度对比：

| 维度 | 物理网络 | 虚拟网络 |
|------|---------|---------|
| **拓扑变更** | 需布线、换设备，耗时数天到数周 | 软件配置，秒级完成 |
| **隔离粒度** | 依赖独立线缆和硬件设备 | 同一硬件上可创建数千个逻辑网络 |
| **跨数据中心** | 需要专线或 MPLS | 通过 Overlay 隧道，基于公网传输 |
| **故障域** | 物理设备故障影响范围大 | 逻辑网络可独立迁移、重建 |
| **性能** | 原生硬件转发，近乎零损耗 | 软件封装带来一定性能开销（5-33% 不等） |
| **运维** | 需现场操作硬件 | 集中管理平台，远程自动化 |

> **技术上：** 物理网络的转发路径由硬件布线决定，虚拟网络的转发路径由软件逻辑决定（流表、隧道表、路由表）。
>
> **实践中：** 现代数据中心几乎全部采用虚拟网络。物理网络退化为 "Underlay"（承载层），只负责连通性；所有网络策略都在虚拟网络层实现。

## 1.3 虚拟网络发展历程

虚拟网络不是一夜之间出现的。它的发展经历了四个关键阶段，每一阶段都解决了前一阶段留下的瓶颈。

### 阶段一：VLAN — 二层网络虚拟化（1998 年）

IEEE 802.1Q 标准首次在以太网帧中插入 VLAN Tag，让一台物理交换机可以虚拟出多个逻辑交换机。这是虚拟网络最早、最成功的标准化尝试。

**成就**：实现了二层网络的逻辑隔离。
**瓶颈**：12 位 VLAN ID 只能标识 4094 个网络；且无法跨越三层边界（路由器）。

### 阶段二：VXLAN — Overlay 网络的崛起（2014 年）

VXLAN 将二层以太网帧封装到 UDP 报文中，通过 IP 网络传输。24 位 VNI 支持约 1600 万个虚拟网络，彻底打破了 4094 的限制。同时，**Overlay 网络**的概念成型——在物理 IP 网络（Underlay）之上叠加一层逻辑网络。

**成就**：规模从千级跃升到千万级；虚拟网络与物理拓扑解耦。
**瓶颈**：封装/解封装引入额外 CPU 开销；缺乏集中控制。

### 阶段三：SDN — 控制面与数据面分离（2010 年代）

SDN 的核心思想是：把网络设备的**控制平面**（决定流量怎么走）和**数据平面**（实际转发流量）分离开。控制平面上移到集中的 SDN 控制器，数据平面设备只负责按流表执行转发。

**成就**：网络变得可编程；Google B4 将网络利用率从 30-40% 提升到 95%。
**瓶颈**：OpenFlow 过于底层，产业落地缓慢。

### 阶段四：云原生网络 — 容器与 eBPF（2015 年至今）

Kubernetes 和容器化推动了第三波虚拟网络创新。CNI 规范定义了容器网络接口标准；Calico 引入了 BGP 三层路由；Cilium 利用 eBPF 技术将网络处理直接下推到内核，绕过传统协议栈。

**成就**：微秒级延迟、细粒度安全策略、全面的可观测性。
**瓶颈**：技术栈复杂度指数级增长。

### 发展脉络一览

```
1998 ─── VLAN (802.1Q) ────── 4094 个网络，二层隔离
  │
2014 ─── VXLAN ────────────── 1600 万网络，Overlay 架构
  │
2010s ── SDN ──────────────── 转控分离，可编程网络
  │
2015+ ── 云原生 (CNI/eBPF) ── 容器原生，内核级处理
```

## 本章总结

- 虚拟网络的核心价值是**隔离**和**灵活性**——在共享物理基础设施上创建逻辑网络
- 物理网络靠硬件绑定，虚拟网络靠软件定义；变更速度从数天缩短到秒级
- 虚拟网络经历了 VLAN -> VXLAN -> SDN -> 云原生四个阶段，每一阶段解决前一阶段的瓶颈
- 当前主流架构是 **Underlay + Overlay** 分层：Underlay 是物理 IP 网络负责连通，Overlay 是逻辑网络负责隔离和策略
