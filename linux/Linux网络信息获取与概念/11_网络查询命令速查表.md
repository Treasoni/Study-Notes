## 二、场景链式排查

> 先确认现象，再按顺序执行排查步骤。不要跳步。

### 上不了网（完全打不开网页）

| 步骤 | 命令 | 检查点 |
|------|------|--------|
| ① | `ip link show` | 网卡状态是否为 `state UP`？ |
| ② | `ip -br addr show` | 有没有 IP 地址？ |
| ③ | `ip route show default` | 默认网关是否存在？ |
| ④ | `ping -c 3 <网关IP>` | 网关是否可达？ |
| ⑤ | `dig +short baidu.com` | DNS 能否解析？ |

### 网速很慢

| 步骤 | 命令 | 检查点 |
|------|------|--------|
| ① | `iftop -i eth0 -n` | 哪个连接在吃带宽？ |
| ② | `nethogs eth0` | 哪个进程产生的流量？ |
| ③ | `ip -s link show eth0` | 是否有大量丢包？ |
| ④ | `ethtool eth0` | 协商速率是否正常？（百兆链路跑千兆流量不可能快） |

### 端口被占用

| 步骤 | 命令 | 检查点 |
|------|------|--------|
| ① | `ss -tulnp \| grep :<端口>` | 哪个进程的 PID 占用了端口？ |
| ② | `lsof -i :<端口>` | 进程详细信息 |
| ③ | `fuser <端口>/tcp` | 快速确认（仅返回 PID） |

### ping 不通但 IP 配置看起来正确

| 步骤 | 命令 | 检查点 |
|------|------|--------|
| ① | `ip route get <目标IP>` | 路由表决策是否符合预期？ |
| ② | `ping -c 3 <网关>` | 网关本身通吗？ |
| ③ | `iptables -L -n \| grep icmp` | 是否被防火墙拦截了 ICMP？ |

### 能 ping IP 但不能 ping 域名

| 步骤 | 命令 | 检查点 |
|------|------|--------|
| ① | `dig +short baidu.com` | DNS 返回了什么？ |
| ② | `resolvectl status` | 当前系统 DNS 服务器是谁？ |
| ③ | `cat /etc/resolv.conf` | 配置文件内容是否合理？ |
| ④ | `ping -c 3 8.8.8.8` | DNS 服务器本身是否可达？ |

### 内网机器互相找不到

| 步骤 | 命令 | 检查点 |
|------|------|--------|
| ① | `ip neigh show` | ARP 表里有对方 MAC 吗？ |
| ② | `ping -c 3 <对方IP>` | 三层是否可达？ |
| ③ | `tcpdump -i eth0 arp` | ARP 请求发出去了吗？对方回复了吗？ |

### WiFi 频繁断开 / 信号差

| 步骤 | 命令 | 检查点 |
|------|------|--------|
| ① | `iw dev wlan0 link` | 信号强度 dBm 多少？（< -80 很差） |
| ② | `iw dev wlan0 scan \| grep <SSID> -A 5` | 信道是否拥挤？同信道 AP 多吗？ |
| ③ | `dmesg \| grep -i iwl` | 驱动有没有报错？ |

## 三、命令输出快速解读

### ip/ss 输出

| 看到这个 | 含义 | 怎么做 |
|---------|------|--------|
| `state DOWN` | 网卡未激活 | 检查网线/驱动，或用 `ip link set eth0 up` |
| `state UP` | 网卡正常工作 | 继续排查上层 |
| `LOWER_UP` | 物理层已链接 | 网线/光模块正常 |
| `NO-CARRIER` | 没插网线 | 检查物理连接 |
| `scope link` | 该 IP 仅在本地链路有效 | 需配置 `scope global` 的 IP |
| `scope global` | IP 全局可达 | 正常 |
| `metric 100` | 路由优先级（越小越优先） | 了解即可 |
| `REACHABLE` | ARP 邻居确认可达 | 正常 |
| `STALE` | 超时未确认 | 下次通信时会重新探测，不一定有问题 |
| `FAILED` | 邻居不可达 | 检查对方是否在线 |
| `DELAY` | 正在等待确认 | 短暂过渡状态，正常 |
| `TIME-WAIT` | TCP 连接已关闭，等待 2MSL | 正常，大量则调内核参数 |
| `CLOSE-WAIT` | 对方关闭连接，本机未关 | 应用层 bug，需要修代码 |
| `SYN-SENT` | 连接请求已发出，未收到回复 | 可能防火墙拦截或端口不通 |
| `Recv-Q > 0` | 接收缓冲区有积压 | 应用没及时 `read()` |
| `Send-Q > 0` | 发送缓冲区有积压 | 对端接收慢或网络拥塞 |

### dig 输出

| 看到这个 | 含义 | 怎么做 |
|---------|------|--------|
| `NOERROR` + IP | 解析成功 | 正常 |
| `NXDOMAIN` | 域名不存在 | 检查域名是否拼写错误 |
| `SERVFAIL` | DNS 服务器无法处理 | 换 DNS 服务器重试 |
| `REFUSED` | DNS 服务器拒绝查询 | ACL 限制或配置错误 |
| `+short` 返回空 | 记录类型或查询方式不对 | 检查 A/AAAA/MX 记录类型是否正确 |

### 无线/信号

| 看到这个 | 含义 | 怎么做 |
|---------|------|--------|
| dBm -30 ~ -50 | 信号极好 | 正常 |
| dBm -50 ~ -67 | 信号良好 | 正常 |
| dBm -67 ~ -80 | 信号一般 | 可能影响大文件传输 |
| dBm -80 ~ -90 | 信号差 | 连接可能不稳定 |
| dBm < -90 | 极差 | 几乎不可用，考虑中继或挪动设备 |
| `bitrate: 72.2 MBit/s` | 当前协商速率 | 受距离和干扰影响，不一定是实际吞吐 |

## 四、输出格式选项速查

| 工具 | 简洁模式 | JSON 模式 | 详细模式 | 其他常用 |
|------|---------|-----------|---------|---------|
| `ip` | `-br` | `-j` | `-d`（全部细节） | `-s`（统计）、`-n`（数字） |
| `ss` | (默认) | — | `-e`（详细）、`-i`（TCP 内核参数） | `-o`（计时器）、`-m`（内存） |
| `dig` | `+short` | `+yaml` | `+trace`（递归追踪） | `+noall +answer`（仅答案）、`+stats`（统计） |
| `tcpdump` | `-nn`（不反解） | — | `-v` / `-vv` / `-vvv` | `-e`（链路头）、`-x`（hex）、`-X`（ASCII+hex） |
| `ethtool` | — | `--json` | `-d`（寄存器 dump） | `-S`（统计）、`-i`（驱动）、`-k`（offload） |
| `resolvectl` | — | — | `statistics`（缓存统计） | `query`（查域名）、`flush-caches`（清缓存） |
| `nethogs` | (默认) | — | — | `-d 2`（刷新间隔 2 秒）、`-t`（trace 模式） |
| `iftop` | (默认) | — | — | `-n`（不反解 DNS）、`-B`（字节模式）、`-i`（指定接口） |

## 五、配套工具安装

```bash
# Ubuntu/Debian
sudo apt install net-tools iftop nethogs nload bmon vnstat mtr ethtool iw

# Arch Linux
sudo pacman -S net-tools iftop nethogs nload bmon vnstat mtr ethtool iw

# RHEL/Fedora
sudo dnf install net-tools iftop nethogs nload bmon vnstat mtr ethtool iw
```
