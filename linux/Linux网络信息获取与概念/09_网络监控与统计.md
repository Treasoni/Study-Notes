# 网络监控与统计

## 从"通不通"到"用多少"

前面章节关注的都是"网络能不能用"——IP 配了吗？路由通了吗？DNS 解析对吗？但实际运维中还有一个无法回避的问题：**网络到底用了多少？**

谁在消耗带宽？哪个连接最占流量？这个月用了多少 GB？网卡有没有在默默丢包？这些问题属于网络监控与统计的范畴，它们回答的不是"通不通"，而是"用多少""谁在用""稳不稳"。

> [!note] 本章定位
> 本章与"网络诊断与排障"笔记的边界：本章侧重**带宽统计、流量归因和性能基线**，而非故障诊断。各工具的输出可以用来建立"正常值"认知，当数值异常时再借助排障工具深究。

---

## 网络监控四维分类

监控工具可以从两个维度分类，帮助你快速选择合适工具：

| 维度 | 分类 | 代表工具 |
|------|------|---------|
| **时间维度** | 实时（看当下） | `iftop`、`nload`、`bmon`、`nethogs` |
| | 历史（看趋势） | `vnstat`（日/月/年统计） |
| **粒度维度** | 接口级（总带宽） | `nload`、`bmon`、`/proc/net/dev` |
| | 连接级（谁↔谁） | `iftop` |
| | 进程级（哪个程序） | `nethogs` |
| **统计维度** | 流量（带宽/字节） | `iftop`、`nload`、`vnstat` |
| | 错误（CRC/丢包/冲突） | `ethtool -S`、`ip -s link` |
| **数据源维度** | 内核计数器 | `/proc/net/dev`、`ethtool -S` |
| | 抓包统计 | `tcpdump` + 后分析（第十章） |

实际使用中，**典型组合是**：日常带宽基线用 `vnstat`，实时看流量峰值用 `nload`，定位谁在吃带宽用 `iftop`，定位哪个程序在跑流量用 `nethogs`，检查网卡质量用 `ethtool -S`。

## iftop：按连接查看实时带宽

### 安装

```bash
# Ubuntu/Debian
apt install iftop

# Arch Linux
pacman -S iftop
```

### 基本用法

```bash
# 监听 eth0，不反解 DNS（推荐加 -n，更快更清晰）
iftop -i eth0 -n

# 同时显示端口号
iftop -i eth0 -n -P
```

### 输出解读

运行 `iftop -i eth0 -n` 后，界面如下示意：

```
                    12.5Kb        25.0Kb        37.5Kb        50.0Kb
└───────────────────┴──────────────┴──────────────┴──────────────┴──────────────
192.168.1.100:54321                   => 93.184.216.34:80           12.5Kb  25.0Kb
                                     <=                            50.0Kb  37.5Kb
192.168.1.100:54322                   => 93.184.216.35:443          8.0Kb   12.0Kb
                                     <=                            30.0Kb  28.0Kb
192.168.1.5:443                       => 192.168.1.100:49152        2.0Kb    1.5Kb
                                     <=                             1.0Kb    0.5Kb
└───────────────────────────────────────────────────────────────────────────────
TX:  cum: 12.3MB   peak: 45.0Kb   rates: 22.5Kb  38.5Kb  37.0Kb
RX:  cum: 45.6MB   peak: 150.0Kb  rates: 81.0Kb  65.5Kb  66.0Kb
TOTAL: cum: 57.9MB  peak: 195.0Kb  rates: 103.5Kb 104.0Kb 103.0Kb
```

| 输出元素 | 含义 |
|---------|------|
| 顶部横轴 | 带宽标尺，单位 bit/s |
| `=>` | 发送流量（从本机到对端） |
| `<=` | 接收流量（从对端到本机） |
| 右侧三列 | 最近 2s / 10s / 40s 平均速率 |
| TX/RX/TOTAL | 累计传输量（cum）、峰值（peak）、2s/10s/40s 平均 |
| 底部三行 | 总发送/总接收/总和统计 |

### 交互快捷键

进入 iftop 界面后，按以下键切换显示模式：

| 按键 | 功能 |
|------|------|
| `n` | 切换 DNS 解析开关 |
| `s` | 切换显示源主机名 |
| `d` | 切换显示目标主机名 |
| `p` | 切换端口显示 |
| `1` / `2` / `3` | 按第 1/2/3 列排序 |
| `<` / `>` | 向左/右移动排序列 |
| `l` | 切换屏幕过滤（输入正则） |
| `t` | 切换显示模式（连接视图/发送视图/接收视图） |
| `q` | 退出 |

> [!tip] 排查突发流量技巧
> 当发现带宽异常时，运行 `iftop -i eth0 -n -P`，然后按 `1` 按第一列（速率）排序，立刻就能看到**哪个连接**在跑最多流量。配合 `-P` 显示端口，可以快速判断是 HTTP、DNS 还是其他协议。

### 实用示例

```bash
# 查看 eth0 上最活跃的连接（按流量排序）
iftop -i eth0 -n -P

# 只看特定端口的流量
iftop -i eth0 -n -f "port 443"

# 过滤只显示与特定 IP 的通信
iftop -i eth0 -n -f "host 192.168.1.100"

# 以带宽条形图模式显示（默认）
iftop -i eth0 -n -B    # 以字节为单位显示
```

## nload：简洁流量总览

如果你只需要一个干净、直观的**接口总带宽**视图，`nload` 是最简单的选择。

### 安装

```bash
# Ubuntu/Debian
apt install nload

# Arch Linux
pacman -S nload
```

### 基本用法

```bash
# 监控 eth0
nload eth0

# 监控所有接口，自动切换
nload

# 以 MB/s 显示
nload -u M eth0
```

### 输出解读

```

============================================================
Incoming:

                                            #

     Avg:  0.98 MByte/s                  # #

     Ttl:  456.78 MByte              # # # # # # #
                                                    #
                                        # # # # # # # #

                                            #
     Curr: 0.34 MByte/s                    #
     Avg:  0.28 MByte/s                  # #

     Ttl:  123.45 MByte              # # # # #
                                    # # # # # #
```

左侧是 ASCII 柱状图，右侧数值含义：

| 字段 | 含义 |
|------|------|
| Curr | 当前瞬时速率 |
| Avg | 从启动以来的平均速率 |
| Min | 观察到的最低速率 |
| Max | 观察到的最高速率 |
| Ttl | 累计传输总量 |

### 切换接口

按 `左` / `右` 方向键可以在多个接口间切换。

> [!warning] 单位陷阱
> `nload` **默认以 bit/s 显示**（如 1.23 Mbit/s），但大多数用户期望的是 Byte/s。**习惯性加 `-u M` 参数**，切换为 MB/s 显示，否则数值可能造成误解（差 8 倍）。
>
> 这个问题在常见坑#4 中强调过——`nload` 是少数默认用 bit 而非 Byte 的监控工具。

### 实用示例

```bash
# 最常用：以 MB/s 监控 eth0
nload -u M eth0

# 监控多个接口
nload eth0 eth1

# 设置刷新间隔（默认 100ms）
nload -t 500 eth0     # 500ms 刷新一次
```

## nethogs：按进程归因流量

带宽被吃光了，但是谁吃的？`iftop` 告诉你哪个连接，`nethogs` 更进一步：告诉你**哪个进程（PID）**。

### 安装

```bash
# Ubuntu/Debian
apt install nethogs

# Arch Linux
pacman -S nethogs
```

### 基本用法

```bash
# 监控 eth0（需要 root）
sudo nethogs eth0

# 监控所有接口
sudo nethogs any
```

### 输出解读

```
PID   USER    PROGRAM                                   DEV        SENT     RECEIVED
?     root   .../firefox                                eth0      12.345   56.789 KB/sec
1234  zhq    /usr/bin/ssh                                eth0       0.123    0.456 KB/sec
5678  zhq    /usr/lib/chromium/chromium                  eth0       3.456   12.345 KB/sec
9012  zhq    /usr/bin/apt-get                            eth0       8.901   45.678 KB/sec
───────────────────────────────────────────────────────────────────────────────────────
TOTAL:                                                  24.825  115.268 KB/sec
```

每行一个进程，显示 PID、用户、程序路径、网卡、发送和接收速率。底部汇总总带宽。

### 交互快捷键

| 按键 | 功能 |
|------|------|
| `m` | 切换显示模式（KB/s / KB / B / MB） |
| `s` | 按发送流量排序 |
| `r` | 按接收流量排序 |
| `q` | 退出 |

> [!tip] 发现偷跑流量的程序
> 某次排查发现服务器带宽跑满，`iftop` 看到大量连接到陌生 IP，`nethogs` 直接定位到 `/usr/bin/恶意程序`——`nethogs` 是"谁在偷跑流量"场景下的终极武器。

### 其他用法

```bash
# 设置刷新间隔（默认 1 秒）
sudo nethogs -d 2 eth0

# 追踪特定 PID
sudo nethogs -p 1234 eth0    # -p 不是 PID 过滤，是 promiscuous 模式

# -v 切换显示模式（0=KB/s, 1=总KB, 2=总B, 3=总MB）
sudo nethogs -v 3 eth0
```

> [!note] nethogs 的限制
> - 需要 root 权限（读取 `/proc/<pid>/fd/` 中的 socket 信息）
> - 只能显示**当前活跃**的进程，进程退出后数据消失
> - 在高吞吐环境（>1Gbps）下自身 CPU 开销不可忽略
> - 不记录历史数据，适合临时排查不适合持续监控

## bmon：ASCII 图表 + 详细统计

`bmon` 是带宽监控工具中的"老派选手"——用 ASCII 字符画出实时流量图表，同时提供丰富的数值统计。

### 安装

```bash
# Ubuntu/Debian
apt install bmon

# Arch Linux
pacman -S bmon
```

### 基本用法

```bash
# 监控指定接口
bmon -p eth0

# 监控所有接口
bmon
```

### bmon 的特色

- **趋势可见**：折线图比 `nload` 的柱状图更直观显示流量变化趋势

- **支持模块化输入**：可对接多种数据源

### 其他用法

```bash
# 以人类可读格式显示
bmon -p eth0 -o ascii

bmon -p eth0 -o ascii:no-graph

# CSV 输出（适合记录到文件）
bmon -p eth0 -o csv
```

## ethtool -S：网卡硬件级统计

前面的工具都是"软件视角"——看的是内核网络栈的流量计数。但网卡硬件本身也有计数器：**CRC 错误、冲突、丢包**等。这些数据由网卡固件维护，通过 `ethtool -S` 读取。

### 基本用法

```bash
# 查看 eth0 的硬件统计
sudo ethtool -S eth0
```

### 输出解读

不同网卡驱动输出的字段不同，以下是常见字段：

```bash
# Intel I219-V 网卡示例
NIC statistics:
     rx_bytes: 1234567890123
     rx_packets: 1234567890
     rx_errors: 0              # ← 接收错误
     rx_dropped: 0             # ← 接收丢包（非内存不足）
     rx_missed_errors: 0       # ← 因硬件缓冲满而丢失的包
     rx_over_errors: 0         # ← FIFO 溢出
     rx_crc_errors: 0          # ← CRC 校验错误 ← 重点关注
     rx_frame_errors: 0        # ← 帧对齐错误
     rx_fifo_errors: 0         # ← FIFO 溢出

     tx_bytes: 345678901234
     tx_packets: 456789012
     tx_errors: 0              # ← 发送错误
     tx_dropped: 0             # ← 发送丢包
     tx_carrier_errors: 0      # ← 载波错误（物理层问题）
     tx_collisions: 0          # ← 冲突计数（半双工才有意义）
     tx_fifo_errors: 0         # ← FIFO 溢出
```

### 关键指标解读

| 指标 | 正常值 | 异常含义 |
|------|--------|---------|
| `rx_crc_errors` | 持续为 0 | 网线/网卡硬件问题、电磁干扰 |
| `rx_missed_errors` | 接近 0 | 硬件缓冲不足，流量超过网卡处理能力 |
| `rx_errors` | 接近 0 | 物理层问题 |
| `tx_carrier_errors` | 接近 0 | 网线松动、交换机端口故障 |
| `tx_collisions` | 接近 0 | 半双工模式下正常，全双工出现则说明配置不匹配 |

> [!warning] 捕获瞬间异常
> 硬件错误通常是偶发的、瞬间的。如果怀疑网卡有问题，可以用 `watch` 持续观察：
>
> ```bash
> # 每 2 秒刷新一次，只关注错误计数器
> watch -n 2 'sudo ethtool -S eth0 | grep -E "(error|drop|miss|crc|collision)"'
> ```
>
> 如果某个计数器在短时间内持续增长，说明硬件层面存在问题。

### 网卡复位后计数器行为

`ethtool -S` 的计数器是网卡驱动维护的，**通常随着网卡复位（`ip link set eth0 down` / `up`）而清零**。但这不是标准行为，取决于驱动实现。

### 与 `ip -s link` 的对比

```bash
# 软件视角（内核统计）
ip -s link show eth0

# 硬件视角（网卡固件统计）
sudo ethtool -S eth0
```

两者差异在于：`ip -s link` 看到的是内核网络栈的计数，`ethtool -S` 看到的是网卡硬件的计数。如果内核计数显示丢包但硬件计数正常，说明问题出在内核（如 socket 缓冲区满）；如果硬件计数也丢包，说明是物理层问题。

## vnstat：历史流量统计

前面的工具都是"看了就过了"。如果你需要**追踪一个月用了多少流量**、**每天什么时间段流量最高**，需要 `vnstat` 这样的历史统计工具。

### 原理

`vnstat` 以后台守护进程（daemon）方式运行，默认**每 5 分钟**从 `/proc/net/dev` 读取一次接口流量数据，存入本地数据库（通常位于 `/var/lib/vnstat/`）。因此它可以查询过去任意时间段的总流量。

### 安装与初始化

```bash
# 安装
apt install vnstat

# 启动服务
sudo systemctl enable --now vnstat

# 确认运行状态
systemctl status vnstat
```

安装并启动后，`vnstat` 会自动为你系统上所有非回环接口创建数据库条目。

### 基本用法

```bash
# 查看 eth0 的默认统计（显示当日、当月、全部）
vnstat -i eth0

# 实时模式（类似 nload，约 2 秒刷新一次）
vnstat -l
```

### 输出解读

```bash
$ vnstat -i eth0
Database updated: 2026-07-29 14:30

   eth0 since 2026-07-01

          rx:  45.67 GiB      tx:  12.34 GiB      total:  58.01 GiB
   ─────────────────────────────────────────────────────────────
   monthly:
                     rx      |     tx      |    total    |   avg. rate
     Jul '26       45.67 GiB |  12.34 GiB  |  58.01 GiB  |   180.23 kbit/s
     Jun '26       89.01 GiB |  23.45 GiB  | 112.46 GiB  |   350.12 kbit/s
     May '26      120.34 GiB |  34.56 GiB  | 154.90 GiB  |   470.45 kbit/s
   ─────────────────────────────────────────────────────────────
   daily:
                     rx      |     tx      |    total    |   avg. rate
       today        1.23 GiB |   0.34 GiB  |   1.57 GiB  |   150.23 kbit/s
     yesterday      2.34 GiB |   0.56 GiB  |   2.90 GiB  |   270.12 kbit/s
     2026-07-27     1.89 GiB |   0.45 GiB  |   2.34 GiB  |   220.45 kbit/s
     2026-07-26     2.01 GiB |   0.67 GiB  |   2.68 GiB  |   250.34 kbit/s
```

### 查询指定时间段

```bash
# 查看本月统计
vnstat -i eth0 -m

# 查看今日统计
vnstat -i eth0 -d

# 查看本周统计
vnstat -i eth0 -w

# 查看指定月份
vnstat -i eth0 -m 2026-06
```

### 实时模式

```bash
$ vnstat -l -i eth0
Monitoring eth0...    (press Ctrl-C to stop)

   rx:       312 kbit/s     123 p/s          tx:       156 kbit/s      45 p/s
```

`vnstat -l` 会启动一个连续监测（约 2 秒刷新一次），按 Ctrl-C 停止后，它会显示这段监测期间的总流量。

> [!tip] 建立"正常值"基线
> 持续运行 `vnstat` 一周后，你就知道这台机器的**日常流量基线**——每天大约多少 GB、什么时段峰值。当某天流量突然翻倍时，你立刻就能感知到异常。这是 `iftop`/`nload` 这类瞬时工具做不到的。

## /proc/net/dev：底层数据源

所有监控工具的根基，其实是同一个文件：**`/proc/net/dev`**。

内核网络栈会为每个网络接口维护一组计数器，这些计数器的原始数据就暴露在这个文件中。`iftop`、`nload`、`bmon`、`vnstat` 本质上都是在读取 `/proc/net/dev`，然后做计算和展示。

### 直接查看

```bash
$ cat /proc/net/dev
Inter-|   Receive                                                |  Transmit
```

### 为什么需要专门工具？

直接 `cat /proc/net/dev` 只能看到**累计值**。要得到"当前带宽"需要：

1. 记录 `t1` 时刻的 `bytes` 值
2. 等待 `delta` 秒
3. 记录 `t2` 时刻的 `bytes` 值
4. 带宽 = `(bytes2 - bytes1) / delta`

这就是 `nload`、`bmon` 等工具所做的核心计算——所谓"实时带宽"就是这么算出来的。

### 脚本示例：自己动手算带宽

```bash
#!/bin/bash
# 简易带宽监视器（基于 /proc/net/dev）
IFACE=eth0
INTERVAL=1

# 读取当前计数
read_bytes() {
    grep "$IFACE" /proc/net/dev | awk '{print $2}'
}

# 首次读取
rx1=$(read_bytes)

sleep $INTERVAL

# 二次读取
rx2=$(read_bytes)

# 计算带宽（bytes/s → bit/s）
diff=$((rx2 - rx1))
bandwidth=$((diff * 8 / INTERVAL))

echo "Current RX bandwidth on $IFACE: ${bandwidth} bit/s ($((bandwidth / 1000)) kbit/s)"
```

```bash
# 输出示例
Current RX bandwidth on eth0: 1234567 bit/s (1234 kbit/s)
```

> [!note] 增量计算是核心
> 所有实时带宽工具的核心逻辑都是**"差值/时间"**，区别只在于：
> - 计算后的展示方式（柱状图 `nload` / 折线图 `bmon` / 表格 `iftop`）
> - 是否进一步按连接拆解（`iftop` 解析 `/proc/net/tcp`）
> - 是否按进程归因（`nethogs` 关联 `/proc/<pid>/fd`）

## 各工具适用场景对比

| 场景 | 推荐工具 | 原因 |
|------|---------|------|
| 快速看一眼当前总带宽 | `nload -u M eth0` | 干净、直观、零配置 |
| 想知道哪个连接最占带宽 | `iftop -i eth0 -n -P` | 按连接/端口逐条展示 |
| 怀疑某个程序在偷跑流量 | `sudo nethogs eth0` | 直接显示 PID 和程序名 |
| 看流量变化趋势 | `bmon -p eth0` | ASCII 折线图展示时序变化 |
| 检查网卡硬件是否有问题 | `sudo ethtool -S eth0 \| grep error` | 硬件级计数器，发现物理层问题 |
| 月底报告这个月用了多少流量 | `vnstat -i eth0 -m` | 日/月/年历史统计 |
| 持续采集流量数据建立基线 | `vnstat` 守护进程 + 定期查看 | 长期运行，自动记录 |
| 编写自定义监控脚本 | `cat /proc/net/dev` | 最原始的计数器，无依赖 |

## 本章小结

- 网络监控按**时间维度**分实时（iftop/nload/nethogs/bmon）和历史（vnstat），按**粒度**分接口级（nload）、连接级（iftop）、进程级（nethogs）
- **iftop** 按连接（IP:Port 对）展示实时带宽，快捷键 `n` 关闭 DNS，`P` 显示端口，`1/2/3` 切换排序列
- **nload** 最简洁的接口级总带宽视图，**务必加 `-u M`** 以 MB/s 显示，避免 bit/s 陷阱
- **nethogs** 唯一能按 PID 归因的工具，适合追查"哪个程序在吃带宽"
- **bmon** 以 ASCII 折线图展示流量变化趋势，适合观察"曲线走势"
- **ethtool -S** 读取网卡硬件计数器，`rx_crc_errors` 和 `rx_missed_errors` 是网卡硬件质量的直接指标
- **vnstat** 以后台守护进程记录历史流量，支持日/月/年查询，适合建立流量基线
- **`/proc/net/dev`** 是底层数据源，所有监控工具最终都在读这个文件做差值计算
