# 原始心得输入

主题：Claude Code 项目动态技能发现机制

正文：

在我的技能和subagent过多的时候不会导致CLAUDE.md过于长吗？
如果你的系统里最终沉淀了 20 个 Skills 和 5 个 Subagents，把它们全部写在根目录的 CLAUDE.md 里，不仅会让每次对话的初始加载变得冗长，还会分散大模型的注意力，导致它在处理核心逻辑时"失焦"。

为了保持根目录指令的绝对清爽，我们需要把"静态的硬编码列表"升级为"动态的发现机制（Dynamic Discovery）"。

以下是两种针对中大型 Agent 系统的优雅解法，你可以根据目前的技能数量来无缝切换：

解法一：规则寻址法（Globbing）—— 最适合 Claude Code 的原生姿势
既然 Claude Code 拥有调用本地系统工具（如 Glob, ls, Read）的能力，你完全不需要告诉它每一个文件的具体位置，只需要告诉它"寻找的规则"。

你只需要在根目录的 CLAUDE.md 中写下这样短短一段话，替换掉原来长长的列表：

Markdown
## 动态技能调用机制 (Dynamic Skill Routing)
本系统的所有扩展功能（如 /collect, /update, /moc 等）均已模块化，存放在 `./.claude/skills/` 目录下。
**执行规则：**
当你收到以 `/` 开头的指令，或判断需要执行特定的系统任务时：
1. 不要凭空猜测逻辑，**必须**先使用 `Glob` 或 `ls` 工具列出 `./.claude/skills/` 目录下的可用子文件夹。
2. 找到名称匹配的技能文件夹后，使用 `Read` 工具读取该目录下的 `SKILL.md`（例如 `./.claude/skills/update/SKILL.md`），并严格按照其中的指示执行。
为什么这很优雅？
无论你以后增加多少个技能，根目录的 CLAUDE.md 永远只有这几行字。Claude Code 会像一个聪明的操作员一样，收到指令后先去"仓库"看一眼目录，然后精准拿出对应的说明书。

解法二：引入入口注册表（Manifest / Index）—— 适合极大规模系统
如果你的技能数量多到连使用 ls 命令列出来都嫌长，或者你想为技能添加详细的触发条件说明，你可以采用"二级目录"的策略。

创建注册表文件： 在技能文件夹的根部创建一个清单文件，比如 ./.claude/skills/INDEX.md。把你原来准备写在 CLAUDE.md 里的长列表写在这里。

极简的 CLAUDE.md： 在项目根目录的 CLAUDE.md 里只留下一句话：

"本系统包含多个自定义技能与子代理。执行任何扩展任务前，请先读取 ./.claude/skills/INDEX.md 获取全局技能注册表与调用路径。"

运作逻辑：
大模型每次启动后，如果需要调用工具，会先去读取 INDEX.md 这个比较轻量的文本，拿到路由后再去读具体的 SKILL.md。这相当于在操作系统中注册了环境变量，隔离了主配置文件的复杂度。

最佳实践建议：
对于你目前正在搭建的 Study System 来说，强烈建议直接采用 解法一（规则寻址法）。它利用了大模型自主使用工具的特性，彻底免去了你每次新建一个技能还要去别的文件里注册登记的繁琐步骤，让你做到真正的"热插拔"。
