# 1. 使用 Docker 进行搭建

> [!summary] 一句话看懂
> Suwayomi 是一个**自托管的漫画阅读服务器**：你用 Docker 把它跑在自己的电脑或 NAS 上，它开一个网页界面，你就能在浏览器里搜漫画、看漫画、下载漫画。
> 它自己**不含任何漫画内容**，漫画要靠「扩展库」去各个漫画网站现抓——所以**这一章只负责把它跑起来**，跑起来后里面是空的，这是正常的，加漫画在第 2 章。
>
> 全程 3 步：**建目录 → 写一份 compose → 一条命令启动**。

## 1.1 动手前的两个前提

1. 电脑上已经装好 **Docker** 和 **Docker Compose**。
   - Linux / Windows 安装见 [[Linux-Docker与DockerCompose安装指南-国内网络版]]、[[Windows-DockerDesktop安装指南-国内网络版]]。
2. 能拉到 `ghcr.io` 上的镜像。国内网络这一步**最容易卡住**，先看 1.7 的坑，别等到一半才发现拉不动。

## 1.2 先认识 3 条「固定管路」

Suwayomi 的 docker 镜像里，有 3 个位置是**作者定死的**，你只能改左边、改不了右边。先看懂这张图，后面就不会写错：

```text
你这边（宿主机 / NAS）                     容器内部（suwayomi）
./data/downloads   ──── 挂载 ────►   /home/suwayomi/.local/share/Tachidesk/downloads   # 下载的漫画
./data             ──── 挂载 ────►   /home/suwayomi/.local/share/Tachidesk             # 配置 + 数据库 + 全部数据
4567（可改）        ──── 端口 ────►   4567                                               # 网页界面
```

| 位置 | 写法示例 | 谁说了算 | 能不能改 | 改错的后果 |
| --- | --- | --- | --- | --- |
| 宿主机路径（冒号左边） | `./data` | 你 | 随便改，指向你自己的目录 | 指向空目录 → 换容器后配置全丢 |
| 容器内路径（冒号右边） | `/home/suwayomi/.local/share/Tachidesk` | 镜像作者 | **不可改** | 改了就找不到数据，等于没挂 |
| 宿主机端口（`-p` 左边） | `4567` | 你 | 可改，端口冲突就换 | 记错端口 → 浏览器打不开 |
| 容器内端口（`-p` 右边） | `4567` | 镜像作者 | **不可改** | 改了就连不上服务 |

> [!tip] 大白话
> 把容器想象成一套**随时能拆掉重盖的样板房**，`./data` 是你给它租的**储物间**。程序本身（容器）拆了不要紧——账号、书架、下载的漫画都在储物间里，重新盖上房接着用。但你要是把 `./data` 删了，等于把储物间清空，再启动就是一个全新的空 Suwayomi。

## 1.3 第 1 步：建目录

```bash
mkdir -p ~/suwayomi/data/downloads
cd ~/suwayomi
```

- `~/suwayomi`：整个项目放这里，随便换路径。
- `data/`：对应上面的「储物间」。
- `data/downloads/`：专门放下载下来的漫画。

## 1.4 第 2 步：写 docker-compose.yml

在 `~/suwayomi` 里新建一个 `docker-compose.yml`，内容如下：

```yaml
services:
  suwayomi:
    image: ghcr.io/suwayomi/suwayomi-server:stable
    container_name: suwayomi
    environment:
      - TZ=Asia/Shanghai
    volumes:
      # ⚠️ downloads 这一行必须写在前面，否则下载功能不生效
      - ./data/downloads:/home/suwayomi/.local/share/Tachidesk/downloads
      - ./data:/home/suwayomi/.local/share/Tachidesk
    ports:
      - "4567:4567"
    restart: unless-stopped
```

每一行是什么意思：

| 这一行 | 作用 | 要改吗 |
| --- | --- | --- |
| `image: ...:stable` | 用官方**稳定版**镜像 | 不用改。想尝鲜可换 `:preview`（可能不稳定） |
| `container_name: suwayomi` | 给容器起固定名字，方便 `docker logs suwayomi` | 可改可不改 |
| `TZ=Asia/Shanghai` | 时区，影响日志时间和自动更新 | 建议保留 |
| `./data:/home/.../Tachidesk` | 把数据存到当前目录的 `data` 文件夹 | 想换位置就改左边 |
| `"4567:4567"` | 左边是你访问用的端口 | 端口被占用就改左边，如 `"8080:4567"` |
| `restart: unless-stopped` | 开机 / 重启后自动拉起容器 | 不用改 |

## 1.5 第 3 步：启动

```bash
docker compose up -d
```

第一次会从网上下载镜像，耐心等一会儿。看到类似下面的输出就算成功：

```text
Container suwayomi  Started
```

## 1.6 验证：能打开网页就搭好了

浏览器打开：

```http
http://localhost:4567
```

如果装在 NAS 或别的服务器上，把 `localhost` 换成那台机器的 IP，例如 `http://192.168.1.10:4567`。

想确认运行状态：

```bash
docker compose ps          # 看容器是不是 Up
docker compose logs -f suwayomi   # 实时看日志，Ctrl+C 退出
```

> [!success] 判断标准
> 能看到 Suwayomi 的网页界面 = 搭建完成。
> **此时里面没有漫画是正常的**——Suwayomi 只是个「阅读器」，书得靠扩展库去抓，见第 2 章。

## 1.7 常见的 4 个坑

> [!warning] 坑 1：国内网络拉不动 `ghcr.io` 镜像
> 报错多为超时 / `connection refused`。两个办法：给 Docker 配镜像加速器（见 [[DockerDesktop镜像加速器配置]]），或让 Docker 走代理（见 [[docker进行代理]]）。

> [!warning] 坑 2：目录权限报错（Permission denied）
> 容器内部固定用 UID / GID 都是 `1000`、名为 `suwayomi` 的用户运行，它会去写 `./data`。日志里出现 `Permission denied` 时，把目录交给这个用户：
> ```bash
> sudo chown -R 1000:1000 ~/suwayomi/data
> ```
> 原理见 [[docker里的GID和UID]]。

> [!warning] 坑 3：端口被占用
> 报错 `port is already allocated` → 改 compose 里**左边**的端口，比如 `"4568:4567"`，再跑一次 `docker compose up -d`。

> [!warning] 坑 4：改了配置没生效
> 容器启动时传的环境变量会**覆盖**网页界面里的设置。所以要么全在 compose 里配，要么全在网页里配，别两边打架。

> [!tip] 官方文档
> 本章只覆盖「能跑起来」的最小配置。认证登录、换数据库、自动备份等完整参数见官方仓库：
> ```http
> https://github.com/Suwayomi/Suwayomi-Server-docker
> ```

但是我们搭建后是没有漫画的。
