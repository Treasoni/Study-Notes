# OpenList → WebDAV → Rclone → Docker 全链路实战

> **一句话**：把散落在多个网盘里的文件聚合成一个目录 → 用 WebDAV 把它暴露出来 → 用 rclone 挂成宿主机上的一块"本地磁盘" → 再把这块磁盘映射给 Docker 容器使用。

本分册共 6 册，按上面这条链路的顺序编排。每一册都能独立读，但**按顺序执行**才是一条能跑通的完整路径。

## 链路总览

```mermaid
flowchart LR
    A["多个网盘<br/>阿里云盘 / OneDrive / 本地目录 …"] -->|存储驱动逐条挂入| B["OpenList<br/>Docker 容器<br/>:5244"]
    B -->|每用户开权限| C["WebDAV 服务<br/>/dav/"]
    C -->|rclone mount<br/>FUSE| D["宿主机挂载点<br/>/mnt/…"]
    D -->|bind mount| E["Docker 容器<br/>只读 / 读写"]
```

链路里有两个容易搞混的"挂载"，它们不是一回事：

- **第 4 册的挂载**（`rclone mount`）：把**远端**变成宿主机上的一个目录，靠 FUSE 实现。
- **第 5 册的挂载**（`docker run -v` / `--mount`）：把**宿主机上已存在的目录**交给容器，靠 Docker 的 bind mount 实现。

先有前者，才有后者 —— 顺序不能颠倒。

## 前置要求

- **一台 Linux 宿主机**（或 NAS / WSL），有 `sudo` 权限，Docker 与 Docker Compose 可用
- 会基础 Docker / Linux：能读懂 `docker run`、`-v`、`compose.yaml`、`systemctl`
- 内核支持 FUSE（第 4 册需要），并能安装 rclone
- 第 2 册起需要一个可用网盘账号；**只想打通链路时可以先用本地存储驱动**，把"配置问题"和"驱动问题"分开定位

> [!warning] 执行环境
> **本分册所有命令一律以 Linux 宿主机 + Docker / Docker Compose 为准。**
> Windows 与 WSL 侧**未被任何来源覆盖**（见下方"已知缺口"）。Windows 原生环境尤其注意：`rclone mount` 依赖 WinFsp，且 `--allow-other`、`--uid`、`--umask` 等参数在 Windows 上**不支持**。请把命令放到远程 Linux 宿主机 / NAS / WSL 里执行。

## 学完能做什么

- 独立跑通整条链路：OpenList 聚合网盘 → 开启 WebDAV → rclone 挂载到本地 → 映射给 Docker 容器
- 给任意容器做只读 / 读写两种映射，并说清**为什么这里该用 bind mount 而不是 volume**
- 判断 `PUID`/`PGID` 与 `user:` 两套运行身份机制该用哪一套，以及**为什么同一条链路上可能两套并存**
- 自行定位该链路的常见故障，并且**知道哪些结论有官方依据、哪些只是社区经验或推断**

## 执行顺序建议

1. 按 **1 → 2 → 3 → 4 → 5 → 6** 顺序推进，不要跳册。
2. 第 2 册**先用本地存储驱动**打通闭环，再换成真实网盘。
3. 第 4 册**先按 `--vfs-cache-mode off` 跑通**，再按用途调档；不要在第一次挂载就上 `full`。
4. 第 5 册先用一个**一次性测试容器**验证映射，再换成真正的消费者容器。
