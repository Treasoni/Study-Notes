## [ERR-20261007-024] 引文「出处」列标到了别的文件（行号对得上，句子却在另一份快照里）

**Logged**: 2026-10-07
**Phase**: P4 · run `searxng-hermes` 第 3 章
**Status**: 已修复（成品已改）；预防措施仍是**人工纪律**，未落到自动校验
**Area**: 学习笔记 / 引文纪律

### 错误
第 3 章引文对照第 1 条 `If you want to consume the results as JSON, CSV, or RSS, you need to set the format parameter accordingly.` 的出处写作 `L2-4 · sources/l2-4_settings_search.html:444-445`；该句子实际在 `sources/l2-6_search_api.html:444-445`（l2-4 的 444-445 行是 YAML `default_lang` / `ban_time_on_fail`）。

### 触发场景
同一主题下抓了多份同源快照（`l2-4_settings_search.html` 与 `l2-6_search_api.html` 都是 docs.searxng.org 的镜像页），写者按「记得的行号」跨文件跳了；两个文件行号恰好都可疑地接近，肉眼不易察觉。

### 根因
校验器 `V` 只验「这句英文能否在语料里逐字命中」，**不验「被标为出处的那个文件是否就是含该句的文件」**——同一语料里存在该句子，所以 V 全绿。这类缺陷因此**不被任何自动门覆盖**。

### 修复
父流程逐条 `grep` 回源核对时发现；出处改 `L2-6 · sources/l2-6_search_api.html:444-445` 并复跑校验（V 全绿）。

### 预防措施
1. **已在用**：出处列必须逐行 `grep` 回源确认「这句在不在被标的**那个**文件里」，写进该批次 dispatch 与 P4 验收清单（不只看有没有来源 ID）。
2. **未落地**：给校验器加一档「V-归属」——对出处列 `sources/<file>:<range>`，断言该 quote **在该文件内**命中，而不只在全局语料命中。这是把上条人工纪律变成门禁的唯一办法；在它落地前，本条只能靠人工。

## [ERR-20261007-025] HTML 快照引用的行号基准漂移（去标签文本行号 ≠ 原文件行号）

**Logged**: 2026-10-07
**Phase**: P3 · run `searxng-hermes`
**Status**: 已修复（回写修正 6 处并复跑校验）
**Area**: 学习笔记 / 来源快照

### 错误
`02_deep_research.md` 里 6 处 `sources/*.html:行号` 记的是**去标签后**文本的行号，而留档快照是**原始 HTML 文件**；按记录行号回源会落到别的行。

### 触发场景
需要「给 HTML 快照标行号」的一切场合；docs 镜像页尤其容易——单行内含大量标签，剥标签时一标签是否换行，能让同一句话的「行号」差几十行。

### 根因
抓取留档的是原始 HTML，计数却发生在剥标签后的文本上；两者行号基准不同，却写成同一种 `文件:行号` 指针。

### 预防措施
凡对 `sources/*.html` 记录行号，一律**在原始文件上** `grep -n` 取值；剥标签文本只用于阅读，绝不作行号基准。引用前回源核对一次。

## [ERR-20261007-026] 步骤与 compose 自洽性未核对（把「必经的四步」写在绑定挂载已经免掉的地方）

**Logged**: 2026-10-07
**Phase**: P4/P6 · run `searxng-hermes`（用户读成品时指出，P6 之后修正）
**Status**: 已修复（章文件 + 全部下游副本已改）；预防措施未落到任何自动校验
**Area**: 学习笔记 / 教程步骤与配置自洽性

### 错误
第 3 章把「取回配置」写成开 JSON 的**第一步**（「取回 → 改 → 写回 → 重启」四步），并给出 `docker cp searxng:/etc/searxng/settings.yml ~/searxng/searxng/settings.yml`。但同一册第 2 章给出的两条 compose **都把宿主目录绑定挂载到容器 `/etc/searxng`**（路径① `./searxng:/etc/searxng:rw`、路径② `./core-config/:/etc/searxng/:Z`），容器首启生成的 `settings.yml` 本来就落在宿主——`docker cp` 是自己复制自己。第 2 章另有两处呼应错说法（「取出来改完再放回去」的比喻、「后面的 `docker cp` 按你实际路径来」）。官方 Docker 安装文档该步也是直接编辑宿主文件，没有 `docker cp`。

### 触发场景
教程里出现「必须先在容器里执行某条命令取出 / 写回文件」这类步骤，而该容器**已经**把对应目录挂载到宿主时；或上游示例的步骤写于**未挂载**的部署形态，被整段搬进一个**已有挂载**的配方。

### 根因
写每一步时只对本步的来源负责（该来源确实描述了「未挂载」形态下的四步），没有回头与**本册自己给出的 compose** 对账：我给出的前置条件，是否已经让这一步变成空操作。逐句引文校验查不到这类缺陷——每一句都能回源命中，冲突发生在两句**各自都正确**的话之间。

### 修复
canonical 章文件改正（第 2 章 3 处；第 3 章 3.1 收尾句与整节 3.3，+ 新增脚注 `[^c3-j/k/l]` 给出挂载点与官方出处），`docker cp` 降级为「仅在未挂载时才需要」的条件步骤；机械回填 `_merged.md` / `output/final_note.md` / 7 个 vault 成品 / README 快速上手 / MOC 摘要，并复跑引文校验与结构自检（0 处）。

### 预防措施
1. **写「必须执行某条容器命令」之前，先回读本册自己给出的 compose / 部署配置**，确认这一步在**这个**配方下不是空操作；是空操作就标成可选，并写明它究竟在什么部署形态下才必需。
2. **上游示例整段搬用前，先对齐它的前置条件**与本册的部署形态（挂载了没有、路径是否同一处）；不一致就显式列出差异。
3. 章节验收加一条**脚本查不到**的人工检查：逐条把「第一步 / 必须 / 一定」这类措辞，与本册给出的配置对读，看有没有被自己的配置免掉。
