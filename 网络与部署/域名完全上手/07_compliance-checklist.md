# 第7章 大陆合规速查与 0→1 上线串联

前面的章节把域名从注册、解析到接上 HTTPS 讲完了，但很多人恰恰在最后一步才返工：服务能跑、域名能用，却因为「部署地 vs 备案」没想清楚，或把「域名被墙」和「IP 被封」混为一谈，导致排查方向整个反掉。本章不再讲新原理，而是把全书收束成两张速查表和一条可勾选的上线路径：先看合规怎么判，再分清两种「打不开」，最后照单上线。

## 7.1 合规决策速查表：第一分叉永远是「源站放哪」

一句话判据：**要不要备案，看的是源站服务器的物理位置，不是域名在哪注册、也不是前面套了什么 CDN** [^c7-1][^c7-2]。所以只需要回答一个问题：源站放大陆，还是放境外/香港？

| 源站物理位置 | 备案要求 | 想让大陆访问快 | 想免备案、少折腾 | 呼应章节 |
|---|---|---|---|---|
| **中国大陆** | 必须 ICP 备案（非经营性备案制）[^c7-1] | 备案 + 大陆服务器 + 国内 CDN（或京东云运营的 Cloudflare 中国版）[^c7-2] | 不可行，这是红线 | 第3章 |
| **境外 / 香港** | 不需要备案 | 不保证：大陆访问有延迟与 QoS 波动[^c7-3] | 境外/香港服务器 + Cloudflare 全球版[^c7-2] | 第6章选型 |

> [!warning] 误区：「套 CF 免备案」不成立
> 备案看的是源站（你的服务器）在哪，不是访客从哪个 CDN 边缘进来。把大陆服务器藏到境外 CDN 后面，服务实际仍托管在大陆，一样触碰政策红线；未备案解析到大陆服务器，接入商监测到会直接阻断[^c7-1][^c7-2]。Cloudflare 全球版只适合「源站本来就在境外」的场景。

> [!tip] 大白话：把源站想成餐厅后厨
> CDN 是骑手，源站是后厨。骑手跑得再快，后厨开在大陆就得有经营登记（备案）；想用「境外骑手」绕开，可后厨还在大陆，检查人员查的正是后厨位置。所以先定后厨开在哪，再谈骑手——先定部署地，再谈备案与 CDN。

## 7.2 两种「打不开」要分清：DNS 污染 vs IP 被封

上线后打不开，先别急着改配置——先判断是哪一种「打不开」，因为对象和处理方式完全不同。下面的对照来自社区排障经验，标注为经验参考，不作官方定论[^c7-4]。

| | 域名被墙（DNS 污染/封锁） | 服务器 IP 被封 |
|---|---|---|
| 被切断的对象 | 域名在解析层被污染或拦截 | 到该 IP 的流量被丢弃/拒绝 |
| 典型表现 | 换一台服务器（换 IP）域名仍打不开；`dig` 结果异常或超时 | 换别的域名指向同一 IP 也打不开；用 IP 直连同样失败 |
| 常见应对（社区经验） | 换域名 / 换解析链路，或改用加密 DNS | 换服务器 IP / 换机房 |

> [!tip] 大白话：通讯录被改 vs 号码被拉黑
> 域名被墙像「通讯录被人撕掉或改错」——名字没错，但查不到号或查到错号；IP 被封像「这个号码本身被运营商拉黑」。所以换号码（换 IP）治不好「通讯录被改」，换名字（换域名）也治不好「号码被拉黑」。先分清是哪一层，再动手。

再提醒一句社区共识：备案通过只代表「可以合法接入」，不等于「访问一定有保障」；海外域名在大陆通常能解析，但延迟与 QoS 会有波动[^c7-3]。

## 7.3 0→1 上线串联清单：把全书走成一条可勾选路径

下面把前六章收束成一条路径。每步勾掉后再走下一步，能省掉大量返工。

- [ ] **① 定部署地**：源站放大陆还是境外？这一步决定后面所有分支（见 7.1，呼应第3章 3.1）。
- [ ] **② 选后缀 + 注册商**：长期项目选 .com/.cn/.net 并开自动续费；**大陆源站先确认后缀在工信部批复列表**（第2章 2.4）。
- [ ] **③ 实名模板先行**：个人准备身份证彩色件，企业备营业执照且联系人填个人；实名四要素要能和备案主体对上，别等备案时才补（第3章 3.2）。
- [ ] **④（仅大陆源站）备案**：确认主域到期 >45 天、实名一致、注册商为批复机构后提交；只备主域名，子域免额外备案（第3章 3.3/3.4）。
- [ ] **⑤ 解析托管 + 安全基线**：把 DNS 托管到 Cloudflare/DNSPod/阿里云，域名留在注册商；开 MFA + 禁止转移锁；**若已开 DNSSEC，改 NS 前先关并等 TTL 过期（约 24–48h）**（第4章 4.2/4.5）。
- [ ] **⑥ 按有无公网 IP 接 HTTPS**：有公网 IP + 自有域名 → 第5章 Caddy 或 Nginx+certbot；无公网 IP → 第6章 Cloudflare Tunnel / frp+Caddy / Tailscale Funnel 三选一。
- [ ] **⑦ 上线自查**：用 `dig @1.1.1.1` 与 `dig +trace` 验证记录与 NS 生效；上线前调低的 TTL 记得改回；证书续期链路（deploy-hook / 自动续期）正常；复查锁与 DNSSEC 状态；走 staging 测试过的签发流程记得切回生产（第4章 4.3、第5章 5.4/5.6）。

> [!tip] 大白话：备案是「贴门牌」不是「考执照」
> 大陆非经营性备案是登记制：像开店先把门牌登记一下，材料齐了等审核即可，不是评你内容好坏的发证考试。所以别被「备案」两个字吓住——真正的门槛在前面：后缀要批复、实名要一致、到期要 >45 天，材料齐了就只是等。

## 7.4 常见坑速查与下一步

一句话避坑表（出处可回看对应章节）：

| 坑 | 一句话避坑 |
|---|---|
| 改解析前 TTL 忘调低 | 上线/迁移前把 TTL 调到 60s，改完再调回（第4章 4.3） |
| CNAME 放到根域 | 根域/apex 不能 CNAME，需要时用 ALIAS/ANAME（第1章 1.5） |
| staging 忘切就反复签发 | 测试/续期逻辑先切 Let's Encrypt staging，否则限流最长一周（第5章 5.4） |
| 通配证书走 HTTP-01 | 通配证书只能 DNS-01，需要 DNS 商凭据（第5章 5.4） |
| 换 NS 忘关 DNSSEC | 已开 DNSSEC 时改 NS 前先关、等 TTL 过期约 24–48h（第4章 4.5） |
| 实名没先行就急着备案 | 实名四要素须与备案主体一致；实名失败会进 Serverhold（第3章 3.2） |
| 后缀未批复就规划大陆上线 | 后缀须在工信部批复列表，.org 等未批复不可用于大陆备案（第2章 2.4） |
| 大陆源站套境外 CDN 想免备案 | 备案看源站位置不看 CDN，红线误区（7.1） |

**延伸阅读与开放问题**：学到这里，整本笔记主线已闭环，但仍留了几个可继续深挖的方向：Punycode 编码细节与同形攻击（承接第1章 1.7，需补技术源）；大陆注册局对 DNSSEC 的支持范围（尤其 .cn、算法 13）未核实，「开 DNSSEC 是否影响大陆解析/备案」待确认；Cloudflare Tunnel 免费套餐并发/带宽与 Tailscale Funnel 限速值官方未披露；2026 年 Let's Encrypt 证书有效期与续期策略是否继续演进，也需等官方更新。

**本章小结**：

- 合规的第一分叉是源站物理位置：大陆源站 = 备案 + 国内 CDN/CF 中国版；境外源站 = 免备案 + CF 全球版，代价是大陆延迟与 QoS 波动。
- 「套 CF 免备案」是误区——CDN 改变不了源站所在位置这一事实。
- 「域名被墙」和「IP 被封」是两层阻断，先分清对象再排查（社区经验，非官方定论）。
- 0→1 的关键是顺序：先定部署地，再做实名与备案，再解析与加固，最后按有无公网 IP 接 HTTPS。
- 全书到此闭环；要动手巩固，建议回到第1章 1.6 与第4章 4.3，把 `dig` 排查练成肌肉记忆。
